micron::sstring

Defined in header <micron/string/sstring.hpp>.

Aligned mutable inline string containing public T memory[N] and usize length, with optional checks and no dynamic capacity growth.

Capacity and construction

N includes the normal terminator slot. Alignment is 32 for at least 32 representation bytes, 16 for at least 16, otherwise sufficient for T and usize. Default construction zeroes the buffer. Same-type copies copy N slots; moves copy then zero the source instead of transferring an allocation. Cross-capacity construction can truncate to N-1; selected assignment forms instead require the source capacity to fit statically. Array construction records M-1 and copies the array, so an oversized array with an early null is not treated like the heap constructor's bounded C-string scan.

Operations and complexity

The interface includes forward/reverse find, character-set searches, prefix/suffix/membership, replacement, nonoverlapping counts, ASCII case conversion, trimming, reversal, repetition, substrings, and checked/unchecked access. Single-character scans are linear and selected by compile-time SIMD capability. Small set searches compare up to eight values; larger sets and several not-of overloads build a byte bitmap. Those bitmap paths narrow values to u8 and are not general full-width Unicode set operations. trim recognizes space, tab, newline, and carriage return; fixed_string trim uses a wider six-byte ASCII whitespace set.

Append results and termination

room() excludes the terminator slot. try_append(character) returns false without appending when full. Pointer/count try_append appends min(requested,room) code units, terminates, and reports whether the whole request fitted. Ordinary push_back silently ignores overflow, whereas most checked append/insert operations diagnose it. Not every ordinary append writes a fresh terminator; null_term() explicitly writes memory[length]. try_append_int/hex use 24-element temporary digit arrays, so they are intended for widths whose complete representation fits those temporaries.

Access and invalidation

Member types follow T/usize and pointer/reference aliases; iterator and const_iterator are raw pointers. operator& returns byte storage and addr() returns this. Capacity never reallocates; references are invalidated by object lifetime/move and can change logical meaning after shifts. last() is an element pointer and requires nonempty input. size/len are the stored length; set_size clamps to N-1 with checks enabled and writes a terminator. fast_clear only changes length. The Sf destructor clears through the fixed zeroing kernel.
