micron::rope

Defined in header <micron/string/rope.hpp>.

Persistent character tree with non-atomic reference-counted nodes, value-returning edits, and an optional per-object flat cache.

Representation and ownership

Leaves store contiguous character segments, initially split at 256 T elements; branches store child pointers, reference count, and subtree length. The maximum leaf setting is an element count despite a source comment describing bytes, and some array-append paths can create larger leaves. Initial construction divides input into a balanced tree. Copy retains the root in O(1) and starts with no flat cache; move transfers root/cache. There is no configurable allocator template; node, walker-stack spill, and flat-cache allocation use abc allocation.

Height-dependent complexity

Concatenation normally creates a branch and shares both operands, merging two small leaves when possible. Push-back path-copies the right spine; split-based insert/erase/substr/truncate copy boundary paths and share unaffected subtrees. These operations cost O(H) path work plus copied leaf/payload work for height H. The edit kernels do not rebalance the resulting tree, so H is not guaranteed logarithmic after repeated concatenation or editing. Indexing/front/back traverse a root-to-leaf path. Traversal and flattening cost O(n + number of nodes), with walker stacks using 64 inline entries and heap spill for deep trees.

Flattening and lifetimes

data/cdata/c_str create and cache an n+1-element terminated flat buffer on first use; later calls reuse it. c_str on an empty rope returns a static empty string. Flat publication uses an atomic compare/exchange and releases a losing duplicate allocation. A copied rope shares tree nodes but gets its own cache. flatten() rebuilds a balanced tree from the flat bytes instead of returning the cache itself. for_each_chunk and the tree iterator can traverse without flattening; substring search and several comparisons/bitwise operations can trigger it.

Results and limits

clear/fast_clear and ordinary edit members return new ropes and leave the source value intact; compound operators replace the target with such a value. Pointer/count append consumes n-1 units, treating n as including a terminator, while buffer/slice append consume n units. Insert indices beyond the end are effectively handled by split's end clamp rather than a uniform index error. Iterator last() records the last index but opens the leftmost leaf, so back() is the working last-character accessor. A default end cursor has index zero, which limits APIs using end.index() to derive an endpoint.

Sharing and concurrency

Tree-node reference increments/decrements are plain u32 operations; concurrent copying/destruction/editing of shared nodes requires external coordination. Atomic flat-cache publication alone does not make the ownership protocol thread-safe. Iterators/subtree references do not themselves retain the root; a rope retaining those nodes must stay alive. Reassigning a rope frees its old flat cache, invalidating flat pointers even if another rope still retains shared tree nodes. No normalization or Unicode transcoding is supplied.

micron::rope::const_iterator

Defined in header <micron/string/rope.hpp>.

Forward tree cursor containing a current leaf, leaf offset, global index, and an inline/spill traversal stack.

Operations and lifetime

Dereference and arrow borrow a leaf element; increment advances within a leaf or walks to the next leaf. index() exposes the cursor's global index, used by iterator-taking edits. End is represented by a null leaf, and two null-leaf cursors compare equal. Copying the cursor copies its stack and can allocate when it has spilled. The cursor does not increment node reference counts and has no decrement/random-access interface. iterator aliases const_iterator.
