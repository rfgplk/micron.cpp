micron::immutable_table

Defined in header <micron/maps/itable.hpp>.

A persistent ordered map restricted to integral keys and integral mapped values, implemented as a binary Patricia trie.

Representation and ordering

Both K and V satisfy integral. Signed keys have their sign bit flipped for routing, so unsigned bit order corresponds to ascending signed order. Each branch stores a differing-bit position and two tagged child pointers; a low pointer bit distinguishes leaf nodes, which own the original integral key and value.

Branches compress stretches of equal bits rather than storing one node for every bit. A modification allocates the affected branch path and leaf while retaining unchanged children. Allocations use abc::alloc and matching deallocation. Atomic u32 reference counts saturate at their maximum; a saturated node becomes permanently live.

Member functions and types

insert, set, and emplace return an updated table and replace an existing value. erase and clear also return versions. update transforms an existing value; update_or transforms the stored or supplied fallback value. find is nullable; at reports absence; operator[] returns the stored const value or static V{} without insertion.

capacity() equals the entry count and load_factor() is zero or one. identity() returns the tagged root identity. iterator aliases const_iterator, pins its root, and walks in ascending integral-key order with a stack bounded by sizeof(K)*8. Dereference and arrow expose a const leaf; key() and value() return integral copies. Equality checks root identity first and otherwise compares all ordered entries.

Complexity

At most W=sizeof(K)*8 increasing branch-bit positions occur on a path. Lookup, insertion, and erasure cost O(W); updates allocate O(W) nodes. Copy construction and move construction are O(1); enumeration and content equality are O(n). Last-owner reclamation can be O(n).

Iterator invalidation and thread safety

Iterators retain their version and survive reassignment of the originating handle. Plain returned pointers require an owner of the relevant version to remain alive. Independent immutable handles share atomically counted nodes; concurrent mutation of the same handle is not synchronized.
