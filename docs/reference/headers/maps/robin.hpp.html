micron::robin_map

Defined in header <micron/maps/robin.hpp>.

A move-only, fixed-capacity Robin Hood hash table storing a cached hash, the original key, and a mapped value in each occupied slot.

Template parameters and representation

K is the key, V is move-constructible, Alloc defaults to allocator_serial<>, and Nd defaults to robin_map_node<K,V>. Operations additionally require the copying, assignment, swapping, equality, and hashing used by the selected overload. A custom Nd must implement the same hash, key, value, and construction interface.

Nodes and one-byte probe-distance controls occupy separate allocator-owned blocks. Capacity is rounded upward to a power of two, with a minimum of 16 slots. The default derives its requested slot count from Alloc::auto_size()/sizeof(Nd). A zero control byte denotes an unconstructed slot; occupied bytes store displacement plus one.

Insertion swaps entries when the incoming entry has travelled farther from its home slot. Erasure shifts the following displaced cluster backward, avoiding tombstones. Control scans use the compiled SIMD tier where selected, with scalar probe logic otherwise.

Member functions

insert, insert_hash, emplace, and add replace an existing value. insert_hash_if_absent preserves it and returns {inserted, pointer}. find and find_hash return null on absence; at reports a library error; operator[] inserts V{}. contains, exists, and count test membership, with the latter two returning zero or one.

max_size() is the number of allocated table slots, not the permitted population. Inserting a new key at floor(7*C/8) entries reports a library error; an existing value can still be replaced. Probe distances above 253 or an exhausted traversal also report an error. There is no growth operation; reserve() is deleted.

value_type is Nd, and reference, ref, pointer and their const counterparts refer to nodes. Iterators skip empty slots and expose nodes, including their cached hashes and keys. for_each accepts a node callback or a constrained (const K&, V&) callback. raw_begin()/raw_end() span every slot, including unconstructed storage; use the control bytes or slot_occupied before accessing a slot.

Complexity

Lookup is expected O(1) with distributed hashes and bounded by the representable probe run. Insertion can inspect O(C) slots and perform swaps; erasure can shift O(C) entries in a cluster. Iteration and clear are O(C). Move construction and swap are O(1); copying is deleted.

Iterator invalidation

Insertion may swap existing entries even though it never reallocates. Erasure relocates following displaced entries. Pointers, references, and slot iterators into affected entries therefore do not provide stable element identity. Clear and destruction invalidate all entries. Mutating a node key or hash through a mutable iterator breaks table invariants.

Notes

The header's early hash-collision comment is superseded by the implementation: hash matches are followed by key == key, so different keys sharing a hash remain distinct. Insertion does not roll back swaps if a later probe-limit error or user operation throws. Choose this table when capacity can be planned and relocation is acceptable.

micron::robin_map_node

Defined in header <micron/maps/robin.hpp>.

The default Robin Hood table entry: hash64_t hash, K key, and V value.

Construction and use

Constructors accept a cached hash with moved or copied key/value arguments; a forwarding constructor constructs the mapped value from arguments. Special members are defaulted. This is an entry object, not an owning container or an intrusive link. The map controls its lifetime with placement construction and the corresponding control byte. The stored hash is a filter, not a replacement for original-key equality.

    skip_empty() noexcept

Effects

Equivalent to the following definition. Expressions, calls, initialization, and conditional branches are evaluated in the order specified here.

Equivalent definition
__attribute__((always_inline)) void
    skip_empty() noexcept
    {
      while ( i_ < n_ && ctrl_[i_] == 0u ) ++i_;
    }

Return value

The body contains no explicit return statement. Constructors and destructors do not produce a return value; a void function returns without a value when its body completes.
