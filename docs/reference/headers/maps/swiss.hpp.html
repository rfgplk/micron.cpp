micron::stack_swiss_map

Defined in header <micron/maps/swiss.hpp>.

A fixed-capacity Swiss-style hash table whose control bytes and entry storage are embedded in the map object.

Template parameters and representation

N must be at least 16 and divisible by 16; NH <= N bounds the number of slots inspected from a key's home position. The class default is NH=N; the swiss alias defaults to 16. N need not be a power of two. NH=0 is admitted by the declaration but prevents every insertion.

Entries own K and V in raw aligned storage; only occupied entries are constructed. Each control byte is empty, deleted, or a seven-bit hash fingerprint with its high bit set. Probing proceeds in groups of 16, clips the final partial NH window, and handles wraparound without reading past the control array. SIMD or scalar fingerprint scans filter candidates before key equality.

Copy and move scan the entire table and construct occupied entries. Moving clears the source. The public __swiss_entry, __emplace_tag, control array, raw storage, and size counter are implementation surfaces; changing them bypasses lifetime and lookup invariants.

Member functions

insert, prehashed insert_hash, and emplace preserve existing values and return {false, existing_pointer} for duplicates. A new entry returns {true, pointer}. A full table or exhausted home window returns {false, nullptr}; failure can occur with size() < N. insert_or_assign replaces an existing value. operator[] and load_find report a library error when insertion cannot find a slot.

For K = u64, load treats the supplied integer simultaneously as the stored key and its already-computed hash. exists performs the matching prehashed lookup, whereas ordinary find hashes the integer again. These two key-placement conventions must be used consistently.

find returns a nullable V pointer; at reports absence; contains and count test presence. Erasure destroys the entry and leaves a tombstone. Iterators return pair<const K&, V&> or its const counterpart; arrow operators return pairs of pointers rather than a pointer to a stored pair. for_each visits (key,value) in physical slot order. Both capacity accessors return N.

Complexity

Lookup, insertion, and erasure inspect at most NH slots, so their worst-case table work is O(NH), with expected O(1) work for suitable hashes and spare probe windows. No allocation or rehash occurs inside the table. Construction initializes N control bytes; copying, moving, clearing, and full iteration cost O(N).

Iterator invalidation

Insertion constructs an unused slot and does not move existing entries. Erasure invalidates the erased entry; other slot addresses remain valid. Clear, assignment, movement, and destruction invalidate affected entries. Tombstones remain until reused or cleared; there is no separate compaction operation.

Notes

Use a sufficiently large NH when many keys can share a home neighborhood. The N-slot capacity alone does not guarantee that N distinct keys can be inserted. In-object storage follows the lifetime and location of the containing object; it is not necessarily on a thread's stack.
