micron::posix::pipe_pair

Defined in header <micron/linux/io/sys.hpp>.

Two non-owning descriptor values returned by the raw make_pipe helper.

Result

Fields read_end and write_end identify the two pipe directions. make_pipe uses pipe2(flags); failure places the same negative error in both fields. Success requires the caller to close both endpoints explicitly or adopt them into owners. The record does not set close-on-exec/nonblocking except as requested by flags, and does not supply a complete-transfer protocol. linux/io.hpp reexports the record as micron::pipe_pair.

micron::posix::open_how

Defined in header <micron/linux/io/sys.hpp>.

The fixed three-u64 Linux openat2 request record.

Fields

flags and mode are open parameters; resolve selects restrictions such as no_xdev, no_magiclinks, no_symlinks, beneath, in_root, and cached. The wrapper passes sizeof(open_how), with no extensible trailing-size argument, fallback, or userspace path resolution. Value-initialize unused fields. Availability and validation are determined by the kernel; one call returns a descriptor or negative error.

micron::posix::utimbuf_t

Defined in header <micron/linux/io/sys.hpp>.

An actime/modtime seconds record adapted to the timestamp syscall helpers.

Conversion

utime converts its two time_t values to zero-nanosecond timespecs. utimes/futimesat/lutimes convert timeval microseconds to nanoseconds. Null timestamp input requests current times. The record owns no OS resource; its time_t range is the selected ABI's range even when the eventual syscall accepts time64.

micron::posix::inotify_event_t

Defined in header <micron/linux/io/sys.hpp>.

A Linux inotify variable-length event header.

Record traversal

Fields wd, mask, cookie, and len precede a flexible name array. len includes the kernel-supplied name storage/padding; advance by sizeof(header) + len within the returned read buffer, after validating its extent. The wrapper supplies mask constants and inotify syscalls, not a buffered parser or registration owner. Event names and headers borrow that buffer and become invalid on reuse. Zero len is valid for events without a name. linux/io.hpp reexports the record as micron::inotify_event_t.
