Storage and interface

Requires move construction of T. The anonymous union supplies N raw slots; default construction is empty. Count and list construction reject oversized input, then construct live elements in order. Copying copies live elements; moving move-constructs them into a different inline buffer and clears the source. Copy members additionally require copying, while swap additionally uses move assignment.

Push, emplace, top-relative subscript, top, and pop check capacity/range/nonemptiness. pop() destroys and discards the top and returns void; operator()() moves out the top value and then pops it. move(value) forwards to moved push. Clear destroys active class-type elements and resets length. full, overflowed, and full_or_overflowed compare length with N; max_size is the hard bound.

iterator/const_iterator alias element pointers, but no begin/end or data members are declared. There is no general reserve or resize API. The class does not allocate.

Complexity and iterator invalidation

Push, emplacement, pop, and indexed/top access take constant element work. Copy/move and swap process the live elements, so are linear; clear is linear for class-type elements and constant time otherwise. Storage addresses do not relocate, but pop/clear/assignment end element lifetimes. Move and swap are declared noexcept, so throwing element operations terminate. No synchronization is provided.

Operations and limits

Requires move construction. Count/list constructors reject input beyond N, but ordinary push/emplace do not check capacity, and top/subscript/pop/call-operator do not check logical size. A full push writes outside storage; an empty pop underflows length. The status queries report state and do not repair overflow. max_size() is exactly N.

Copy and move process the active prefix; moved-from sources are cleared. pop() discards while the call operator returns the removed value. Clear destroys active class-type objects. Reserve and swap are explicitly deleted. Pointer aliases are declared, but begin/end/data are absent.

Complexity and lifetime

Single valid LIFO operations are constant time; copy/move/clear follow the same bounds as sstack. Inline storage does not reallocate. A returned value is independent, and references to popped or cleared objects have ended lifetimes. Move operations are noexcept; no synchronization is provided.
