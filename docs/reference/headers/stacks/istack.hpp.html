Nodes and value operations

Each heap node stores a value, a successor, and a non-atomic incoming-reference count. Default construction is empty. Count construction adds defaults; list construction pushes in list order, leaving the final value on top. Construction from a mutable stack preserves its top-to-bottom order. Copy construction retains the head in constant time; moving transfers it and empties the source.

push, default push, pop, and clear return new stack values. Push allocates one node and shares the old head; pop shares its successor and rejects an empty input. Top and the call operator return a checked const reference without removing it. Checked operator[](n) walks n successor links from the top. max_size() returns the largest usize value as a nominal bound, not reserved storage.

Pointer and iterator aliases are const element-pointer types, but no begin/end traversal interface is provided; linked nodes are not a contiguous array.

Complexity and lifetime

Push/pop and copying/moving a new version take constant node work apart from allocation and element construction. Indexed lookup is linear in the index. Assignment/destruction can reclaim an entire uniquely owned chain; clear creates a constant-size empty result without changing the source.

New versions preserve references into retained nodes, but an element reference requires some live version retaining that node. Reference-count changes are not atomic, so concurrent copying/updating/destruction of versions sharing nodes requires external synchronization. Count/list/conversion construction does not wrap its growing raw-node chain in rollback ownership; a throwing later element construction does not establish cleanup of the earlier prefix.
