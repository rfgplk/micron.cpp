micron::pvector

Defined in header <micron/vector/pvector.hpp>.

A persistent variable-length sequence implemented by a shared branching trie with path copying and a compile-time maximum capacity.

Template parameters and representation

T satisfies is_movable_object. K is 1 through 6 and determines branching B = 2^K; H is 1 through 8 and determines trie height. The static capacity is B^H, or 32768 with the defaults. The product must fit usize. Sf, defaulting to true, controls guarded bounds and capacity checks.

The object stores a root pointer and a logical size. Leaves contain B live objects, including defaults beyond the logical end of a partial leaf. Null subtrees denote implicit defaults. Nodes and leaves use abc allocation directly and atomic reference counts. An edit returns a new root and shares every untouched subtree. There is no contiguous data() buffer or allocator template parameter.

Value operations

Default construction is empty and allocates no trie nodes. Count/value, list, pointer/count, C-array, generic-container, and index-generator constructors are available. size() reports logical size; max_size() reports the static hard limit. identity() returns root identity. Copy construction and clone retain the root in constant time; move construction transfers it. Assignment additionally releases the old destination tree.

set, update, push_back, emplace_back, and pop_back return new versions. pop_back writes a default at the former last index and decreases size; it does not prune the branch. insert, erase, resize, append, remove, fill, assign, map, and filter also return values. clear returns a new empty value. append(first, count) where first is const T& treats its address as the start of count contiguous source elements; it does not repeat that value.

operator+(pvector) concatenates. Arithmetic with a scalar transforms every live value. Reductions include sum, product, ordered difference/quotient, min/max, and two forms of reduce. for_each visits live elements with their indices. sort copies live values into a temporary contiguous buffer, heap-sorts it, and builds a fresh trie.

Element access and complexity

at, checked edits, and empty-sensitive members use Sf-guarded checks. get and single-index subscript are always unchecked. Two-index subscript returns a newly built vector containing the requested nonempty range; it is not a view. find returns end() when absent, unlike the null-pointer convention of contiguous vectors.

Lookup and iterator dereference traverse H levels. A point update allocates a path of H nodes, copies the child table at each internal level, and copies or default-constructs B leaf values: O(B * H) work and H allocations. Retaining a version costs constant time, while destroying its final unique nodes is proportional to those nodes and their elements.

An insertion or erasure repeats path copying for the shifted suffix, taking O((size() - position) * B * H) work. Range extraction, append, map, filter, scalar transforms, and resize likewise repeat point updates for their affected elements. Most index-based reductions and searches cost O(size() * H); sum and for_each traverse the tree directly. Sorting uses O(n log n) heap comparisons, O(n * H) value lookup work, and a temporary array of n elements, in addition to the new trie.

Iterator invalidation and thread safety

Producing a new version leaves every retained original version unchanged. A reference into a leaf remains valid while a retained version owns that leaf. An iterator stores a pointer to the owner object and an index only; replacing or destroying that owner changes or ends its observations even if another container still shares the old root.

Atomic reference counting supports separately published versions, not concurrent assignment to one root variable or synchronization of state reachable through T. Updates that copy existing leaves require actual copying support from T despite the broad class-level movable constraint. The current multi-update and temporary-sort paths do not uniformly provide cleanup for every throwing element operation.

An owner-and-index iterator over a pvector; the iterator alias names the same type.

Operations and notes

Dereference and arrow perform a trie lookup and expose a const element. Increment/decrement and index() take constant time. Equality compares only indices, so iterators at the same position in different owners currently compare equal. Cross-owner comparison must not be used to establish range identity. The iterator has no independent root ownership or random-access arithmetic.
