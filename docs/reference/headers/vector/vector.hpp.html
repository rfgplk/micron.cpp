Construction and ownership

The default constructor allocates the allocator's automatic byte extent and starts with size zero. Count constructors initialize live elements; generator and transform constructors first construct n defaults. List construction copies its values. Copy construction allocates for the source's logical length and copies its elements; spare capacity need not match the source. Move construction transfers storage and resets the source's pointer, capacity, and length.

The specialization for a movable, noncopyable element type deletes container copy construction and copy assignment, copying append, copying insertion, and repeated-value assignment. Its move insertion and emplacement paths retain the contiguous representation. Interfaces whose selected body requires copying an element remain unavailable for a noncopyable T even where a declaration is present.

Construction from chunk<byte>&& adopts allocator-compatible aligned raw storage and starts with logical length zero. It does not infer or construct live elements from the byte count. Destruction destroys the recorded live prefix and releases the allocation through Alloc.

Element access and insertion positions

With Sf == true, subscript, at, itr, and indexed get/cget check the live length. at_n(pointer) accepts a pointer through the one-past-end position. Two-index slicing of the ordinary specialization checks a nonempty range against capacity, not live length; a valid capacity range can contain unconstructed slots. That overload is deleted in the move-only-element specialization.

Index-based insertion into a nonempty vector requires n < size(). Iterator insertion accepts end() for appending. On an empty vector, the insertion overloads take their special append path. insert_sort requires that the existing sequence is sorted and places the new value after existing equal values.

Complexity

Access, size queries, and append within capacity take constant time apart from element construction. Reallocation relocates the live prefix and is linear in size. Insertion and erasure are linear in the shifted suffix, copying append is linear in the appended count plus any reallocation, and linear search is linear in size. Slice construction and into_bytes allocate and copy their selected range. Repeating remove for several values makes a separate compaction pass for each value.

Copy construction and cloning are linear in source size. Move construction and storage exchange are constant time; move assignment also destroys the destination's former values. Clearing is linear in the recorded live storage, including zeroing for trivial types. drop and fast_clear are constant time for trivially destructible elements. Sorting follows the selected sorting algorithm; no stability guarantee is added by the container.

Iterator invalidation and notes

Reallocation may invalidate every pointer, reference, and iterator into the old buffer. Without reallocation, append preserves existing element addresses but changes the end position; insertion and erasure change the suffix beginning at the operation's position. Clearing ends the live prefix while retaining its allocation. Move and swap transfer storage to another owner. Previously returned slice copies own separate allocations and are unaffected.

No synchronization is provided. Sf == false removes the guarded checks, including guarded self-assignment handling. No general strong exception guarantee is established for element-throwing operations: shared append/emplace code increments length before the element construction completes, and suffix shifting assumes suitable move operations.
