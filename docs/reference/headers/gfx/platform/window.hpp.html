micron::gfx::platform::window

Defined in header <micron/gfx/platform/window.hpp>.

Owns an X11 window or a Wayland xdg-toplevel while borrowing a display and optional integration hooks.

Parameters and callbacks

Construction takes a live display, initial dimensions, title and optional window_hooks. x11_visual_choice supplies a borrowed XVisualInfo pointer plus an opaque extra value for a visual-selection hook. window_hooks contains caller-provided native Wayland create/resize/destroy functions and user data; it does not own those functions or that data. Without a visual hook the X11 path tries 24-bit and then 32-bit TrueColor visuals.

The set_resize_func, set_close_func, set_expose_func, set_focus_func, set_move_func and set_visibility_func templates adapt compile-time callable values, with or without a window reference. Their bridges are noexcept. A throwing callback terminates through that boundary. Native Wayland resize hooks run before the internal resize callback and then the user resize callback. There is one internal resize callback slot, used by GL context integration.

Dimensions and event processing

X11 resize requests take effect asynchronously through server events. Wayland resize changes the local logical dimensions and invokes its native resize hook; it does not impose a size on the compositor. Wayland render_scale multiplies logical dimensions to produce rounded render dimensions and accepts values from 1 through 8. The wrapper does not translate keyboard, pointer or touch input into a general input-event interface.

poll_events drains the native backend's available work. The X11 implementation drains the shared display event queue and can consume events for other windows. Wayland dispatches pending protocol work through the display connection. Event callbacks receive borrowed references and must not retain references beyond the corresponding object lifetime.

Lifetime and invalidation

The window is neither copyable nor movable. Its display must remain alive at the same address. Native surface/window handles cease to be usable after destruction; GL contexts, EGL native windows and Vulkan surfaces using them require an appropriate earlier destruction order. The wrapper contains no GPU-completion wait or shared ownership of its dependants.

  __build_x11(i32 width, i32 height, const char *title)
  {
    auto *xd = __dpy->as_x11();
    if ( !xd ) throw except::logic_error("gfx::window: display is not x11 but backend says x11");

    if ( __hooks.x11_pick_visual ) {
      auto choice = __hooks.x11_pick_visual(*xd, x11_lib(), __hooks.x11_user);
      __x11_visual = choice.visual;
      __x11_extra = choice.extra;
    } else {

      auto &lib = x11_lib();
      if ( !lib.XMatchVisualInfo ) throw except::library_error("gfx::window: x11_pick_visual hook absent and XMatchVisualInfo unavailable");
      const int xscreen = xd->screen();

      if ( !lib.XMatchVisualInfo(xd->display(), xscreen, 24, TrueColor, &__x11_visual_storage)
           && !lib.XMatchVisualInfo(xd->display(), xscreen, 32, TrueColor, &__x11_visual_storage) ) {
        throw except::library_error("gfx::window: XMatchVisualInfo found no TrueColor visual");
      }
      __x11_visual = &__x11_visual_storage;
    }
    if ( !__x11_visual ) throw except::library_error("gfx::window: no X11 visual picked");

    __x11.create(*xd, __x11_visual, width, height, title);
  }
