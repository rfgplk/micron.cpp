micron::coro::async_mutex

Defined in header <micron/tasks/async_sync.hpp>.

A nonrecursive coroutine mutex storing unlocked/held sentinels or a stack of waiting awaiters in one atomic word.

Acquisition and release

co_await lock() acquire-claims the unlocked sentinel or links the awaiter and suspends. try_lock() makes one strong attempt. Unlock either publishes unlocked or removes the newest waiter and hands it ownership before resuming it. Waiting is LIFO, so older waiters can starve. Unlocking an unlocked mutex is unsupported and interprets the sentinel as an invalid waiter pointer.

There is no native-thread owner check, recursive count, timed acquisition, or automatic cancellation. Uncontended operations have constant atomic work; CAS retries and scheduler submission can wait. Use co_await coro::scoped_lock(m) for an owning guard after acquisition.

Lifetime and resumption

Suspended operations retain pointers to waiter nodes inside coroutine frames. The primitive, frame, and any referenced data must remain live at stable addresses until the operation completes. These primitives have no general cancellation registration or destructor that removes a queued waiter. Destroying a waiting task can therefore leave a dangling registration.

Wakeup submits a frame to the global engine when one exists, otherwise resumes it inline on the notifying thread. Callers must allow continuation execution and reentry around notification. Internal list locks spin briefly; suspending the coroutine does not eliminate all spinning from the implementation. No FIFO or starvation bound follows from an awaitable interface.

micron::coro::manual_reset_event

Defined in header <micron/tasks/async_sync.hpp>.

A coroutine event that retains set state until explicitly reset.

Operations

Construct with an optional initial set flag. Await returns immediately when set, otherwise it pushes a waiter onto the atomic stack. set() exchanges the set sentinel and resumes every detached waiter; repeated set is a no-op. reset() changes only the set sentinel back to unset, leaving an existing pending waiter stack intact. is_set() acquire-loads a snapshot.

State changes are constant atomic work; set takes linear work in the number of detached waiters. The event supplies no counted permits, value result, timed wait, or cancellation/unlink operation. Copying and moving are unavailable.

micron::coro::async_semaphore

Defined in header <micron/tasks/async_sync.hpp>.

A coroutine permit counter with a spinlocked LIFO stack of waiting acquisitions.

Permit and abort protocol

Start with a nonnegative permit count. Awaited acquire() decrements the counter; a positive prior count returns true immediately, otherwise it registers a waiter. release(n) adds one permit at a time and marks/resumes each owed waiter. try_acquire consumes one positive permit, and try_acquire_many(n) consumes up to the requested positive count. They return false/zero after abort.

There is a registration interval between the awaited counter decrement and waiter insertion. A releaser seeing that negative reservation busy-waits until a waiter appears, so release is not a bounded nonblocking operation and can stall a native worker if the waiter cannot complete registration. Arbitrary negative initial counts likewise cannot be used as unregistered debt.

abort() permanently sets the aborted flag, wakes registered acquisitions with false rather than a permit, and posts until the count reaches at least 256. It is a close/wake mechanism, not reset; it can perform work proportional to waiters plus those extra posts. Release with nonpositive n performs no additions. Counter overflow is unchecked. acquire after abort returns false immediately.
