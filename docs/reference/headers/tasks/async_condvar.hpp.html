micron::coro::async_condvar

Defined in header <micron/tasks/async_condvar.hpp>.

A coroutine condition wait that releases and later reacquires an async_mutex.

Condition protocol

wait(m) returns a lazy task<void>; the caller must own m when that task runs. It registers an internal node, unlocks the mutex, waits for notification with a signal/park handshake, then awaits mutex reacquisition before completion. Test the actual shared predicate in a loop while owning the mutex; notification itself carries no predicate value.

notify_one() signals the newest waiter; notify_all() detaches and signals all. Notify without waiters is not remembered. The handoff handles notification during suspension registration, but does not add an ownership check to the supplied mutex. Notification work is constant for one or linear for all, apart from list contention and engine submission.

Lifetime and resumption

Suspended operations retain pointers to waiter nodes inside coroutine frames. The primitive, frame, and any referenced data must remain live at stable addresses until the operation completes. These primitives have no general cancellation registration or destructor that removes a queued waiter. Destroying a waiting task can therefore leave a dangling registration.

Wakeup submits a frame to the global engine when one exists, otherwise resumes it inline on the notifying thread. Callers must allow continuation execution and reentry around notification. Internal list locks spin briefly; suspending the coroutine does not eliminate all spinning from the implementation. No FIFO or starvation bound follows from an awaitable interface.
