Type reference

micron::unbounded_channel

Defined in header <micron/tasks/unbounded_channel.hpp>.

An allocated FIFO linked-node channel with coroutine receive waits and no space backpressure.

Storage and operations

push(T) checks close, allocates one value node, appends it under an internal spinlock, and posts the item semaphore. It returns a bool rather than a task. pull() awaits an item, removes the head under the lock, then moves/destroys its node and returns chan_pull<T>. try_pull(out) returns a status after a permit/closed check and direct list removal.

close() marks closed and aborts the item semaphore; existing nodes can drain. Push only checks close before allocation/append, so an in-flight producer can append after close or a prior drained observation. There is no capacity bound beyond allocation resources. An exception while moving a removed value can bypass node deletion, while try-pull's noexcept interface cannot propagate a throwing assignment.

Destruction deletes remaining nodes but neither wakes nor waits for consumers; all registrations must finish first. Each normal push/pop has constant list work plus allocation/deallocation, permit handoff, and element costs. Destruction is linear in buffered values. Copying/moving are unavailable.

Lifetime and resumption

Suspended operations retain pointers to waiter nodes inside coroutine frames. The primitive, frame, and any referenced data must remain live at stable addresses until the operation completes. These primitives have no general cancellation registration or destructor that removes a queued waiter. Destroying a waiting task can therefore leave a dangling registration.

Wakeup submits a frame to the global engine when one exists, otherwise resumes it inline on the notifying thread. Callers must allow continuation execution and reentry around notification. Internal list locks spin briefly; suspending the coroutine does not eliminate all spinning from the implementation. No FIFO or starvation bound follows from an awaitable interface.
