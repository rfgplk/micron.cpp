micron::arena_resource

Defined in header <micron/memory/allocation/allocator_types/arena_resource.hpp>.

An instance-owned monotonic byte resource with optional caller-provided initial storage, marks, and bulk rewind. It is neither copyable nor movable.

Construction and storage

The default resource acquires upstream blocks lazily, using a page-sized configured block request. A block-size constructor changes that request without allocating immediately. An external chunk<byte> or pointer/length constructor borrows the initial span; the default overflow policy is arena_overflow::fail. arena_overflow::upstream permits spill blocks. External storage must remain valid for the resource's lifetime and is never freed by it.

allocate(bytes, alignment) and allocate<Alignment>(bytes) reserve an exact byte grant from a retained block. Runtime alignment defaults to alignof(max_align_t) and must be a nonzero power of two. allocate_objects<T>(count) checks multiplication and reserves aligned raw storage for count objects without constructing them.

resize can extend or shrink the last bump in place; otherwise it reserves replacement storage and copies a bounded prefix. It checks that the old pointer lies in owned storage, rather than proving that the descriptor identifies one exact live allocation. deallocate does not recover bump space.

Marks and bulk lifetime

mark() returns a marker containing resource identity, block identity, cursor offset, generation, and serial. rewind(marker) returns false for an invalid or foreign marker. A successful rewind restores the marked cursor and rewinds later blocks, retaining their storage. It invalidates allocations and marks created after the selected mark. The selected mark can remain reusable.

Marker invalidation retains at most eight serial ranges; exhausting this bookkeeping advances the generation and conservatively invalidates existing markers. reset rewinds every block and invalidates every marker. release frees owned blocks, rewinds external storage, and invalidates every marker. Destruction releases owned blocks. None of these operations invoke destructors for allocated objects.

Complexity and invalidation

A current-block allocation and eligible last-allocation resize perform constant work. Slow allocation, membership queries, aggregate metrics, reset, and release can traverse the block chain. Rewind traverses relevant blocks and marker bookkeeping. Replacement resize adds linear copying in preserved bytes.

Allocation alone preserves earlier grants. Replacement resize leaves the old monotonic storage reserved but transfers the caller's logical allocation to the new grant. Rewind, reset, release, and destruction end the validity of the affected grants. Resource storage must outlive all containers that use it. Shared metadata locking does not protect object accesses or make concurrent bulk invalidation safe.

micron::arena_allocator

Defined in header <micron/memory/allocation/allocator_types/arena_resource.hpp>.

A stateless container-allocator adapter bound to the resource reference supplied as its template argument.

Effects

create/allocate, resize, and destroy/deallocate forward to the referenced resource, preserving its alignment and failure behavior. allocation_extent is the requested byte count, auto_size is 16 bytes, and recommend uses checked doubling bounded below by the requested minimum. Telemetry is forwarded to the resource.

The referenced resource must have suitable static storage duration and outlive every dependent container. Ordinary container destruction calls the resource's no-op individual release; bulk resource operations remain the caller's responsibility. Every copy of this allocator specialization addresses the same resource. It adds no synchronization beyond the resource's selected mode.
