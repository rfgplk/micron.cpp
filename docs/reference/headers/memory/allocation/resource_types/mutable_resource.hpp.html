Type reference

micron::__owned_memory_resource

Defined in header <micron/memory/allocation/resource_types/mutable_resource.hpp>.

An internal owner of typed raw storage with a constructed-element count, used as a base for containers.

Storage and related resource bases

length counts constructed elements; the inherited capacity counts available element slots. Sized construction reserves storage and starts with zero length. Default construction uses at least the allocator's automatic byte request and one T slot. nullptr construction leaves storage empty.

Adoption checks alignment and that the exact allocator grant is reconstructible from element capacity, then clears the supplied chunk. Copy is deleted. Move transfers storage and length; move assignment destroys the destination's recorded elements before releasing its old raw storage.

InterfaceDescription
__mutable_memory_resource<T, Alloc>Owning base constrained to copy- and move-constructible T; the resource itself remains noncopyable.
__mutable_memory_resource_move_only<T, Alloc>Owning base for move-constructible elements.
__immutable_memory_resource<T, Alloc>Related owning base; its name does not seal memory or impose operating-system read-only protection.

Capacity changes

expand(elements) grows only; realloc(elements) can shrink. Trivial elements use the allocator's byte resize operation. Nontrivial elements are placement-constructed in replacement storage using a nothrow move, a required move when copying is unavailable, or a copy otherwise. Successfully replaced old elements are destroyed and the old storage is freed. Shrinking destroys discarded elements.

When exception handling is available, a failed construction destroys the constructed destination prefix and releases its storage. A throwing move without a copy alternative can leave an already moved source prefix changed. These functions do not default-construct extra elements merely because capacity increased.

recommended_capacity converts element counts to checked byte counts, applies allocator recommendation, and rounds back up to elements. has_space tests remaining element slots. data/operator* expose the reconstructible byte allocation, and swap exchanges descriptors and length.

Lifetime and complexity

The destructor and free() release raw storage without destroying length elements. The enclosing container must first destroy its live objects. Calling accept on a resource that already owns storage replaces its descriptor without releasing that prior storage; adoption requires an empty/resource-managed state.

Descriptor moves and swaps are constant time. Nontrivial relocation is linear in retained elements, plus backend allocation/release; trivial relocation follows the byte allocator's cost. Reallocation invalidates old pointers when the address changes. The bases supply no object-level synchronization.

  __extent_matches(chunk<byte> memory, usize required_bytes = 0) noexcept
  {
    if ( memory.ptr == nullptr ) return memory.len == 0 && required_bytes == 0;
