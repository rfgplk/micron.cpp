micron::coro::executor

Defined in header <micron/thread/coroutine/executor.hpp>.

A structural concept requiring frame submission and an observable worker count.

Requirements

For an executor E, e.submit(coro::__frame_base*) must return void and e.worker_count() must be convertible to u32. The concept does not check frame ownership, scheduling fairness, exception behavior, or shutdown protocol. A submitted frame must remain live until all possible resumptions are finished.

micron::coro::work_stealing_executor

Defined in header <micron/thread/coroutine/executor.hpp>.

A non-owning concrete executor referring to a coroutine engine.

Operations

executor_tag is void. Default construction has no engine; submitting then traps. submit(frame) forwards to the engine and worker_count() returns its n, or zero for null. default_executor() starts the global runtime and returns a view of its engine. Copying the executor copies its borrowed pointer; stopping/restarting the runtime invalidates previously obtained engine views.

micron::coro::any_executor

Defined in header <micron/thread/coroutine/executor.hpp>.

A non-owning erased executor containing an object pointer and two function pointers.

Operations

make(e) binds any object satisfying executor, retaining its address without allocating or extending its lifetime. submit(frame) invokes the erased submit function and traps if unbound. worker_count() returns zero when unbound. These methods are noexcept, so an exception escaping a custom executor cannot propagate through them. Copies retain the same borrowed executor; that executor and its scheduling state must outlive all uses.
