Type reference

micron::io::coro::file

Defined in header <micron/io/coroutine/file.hpp>.

A move-only descriptor owner with an independent unsigned logical cursor, recorded name, and append policy.

Ownership and lifecycle

State is fd_t, u64 cursor, sstr<128> name, a cached classification, and an append flag. Default construction is invalid at cursor zero. Adopting fd_t transfers responsibility for closing it and records the optional name; it does not duplicate the descriptor. The path constructor performs a synchronous open, while open_file is the awaited factory with additional inode checks. Copying is deleted; moving transfers descriptor/name/cursor/append state and invalidates the source. Move assignment synchronously closes its previous descriptor first.

close and destruction call synchronous posix::close for a nonnegative descriptor, ignore its error, invalidate the handle, and reset cursor/cache. release returns fd_t and invalidates/reset state without closing; the caller then owns the descriptor. Neither waits for outstanding member tasks. The recorded name is descriptive, not a live directory entry; name returns a borrowed reference and as_path constructs a path value.

seek(off) and rewind change only the logical cursor, with no lseek or range validation. stat and size synchronously fstat; size returns a signed size/error. valid/bool test fd>=0; fd/raw_fd expose the stored descriptor. Accessors and cursor changes cost O(1), while name/path copies and system calls add their own costs.

Byte operations and positions

read/write use full loops at the logical cursor and advance it by positive counts. Appending write uses offset -1 and leaves the logical cursor unchanged. read_at/write_at use the explicit supplied offset and do not change the cursor. read_some/write_some use one capped attempt and update the same cursor/append policy after success.

Full file read/write operations pass explicit offsets without the some-path seekability translation. A nonseekable descriptor adopted as file can therefore fail positional full reads/writes; use fd_io/current-position helpers for streams. Some operations classify regular/block descriptors as seekable and use offset -1 for other kinds. They choose direct syscalls only for nonblocking pollable descriptors; blocking descriptors can still suspend in the ring even under a some name. External changes to descriptor flags/classification are not reflected after the cache is filled.

Typed representation and reads

Input/output familyRepresentation and limits
Strings and contiguous trivially-copyable elementsRaw value_type bytes; write string length excludes its terminator. Reads consume the remainder, floor byte count to complete elements, set supported logical length, and discard trailing incomplete-element bytes while returning the full byte count
Node/nested or nontrivially-copyable iterable containersOwned temporary framed serialization buffer; reads fetch the entire remainder, unframe one value, and return all fetched bytes rather than the decoder's consumed prefix
Trivially-copyable noncontainer objectsRaw sizeof(T) object representation; a short read returns -io_error after possibly overwriting an output prefix
Character array literalN-1 raw bytes for char[N], omitting the last array element

Whole-value storage and costs

read<T>() default-constructs T and returns option<T,error_t>; read(T&) updates a borrowed object and returns bytes. Bulk/framed reads use fstat size when positive and greater than the offset; otherwise they allocate an initial 64 KiB probe buffer and double it until EOF. Growth copies accumulated bytes and can allocate O(B) temporary storage for B bytes. A probe-path error discards its temporary accumulation, while a known-size full read can report a positive prefix after a later failure.

Bulk reconstruction reserves elements+1 when reserve exists, checks max_size when available, and changes length through set_size/_buf_set_length when supported; a merely contiguous type must still supply sufficient writable capacity and compatible reconstruction. A framed read treats empty remainder as zero-byte success without invoking the decoder. Raw object representation is neither canonical serialization nor a portability contract. Total typed cost includes bytes, output growth, and the selected serializer/decoder work.

Returned read values own their members. User output references and writer inputs remain borrowed through completion. file name references are invalidated as associations by owner move/replacement/destruction; no element or file iterator is supplied.

Callbacks and rewriting

write(fn) calls a nonvoid nullary producer synchronously, retains its returned local value through the awaited write, and returns bytes. read(fn) deduces one input argument, reads it, advances the cursor, then synchronously invokes fn; void maps to unit_t and a nonvoid result is wrapped in option. These member callbacks do not automatically await a returned task.

modify rejects append mode, reads from offset zero, applies an in-place void(T&) or returning transform, computes the serialized size, writes at zero, checks the exact byte count, and truncates only when the new representation is shorter. On success it sets cursor to new bytes. It is not atomic, durable by default, or rolled back after callback/write/truncate failure.

read_with allocates one fp_window=16384 byte buffer and calls fn after each full-window read; write_with reuses that capacity for producer output and rejects oversized/short-write results. each_line/fold_lines allocate a line cursor and reusable string, process to EOF, and update the file cursor only on overall success; a later error does not undo callback effects. Streaming callback cost is added once per delivered chunk/line, and total memory includes the longest line where relevant.

Durability and extent operations

sync/datasync await fsync with ordinary/data-only flags; truncate awaits ftruncate; allocate awaits fallocate with mode zero. These return i32 status, not transferred-byte counts, and do not adjust the logical cursor. advise splits its range into at-most-1-GiB fadvise requests and attempts one zero-length request when len==0. There is no synchronous fallback here for an unsupported ring opcode. Destruction alone does not perform fsync.
