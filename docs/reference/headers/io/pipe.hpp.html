micron::io::pipe_result_t

Defined in header <micron/io/pipe.hpp>.

A simplified pipe-transfer result containing ok, bytes, and eof.

Result limits

Explicit bool returns ok. read_bytes/read set eof only when their accumulated count is zero, so a short read followed by EOF can return eof=false. Errors set ok=false and bytes=0 even after an earlier partial transfer; no errno field is retained. Writes leave eof=false. A true result can be short if the underlying write returns zero.

micron::io::upipe

Defined in header <micron/io/pipe.hpp>.

A move-only owner of both anonymous-pipe endpoints.

Construction, flags, and shutdown

Default construction creates a blocking pipe with both directions open; the bool constructor selects close-on-exec through pipe2. Failure throws. Destruction closes whichever ends remain owned; close_read/close_write disarm individual endpoints. Move transfers both fds/open flags and invalidates the source. Raw public fd[2], get, and read_fd/write_fd expose borrowed numbers; direct mutation can violate ownership flags.

Nonblocking and close-on-exec setters use separate F_GET*/F_SET* calls. The combined setter attempts both ends even when the first fails. Capacity methods use the kernel F_GETPIPE_SZ/F_SETPIPE_SZ and return their result. Dup-to helpers create descriptors outside this owner; callers must close those separately. Keeping any write-end duplicate open prevents EOF. Writing more than the available pipe capacity before arranging a reader can block even when both ends belong to this object.

Including this header registers a hosted constructor that ignores SIGPIPE process-wide; the retained boot function does the same. This changes process signal disposition rather than only this pipe. No per-object restoration is provided.

Transfers

write_bytes/read_bytes loop to their byte request but do not retry EINTR; a later error loses the progress count in pipe_result_t. peek consumes one byte; it is not a nondestructive lookahead. String write/read use element width, while call-operator string forms transfer size bytes. Read targets keep their original logical size; read_all appends until a nonpositive read and conflates error/EOF. Wide-string read_all counts returned bytes as elements and is unsuitable for that representation.

Stream output rewinds the source unconditionally after the internal write attempt, including failure/short output. Stream input reads one allocated window up to available capacity; drain_to_stream loops until capacity, EOF, or error. read_buffer returns the full requested-size buffer, zeroing its unread tail, without returning actual bytes read. It cannot distinguish an empty read from an all-zero payload.

each_chunk retries EINTR, treats EAGAIN as a drained nonblocking pipe, and returns an accumulated positive total instead of a later error. write_with calls a producer on a reusable window, rejects produced length beyond capacity, and similarly favors a previous positive total over a later write error. Its write loop can have transferred a partial current chunk without reporting that part if the next syscall fails. Splice/tee/sendfile methods are single possibly partial kernel operations; tee duplicates data without consuming it.

Complexity and lifetime

No user heap buffer is retained by the pipe owner itself. Chunk/drain/read_buffer operations allocate their named windows; string accumulation can grow without a fixed bound. Transfer work is linear in copied bytes plus syscall/producer/callback costs, with unbounded blocking latency. Callback windows are valid only during the callback. Move/close invalidates borrowed endpoint assumptions; object methods are not synchronized against each other or external closes.

micron::io::npipe

Defined in header <micron/io/pipe.hpp>.

A move-only named-FIFO descriptor owner with optional ownership of the filesystem entry.

Creation and lifetime

The (name, permissions) constructor creates a new FIFO then opens it read/write; an existing path is an error. The (name, bool, flags) constructor ignores the bool value and opens an existing path with the supplied flags, default read/write, without owning the entry. Owned entries are unlinked on destruction after close. If creation succeeds but the subsequent open throws, construction does not complete and the created FIFO is not removed by this destructor.

Move transfers fd/path/unlink ownership; move assignment closes/unlinks the destination's previous resources first. close leaves path ownership active. unlink ignores its syscall result and disarms future removal even if unlink failed. reopen closes the previous fd before attempting a new open. Nonblocking/cloexec settings are explicit fcntl changes. Path access/permission helpers query the stored pathname, which may have been renamed or replaced independently of the open fd.

Opening read/write keeps an internal writer present, so a blocking read_all can wait indefinitely rather than observe EOF after outside writers close. open_npipe_read uses blocking read-only; open_npipe_write uses nonblocking write-only and can fail without a reader. These factories open existing paths, not create them.

Transfers and invalidation

Byte read/write use complete-request loops without EINTR retry and simplify errors to pipe_result_t. String/container read writes only the existing logical extent and does not resize; read_all appends and conflates nonpositive read outcomes. The wide-element and callback/partial-progress limitations match the corresponding upipe loops. read_buffer returns its original requested size and no actual length. Stream output rewinds even after failed transfer. Splice is a single kernel operation.

The owned name can allocate and moving/replacing it invalidates references returned by path. Access to raw fd is borrowed; closing externally can produce a later double close after fd reuse. No method synchronizes descriptor flags, reads/writes, lifetime, or unlink with other threads. FIFO byte-stream framing and application message boundaries remain the caller's protocol.

micron::io::pipe_pair_t

Defined in header <micron/io/pipe.hpp>.

Two owned anonymous pipes arranged for parent-to-child and child-to-parent traffic.

Endpoint protocol

p2c and c2p initially retain both ends. parent_side closes p2c's read end and c2p's write end; child_side closes their opposites. These calls must be made in the appropriate copies after process creation, not both on the same object. child_side(true) dup2-redirects the remaining ends to stdin/stdout then closes them, ignoring dup2 errors; stderr is unchanged. Destruction closes still-owned endpoints. Copy is unavailable and moves follow the two upipe members. No process creation, wait, cancellation, or message framing is included.
