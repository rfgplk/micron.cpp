micron::io::output_sink

Defined in header <micron/io/echo.hpp>.

The structural printing sink protocol: put(span), put(char), and flush results convertible to max_t.

Protocol

The character span count is bytes. The concept does not require complete output, error retention, a destructor flush, or thread safety. fd_backed_sink additionally detects target() convertible to fd_t for selected native-wide output. echo_target recognizes fd_t, stream specializations, and a class whose const fd() returns exactly fd_t. A stream_view alone is not a recognized echo target.

Custom sinks own their buffering/error/lifetime rules. printk and format_to borrow a sink during the call, and format_to does not flush it. User formatters/callbacks can allocate or throw; the protocol adds no exception boundary.

micron::io::stdout_sink

Defined in header <micron/io/echo.hpp>.

A stateless adapter to the global buffered standard-output path.

Standard sink adapters

put(span) returns a negative fwrite result or the requested byte count. put(char) calls void fput and returns 1, so it cannot report its write failure. flush calls void fflush and returns 0. stderr_sink is the corresponding stderr adapter. Neither owns an fd, isolates global buffer state, locks, or guarantees that a returned count has reached the device; newline/explicit flushing follows the global buffering policy.

micron::io::fd_sink

Defined in header <micron/io/echo.hpp>.

A borrowed runtime descriptor with an inline CAP-byte printing buffer and sticky error.

Buffering and errors

CAP defaults to 1024 and must be positive for character insertion. put flushes when necessary and directly writes large spans; internal output retries EINTR. flush clears the buffer even on failure or zero/short output and records the first negative result in public __err. Destruction does not flush, and copying duplicates the pending text while aliasing the descriptor. A caller using the adapter directly must inspect flush/__err and arrange final flush.

The sink owns only its inline characters, never the fd. Redirected echo functions construct one, render, flush, and inspect sticky error before returning. A nonnegative short flush can still be reported using the formatted requested count. Work is linear in emitted bytes plus syscall time, with fixed stack storage and no sink allocation. Concurrent use requires external synchronization.

micron::io::stream_sink

Defined in header <micron/io/echo.hpp>.

A borrowed adapter that appends rendered bytes to a stream specialization.

Bounded output

It stores a stream reference, appends each span/character, and returns the requested byte count. The underlying stream silently clips ordinary append to remaining capacity, so a positive sink count does not prove retention of every byte. flush is a no-op; no descriptor output occurs. The referenced stream must outlive the adapter. Mutation and hook execution follow stream's contracts.
