micron::contract

Defined in header <micron/sync/contract.hpp>.

An asynchronous condition check with borrowed atomic requirements and a selectable violation policy.

Construction, signing, and lifetime

contract<S, T> allocates a virtual condition callback and stores a queue of pointers added by require. requirement_t<T> aliases atomic_token<T>. sign() or sign(enforcing_callback, args...) claims the signed flag and launches an arena go worker capturing this. The worker polls all requirements and the condition until success or a millisecond duration budget expires; a nonpositive budget evaluates once. It records violation and release-clears the signed flag last.

wait() waits for that flag to clear, then applies the policy to a recorded breach. Destruction also waits before deleting stored callbacks; strict and lenient modes do not throw a recorded violation from the destructor. A requirement object and every referenced callback input must outlive the worker. duration, enforce, and require modify ordinary state and must not race a signed worker.

Move construction transfers callback pointers, requirements, and token values but cannot retarget a running worker's captured this. Move only an unsigned, quiescent contract. satisfy() merely clears the signed flag; it does not stop or join the worker, so calling it while a worker is live can let destruction race that worker. Signing again does not clear an earlier violated flag, and failed worker creation can leave the signed flag set.

Violation policy

contract_state is lenient, enforcing, or strict. Lenient records the breach and returns. Enforcing invokes the optional enforcing callback and aborts when it returns true. Strict reports a future error from wait(). Callbacks must return a value convertible to bool and must not let exceptions escape the background worker. This facility is unrelated to language contracts or automatic precondition checking.

Polling work is linear in the number of requirements per sample plus the condition cost. Callback storage is allocated, and wait duration also depends on worker scheduling and callback termination.

template<contract_state S, typename T, typename Fn>
void
violation(contract<S, T> *c, Fn *fn)
{
  (void)c;
  if constexpr ( S == contract_state::lenient ) {
    (void)fn;
  } else if constexpr ( S == contract_state::enforcing ) {
    // enforcing: run the (optional) enforcing callback; if it returns true the breach is fatal -> abort; abort() is noreturn and safe to

    exc<except::future_error>("contract::violation(): strict enforcement, contract violation detected");
  }
}

~contract()
  {
    // if contract has been signed, the worker is in flight; it is deadline-bounded so this terminates;
    // it clears is_signed on completion. we never re-enter the worker, only observe its result
    while ( is_signed.get(memory_order::acquire) ) cpu_pause<5000>();

    }
  }

Equivalent definition
void
  __spawn_worker(void)
  {
    go([this]() {
      // __duration <= 0 => evaluate once, no waiting. otherwise treat __duration as the total budget (ms)
      const fduration_t budget = this->__duration;
      const fduration_t deadline = micron::steady_clock::now() + (budget > 0 ? budget : 0);
      // poll slice: a fraction of the budget, clamped to a sane [1ms, 50ms] range
      const fduration_t slice = budget > 0 ? (budget > 50.0 ? 50.0 : (budget < 1.0 ? budget : budget / 4.0)) : 0;
      bool ok = this->__all_satisfied();
      while ( !ok && budget > 0 && micron::steady_clock::now() < deadline ) {
        sleep_duration(slice);
        ok = this->__all_satisfied();
      }
      if ( !ok ) this->__violated.store(true, memory_order_release);
      // release the contract last; ~contract/wait() observe this with acquire and then surface a breach
      this->is_signed.store(false, memory_order_release);
    });
  }
