Storage and ordering

Requires a regular object type and the same positive extent and storage-size bound as array. Construction creates all N elements from T{} and starts with logical size zero. Container construction inserts each source value; the source need not be sorted. static_size and the public constant __length equal N; there is no max_size() member.

insert(value) uses right bisection with operator<, then shifts the suffix by assignment. A new value follows equivalent values. It rejects insertion when full. erase(i) checks the active index and shifts later values left. It decreases logical size without destroying the now-unused final slot. All N objects remain alive until array destruction.

Copy and move operations process the complete underlying extent and copy the logical size. A move resets the source logical size to zero.

Complexity and iterator invalidation

Index access and size/full/empty queries are constant time. Bisection uses logarithmically many comparisons, followed by up to size() assignments, so insertion and erasure are linear in the active suffix. Building from an arbitrary n-element container by repeated insertion is quadratic in the worst case. Copying, moving, and destruction are linear in N.

Storage does not relocate. Insertion and erasure change the values represented by positions at and after the changed index. The old end position no longer marks the logical end after a size change.

Notes

Const subscript checks the active size. get/cget check capacity N instead, and mutable data and iterators allow direct edits that can break sorted order. front/back require a nonempty logical sequence. The mutable range has begin/end; const traversal is provided through cbegin/cend. There is no public search or bisection member.
