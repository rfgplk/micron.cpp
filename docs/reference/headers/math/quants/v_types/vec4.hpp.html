Type reference

micron::vector_4

Defined in header <micron/math/quants/v_types/vec4.hpp>.

An owning fixed vector of 4 floating-point components with named members and componentwise arithmetic.

Storage and construction

T defaults to float and must satisfy is_floating_point_v. Public components are x,y,z,w. Default construction zeros every component; the scalar constructor accepts exactly 4 values. An initializer list of another length reports library_error. Copy and move operations copy numeric components; a move does not clear the source.

Components are embedded in the object. Alignment is 16, 32, 64, or 128 bytes according to N*sizeof(T), capped at 128; object size can include padding. There is no allocation, subscript operator, data() member, or iterator interface. Component references remain associated with their original object through assignment, and cease to be valid when that object is destroyed.

Dimension-specific operations

Pair/triple/four-component swizzles include xyzw, wzyx, repeated coordinates, zwxy/yxwz, and rgba/color permutations. quat, dquat, and dlquat are aliases of this componentwise vector class. Their multiplication is componentwise and does not call the dedicated Hamilton multiply function.

Arithmetic and complexity

The common named-vector operations below apply to this type: arithmetic and relational operators act on each component, dot/norm/distance reduce components, and swizzles return independent values. Every arithmetic, comparison, reduction, or swizzle costs O(N) or less with N=4; elementary functions additionally perform their scalar function on each selected component. N is fixed by the type, so these operations use bounded local storage.

Normalization and geometric operations use the named-vector epsilon conventions described below. They do not provide the NaN-tagged error convention of quaternions::quaternion. Choose this type for named-coordinate arithmetic and its dimension-specific geometric operations.
