micron::math::montgomery

Defined in header <micron/math/arbint/modular.hpp>.

An owning modular context for an odd nonzero arbuint modulus, precomputing R and R² residues and a word inverse.

Representation and operations

U must satisfy arb_unsigned. The context owns modulus md, R mod md, R² mod md, inverse word, and active modulus limb width n; R=2^(n*limb_bits). Construction rejects zero/even modulus with domain_error. Copies own independent values; returned modulus()/one_form() references borrow the context.

to_form(a) first reduces an ordinary a and returns a*R mod m. from_form(a), also named reduce(a), multiplies by R^-1; it is not an ordinary a%m operation. mul and sqr accept reduced Montgomery-form residues and return Montgomery form. Their spreading step truncates an argument to n limbs rather than validating/reducing arbitrary wider operands.

pow accepts an ordinary base and an unsigned integer/u64 exponent and returns an ordinary residue. It calls the sliding-window engine from the modulus, so it does not reuse every precomputed context value for exponentiation. Exponent zero gives one modulo m; modulus one gives zero.

Complexity and scratch

Setup computes word inversion and two power-of-radix divisions. A product costs selected multiplication plus O(n²) Montgomery REDC; conversion to form can include ordinary division. Exponentiation uses O(exponent_bits) modular squares/products plus an odd-power table of 2^(window-1) residues, capped by the configured limb budget.

Every operation creates fresh scratch, embedded for bounded U and heap-backed for dynamic U. Bounded context instantiation rejects a configured exponentiation frame exceeding 256 KiB. Context copies do not retain pointers into another context; mutation/replacement invalidates borrowed modulus references.

micron::math::barrett

Defined in header <micron/math/arbint/modular.hpp>.

An owning modular context for any nonzero arbuint modulus, with a normalized modulus and precomputed reciprocal.

Storage and operations

The context owns U modulus plus two wide_type values for normalized modulus and reciprocal, a limb width, and a normalization shift. For bounded U, wide_type adds one limb of magnitude capacity; dynamic U stays dynamic. Zero modulus reports domain_error. modulus()/inverse() return borrowed references.

reduce(a) performs ordinary a%m by division when necessary; it does not apply the reciprocal reducer directly. mul/sqr use reciprocal product reduction after spreading operands to n limbs. Supply reduced operands; arbitrary wider U values are truncated by spreading rather than automatically reduced. pow accepts an ordinary base and returns an ordinary residue using the Barrett sliding-window engine.

Reciprocal setup uses basecase division below its threshold and Newton refinement with exact correction above. Product reduction uses multiplication, shifted high pieces, and correction subtraction loops. Its cost is multiplication-scale plus those correction passes; each call allocates/embeds fresh scratch. The same 256 KiB bounded exponentiation-frame limit applies.

One-shot modular arithmetic

mulmod/sqrmod form a full-width temporary product before ordinary division, avoiding the bounded high-level product's early truncation. powmod chooses Montgomery for odd moduli and Barrett for even moduli by default; MICRON_ARBINT_POWM_ENGINE can override selection and must remain compatible with the modulus. Signed powmod rejects negative exponents, uses |m|, normalizes negative bases, and returns a nonnegative residue.

Unlike reusing a context for a chain of form products, one-shot calls rebuild their work state. The unsigned powmod(a,u64,m) overload first constructs U from the exponent, so a bounded U narrower than 64 magnitude bits truncates that exponent. Context pow(a,u64) instead supplies the full native exponent through raw limbs. The modular routines do not return overflow or convergence statuses; domain errors and integer storage behavior follow their documented branches.
