micron::math::arbuint

Defined in header <micron/math/arbint/unsigned.hpp>.

An owning nonnegative multi-precision integer with selectable magnitude width, multiplication solver, and allocator.

Storage and special members

The parameters are Bits=0, Solver=solver::automatic, and Alloc=allocator_serial<>. value_type is mpn::limb_t; width_bits, bounded, and cap_limbs describe storage, while capacity() is measured in limbs. Dynamic storage is vector<limb_t,Alloc,false>. Bounded storage embeds ceil(Bits/limb_bits) limbs, an active u32 count, and alignment selected from limb alignment, 32, or 64 bytes according to capacity.

Copying a dynamic value duplicates active vector storage; a bounded copy copies its entire embedded store. Dynamic movement transfers vector storage; bounded movement moves/copies embedded limbs, without redirecting pointers into the destination. No separate reserve member is provided. Public __raw_ensure, __raw_finish, and direct mutable limbs/subscript access expose representation management and require the caller to maintain normalized size and width invariants.

Arithmetic and conversion

Default construction yields numeric zero. Integral construction first converts through the native argument's unsigned counterpart: a negative i32 argument becomes its 32-bit unsigned representation before any configured-width truncation. Integral conversion takes low limbs and casts, without an overflow result. Comparison with a native integral value follows that same unsigned conversion convention.

Addition, multiplication, left shift, and complement are capped modulo 2^Bits for bounded values. Bounded subtraction wraps at that width; dynamic subtraction with a larger right operand instead sets zero. ~/flip_bits require nonzero Bits because an unbounded positive complement has no finite width. Right shift drops low bits. Division/modulo reject zero divisors with domain_error.

size/is_zero/bool/odd/even are constant-time metadata/low-limb queries; bit_length normalizes the active span and popcount scans it. testbit is range-aware, while operator[] indexes a limb without bounds checks. power_of_two returns zero if its required limb cannot fit, and top-bit masking can also turn an excessive bounded bit into zero.

Complexity and invalidation

Let n be active limbs and C bounded capacity. Copy/swap of bounded values costs O(C); dynamic copy costs O(n) and vector swap/move transfers storage. Addition, subtraction, comparison, logic, and shifts cost O(n) worst case, plus growth/copy work. Multiplication/squaring use the tier table; quotient and remainder use the division ladder. pow uses O(log exponent) squarings/products with growing or capped operands.

Value-returning binary operators copy the left operand before compound arithmetic. Temporary multiplication/division scratch is embedded for bounded values and allocator-backed for dynamic values. Large bounded widths can therefore create large stack frames. Several compound operations ignore ensure's failure result; there is no uniform checked-allocation/overflow status contract. Borrowed limb addresses can move when dynamic storage grows or is replaced.

RecordMembers and behavior

sinv_result<B,S,A>arbint value and bool exists; inverse is returned nonnegative modulo |m|

gcd, lcm, and inverse

gcd handles zero operands and returns a nonnegative result for signed input. lcm returns zero if either argument is zero, otherwise (a/gcd(a,b))*b, so a bounded lcm can truncate. invmod rejects zero modulus, returns exists=false for a noninvertible residue, and treats modulus one as an existing zero inverse. Signed inverse first normalizes the base modulo the modulus magnitude.

The low-level inverse uses extended Euclid with nonnegative checkerboard cofactors and validated leading-limb Lehmer batches, falling back to full divisions. Result records own their integer fields and copy/move at those fields' costs. No result record retains the input operands.
