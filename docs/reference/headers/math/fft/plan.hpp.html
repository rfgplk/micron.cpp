micron::math::fft::plan

Defined in header <micron/math/fft/plan.hpp>.

An owning reusable complex/packed-real transform plan with per-axis engines and precomputed coefficients.

Construction and dimensions

plan(n,norm) constructs a one-axis complex plan. plan(descriptor) validates positive nonempty shape, domain/normalization, distinct in-range axes, signed layouts, and checked size products. It builds one engine per transformed axis. Real even lengths use a half-length complex engine plus real recombination; odd lengths use a full complex engine.

configuration(), input_shape(), and output_shape() return borrowed const references to completed plan state. input_size/output_size count logical elements over all batches, excluding stride gaps. real_forward shortens the last selected output axis to n/2+1; real_backward shortens that input axis. Normalization N is the product of selected full axis lengths, excluding batches and untransformed axes.

Execution overloads

Complex execution accepts interleaved complex pointers or split_input/split_output records plus an explicit direction. Real forward accepts F input and complex/split output; real backward accepts complex/split input and F output. execute_inplace(F*) writes packed complex pairs into scalar storage or reconstructs real values without creating complex objects that alias F storage.

All variants stage/gather data in supplied scratch except selected contiguous one-dimensional fast paths. Those paths specifically handle exact input/output equality; they do not establish arbitrary partial-overlap safety. workspace_size(workers) reports complex elements, workspace_bytes reports bytes, and zero workers is rejected. A generic serial plan needs full-volume batch staging plus 5*maximum_axis_length and the largest engine scratch per worker.

Ownership and invalidation

Copies duplicate descriptor and coefficient vectors; moves transfer vector storage. Execution does not mutate plan coefficients. Returned configuration/shape references and any pointers into them are invalidated by replacing or destroying the plan. The plan does not retain the input, output, or supplied workspace after a completed synchronous call.
