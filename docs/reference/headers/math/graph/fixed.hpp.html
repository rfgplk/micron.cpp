Type reference

micron::math::fixed_graph

Defined in header <micron/math/graph/fixed.hpp>.

A fixed-capacity graph with embedded vertex and edge arrays and append-only slot high-water marks.

Capacity, lifetime, and errors

VertexCapacity and EdgeCapacity precede the property/index/policy parameters. All property types must be default-constructible. Every physical property slot is constructed with the graph, including unused slots. Removal clears live flags without destroying property values; ordinary object destruction destroys the embedded arrays.

No container storage is allocated. Vertex insertion returns an invalid descriptor at capacity; edge insertion reports index_overflow. Erased slots are not reused, so capacity bounds lifetime append counts rather than current live counts. There is no clear/compact member. Both numeric and descriptor add_edge overloads can create missing default vertices. Edge capacity is checked before duplicate lookup, so a full graph reports index_overflow even for an existing edge.

Many members are constexpr/noexcept; throwing property operations violate that noexcept contract. allocator_type is a compatibility alias, not a runtime allocation mechanism.

Traversal and complexity

Public vertex_range scans vertex high-water slots. edge_range produces const_edge_reference proxies; incident_range and neighbor_range scan edge slots. Their returned iterator classes are private implementation types. The stable_adjacency_t storage tag does not imply that adjacency vectors exist.

Membership is O(1). Neighborhoods, degrees, duplicate lookup, and vertex removal scan O(T). Traversals can therefore cost O(V*T). Embedded storage costs O(VertexCapacity+EdgeCapacity), including property storage and construction. Numeric IDs and surviving property addresses remain stable during insertion/removal, but moving or replacing the containing object moves/replaces its embedded properties.
