micron::math::dense_adjacency_graph

Defined in header <micron/math/graph/dense.hpp>.

A simple graph storing a full V-by-V array of independently live edge-property cells.

Layout and modifiers

VertexProperty, EdgeProperty, GraphProperty, Index, Direction, Loops, and Alloc are selectable; parallel edges are not supported. Undirected endpoints use the canonical upper-triangle cell, although the full square is allocated. Presence is a live flag, so a zero-valued property can represent an existing edge. Edge ID is the cell offset u*V+v; edge_slots is V².

Adding a vertex rebuilds the square and moves existing edge properties. Numeric endpoint insertion can enlarge the matrix; descriptor insertion requires existing vertices. Removing a vertex swaps the last vertex into its slot and rebuilds/remaps the square. reserve_vertices, reserve_edges, and reserve_adjacency are no-ops. Repeated add_vertices performs repeated square rebuilds.

Traversal types and complexity

Public vertex_range enumerates vertices. basic_edge_reference<Const>, basic_edge_range<Const>, and edge_reference/const_edge_reference describe property proxies and cell scans. incidence_range<Neighbors> scans a row or column for neighbor or edge descriptors. Returned iterator classes are private implementation types. All borrow the graph.

Storage is O(V²) property-cell slots plus vertices. Edge lookup, insertion into an existing square, and edge removal are O(1). Neighborhood/degree scans cost O(V); full edge iteration costs O(V²). A vertex change costs O(V²) cell work; adding V vertices one at a time costs O(V³) cumulatively, excluding property work.

Iterator invalidation

Any vertex-count change alters the row stride and edge descriptor interpretation, rebuilds edge storage, and invalidates edge/property references. Vertex-vector growth can invalidate vertex properties. Removing an edge ends that property's lifetime. Choose this representation for dense property-bearing topology and frequent pair lookup when quadratic storage is appropriate.
