micron::is_container

Defined in header <micron/concepts.hpp>.

Checks the data/iterator alias protocol and excludes a const char* C-string accessor. Other container concepts select distinct protocols.

Container and storage concepts

These are expression and tag tests. For example, is_map can accept a non-associative type through its size/capacity protocol, and a nested contiguous_tag is a declaration by the container, not an address-layout proof. Use the narrow concept required by the algorithm.

micron::same_as

Defined in header <micron/concepts.hpp>.

Requires exact type identity. The related concepts constrain conversions, values, callbacks, and sum-like interfaces.

Value and callable concepts

Concepts with familiar standard-library names have the requirements implemented here. In particular, common_reference_with uses a common value type, and relation concepts do not establish semantic laws. Code must still supply a valid ordering, maintain object lifetimes, and meet the called function's preconditions.

micron::option_traits

Defined in header <micron/concepts.hpp>.

Extracts value and error types from a type declaring first_type and second_type.

Related traits

The primary option_traits<T> is empty. Its constrained specialization defines value_type = T::first_type and error_type = T::second_type. option_value_t<T> and option_error_t<T> remove cv/reference qualification before selecting those members. This extraction requires more than the is_option concept's two query expressions.

is_string_tt<T> is the substitution-based trait equivalent of the is_string expression protocol; is_string_v<T> exposes its value. string_len(t) prefers len() when available and otherwise uses size(), converting the result to usize. The size_of<T,N> variable template tests sizeof(T) == N.

template<typename T>
constexpr inline usize
string_len(const T &t) noexcept
{
  if constexpr ( requires {
                   { t.len() } -> micron::convertible_to<size_t>;
                 } )
