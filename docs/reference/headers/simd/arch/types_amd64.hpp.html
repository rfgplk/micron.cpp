micron::simd::f128

Defined in header <micron/simd/arch/types_amd64.hpp>.

Architecture-selected raw 128-bit f32 register alias, accompanied by integer, f64 and wider storage aliases.

Raw register families

NamesMeaning and availability
b6464-bit integer/raw carrier; x86 MMX representation or NEON byte vector, WebAssembly 8-byte storage
f128, d128, i128128-bit f32, f64 and canonical integer representation; d128 absent on ARMv7
f256, d256, i256x86 256-bit vectors; two NEON 128-bit registers (d256 only ARM64); WebAssembly two-block composites
f512, d512, i512x86 512-bit vector storage; WebAssembly four-block composites; no native NEON definitions
h128, h256, h512x86 _Float16 vector aliases; require the compiler half-type definitions and are excluded from is_simd_type

Representation and use

Integer raw aliases do not carry a unique scalar lane type. The operation suffix selects the interpretation. Natural compiler-vector alignment is 16/32/64 bytes for the x86 widths, while NEON 256-bit records inherit their component alignment rather than representing a native256-bit register. These aliases own only inline bits and supply neither allocation nor bounds checking. The common typedef header can define wide storage even when the current target does not enable instructions for using it.

micron::simd::is_simd_type

Defined in header <micron/simd/arch/types_amd64.hpp>.

Architecture-specific exact-type classification of raw SIMD storage rather than packet wrappers.

Related concepts

ConceptAccepted values and limits
is_simd_typex86 b64 and f/d/i128/256/512; ARM64 b64, native 128 and two-register 256 records; WebAssembly packet-traits-recognized storage. No is_simd_type definition in the reviewed ARMv7 type header
is_simd_128_typeExact f128/d128/i128 types where defined; ARMv7 omits d128
is_simd_256_typeExact f256/d256/i256 types where defined, including native ARM records
is_simd_512_typex86 f/d/i512 or WebAssembly 64-byte recognized storage; absent from native NEON headers

Constraints

The native tests do not establish instruction availability, a uniform load interface or a valid type/flag pair. Half aliases are excluded. WebAssembly recognition is based on its internal packet-traits element member plus the requested byte size. Native ARMv7 headers using an absent common is_simd_type definition can therefore require additional correction before their declared wrappers are usable.

micron::simd::is_flag_type

Defined in header <micron/simd/arch/types_amd64.hpp>.

Lane-flag concept selecting the scalar interpretations admitted by native packet declarations.

Flags and requirements

NamesInterpretation
__v8, __v16, __v32, __v64i8/i16/i32/i64 signed lane flags
__uv8, __uv16, __uv32, __uv64u8/u16/u32/u64 helpers recognized by is_int_flag_type
__vf, __vdf32/f64 flags; native ARMv7 has the scalar __vd alias but omits it from is_flag_type
is_int_flag_typeAll eight signed/unsigned integer flags
is_flag_typeNative signed integer flags and supported real flags; WebAssembly additionally admits unsigned integer flags

Use

The __-prefixed aliases support implementation dispatch and are not independent storage wrappers. Native packet class constraints exclude unsigned flags even though helper width tests recognize them. Signedness and width must also match the chosen raw operation: concept acceptance alone is not a conversion or supported-operation guarantee.
