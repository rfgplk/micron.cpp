Scalar and tuple forms

float32_t/float64_t alias float/double; float16_t and bfloat16_t depend on their type gates. poly8_t/poly16_t/poly64_t use the corresponding unsigned integer width, and ARM64 poly128_t uses unsigned __int128 for carryless-product representation. For every generated base family, BASE x2_t/x3_t/x4_t records hold val[2], val[3] or val[4] component registers in order. Thus a 128-bit base has 32/48/64-byte tuple storage; these records are not native 256/384/512-bit registers.

Use and operations

Register tuple loads/stores and zip/unzip helpers populate component streams explicitly, sometimes with scalar loops rather than a single interleaved instruction. All storage is inline and has the component vector alignment. Native ARM 256-bit f/i/d aliases refer to x2 tuples but have no corresponding native v256 packet class. Hardware AES/PMULL operations additionally require their feature gate even when polynomial carrier types exist.
