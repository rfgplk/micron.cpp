Computation graphs

From micron reference
micron reference › Numerics and mathematics

Static-shape numeric computation graphs parametrized by a compile-time operation registry and memory-domain provider. A builder finalizes descriptors, dependencies, aliases, and reusable arena slots; a session binds inputs and executes the resulting plan.

Objects and execution flow

Registry and descriptors

Ops supplies operation_type, dtype_type, context_type, dtype_size(dtype), output_count(operation), infer, validate, and noexcept execute. Optional aliases declares output views/destructive updates. The module does not provide built-in tensor arithmetic kernels or automatic differentiation: accepted operations and numeric behavior come from that registry. Domain providers supply allocation/release, copy, synchronization, validity and minimum alignment.

Descriptors store dimensions and signed byte strides. Missing strides are filled in contiguous row-major order from dtype_size. Rank zero is a scalar; a zero dimension is an empty tensor. Negative strides are supported by computing minimum/maximum addressed offsets and shifting the runtime logical origin. byte_size is the full addressed byte extent, including holes, not the product of dimensions times element size. A nonzero supplied byte_size must equal that extent; alignment must be a nonzero power of two, with zero replaced by the domain default. Arithmetic overflow and invalid domains/type sizes are rejected during normalization.

Access flags and typed as<T>() casts are metadata and reinterpretation rather than automatic runtime dtype/access enforcement. Kernels must honor descriptors and tensor_access. Alias offsets must stay inside the input address extent and meet output alignment; destructive aliases require read-write input/output metadata. Negative-stride descriptors affect copy/binding origins, so the provided pointer must denote the normalized logical element zero, not necessarily the lowest addressed byte.

Planning, reuse, and allocation

Inputs are externally bound; state is read-write, retained and initially zeroed. finalize runs inference/validation in operation insertion order, adds producer dependencies, follows alias roots, and computes root consumers/lifetimes. It assigns temporary roots to reusable same-domain slots when prior uses precede the new producer; slots grow to maximum required bytes/alignment. Retained values and state receive dedicated slots. Extra anti-dependencies prevent parallel reuse or destructive aliasing from racing earlier consumers, and a topological pass rejects cycles.

Planning allocates vectors and can perform linear dependency deduplication, per-consumer reachability searches, and linear slot searches. Its cost is not merely O(vertices+edges): dense alias/dependency sets can require repeated graph traversal, plus descriptor-rank and user infer/validate work. peak_bytes() is the sum of assigned slot byte capacities, excluding metadata/control blocks, allocator padding and external bindings; it is not a globally minimal arena solution.

A session allocates and zeroes every arena slot once, and allocates its runtime tensors, callback jobs, dependency counters and input/output views. execute reuses those arrays and storage, apart from work performed by Ops/executor/domain implementations. Session construction diagnoses arena allocation failure through memory_error; planning diagnoses invalid arguments through exc<invalid_argument>. finalize moves operation objects out of the builder while retaining its other records; reusing that builder depends on the moved-from operation values and is not an immutable repeatable snapshot operation.

Bindings, lifetime, and results

bind_borrowed checks descriptor compatibility, pointer alignment and required nonnull storage, and retains no owner. Its const-pointer form rejects read-write input metadata. bind_shared retains a storage owner and checks domain, descriptor, offset and addressed extent; it can replace external or persistent-state roots. Compatibility compares dtype/domain/bytes/alignment/dimensions/strides, while the actual descriptor's access flag is not part of that comparison. All binding owners and the plan must remain valid for execution; moving/destroying the borrowed plan invalidates sessions and descriptor pointers.

execute waits for all submitted work and returns compute_result. Missing bindings and domain synchronization errors can fail before scheduling. Executor submission failure is reported; failed dependencies skip downstream kernel execution. Independent work can still complete. The result identifies the smallest operation index with a direct failure, not the wall-clock first failure; dependency-only failures do not replace that direct cause. Kernel output/state changes are not rolled back.

data(id) returns a pointer only when runtime metadata is valid. export_tensor requires a valid owned retained output or persistent root, and returns a shared allocation plus copied descriptor/offset; borrowed inputs cannot be exported. Retention prevents transient-slot reuse within the plan but exported storage is still shared with the session: later executions or mutations can change its contents. reset invalidates nonstate intermediate results while preserving allocations/bindings/state. hard_reset zeroes session slots, removes external bindings and restores slot-backed state, then invalidates intermediates.

Execution and concurrency

Scheduling uses atomic pending counts and dependency flags; the executing thread waits through a futex until all operations complete. inline_executor runs each callback synchronously and can recursively schedule dependent operations. A concurrent executor may run independent nodes against the same context object, so Ops/context and external storage must support that concurrency. A session is not a generally synchronized object for concurrent execute/bind/reset calls; its __executing flag prevents ordinary reentry but is not a lock.

Per-execution scheduler work is proportional to operations, edges, tensors and input/output slots, plus domain synchronization and kernel costs. Worker-count speedup is not guaranteed by graph construction. thread_pool_executor borrows an existing arena rather than owning a pool; the arena must outlive submitted work and remain able to complete accepted callbacks. The adapter's separate header depends on thread/pool.hpp; availability therefore follows that threading header in the selected checkout.

micron::math::compute::compute_status

Defined in header <micron/math/compute.hpp>.

Status enumeration for registry, binding, allocation/domain, scheduling and kernel failures.

Values

ok indicates success. invalid_plan, invalid_tensor, invalid_binding, incompatible_binding and missing_binding describe setup/use failures; allocation_failure and domain_failure describe storage/provider failure; dependency_failed, executor_failure and kernel_failure describe execution; overflow is available to registries/providers. Not every enumerator is emitted directly by this implementation: graph validation usually diagnoses through invalid_argument, and session allocation failure diagnoses through memory_error.

micron::math::compute::compute_result

Defined in header <micron/math/compute.hpp>.

Execution result containing status and the failing operation identifier.

Access

Defaults to ok with an invalid failing_operation. succeeded() and explicit bool are true exactly for ok. Failure before a specific operation has an invalid identifier; scheduled direct failures identify the lowest failing index after all work finishes. The result owns no tensor data and does not imply rollback.

micron::math::compute::tensor_id

Defined in header <micron/math/compute.hpp>.

u32 tensor identifier with the all-ones value reserved for invalid.

Related operation identifier

tensor_id supports equality and ordering; operation_id supports equality with its own u32 value and matching invalid()/invalid_value()/valid() convention. These are indices into a particular graph/plan, not global handles or owners. valid() only excludes the sentinel and does not check a particular plan's bounds.

micron::math::compute::tensor_descriptor

Defined in header <micron/math/compute.hpp>.

Owned descriptor containing dtype, u16 domain, dimensions, signed byte strides, byte extent, alignment and access metadata.

Storage and operations

dimensions and strides are unchecked serial-allocator vectors; rank returns dimensions.size and scalar tests empty dimensions. Copying copies these vectors. Normalization computes missing contiguous strides and the addressed extent, checking arithmetic overflow. A descriptor does not allocate its tensor payload or validate addresses. tensor_access values read_only/read_write describe intended kernel access.

micron::math::compute::tensor_view

Defined in header <micron/math/compute.hpp>.

Borrowed void pointer plus descriptor pointer and access metadata supplied to registry kernels.

Access and lifetime

as<T>() reinterprets storage without checking dtype, alignment, rank or access. Const as returns const T*, while the mutable overload returns T*. Explicit bool accepts a nonnull pointer or a descriptor with zero byte extent. Session input/output view arrays and plan descriptors must remain alive; copying the view neither retains storage nor copies metadata/payload.

micron::math::compute::alias_declaration

Defined in header <micron/math/compute.hpp>.

Registry alias record selecting a source input index and a nonnegative byte offset for an output.

Modes

alias_mode::none allocates independent output storage; read_only_view follows an input root and forces read-only output metadata; destructive_in_place shares writable storage and introduces anti-dependencies on other consumers. The graph validates the declared address extent/alignment; it does not infer arbitrary aliases from pointer overlap.

micron::math::compute::host_domains

Defined in header <micron/math/compute.hpp>.

Default domain provider implementing domain zero as aligned host memory.

Provider contract

domain_type is u16 and host is zero. valid accepts only zero; minimum_alignment returns alignof(max_align_t). allocate rounds bytes to alignment and rejects invalid/non-power-of-two/overflow requests; release frees through the matching aligned allocation seam. copy uses byte memcpy and reports invalid domain/null ranges; synchronize is an immediate success. domain_provider requires equivalent static validity/alignment/allocate/release/copy/synchronize expressions, but custom providers define their own actual domain behavior.

micron::math::compute::basic_tensor_storage

Defined in header <micron/math/compute.hpp>.

Shared byte-allocation owner with atomic reference counting, parametrized by a domain provider.

Ownership and complexity

A separately allocated control block stores pointer, bytes, alignment, domain and atomic count. Copies retain in O(1), moves transfer, and the last release invokes Domains::release then deletes the control block. allocate returns an empty owner when payload allocation fails, but control-block allocation can diagnose/throw; a zero-byte request still allocates a control block. data/size/alignment/domain/use_count inspect that owner. Atomic lifetime management does not synchronize mutable payload access. tensor_storage aliases basic_tensor_storage<host_domains>; domain_type aliases the provider's type.

micron::math::compute::shared_tensor

Defined in header <micron/math/compute.hpp>.

Shared storage owner, owned descriptor and byte offset identifying a tensor's logical origin.

Access

data adds offset_bytes to a nonnull storage pointer; explicit bool tests storage ownership rather than validating shape/offset. Direct aggregate construction performs no bounds normalization. Session bind_shared performs the relevant descriptor/domain/extent/alignment checks. Copies retain the byte allocation and independently copy descriptor vectors; they share mutable payload bytes.

micron::math::compute::inline_executor

Defined in header <micron/math/compute.hpp>.

Immediate executor invoking a supplied noexcept callback before submit returns true.

Requirements

The function pointer must be nonnull and its argument valid; this executor does not perform a null check or queue work. It owns no threads or submitted state. Dependency callbacks may submit more callbacks recursively.

micron::math::compute::thread_pool_executor

Defined in header <micron/math/compute/thread_pool.hpp>.

Borrowed adapter submitting noexcept callback/argument work to an existing concurrent_arena.

Submission

Constructor stores the arena address. submit rejects a null callback and returns false if arena submission throws in exception-enabled configurations; otherwise it calls add and returns true. It owns no arena and adds no standalone completion protocol; compute_session waits on its job counter. The separate threading dependency is required to instantiate this adapter.

micron::math::compute::compute_graph

Defined in header <micron/math/compute.hpp>.

Move-only graph builder parametrized by a statically dispatched operation registry and domain provider.

Members

add_input and add_state append descriptors; state must be read-write. add_operation/add/add_one append operations and return output tensor IDs, with add_one diagnosing a non-single result. set_descriptor changes a builder tensor; retain reserves its output root against temporary reuse. finalize performs inference, descriptor/alias validation, dependency construction and slot planning, moving operation values into its returned plan. Existing session execution is not affected by later independent builder edits because it consumes the plan, not this builder.

Registry requirements

operation_registry checks the named registry types/functions, including noexcept execute. The registry may additionally define aliases(operation,input_descriptors,output_descriptors,declarations). Registry inference/validation work and operation copy/move behavior are part of construction cost and failure behavior.

Member aliases

operation_type and dtype_type are selected from Ops; descriptor_type is tensor_descriptor<dtype_type>, and plan_type is compute_plan<Ops,Domains>. They expose the statically selected operation/metadata/plan types without runtime type erasure.

micron::math::compute::compute_plan

Defined in header <micron/math/compute.hpp>.

Move-only finalized tensor/operation/dependency metadata and arena-slot layout.

Inspection and lifetime

tensors_count, operations_count, slots_count and peak_bytes inspect metadata. descriptor(id) returns a borrowed normalized descriptor pointer or nullptr; retained/persistent return false for invalid IDs. registry_type, domains_type and descriptor_type identify the selected policies/metadata. Sessions borrow this exact object, so its lifetime and address must remain stable during their use.

micron::math::compute::compute_session

Defined in header <micron/math/compute.hpp>.

Nonmovable, noncopyable execution instance retaining a borrowed plan and its own registry context, storage slots and scheduling arrays.

Members and use

Construct from a plan and default/copied/moved context. Bind borrowed or shared inputs; initialize writable state through copy_from or typed data access; execute with an immediate or caller executor; inspect/export retained outputs. reset/hard_reset control validity and reuse without rebuilding the plan. Members return status values for ordinary binding/execution errors; construction/planning still use diagnostics for invalid setup or allocation. plan_type, operation_type, dtype_type, context_type, descriptor_type, storage_type and shared_tensor_type identify its policy-selected types.
