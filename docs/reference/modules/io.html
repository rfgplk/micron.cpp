Input and output

From micron reference
micron reference › Input and output

Linux descriptor operations, byte streams, pipes, printing sinks, and synchronous line traversal. Descriptor values and borrowed buffers are separate from owners; most data paths return a byte count or a negative error, while selected stream and setup interfaces throw.

Counts, errors, and complete transfers

Raw Linux wrappers do not translate negative results into libc errno or automatically retry EINTR. Counts passed to pointer/reference read/write, vector descriptors, splice, and sendfile are bytes. A nonnegative result can be shorter than requested. An ordinary reference overload exposes the object's address for the requested byte count; it does not prove the object is large enough. Explicit offsets do not change the descriptor position for pread/pwrite, while sequential read/write and seek do.

posix::read_all, write_all, and copy_fd retry interruptions and accumulate until the request is complete, EOF/zero transfer occurs, or another error occurs. An error returns the negative result even after earlier progress, so these helpers do not report both progress and error. copy_fd uses sendfile and supplies no buffered fallback. Whole-file posix::copy_file returns 0 after a nonnegative short copy and ignores close failures; success does not establish that a concurrently changing source was copied completely.

io::read(fd, pointer, count) rejects a null pointer with -EINVAL and a negative fd with -EBADF, then makes one read. io::write likewise makes one write; its raw-int pointer overload reports a null pointer as -EBADF, whereas the fd_t overload reports -EINVAL. Reference/array overloads differ in the extent information they supply. No wrapper changes a descriptor to nonblocking merely because a name ends in d.

Container-count read compares count against max_size() and then reads count bytes. If set_size exists, it sets the logical size to the byte result without dividing by element size. The no-count reservable-container branch seeks to end, seeks to the beginning for a positive size, reserves from that byte size, reads in a loop, and divides the final count by sizeof(value_type). Its fallback reads max_size bytes and sets size to bytes; an empty seekable file can be left at end. These interfaces are most directly consistent for byte-sized elements. They do not preserve an existing descriptor position, retry EINTR in the reservable loop, or validate the actual allocation represented by max_size.

Standard streams and buffered output

The standard fd variables begin invalid. Boot assigns 0/1/2 only if all three pass F_GETFL, then selects stdout line buffering from isatty(1). A process with one standard descriptor closed can therefore leave all three wrapper variables invalid. Two inline 4096-byte streams with 1024-byte output chunks provide initial stdout/stderr buffers without heap allocation. Hosted constructors and retained CRT hooks initialize them; shutdown flushes and does not close standard descriptors.

Pointer fwrite(ptr, num, fd) interprets num as elements and multiplies by sizeof(T), but returns num on successful completion. It buffers stdout/stderr, flushing stdout on newline only for a terminal and stderr on newline. Other descriptors use write_all. The reference overload instead transfers num bytes and can report num after an unchecked direct write. Full-buffer flush errors can throw through stream output; void fput/fflush helpers do not expose a structured error result. A zero-write result can produce a short transfer that is still reported as num.

Global standard buffers and the ordinary print families are unsynchronized. Their output may interleave or race under concurrent mutation. Protected printing uses a different buffer and mutex, so mixing protected calls with ordinary print, direct writes, or external descriptor users does not create one global serialization order. None of these buffers are async-signal-safe.

Rendering limits

Arithmetic rendering uses bounded stack scratch; character strings are emitted as null-terminated text, ordinary noncharacter pointers as addresses, fd_t as its integer, pairs as bracketed two-element sequences, and classified micron containers through the shared renderer. A string's embedded NUL truncates the c_str-based printk overload. Raw print is not a binary-preserving string serializer. Wide/Unicode printkn special cases write native code-unit bytes to fd-backed sinks; they do not transcode to UTF-8. General wide c_str arguments are not uniformly accepted by narrow sink operations.

Brace formatting scans the format string at runtime. Escaped {{ and }} produce literal braces. An unmatched opening brace stops rendering; a field with an unavailable argument emits no value. The parser does not supply a format-error result, and accumulated sink counts do not uniformly preserve the first output error. Formatter buffer/precision/width behavior comes from the selected specialization. Redirected fd sinks expose a sticky write error, whereas stream sinks can report requested bytes even when their bounded stream truncates them.

bin emits lowercase hexadecimal in bounded chunks without a trailing newline. Its generic container overload uses size as a byte count but advances an element index, so multi-byte elements do not yield a coherent full object-representation dump. The string overload prefixes chunks with 0x text and uses string_len. print_buffer(char**) is empty. Compatibility console/consoled/console_bin forward to printing; console_newline prints a newline argument plus println's newline. Color helpers emit SGR controls through stdout; cerror colors stdout, writes stderr text, and may throw a supported standard_error. No capability detection, escaping, or restoration guard is supplied.

Settling before output

Printing overloads accepting settling arguments resolve them in argument order before emitting the first value. Routine-like objects are finished and yield their result; future-like objects use get; eventual-like objects check/fetch their stored result; thread-like objects join and produce a status note. Exceptions during settling propagate before rendering begins. A stored reference result remains borrowed. Const objects are accepted only when the underlying consuming operation permits it; ordinary const routines/futures cannot be made consumable by the printer.

as<R>(thread) retrieves result<R>() before joining and passes the result to rendering. Plain thread rendering captures its id, ignores the join return, and renders a joined note; the note itself is not proof that every backend join condition succeeded. Void routine/future/eventual results render completion notes. Eventual get yields a reference rather than automatically moving the stored value. Task/executor objects that do not match these structural protocols are not run merely by printing them.

Protected printing settles arguments before acquiring its mutex, so a task that prints through the same protected family can complete before the caller takes the print lock. Callbacks/formatters executed while that nonrecursive lock is held must not reenter protected printing. Settling may block indefinitely according to the object's own completion/join protocol; output formatting adds no timeout or cancellation.

Terminal input

terminal and from_terminal append one byte at a time until the selected delimiter (included), EOF/error, or a limit. Stack-backed strings use max_size; heap strings stop after 16 MiB of newly read bytes. Existing destination contents are retained, and the limit does not subtract their current size. Only the initial invalid descriptor is distinguished; later EOF, read failure, and truncation all return through the same successful helper path. Optional echo uses println. copy_to(fd) is empty. These are blocking byte readers, without line editing, Unicode decoding, or a detailed read-error result.

Complexity

Direct wrappers use constant user-space state and one syscall, apart from helper loops and path copying. Kernel/filesystem/device work and blocking time are external to that bound. Buffer copies, scans, hex rendering, and unformatted rendering take work proportional to bytes/elements visited plus element formatters and callbacks. Indexed brace arguments are selected by recursive argument traversal for each field. Complete-transfer loops can make arbitrarily many syscalls under repeated interruptions; no finite latency bound follows from a requested byte count.

micron::posix::fd_t

Defined in header <micron/linux/io/fd.hpp>.

A copyable, non-owning Linux descriptor/error integer.

Representation and lifetime

The only field is i32 fd. Default construction produces 0, not the invalid sentinel; invalid_fd is -1. open() and bool test fd >= 0; closed() tests exactly -1; invalid() tests any negative number. has_error() returns the unsigned magnitude of a negative value. reset() stores -1 without closing. Destruction, copying, and moving do not close, duplicate, or transfer an OS resource.

Comparison, integer conversion, arithmetic, and increment/decrement operate only on the stored number. Arithmetic can accidentally select another descriptor and is subject to signed overflow. A copied fd_t aliases the same open file description; external close/reuse invalidates that interpretation for all copies. close(fd_t&) resets even after a close error; the raw-int close overload cannot reset a caller's variable. Use an owner when scope-based close is required.

micron::posix::auto_fd

Defined in header <micron/linux/io/ext.hpp>.

A move-only scoped owner of an adopted descriptor.

Ownership

Default construction is invalid; fd_t/int construction adopts without duplication. Destruction closes a nonnegative fd, ignoring close errors. Move transfers the integer and resets the source; move assignment closes the previous destination first. raw/int return a borrowed number; release returns fd_t and disarms close. There is no separate reset/open member, though the public fd field can be changed by the caller.

The open_read_s/open_write_s/open_append_s/open_rdwr_s factories combine an opener with this owner. Ordinary open_read/write/append/rdwr/excl return non-owning fd_t. Accessor/move work is constant apart from close; no heap storage or synchronization is added.

micron::posix::iovec_t

Defined in header <micron/linux/io/io_structs.hpp>.

A borrowed scatter/gather record with a base pointer and byte length.

Fields and use

iov_base is T* and iov_len is usize bytes, independently of sizeof(T). The record neither owns memory nor enforces extent, mutability, vector-count, or kernel-limit constraints. A readv target must be writable; a writev source must remain readable for the syscall. Records and payload must outlive the operation; copying copies only pointer/count. Multiple records are supplied as contiguous ABI-compatible storage. linux/io.hpp reexports this type as micron::iovec_t.

micron::posix::pipe_pair

Defined in header <micron/linux/io/sys.hpp>.

Two non-owning descriptor values returned by the raw make_pipe helper.

Result

Fields read_end and write_end identify the two pipe directions. make_pipe uses pipe2(flags); failure places the same negative error in both fields. Success requires the caller to close both endpoints explicitly or adopt them into owners. The record does not set close-on-exec/nonblocking except as requested by flags, and does not supply a complete-transfer protocol. linux/io.hpp reexports the record as micron::pipe_pair.

micron::posix::open_how

Fields

An actime/modtime seconds record adapted to the timestamp syscall helpers.

Conversion

utime converts its two time_t values to zero-nanosecond timespecs. utimes/futimesat/lutimes convert timeval microseconds to nanoseconds. Null timestamp input requests current times. micron::posix::inotify_event_t

Defined in header <micron/linux/io/sys.hpp>.

A Linux inotify variable-length event header.

Record traversal

Fields wd, mask, cookie, and len precede a flexible name array. len includes the kernel-supplied name storage/padding; advance by sizeof(header) + len within the returned read buffer, after validating its extent. The wrapper supplies mask constants and inotify syscalls, not a buffered parser or registration owner. Event names and headers borrow that buffer and become invalid on reuse. micron::posix::readdir_ctx

Defined in header <micron/linux/io/ext.hpp>.

An independent 8192-byte getdents64 cursor buffer for readdir_r.

Iteration

Value-initialize a fresh context per directory traversal. bufpos and nread track validated variable-length records; readdir_r returns a copied fixed-name entry and dt_end on EOF, syscall error, or malformed record, without distinguishing those cases. Reusing one context with another descriptor before its buffered data is exhausted reads old-directory entries; reset the context explicitly.

Ordinary readdir instead has one static buffer/cursor and remembers only the last numeric fd. It is not thread-safe, cannot maintain interleaved directory traversals, and can retain stale bytes when a descriptor number is closed/reused. Both validate record lengths, alignment, and terminated names before returning. Traversal costs are linear in records/bytes read, with one fixed window and no heap allocation.

micron::posix::dir_handle

Defined in header <micron/linux/io/ext.hpp>.

A directory descriptor owner whose next operation uses the shared readdir cursor.

Lifetime and traversal

Default construction is invalid; path construction opens O_DIRECTORY|O_CLOEXEC and dir_t construction adopts. Destruction closes a valid fd. Copying and assignment are unavailable; move construction transfers and disarms the source. next returns the end record when invalid and otherwise delegates to readdir, inheriting its shared-state limitations. rewind seeks to 0 but does not reset the shared buffered cursor, so buffered entries can still be returned before the new directory position is read.

for_each_entry uses its own value-initialized readdir_ctx and skips . and .., avoiding the shared cursor while retaining the end/error conflation. Callback exceptions propagate under scoped close. Directory mutation while traversing has kernel-defined observations rather than a stable snapshot.

micron::posix::node_types

Defined in header <micron/linux/io/inode.hpp>.

An inode-format classification enum used by metadata predicates.

Classification and queries

Values name socket, symlink, regular_file, block_device, directory, character_device, fifo, not_found, and unknown. get_type uses stat and follows symlinks; is_symlink uses lstat, and the corresponding *at predicate selects AT_SYMLINK_NOFOLLOW. Metadata failure becomes false or not_found, rather than retaining a precise error. not_found can therefore also represent access/other query failure. Queries from an existing stat record avoid another syscall.

Mode predicates test individual stored permission/special bits; is_readable/writable/executable ask access/faccessat and do not merely inspect those bits. is_virtual_file means regular file with device major 0, a heuristic. is_same_file compares device/inode. Size queries return -1 on stat failure; inode/mode/link queries use zero sentinels, uid/gid/device/block/time queries use cast -1, so distinguish these from actual field values when required.

is_empty_dir duplicates a descriptor but the duplicate shares the same open-file-description offset: its rewind and getdents therefore change the original descriptor position. Errors return false; has_content negates emptiness, so it can be true after an error. is_mountpoint compares the device id with a text-derived parent and special-cases /; it does not detect every bind mount and is not a general canonical mount resolver. Path strings must be valid and terminated. Predicates allocate no heap, while empty-directory scanning has linear entry work and kernel-dependent cost. linux/io.hpp reexports the classification enum as micron::node_types.

micron::io::error_t

Defined in header <micron/io/bits.hpp>.

A small positive-magnitude error value used as an option's error alternative.

Value semantics

Public code defaults to zero. Explicit construction negates a negative i32 through unsigned arithmetic and keeps a nonnegative value; INT_MIN cannot become a positive signed i32. bool tests code != 0 and message delegates to the errno-description table. The record owns no descriptor, exception, or message allocation. It does not imply that option<bool> means success: inspect the option's first/second alternative explicitly.

micron::io::lines_range

Defined in header <micron/io/__lines.hpp>.

An immovable single-pass line range over a borrowed descriptor.

Line policy and cursor

Construction allocates a window (4096 bytes by default; zero selects that default) and a reusable string, without owning or closing the fd. begin immediately reads the next line; calling begin again consumes another line rather than restarting. Increment advances the shared cursor. The iterator's value_type is string, but dereference returns const string& into reused storage. iterator/sentinel only compare exhaustion; copied iterators are aliases of the same cursor, not independent positions.

LF terminates a line; exactly one preceding CR is stripped. A final unterminated nonempty line is emitted with a trailing CR retained; trailing LF adds no extra final line, and an empty file has no lines. EINTR retries. An error clears the current line and stops; error returns negative errno, while bool means only that no error has yet been recorded. End-of-range alone does not distinguish EOF from error.

Destruction seeks backwards by unread prefetched bytes, ignoring seek failure. On seekable files this restores the offset to the consumed boundary; on pipes/sockets the unread prefetched bytes cannot be restored and are lost to this traversal. Do not interleave other operations on the same open file description while the cursor is live.

Line references/pointers are invalidated by increment, begin, or range destruction. Work is linear in input bytes plus string growth/callback work; storage is one window plus the longest accumulated line. line_fold_raw requires fn(R,const char*,usize)->R; line_fold_str requires fn(R,const string&)->R, both with exact R result. They select fold interfaces rather than retaining a collection of lines.

micron::io::stream_result_t

micron::io::stream

Defined in header <micron/io/stream.hpp>.

A move-only fixed-capacity byte staging buffer with optional inline storage, interception, and encoding.

Storage and capacity

Template parameters are byte capacity __sz (32768), transfer chunk __chnk (4096), and inline-storage flag (false). The default owns a pointer<buffer> allocation; true stores a 64-byte-aligned byte array in the object, as used by standard streams. There is no growth. size/remaining count valid/free bytes and max_size returns __sz. full(extra) uses size + extra >= __sz, so an exactly fitting append is reported full. Positive sensible template sizes and overflow-free counts are caller constraints.

Copy is deleted. Move transfers the allocated buffer or copies the inline storage through its member move, relocates the hook, and sets source size to zero. An allocated moved-from stream lacks a usable buffer until storage is restored. Destruction destroys the hook and owned storage but does not flush or close any descriptor. Move assignment discards the old staged content.

append and insertion copy only the prefix that fits; they do not return the rejected byte count. append_byte throws when full. Empty string/container insertion throws. Raw append sources must cover the requested extent and must not overlap memcpy's destination improperly. data/begin/end expose the current bytes; operator[] checks logical size. clear zeroes the entire template capacity, clear_valid only current bytes, and rewind just sets size to zero.

pass releases the owned buffer and resets size; receive adopts a nonnull buffer without changing logical size or validating its capacity. These members require the allocated-storage variant: the inline block has no release/pointer-adoption protocol. Adopted storage must support the template capacity used by subsequent operations; pass leaves the object without usable storage.

Descriptor and destination operations

Insertion from fd fills the remaining capacity in chunks, retries EINTR, and silently stops on EOF/other read error. Output operator>> retries EINTR, consumes size as bytes are written, throws on other errors, and stops on zero write. If a partial transfer is followed by zero/error, the remaining suffix is not compacted to the start even though size has decreased; later operations can therefore address the wrong retained prefix. flush_to avoids that state mutation and reports progress but leaves all bytes staged, so the caller must account for already-written bytes before retrying.

Extraction into a string appends size as an element count from a reinterpreted byte pointer and clears; wide-element strings can read beyond the valid bytes. Container extraction appends one converted element per byte. dump preserves staged contents; the string variant has the same element-count limitation, the raw variant copies at most destination capacity, and the buffer variant grows the target if needed. pipe/pipe_encode append/encode into another default-storage stream and then rewind the source even if the destination accepted only a prefix.

Interception and encoding

An intercept receives the entire currently staged writable byte span after append/read/encode, and can mutate earlier bytes again on every invocation. The owned closure has a 64-byte inline context aligned to 16, plus call/destroy/move thunks. Size is checked, but a closure requiring stricter alignment is not rejected. Supply an ownable concrete closure of suitable alignment; the forwarding setter is not a general reference-wrapper facility. Closure move during stream move is declared noexcept, so a throwing move terminates.

encode_fn requires fn(dst,dst_capacity,src,source_bytes)->usize. encode allocates __sz scratch bytes unless scratch is supplied, invokes the encoder, and appends only what fits. A scratch argument is checked against source length, not a known expansion bound. encode_inplace allocates scratch of current size and can retain only up to __sz bytes. The encoder must obey the provided destination capacity and return a valid initialized output length; an oversized result can cause out-of-bounds scratch reads even though final append is bounded. The string encode overload passes string.size without multiplying element width; container encode uses size*sizeof(value_type). encode_into delegates directly without independent length validation. byte_container detects begin convertible to const byte*, a size convertible to usize, and value_type; it does not validate a buffer extent or ownership.

Complexity and invalidation

Appending/clearing/copying/encoding takes linear byte work plus hook/encoder costs; rewind and metadata access are constant. Owning construction allocates the fixed buffer, encode may allocate scratch, and each_line/fold add traversal/callback work. Pointer validity follows the owned buffer: ordinary appends do not reallocate but mutate bytes/end; move/pass/receive/destruction change ownership or storage. Inline moves leave old-address bytes behind rather than retargeting borrowed pointers. Comparison is lexicographic/linear; pointer equality assumes an available prefix of size bytes without checking source length. No synchronization or descriptor snapshot is supplied.

micron::io::stream_view

Defined in header <micron/io/stream.hpp>.

An immovable fixed-template-capacity stream over a borrowed buffer wrapper.

Borrowed storage

Construction stores a wptr<buffer> from the supplied owner/reference and starts with size zero. The underlying owner must retain stable allocated storage throughout use; the view does not extend its lifetime, flush on destruction, or close descriptors. Append/read clamp to min(__sz, actual buffer.size), but max_size/full still use __sz. There is no public append member; insertion supplies its data path.

clear zeroes __sz bytes, independently of the smaller effective read/append capacity, and can overrun a viewed buffer smaller than __sz. Use matching storage or clear_valid/rewind. Output to fd retries interruptions and preserves size rather than consuming bytes; repeated output repeats the staged content. String extraction/dump use byte size as element count and therefore require compatible byte-sized targets. Hook ownership and alignment constraints match stream; encode_into delegates to the encoder.

Pointers stay tied to borrowed storage and are invalidated by its destruction/reallocation or conflicting mutation. Equality/order traverse current bytes. Copying/moving the view is deleted; sharing it or its underlying mutable bytes requires external synchronization. Storage work is bounded copying/zeroing plus user callbacks, without allocation by view construction itself.

micron::io::upipe

Defined in header <micron/io/pipe.hpp>.

A move-only owner of both anonymous-pipe endpoints.

Construction, flags, and shutdown

Default construction creates a blocking pipe with both directions open; the bool constructor selects close-on-exec through pipe2. Failure throws. Destruction closes whichever ends remain owned; close_read/close_write disarm individual endpoints. Move transfers both fds/open flags and invalidates the source. Raw public fd[2], get, and read_fd/write_fd expose borrowed numbers; direct mutation can violate ownership flags.

Nonblocking and close-on-exec setters use separate F_GET*/F_SET* calls. The combined setter attempts both ends even when the first fails. Capacity methods use the kernel F_GETPIPE_SZ/F_SETPIPE_SZ and return their result. Dup-to helpers create descriptors outside this owner; callers must close those separately. Keeping any write-end duplicate open prevents EOF. Writing more than the available pipe capacity before arranging a reader can block even when both ends belong to this object.

Including this header registers a hosted constructor that ignores SIGPIPE process-wide; the retained boot function does the same. This changes process signal disposition rather than only this pipe. No per-object restoration is provided.

Transfers

write_bytes/read_bytes loop to their byte request but do not retry EINTR; a later error loses the progress count in pipe_result_t. peek consumes one byte; it is not a nondestructive lookahead. String write/read use element width, while call-operator string forms transfer size bytes. Read targets keep their original logical size; read_all appends until a nonpositive read and conflates error/EOF. Wide-string read_all counts returned bytes as elements and is unsuitable for that representation.

Stream output rewinds the source unconditionally after the internal write attempt, including failure/short output. Stream input reads one allocated window up to available capacity; drain_to_stream loops until capacity, EOF, or error. read_buffer returns the full requested-size buffer, zeroing its unread tail, without returning actual bytes read. It cannot distinguish an empty read from an all-zero payload.

each_chunk retries EINTR, treats EAGAIN as a drained nonblocking pipe, and returns an accumulated positive total instead of a later error. write_with calls a producer on a reusable window, rejects produced length beyond capacity, and similarly favors a previous positive total over a later write error. Its write loop can have transferred a partial current chunk without reporting that part if the next syscall fails. Splice/tee/sendfile methods are single possibly partial kernel operations; tee duplicates data without consuming it.

Complexity and lifetime

No user heap buffer is retained by the pipe owner itself. Chunk/drain/read_buffer operations allocate their named windows; string accumulation can grow without a fixed bound. Transfer work is linear in copied bytes plus syscall/producer/callback costs, with unbounded blocking latency. Callback windows are valid only during the callback. Move/close invalidates borrowed endpoint assumptions; object methods are not synchronized against each other or external closes.

micron::io::npipe

Defined in header <micron/io/pipe.hpp>.

A move-only named-FIFO descriptor owner with optional ownership of the filesystem entry.

Creation and lifetime

The (name, permissions) constructor creates a new FIFO then opens it read/write; an existing path is an error. The (name, bool, flags) constructor ignores the bool value and opens an existing path with the supplied flags, default read/write, without owning the entry. Owned entries are unlinked on destruction after close. If creation succeeds but the subsequent open throws, construction does not complete and the created FIFO is not removed by this destructor.

Move transfers fd/path/unlink ownership; move assignment closes/unlinks the destination's previous resources first. close leaves path ownership active. unlink ignores its syscall result and disarms future removal even if unlink failed. reopen closes the previous fd before attempting a new open. Nonblocking/cloexec settings are explicit fcntl changes. Path access/permission helpers query the stored pathname, which may have been renamed or replaced independently of the open fd.

Opening read/write keeps an internal writer present, so a blocking read_all can wait indefinitely rather than observe EOF after outside writers close. open_npipe_read uses blocking read-only; open_npipe_write uses nonblocking write-only and can fail without a reader. These factories open existing paths, not create them.

Transfers and invalidation

Byte read/write use complete-request loops without EINTR retry and simplify errors to pipe_result_t. String/container read writes only the existing logical extent and does not resize; read_all appends and conflates nonpositive read outcomes. The wide-element and callback/partial-progress limitations match the corresponding upipe loops. read_buffer returns its original requested size and no actual length. Stream output rewinds even after failed transfer. Splice is a single kernel operation.

The owned name can allocate and moving/replacing it invalidates references returned by path. Access to raw fd is borrowed; closing externally can produce a later double close after fd reuse. No method synchronizes descriptor flags, reads/writes, lifetime, or unlink with other threads. FIFO byte-stream framing and application message boundaries remain the caller's protocol.

micron::io::pipe_pair_t

Defined in header <micron/io/pipe.hpp>.

Two owned anonymous pipes arranged for parent-to-child and child-to-parent traffic.

Endpoint protocol

p2c and c2p initially retain both ends. parent_side closes p2c's read end and c2p's write end; child_side closes their opposites. These calls must be made in the appropriate copies after process creation, not both on the same object. child_side(true) dup2-redirects the remaining ends to stdin/stdout then closes them, ignoring dup2 errors; stderr is unchanged. Destruction closes still-owned endpoints. Copy is unavailable and moves follow the two upipe members. No process creation, wait, cancellation, or message framing is included.

micron::io::output_sink

Defined in header <micron/io/echo.hpp>.

The structural printing sink protocol: put(span), put(char), and flush results convertible to max_t.

Protocol

The character span count is bytes. The concept does not require complete output, error retention, a destructor flush, or thread safety. fd_backed_sink additionally detects target() convertible to fd_t for selected native-wide output. echo_target recognizes fd_t, stream specializations, and a class whose const fd() returns exactly fd_t. Custom sinks own their buffering/error/lifetime rules. printk and format_to borrow a sink during the call, and format_to does not flush it. User formatters/callbacks can allocate or throw; the protocol adds no exception boundary.

micron::io::stdout_sink

Defined in header <micron/io/echo.hpp>.

A stateless adapter to the global buffered standard-output path.

Standard sink adapters

put(span) returns a negative fwrite result or the requested byte count. put(char) calls void fput and returns 1, so it cannot report its write failure. flush calls void fflush and returns 0. stderr_sink is the corresponding stderr adapter. micron::io::fd_sink

Defined in header <micron/io/echo.hpp>.

A borrowed runtime descriptor with an inline CAP-byte printing buffer and sticky error.

Buffering and errors

CAP defaults to 1024 and must be positive for character insertion. put flushes when necessary and directly writes large spans; internal output retries EINTR. flush clears the buffer even on failure or zero/short output and records the first negative result in public __err. Destruction does not flush, and copying duplicates the pending text while aliasing the descriptor. A caller using the adapter directly must inspect flush/__err and arrange final flush.

The sink owns only its inline characters, never the fd. Redirected echo functions construct one, render, flush, and inspect sticky error before returning. A nonnegative short flush can still be reported using the formatted requested count. Work is linear in emitted bytes plus syscall time, with fixed stack storage and no sink allocation. Concurrent use requires external synchronization.

micron::io::stream_sink

Defined in header <micron/io/echo.hpp>.

A borrowed adapter that appends rendered bytes to a stream specialization.

Bounded output

It stores a stream reference, appends each span/character, and returns the requested byte count. The underlying stream silently clips ordinary append to remaining capacity, so a positive sink count does not prove retention of every byte. flush is a no-op; no descriptor output occurs. The referenced stream must outlive the adapter. Mutation and hook execution follow stream's contracts.

micron::io::locked_stdout_sink

Defined in header <micron/io/pecho.hpp>.

A stateless adapter to the protected-printing family's separate output stream.

Locking protocol

The adapter itself acquires no lock and does not initialize the lazy buffer. Use it only while the protected-print guard is held and the buffer has been ensured, as the pecho/pprint wrappers do.
