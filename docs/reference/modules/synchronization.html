Synchronization

From micron reference
micron reference › Concurrency

Native-thread synchronization includes permit counters, condition epochs, completion counters, promises, guarded value cells, and polling helpers. These blocking and polling interfaces are distinct from the coroutine-aware awaitables in tasks/.

Futex primitives

try_wait_futex(ptr, expected, timeout) performs one recoverable private futex wait after an acquire check and returns the syscall result, or -invalid_arg for null. Recheck the application predicate after every return. wait_futex loops with relaxed loads while a 4-byte value equals the expected value, tolerates EAGAIN/EINTR, and reports other errors as thread errors.

release_futex(ptr, value, count) release-stores a 4-byte value and wakes up to the requested number; wake_futex wakes without changing it. An ordinary futex wait is not itself an acquire load of the published application state. Pointer storage must be live, suitably aligned, and shared under a consistent atomic protocol.

On 32-bit Linux, timed calls first probe the time64 syscall and demote only on ENOSYS. The old fallback narrows to a 32-bit timespec and caps excessive positive seconds. Untimed calls use the ordinary syscall. The wasm branch delegates to its host futex interface. Operation constants name the Linux futex values; these helpers ordinarily select futex_private_flag, so they are for threads in one process.

Waiting helpers and duration units

cpu_pause<L>() sleeps for L nanoseconds using nanosleep; it is distinct from the CPU instruction helper __cpu_pause(). sleep_nano uses nanoseconds, ssleep seconds, and sleep, sleep_for, sleep_duration, spin_for, and wait_for use milliseconds. Nanosleep wrappers retry EINTR and run the native park checkpoint. Other errors terminate the sleep loop without a returned status. spin_for busy-polls the steady clock; wait_for sleeps in 1000-nanosecond slices.

pause(callback, args...) waits for SIGCONT with a temporary mask and calls the callback with the signal number on success. Argument-free pause() leaves SIGCONT blocked in the caller's mask. await(signals...) temporarily changes the mask and waits, but returns 0 after the wait without exposing its sigwait error. The pid-based wait, wait_thread, can_wait, and try_wait_thread wrap process wait syscalls; they do not replace the thread objects' join protocol.

expect(token, value) and the two-token overload acquire-poll by default, sleeping 1000 ns between unequal observations. Release/acquire-release load orders are statically rejected. Two-token equality is two separate snapshots. Other expect overloads merely compare and optionally invoke a callback.

Polling algorithm family

until, until_true, until_not, until_in_range, and until_any repeatedly evaluate a callable or predicate until the selected comparison succeeds. until_timeout uses a steady-clock millisecond budget; until_max_iter bounds the number of evaluations. The first callable evaluation normally precedes the timeout check, so even a nonpositive timeout can evaluate once. Forwarded arguments are forwarded on every iteration and may be consumed repeatedly by a callable.

The _with_wait variants call a supplied waiting function after each failed comparison. _with_callback reports every sample, including the successful sample. _backoff doubles pause-instruction bursts up to 1024. Ordinary variants otherwise issue a CPU pause instruction, not a scheduler sleep. until_ready consumes a ready future with get; until_ready_timeout only reports readiness.

_or_future and _or_flag variants stop when the auxiliary result becomes ready or the flag is set; they do not consume that future. Timeout forms return false on auxiliary completion or timeout, without distinguishing those reasons. Atomic-wrapper overloads use __get(acquire), not atomic_token::get. Ordinary reference overloads perform ordinary reads and cannot be used to race another thread's non-atomic writes.

Callable helpers until_any_true and until_all_true use short-circuit OR and AND. In this version until_any_false waits until all callables are false, while until_all_false waits until at least one is false. The _flag_set/clear pack helpers use their explicit OR/AND expressions: any-set waits for OR, all-set for AND, any-clear for not-AND, all-clear for not-OR. Poll counts and completion time depend on external progress; there is no registration, cancellation, or scheduler fairness guarantee.

Dispatch and scope cleanup

async(fn, args...) submits to the concurrent native worker arena and returns its selected worker reference. start_concurrent_pools() must have initialized that arena unless startup initialization is configured. when(flag, fn, args...) launches a native arena thread that polls the flag with acquire loads and 500-nanosecond sleeps. when_any(fn, flags...) launches one independent waiter per flag and may invoke fn once per flag; it is not a single-winner race.

invoke handles ordinary callables and member pointers, including objects, pointers, derived objects, and reference_wrapper. invoke_r additionally converts/discards the result. not_fn decay-stores its callable in not_fn_t and preserves cv/ref invocation categories when negating the result. is_reference_wrapper_v, remove_cvref_t, negate_invocable_impl, and negate_invocable_v support this dispatch.

The global defer(code) macro creates a uniquely named movable scope guard capturing local variables by reference. It executes the code once at scope exit unless its public active member has been cleared; moving transfers that active state. Referenced objects must still be alive at destruction, and a throwing deferred expression follows the guard destructor's conditional exception specification.

micron::futex

Defined in header <micron/sync/futex.hpp>.

A binary acquire/release gate built on an atomic compare-exchange and private futex wait.

Template and operations

T defaults to u32; __D and __L are distinct unlocked and locked values. wait() repeatedly weak-CASes unlocked to locked, then waits on the observed value if acquisition fails. release() sequentially consistently stores unlocked and wakes one. Copy and move are deleted.

Although the declared constraint accepts integral types of other sizes, the kernel operation always reinterprets the storage as a 32-bit futex word. Use properly aligned 4-byte storage; narrower or wider T does not implement a general-sized futex. Acquisition has no bounded wait and requires matching release; this type performs no owner validation.

micron::basic_semaphore

Defined in header <micron/sync/semaphore.hpp>.

A native-thread permit counter with a separate futex wake-token count.

Permit operations

Default construction starts at zero permits. wait() acquire-decrements the signed counter; a nonnegative result consumes an available permit, otherwise it consumes a wake token or parks. flag() release-increments the count and, when waiters are represented by a nonpositive count, adds a wake token and wakes one. try_wait() only consumes a strictly positive permit and never parks.

value() returns the signed snapshot, including negative waiter reservations. An unexpected futex error returns from wait() without a permit-status result and without repairing that reservation. Permit arithmetic overflow is unchecked. reset(init) overwrites both counters and requires no concurrent users. Move uses the tokens' non-atomic move operations and likewise requires quiescence. Copying is deleted.

abort() writes a large positive permit count and wake-token count, waking all. It does not establish a permanent closed state or restore a normal count. Uncontended operations use constant atomic work; waiting and wake consumption can retry indefinitely.

micron::semaphore

Defined in header <micron/sync/semaphore.hpp>.

A compile-time callable gated by an embedded permit counter.

Call protocol

semaphore<Fn> starts with one permit. run(args...) waits and invokes Fn but does not return the permit afterwards; the caller or callback must arrange permit(). get_permit() returns the trigger member-function pointer. permit_ahead(n) issues n separate permit additions, taking linear work in n. Move requires exclusive access to the embedded semaphore; copying is deleted.

micron::event_count

Defined in header <micron/sync/event_count.hpp>.

A 32-bit epoch and registered-waiter count for waiting on an external condition.

Wait protocol

Call prepare_wait() to register and acquire-load an epoch key, then recheck the protected predicate. If the predicate already permits progress, call cancel_wait(); otherwise call commit_wait(key, timeout). Exactly one cancel or commit must balance every prepare. Notify increments the epoch and conditionally wakes one or all registered waiters, preventing a notification between registration and parking from being lost.

commit_wait loops until the epoch differs, timeout occurs, or an unexpected futex error occurs; it returns no reason. Its optional timeout is a relative futex timeout reused after EINTR, so retries may extend the total elapsed duration. The epoch can wrap. This counter does not protect the predicate itself and destruction requires no registrations or parked users.

micron::latch

Defined in header <micron/sync/latch.hpp>.

A one-shot counter whose waiters proceed when its value is nonpositive.

Operations

count_down(n) ignores nonpositive n and clamps a positive decrement to the remaining count. A transition to zero wakes all private-futex waiters. wait() briefly pauses/yields, then parks while the acquire-loaded counter is positive. An unexpected futex error also causes it to return; it does not report that case. try_wait() reports a nonpositive count, and expected() returns the current count.

A nonpositive initial count is already satisfied. There is no reset or arrive-and-wait member. State is inline; direct observations and a successful decrement have constant atomic work, excluding CAS retries. Implicit copy or move construction uses the token's ordinary special-member accesses and requires no concurrent access or outstanding waiters; assignment is deleted by the token. A live latch must retain a stable address.

micron::barrier

Defined in header <micron/sync/latch.hpp>.

A reusable fixed-threshold barrier storing a 32-bit generation and remaining count in one 64-bit token.

Arrival and result

Construction requires a positive participant count for meaningful use; the implementation does not validate it. Each arrive_and_wait() decrements the current generation. The last arrival advances the generation, restores the original threshold, wakes all, and returns 0. Other arrivals wait for the generation change and return their arrival's remaining-count value, not a native-thread index.

arrive_and_drop() performs an arrival without waiting. It does not reduce the next generation's threshold: the threshold member is const and each generation resets to the original value. Future phases still require that original number of arrivals. expected() reports the current remaining count.

Waiters use event_count prepare/recheck/commit after initial backoff. State changes are constant work excluding retries and waiting. The 64-bit token requires target lock-free support. Too many or missing arrivals, generation wrap over a complete observation interval, and destruction with waiters are unsupported.

micron::shared_state

Defined in header <micron/sync/future.hpp>.

The allocated, reference-counted result state used by the spin-wait promise/future pair.

Storage and completion

The primary template holds T in a union and constructs it only at set_value. The void specialization stores completion only; the reference specialization retains T* without ownership. A mutex guards readiness, retrieval, and exception-message state. The message is a borrowed const char*, not a copied exception object.

wait() repeatedly locks, checks readiness, unlocks, and CPU-pauses. wait_for(ms) measures elapsed system-clock time and returns ready or timeout; wall-clock changes affect that budget. wait_until() is declared without a definition. set_value rejects an already ready state; set_exception silently ignores a second completion. get() waits, marks the single retrieval consumed, then moves the value, returns the reference, or completes void.

A stored error causes broken_promise to be thrown in hosted/exception-enabled builds, or the library future-error path in exception-free freestanding builds. A throwing value move still consumes retrieval. __acquire and __release manage state lifetime; they do not permit concurrent producer calls to the same promise object. The state destroys a constructed value when its last reference is released.

micron::future

Defined in header <micron/sync/future.hpp>.

A movable, noncopyable consumer handle for one shared_state<T> result.

State and results

Default construction is invalid. promise::get_future() creates the valid handle and adds a state reference. Destruction or move assignment releases that reference without waiting for completion. get() consumes retrieval in the shared state but leaves valid() true because the handle still has a state; a second get reports a future error. Wait and get on an invalid handle also report a future error.

The void specialization returns nothing; future<T&> returns the borrowed referent and does not extend its lifetime. wait_for delegates to the spin-wait state; wait_until() is declared but undefined. There is no shared-future conversion or deferred-work execution in these classes. Handle moves are constant work; result construction/move/destruction costs depend on T.

micron::promise

Defined in header <micron/sync/promises.hpp>.

A movable, noncopyable producer that allocates and retains one spin-wait shared state.

Producer protocol

get_future() may be called once and gives the consumer its own state reference. set_value copies/moves a value, stores a reference, or completes void. set_exception(message) stores a borrowed message. Calls on a moved-from promise report a future error.

Destruction and move assignment publish a broken-promise message if a future was retrieved and the state has not completed, then release the producer's reference. set_value_at_thread_exit immediately calls set_value; it does not defer publication until thread exit. A state allocation occurs at construction. Producer bookkeeping is not protected for concurrent calls on the same promise.

micron::broken_promise

Defined in header <micron/sync/future.hpp>.

A small error object carrying a borrowed diagnostic string for future retrieval.

Related enums

what() returns the stored string or the default broken-promise text. The string must outlive any access. future_errc names broken promise, already-retrieved, already-satisfied, and no-state conditions; these classes generally use the library future-error path rather than returning these enum values. future_status contains ready, timeout, and deferred; these waits produce ready or timeout. launch contains async and deferred but does not select execution in the promise/future classes.

micron::futex_shared_state

Defined in header <micron/sync/futex_future.hpp>.

A reference-counted result state publishing through a 32-bit futex-ready word and one coroutine waiter slot.

Single-producer protocol

The primary template constructs one T in union storage; the void specialization has no value. Completion release-stores ready, wakes all native waiters, and invokes an armed coroutine-resume callback. wait() parks through wait_futex; wait_for(ms) uses an absolute monotonic futex-bitset deadline and returns ready or timeout, also treating unexpected wait errors as an unsuccessful wait.

Unlike shared_state, the payload, retrieved flag, and producer bookkeeping are not mutex-protected. set_value does not reject repeated completion and can placement-construct over an already live result. Use one producer and one consumer retrieval, completing exactly once. get() checks its ordinary retrieved flag after waiting and moves the value or completes void. Concurrent gets are unsupported.

__arm_waiter(token, resume) permits one pending coroutine token, with 0 meaning unarmed and 1 completed. It returns false when successfully armed and true when already completed/occupied. Multiple simultaneous coroutine registrations overwrite callback bookkeeping and are unsupported. This mechanism does not retain the coroutine frame. Native waiting is separate from coroutine registration; lifetime must be retained by the promise/future handles.

micron::futex_future

Defined in header <micron/sync/futex_future.hpp>.

A movable, noncopyable consumer handle whose native waits park on a futex-backed result state.

State and retrieval

Default construction has no state. valid() tests the pointer; get/wait/wait-for on null report a future error. get() does not invalidate the pointer, but only one retrieval is supported. __shared() exposes the state for the coroutine adapter. The void specialization follows the same protocol without a value; no reference specialization is supplied.

Destruction releases a reference and does not wait or cancel the producer. An outstanding coroutine wait therefore requires some handle or producer to retain the state. Handle moves take constant work; waiting time depends on producer progress.

micron::futex_promise

Defined in header <micron/sync/futex_future.hpp>.

A movable producer that allocates a futex-backed result state.

Operations and limits

Construction allocates one state; get_future() adds a reference and returns a handle. Unlike promise, it does not track whether a future was already retrieved, and allows multiple handles even though the shared state's get() remains single-consumer. Producer calls after a move dereference null rather than reporting a no-state error.

set_value must be called at most once. set_exception ignores an already ready state. Destruction and move assignment publish broken promise if still pending and release the producer's state reference. There is no synchronization for competing producers or repeated get-future calls on the same promise. The void specialization has the same protocol.

micron::base_inlet_t

Defined in header <micron/sync/inlet.hpp>.

A polymorphic base exposing a guarded value cell's borrowed tag, observed lock state, and reset operation.

Interface

It has a virtual destructor and pure virtual tag, locked, and reset members. Construction is protected. It supplies no ownership or scheduling protocol by itself; the inlet specialization implements the value storage and mutex.

micron::inlet

Defined in header <micron/sync/inlet.hpp>.

An immovable inline value protected by a configurable mutex, with scoped retained-access handles.

Access and exceptions

Mtx defaults to mutex. Construction value-initializes or copies/moves T and retains a borrowed tag string. access() locks and returns a move-constructible, noncopyable handle_t; its destructor unlocks. try_access() returns the handle as the first alternative of option<handle_t, tuple<>>, or an empty tuple on failure. A handle must not outlive its inlet; its pointers and references are protected only while it is retained.

apply(fn) holds a local unlock guard and returns fn(value), including any returned reference. Such a reference escapes after unlocking and requires separate protection. reset, load, and store manually unlock after the element operation: an exception from construction, copy, or assignment can leave the mutex held. Calls back into the same nonrecursive inlet while holding its handle deadlock.

tag() returns the retained tag pointer and locked() samples the mutex. Storage and handle state are inline; operation cost is the element/callback cost plus mutex acquisition. No waiter fairness, value versioning, or lifetime extension is supplied.

micron::channel

Defined in header <micron/sync/channel.hpp>.

A mutex-protected last-in-first-out channel backed by stack<T>.

Transfer operations

operator>>(value) pushes a copied lvalue or moved rvalue. operator<<(destination) repeatedly acquires the mutex until the stack is nonempty, pops its top value, assigns it to the destination, and returns the channel. Between failed attempts it executes a CPU pause. operator!() tests emptiness while holding the same mutex. Variadic construction emplaces each supplied value.

There is no close, capacity protocol, cancellation, timed receive, or notification. A receiver can wait indefinitely. Push/pop have the storage/allocation behavior of stack<T> plus lock acquisition; this wrapper does not change LIFO order into FIFO. The mutex makes the wrapper noncopyable and immovable, and channel destruction requires all users to finish.

micron::contract

Defined in header <micron/sync/contract.hpp>.

An asynchronous condition check with borrowed atomic requirements and a selectable violation policy.

Construction, signing, and lifetime

contract<S, T> allocates a virtual condition callback and stores a queue of pointers added by require. requirement_t<T> aliases atomic_token<T>. sign() or sign(enforcing_callback, args...) claims the signed flag and launches an arena go worker capturing this. The worker polls all requirements and the condition until success or a millisecond duration budget expires; a nonpositive budget evaluates once. It records violation and release-clears the signed flag last.

wait() waits for that flag to clear, then applies the policy to a recorded breach. Destruction also waits before deleting stored callbacks; strict and lenient modes do not throw a recorded violation from the destructor. A requirement object and every referenced callback input must outlive the worker. duration, enforce, and require modify ordinary state and must not race a signed worker.

Move construction transfers callback pointers, requirements, and token values but cannot retarget a running worker's captured this. Move only an unsigned, quiescent contract. satisfy() merely clears the signed flag; it does not stop or join the worker, so calling it while a worker is live can let destruction race that worker. Signing again does not clear an earlier violated flag, and failed worker creation can leave the signed flag set.

Violation policy

contract_state is lenient, enforcing, or strict. Lenient records the breach and returns. Enforcing invokes the optional enforcing callback and aborts when it returns true. Strict reports a future error from wait(). Callbacks must return a value convertible to bool and must not let exceptions escape the background worker. This facility is unrelated to language contracts or automatic precondition checking.

Polling work is linear in the number of requirements per sample plus the condition cost. Callback storage is allocated, and wait duration also depends on worker scheduling and callback termination.

micron::not_fn_t

Defined in header <micron/sync/invoke.hpp>.

A stored callable adapter whose invocation returns the logical negation of invoke.

Invocation

not_fn(f) returns not_fn_t<decay_t<F>>. The adapter has lvalue, const-lvalue, rvalue, and const-rvalue call operators when negated invocation is well-formed; their exception specifications reflect that expression. It allocates no memory itself, but construction and invocation inherit the stored callable's costs and ownership behavior. It adds no synchronization when copied or invoked concurrently.

Example

#include <micron/mutex/mutex.hpp>
#include <micron/mutex/locks.hpp>
#include <micron/sync/semaphore.hpp>

int main()
{
  micron::mutex lock;
  int value = 0;
  {
    micron::lock_guard<micron::mutex> guard(lock);
    value = 7;
  }
  micron::basic_semaphore permits(1);
  bool acquired = permits.try_wait();
  return value == 7 && acquired && !permits.try_wait() ? 0 : 1;
}
