Date and time

From micron reference
micron reference › System interfaces

Clock reads and interval measurement, typed durations, Gregorian calendar values, time-zone transition tables, and allocation-free timestamp parsing and formatting.

Units and clock reads

The scalar aliases duration_t and fduration_t are time_t and f64. The global days/hours/minutes helpers convert a seconds value to the named unit. The seconds/milliseconds/microseconds/nanoseconds templates multiply by the selected ratio's denominator and divide by its numerator. These are value conversions, not constructors for chrono::duration.

chrono::clock_ns combines seconds and nanoseconds into i64 and returns a negative syscall result on failure. mono_ns, real_ns, raw_ns, boot_ns, cpu_ns, and thread_cpu_ns select their corresponding clock. now_ns/us/ms/s report realtime in the named unit. Very large clock values can exceed the signed nanosecond range; there is no checked wide timestamp representation.

MICRON_CHRONO_VDSO enables ELF-based vDSO symbol lookup for read_clock; otherwise reads call the syscall wrapper. now_s and the older system_clock sampling members call that wrapper directly. Selecting the option therefore does not change every clock read in this module.

Calendar and conversion algorithms

Calendar functions use the proleptic Gregorian rules and 1970-01-01 as day zero. floor_div/floor_mod give floor-based results for negative values. days_from_civil and civil_from_days use arithmetic era decomposition with constant work and no allocation. Validate month/day fields before conversion; conversion functions generally do not validate them.

weekday_from_days and weekday_of number Sunday as zero. ISO week results number Monday as one and can use a different year from the calendar date. day_of_year is one-based; posix::tm_t::tm_yday is zero-based. Date-to-seconds arithmetic uses fixed 86400-second days and does not maintain a leap-second history.

to_civil applies an offset in seconds east of UTC. civil_secs computes seconds from calendar fields without subtracting c.off; from_civil instead resolves through its explicit transition table and ignores the record's offset. Offset lookup is O(log n), and conversion through a table performs a fixed number of lookups. No process-wide local zone is implicitly loaded.

Parsing contracts

parse_iso8601 accepts a date alone or a date followed by T, t, or space and HH:MM with optional seconds, fraction, and offset. Fractions accept dot or comma, retain at most nine digits, and discard later digits. Offsets accept Z/z, signed HH, HHMM, or HH:MM. parse_rfc3339 adds a required offset to this grammar; it does not further enforce the stricter spelling suggested by its name.

parse_rfc2822 accepts English month/weekday abbreviations, optional weekday and offset, and selected GMT/UTC/UT names. It recognizes a supplied weekday name without checking agreement with the date. Two-digit years use a 50-year cutoff. The explicit input length must be consumed apart from that parser's permitted trailing spaces/CR/LF. Parse failures are result values with static diagnostic strings; callers must test ok() before conversion.

parse_duration_ns accepts unsigned concatenated components such as 1h30m and 2.5s. Units are ns, us, ms, s, m, h, d, and w; an unsuffixed final component means seconds. inf/infinity are case-insensitive special values. The parser checks integer multiplication and addition overflow, but its intermediate fractional numerator can reject an otherwise representable value. It truncates beyond nine fractional digits and does not accept signs or whitespace. Parsing is O(input length), with constant auxiliary storage.

Formatting contracts

The chrono::write_* functions write at most cap bytes, return the complete length on success, and return zero if the complete result does not fit. A failed write can leave a prefix in the buffer. They do not append a null terminator. Matching *_size functions compute the required character count without writing. No writer validates its civil argument.

ISO/RFC3339 writers cap fractional precision at nine digits and truncate rather than round. Numeric offsets are emitted at minute resolution. write_http_date prints GMT without converting its input to UTC; supply UTC fields. date_sep::none currently follows the ordinary ISO writer's T/separator path; write_compact supplies the actual compact representation.

write_strftime implements a fixed English/POSIX vocabulary: names, Gregorian/ISO date fields, clock fields, numeric offsets, epoch seconds, composite formats, whitespace, and percent. Unsupported conversions are emitted literally. It does not implement locale selection, width flags, or E/O modifiers. Its work is linear in the format and output lengths. Duration writers choose HMS, a clock form with hundredths for short values, or concatenated units; their arithmetic has the ordinary u64 range limits.

Sleeping and deadlines

sleep_until uses an absolute deadline on the specified clock and retries interruptions. sleep_until_once reports the first interruption. sleep_ns returns immediately for a nonpositive interval, reads the monotonic clock, checks addition overflow, and sleeps to an absolute deadline. Success is zero and failure is negative errno. Scheduler delays are outside the requested deadline's precision.

remaining_ns clamps an expired deadline to zero; remaining_ms truncates fractional milliseconds and caps its result at one hour. posix::usleep and nsleep retry interrupted relative sleeps using the returned remainder. Their input conversions do not check overflow.

Counter measurement and costs

x86 reads the TSC; AArch64 reads CNTVCT_EL0; ARM32 uses the virtual counter only with MICRON_CHRONO_ARM32_CNTVCT. Other paths sample monotonic-raw nanoseconds. serial selects compiler/instruction/memory serialization, subject to compile-time support. tick_start and tick_end add load fences around a region even when serial::none is selected. RDTSCP and rdpmc require the relevant execution-environment support; the latter is a direct instruction with no permission probe.

tick_hz caches a counter rate from hardware metadata or a timed calibration window, with a fallback rate. core_hz instead estimates an execution frequency from architecture-specific dependent arithmetic kernels, warmup, and repeated clock samples. Its first call can take milliseconds and reflect boost/scheduling effects. Pin the measuring thread before calibration and reset the cached core estimate when its conditions change. The caches do not use an exclusive once-initialization protocol; initialize or change them under application synchronization when needed.

Counter conversion uses integer multiply/divide, using uint128_t where available. The fallback decomposes quotient and remainder but still requires representable intermediate products and results. Zero frequency gives zero for cycles_to_ns/us. timer_overhead and timer_resolution use fixed stack arrays, at most 257 samples, and insertion sorting; for k samples their aggregation is O(k²). Clock and counter costs depend on hardware and environment and are reported as measurements, not fixed performance guarantees.

micron::unit

Defined in header <micron/chrono/units.hpp>.

Enumeration selecting the unit of a floating interval conversion.

Values

Values are days, hours, minutes, seconds, milliseconds, microseconds, and nanoseconds. The enumeration's integers mix seconds-per-unit and units-per-second constants; do not apply them all as a uniform scale factor.

micron::chrono::duration

Defined in header <micron/chrono/units.hpp>.

One Rep count interpreted in units of Period seconds.

Member types and operations

rep names Rep and period names Period. Default construction stores zero; explicit count construction stores a Rep. Arithmetic/comparison requires the same specialization; scalar arithmetic casts the scalar to Rep first. Integer representations therefore discard a fractional scalar before multiplication/division. Remainder requires an appropriate integral representation.

duration_cast<To> forms and reduces the compile-time ratio between periods, then multiplies/divides the count. Truncation and overflow follow the actual representation types; no rounding or overflow status is supplied. zero() returns a zero count. These operations need constant arithmetic work for built-in representations and allocate no storage.

Aliases and timespec conversion

dur_ns, dur_us, dur_ms, dur_s, dur_min, dur_hr, dur_day, and dur_week use i64 counts. ts_of and dur_of_ts bridge dur_ns and timespec_t. ts_of_ns normalizes a negative remainder into the nonnegative nanosecond field; the timespec helpers normalize carry/borrow without allocating.

micron::system_clocks

Defined in header <micron/chrono/clock.hpp>.

Enumeration of the Linux clock identifiers accepted by system_clock.

Selection

realtime, realtime_coarse, realtime_alarm, and taitime select epoch clocks; monotonic, monotonic_coarse, monotonic_raw, since_boot, and since_boot_alarm select interval/boot clocks; cputime and cputime_this select process/thread CPU accounting. Clock availability and sleep support depend on the host. A clock identifier does not itself provide an alarm or wakeup mechanism.

micron::system_clock

Defined in header <micron/chrono/clock.hpp>.

A stopwatch containing public time_begin and time_end samples from the selected clock C.

Operations and units

Construction samples the beginning and zeroes the end. start/reset sample the beginning; stop samples the end; elapsed samples and converts; read converts stored samples without sampling. read(a,b) returns a minus b. lap samples, returns seconds, and advances the beginning. now() returns floating milliseconds since the selected clock's origin. Conversion to duration_t returns whole elapsed seconds.

Sampling errors report except::runtime_error. now_ns() instead returns the nonthrowing signed nanosecond result. read before a successful stop does not implicitly use the current time. stopped() tests whether the end fields are nonzero. Copy duplicates samples; move also zeroes the source. All sample storage is inline, with a fixed number of clock calls per operation.

Aliases

steady_clock selects monotonic, raw_clock selects monotonic_raw, boot_clock includes suspended time, and cpu_clock/thread_cpu_clock select CPU accounting. Use a monotonic clock for elapsed wall time; the default system_clock<> selects realtime and can reflect wall-clock adjustments.

micron::time_point

Defined in header <micron/chrono/clock.hpp>.

A scalar D value associated with a clock type C; default construction stores zero.

Representation

time_since_epoch returns d, and arithmetic/comparison uses that scalar directly. now() stores C::now(). as<U>() assumes d is milliseconds and converts through f64 seconds before casting back to D. D is not constrained to chrono::duration and carries no independent unit metadata. Matching clock and scalar units is the caller's responsibility. Operations use constant scalar work and no allocation.

micron::auto_timer

Defined in header <micron/chrono/clock.hpp>.

Move-only scope timer owning a system_clock<C> and an optional borrowed result pointer.

Lifetime

When the result pointer is non-null, destruction stops the clock and writes elapsed floating seconds. The pointed-to fduration_t must outlive the timer. Moving transfers the output responsibility; assignment replaces it without reporting the destination's previous interval. The default C is realtime. A sampling failure during destruction cannot be treated as an ordinary recoverable result.

micron::scoped_timer

Defined in header <micron/chrono/clock.hpp>.

Move-only monotonic scope timer storing a beginning nanosecond sample and an optional borrowed i64 output pointer.

Results

elapsed_ns samples the clock and returns the delta, or -1 if either sample failed. Destruction writes that result when an output pointer exists. Move transfers the output pointer and clears it in the source. The output must remain alive until destruction. Construction/destruction use a fixed number of clock reads and do not allocate.

micron::chrono::deadline

Defined in header <micron/chrono/clock.hpp>.

A public at_ns monotonic deadline, with zero representing an unarmed value.

Construction

Explicit construction accepts absolute nanoseconds. in_ns and in_ms add an interval to mono_ns(); a clock failure produces the unarmed value. Unlike sleep_ns, these factories do not check multiplication/addition overflow. armed() only tests nonzero; it does not test expiry. The type owns no timer or waiting resource.

micron::chrono::civil_date

Defined in header <micron/chrono/calendar.hpp>.

Aggregate Gregorian date with year y, month m, and day d.

Use

civil_from_days returns this record. Month and day are one-based. The aggregate does not validate assignment; use civil_valid before converting user-provided fields. Calendar arithmetic is constant-time and allocation-free.

micron::chrono::iso_week

Defined in header <micron/chrono/calendar.hpp>.

Aggregate containing ISO week-numbering year, week number, and weekday.

Fields

weekday runs from one for Monday through seven for Sunday. week is one-based. iso_week_date calculates the ISO year/week around Gregorian year boundaries without a lookup table or allocation.

micron::time_of_day

Defined in header <micron/chrono/calendar.hpp>.

Floating hour, minute, second, and fractional-second components.

Construction and access

The single-seconds constructor wraps into a 24-hour day and normalizes negative fractions. The component constructor stores its arguments without validation or normalization. hours/minutes/seconds/subseconds return components; to_duration adds them into seconds. The record carries no date, UTC offset, or zone.

micron::year

Defined in header <micron/chrono/calendar.hpp>.

Explicit integer Gregorian year wrapper, with related month and day wrappers.

Related types

year stores int y, converts to int, and tests leap years. month stores unsigned m and ok() tests 1..12. day stores unsigned d and ok() tests 1..31 independently of any month. Construction does not reject invalid values. These wrappers have constant storage and constant-time operations.

micron::year_month_day

Defined in header <micron/chrono/calendar.hpp>.

A date containing year yr, month mo, and day dy wrappers.

Validation and conversion

ok() validates the combined Gregorian date. to_days and to_unix convert to day zero/seconds at UTC midnight; from_days and from_unix perform the inverse date extraction. Negative Unix seconds use floor division, so the preceding day is retained. weekday() uses Sunday zero and day_of_year() is one-based. Conversion does not silently validate invalid stored fields.

micron::chrono::civil

Defined in header <micron/chrono/civil.hpp>.

Calendar/time record with y, mo, d, h, mi, s, ns, and an offset off in seconds east of UTC.

Validation

Default construction is 1970-01-01 midnight UTC. valid() checks Gregorian fields, h<24, mi<60, s<61, and ns<1e9, but does not validate off. Equality compares every field rather than comparing represented instants. A permitted second value of 60 does not introduce a leap-second-aware time scale; parse-result conversion maps it to second 59. Conversions generally retain no fractional seconds unless an overload explicitly accepts them.

micron::chrono::tz_table

Defined in header <micron/chrono/civil.hpp>.

Non-owning sorted UTC transition times with corresponding offsets and a pre-transition offset.

Storage and resolution

trans and off point to n entries; first applies before the first transition. Construction from arrays marks the table loaded without checking sorting, lengths, or pointers. Unloaded tables act as UTC. tz_fixed makes a loaded zero-transition table; tz_utc is its zero-offset constant. Borrowed arrays must remain valid and unchanged during lookup.

from_civil tests offsets found around local seconds minus/plus one day. For a fold it selects the earlier valid UTC candidate; if neither candidate is valid for a gap it returns the later candidate. It does not return an ambiguity/error result and does not enumerate arbitrary historical transitions. offset_at performs binary search in O(log n); fixed/unloaded tables need constant work.

micron::chrono::tz::tz_storage

Defined in header <micron/chrono/tz.hpp>.

Fixed-capacity owned arrays trans[N] and off[N] with load state and pre-transition offset.

Loading and lifetime

view() returns a borrowed tz_table; moving, copying, destroying, or reloading its storage does not retarget an existing view. parse accepts TZif v2/v3/v4 and uses the second, 64-bit transition block. It discards abbreviations, leap data, and the POSIX future-rule trailer. Capacity truncation and skipped invalid type indices can still produce a successful loaded table. Beyond the stored transitions the last retained offset remains in force.

load_named reads /usr/share/zoneinfo/<zone> after restricting the zone-name characters. load_local uses an acceptable supplied name and otherwise falls back to /etc/localtime. The caller supplies file scratch storage; scratch_recommended is 128 KiB. Reading may fill that buffer without proving that the whole file fit. Parse work is O(type count + transition count) and storage is O(N); there is no heap allocation in this interface.

micron::chrono::civil_result

Defined in header <micron/chrono/parse.hpp>.

Timestamp parse result containing civil c, a nullable static diagnostic err, and has_offset.

Result handling

ok() tests err==nullptr; the default value therefore reports success with the default civil record. Test parser results before reading their fields. to_unix does not inspect err, ignores fractional nanoseconds, subtracts c.off, and clamps second 60 to 59. has_offset distinguishes an omitted zone from an explicit zero offset.

micron::chrono::dur_result

Defined in header <micron/chrono/parse.hpp>.

Duration parse result containing unsigned nanoseconds, a diagnostic pointer, and a forever flag.

Result handling

ok() tests the nullable diagnostic. inf/infinity set forever and ns to the maximum u64. An ordinary representable duration can also have that numeric value, so test forever when the distinction matters. The result owns no input or allocation.

micron::chrono::until_spec

Defined in header <micron/chrono/parse.hpp>.

Parsed absolute epoch, date/time, or next time-of-day request.

Grammar and conversion

parse_until accepts @SECONDS, a date/time, or HH:MM[:SS], optionally with trailing Z for UTC. Numeric UTC offsets are rejected in the date/time form. until_epoch takes an explicit current time and zone table; a time-only value advances to the next day when today's candidate is not later than now. The conversion does not test err; call ok() first. Epoch parsing excludes the minimum i64 value because the magnitude check stops at the positive maximum.

micron::chrono::offset_style

Defined in header <micron/chrono/format.hpp>.

Formatting policy for omitting an offset, selecting Z at zero, or emitting signed compact/colon notation.

Related policy

date_sep selects ISO T, space, or the currently equivalent none path. Offset styles are none, z_or_colon, colon, compact, and z_or_compact. These values control spelling only; they do not convert calendar fields or load zone data.

micron::chrono::epoch::gps_time

Defined in header <micron/chrono/epochs.hpp>.

Signed GPS week and time-of-week seconds record.

Epoch conversion

GPS conversions take an explicit TAI-minus-UTC parameter, defaulting to the fixed value 37. They do not consult a historical leap-second database. Week decomposition uses floor arithmetic. NTP helpers use the 1900 epoch, a 32-bit seconds field, and an explicit era argument for reconstruction; FILETIME helpers use 100 ns ticks from 1601. TAI helpers add/subtract the supplied offset. Julian/MJD helpers implement their stated integer arithmetic without range checks.

micron::chrono::epoch::dos_datetime

Defined in header <micron/chrono/epochs.hpp>.

Two u16 packed FAT/DOS date and time words.

Range and precision

dos_from_civil supports years 1980..2107, returning zero words outside that range. Seconds are stored at two-second resolution; subsecond and UTC offset information is discarded. Other fields are masked rather than validated. civil_from_dos unpacks fields without checking that the encoded month/day/time is valid.

micron::posix::tm_t

Defined in header <micron/chrono/posix.hpp>.

Broken-down time compatibility record with libc-shaped field names.

Fields and ownership

tm_year is years since 1900, tm_mon is zero-based, tm_wday uses Sunday zero, and tm_yday is zero-based. tm_gmtoff is seconds east of UTC; tm_zone is a borrowed name pointer. Defaults select 1970-01-01 fields but leave weekday zero. gmtime_r sets UTC metadata; localtime_r requires an explicit tz_table and does not provide an abbreviation or DST flag.

timegm and mktime update the supplied record through calendar conversion rather than supplying a full general field-normalization engine. tm_isdst does not select fold resolution. asctime_r needs 26 bytes and adds newline/null; posix::strftime reserves and adds a null terminator, unlike chrono::write_strftime.

strptime updates the caller's record and returns the first unconsumed input character, or null on failure; failure can leave partial updates. It supports selected numeric/name/offset/composite conversions, rejects unknown conversions, and does not require whole-input consumption or validate the complete combined date. Its two-digit year cutoff is 69, differing from parse_rfc2822. sysconf currently implements clock ticks and page size; other declared selector constants return -1.

micron::chrono::serial

Defined in header <micron/chrono/cycles.hpp>.

Compile-time counter serialization policy.

Policies

none applies a compiler barrier; lfence applies instruction serialization; mfence_lfence drains memory before serialization. x86 additionally supplies cpuid and rdtscp; serialize requires the corresponding build feature. ARM supplies isb. serial_supported<S> checks the build's policy set, not runtime permissions. CPU/node extraction from tick_aux uses the Linux TSC_AUX encoding assumption.

micron::chrono::tick_timer

Defined in header <micron/chrono/measure.hpp>.

Noncopyable scope counter that stores a beginning tick and an optional borrowed u64 output pointer.

Results

Destruction writes a nonnegative tick difference when an output pointer exists; a backwards/nonadvancing reading is clamped to zero. elapsed_ticks samples again, and elapsed_ns converts through tick_hz. It does not detect migration or report clock/counter failure separately. The result pointer must remain alive. Measurement helpers also provide affinity selection, warmup, compiler sinks, and prepare; prepare returns the affinity result even though it continues warming and calibrating after an affinity failure.

micron::chrono::tsc_traits

Defined in header <micron/chrono/calibrate.hpp>.

Counter metadata describing presence, invariance, optional x86 instructions, and nominal rate.

Related result records

freq_spread holds minimum/median/maximum estimated core rates and sample count. timer_stats contains tick extrema and minimum/median nanoseconds. clock_report combines counter metadata, rate estimates, measured counter overhead/resolution, and selected clock costs/resolution. These records own scalar snapshots; obtaining report() can trigger calibration and many measurements. Zero values can denote unavailable or failed measurements.

micron::chrono::vdso::resolved

Defined in header <micron/chrono/vdso.hpp>.

Cached optional clock_gettime/getcpu function pointers with a tried flag.

Resolution

info() scans the process vDSO ELF dynamic metadata on first use and returns a borrowed reference to the inline cache. available() tests the clock function pointer. The clock wrapper falls back to a syscall when no symbol resolves. getcpu is exposed as a resolved pointer rather than used by the measurement affinity helper. clock_gettime_fn and getcpu_fn describe the expected ABI. The scan assumes a valid kernel-provided image; this is not a general untrusted ELF validator.
