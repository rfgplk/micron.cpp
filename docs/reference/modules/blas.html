BLAS

From micron reference
micron reference › Numerics and mathematics

Real arithmetic vector and matrix kernels in level1, level2 and level3 namespaces, with borrowed strided views, compile-time operation/layout tags, mixed-input matrix multiplication and reusable packed GEMM scratch storage. Kernels mutate caller-provided output buffers; ordinary BLAS interfaces do not resize outputs or return general validation/status records.

Interfaces, scalar types and strides

blas_scalar accepts arithmetic element types; blas_real requires ieee754_floating. Floating-only routines and selected f32/f64 packed paths have narrower constraints than basic arithmetic kernels. Complex scalar classes are not accepted: conj_trans uses the same addressing as trans, while hemv/hemm/herk/her2k forward to real symmetric routines. The complex-style names do not supply complex conjugation or Hermitian arithmetic.

Level-1 pointer interfaces use a half-open contiguous input range or an explicit count and signed element increments. vec_view supplies data, n and inc. A negative increment starts from the caller's pointer to logical element zero; kernels do not relocate the pointer to the last physical element. Zero increments repeatedly access one location and are not rejected. Two-view overloads use the first view's length without checking the second. Generic container adapters also require the concrete pointer/size access used by their bodies, beyond their tag constraints.

Matrix views borrow data, rows, cols and element leading dimension; row-major addresses r*ld+c and column-major addresses c*ld+r. Operation tags select normal/transposed logical dimensions. Leading dimensions, compatible inner dimensions, vector lengths, output dimensions, readable/writable extents and applicable restricted-pointer alias constraints are caller preconditions. The ordinary level-2/3 interfaces do not validate them. No view retains storage or prevents its owner from reallocating or being destroyed.

Except for allocating GEMM paths described below, kernels use caller storage and bounded scalar/inline temporaries. Arithmetic, finite-input behavior and integer overflow follow the selected element operations. Compile-time ISA/FMA selection and reduction grouping can change rounding and nonfinite behavior. These interfaces do not promise identical bits across targets, preservation of floating-point exceptions or a general numerical-error bound.

Vector reduction and rotation notes

nrm2 scales finite values before squaring to reduce intermediate overflow/underflow: its contiguous path updates scale/sumsq in one pass, while the strided path finds a maximum and then accumulates normalized squares. nrm2_fast uses direct squares and can overflow or underflow even when a scaled norm is representable. Neither supplies an exhaustive nonfinite-input guarantee. dot_kahan and the strided asum branch maintain compensation; contiguous asum does not universally use Kahan summation, using a pairwise scalar fallback and ordinary SIMD partial sums instead.

iamax/iamin retain the earliest equal finite magnitude. NaNs follow the implementation's comparison/reduction order rather than a separately specified total order. A result of zero also denotes the first coefficient, so empty input must be known separately. The f32 packed iamax path uses 32-bit packed index lanes and has no guard against indices beyond their range.

rot applies x'=c*x+s*y and y'=c*y-s*x. rotg writes radius r to a and auxiliary z to b; its abs(a)+abs(b) scaling can itself overflow. rotmg writes flag param[0]: -2 is identity, -1 supplies all four coefficients, 0 assumes diagonal ones, and 1 assumes the corresponding off-diagonal signs. Identity construction need not initialize the other four slots. rotm reads coefficients according to that flag. Inputs must keep the generator's rescaling loops and arithmetic well-defined; no finite/status validation accompanies the parameter array.

GEMM aliasing, allocation and dispatch

The general view-based gemm computes conservative byte intervals for C and the addressed A/B extents at runtime. If C overlaps an input interval, it computes a temporary dynmat product, then combines beta*C into the output. This allocation also occurs for overlap caused solely by conservative padded intervals. Constant evaluation bypasses this overlap branch. Direct raw gemm_row/gemm_col and gemm_aligned calls do not provide this guard, so overlap protection is not a property of every GEMM interface.

Ordinary dispatch has a scalar accumulation path, selected small f64 AVX2/FMA 4-by-8 output tiles with an inline packed-B buffer, and panel-blocked paths for eligible floating dimensions. The small kernel can reserve an 8*1024-double (64 KiB) inline B panel; it is not allocation-free in the sense of having no scratch footprint. The ordinary blocking heuristic requires each dimension>=8 and m*n*k>=32768, with layout-dependent alternatives. Those are dispatch thresholds, not measured performance promises for a particular machine.

Panel-blocked GEMM packs A/B, zero-pads edge microtiles, and selects scalar, x86 FMA or NEON microkernels at compilation. Common shapes include scalar 4-by-4, f32 AVX2/FMA 8-by-8 and f64 AVX2/FMA 6-by-8. The ordinary path reuses a ready matrix::pack::workspace selected by scoped_workspace, otherwise allocates panel vectors per call. Explicit aligned/experimental blocked paths instead use aligned thread_local packing arrays; those paths have separate capacity/type assumptions and are not selected by the workspace guard.

gemm_aligned's small x86 path requires an appropriately 32-byte-aligned C base and row stride for aligned loads/stores; its signature does not validate those conditions. Choosing this entry point does not establish alignment or nonaliasing. The generic row/column path scales C for k==0, while a direct matrix::pack::gemm_blocked call returns without scaling for k==0. alpha==0 does not generally suppress all A/B reads in ordinary GEMM. beta==0 avoids old-C reads in several kernels, but scalar full packed microtiles can still evaluate beta*C; do not infer uniform exceptional-value behavior from the mathematical formula.

Mixed results and bounds

mixed::status is ok, bad_dimension, bad_zero_point or accumulator_overflow. Floating GEMM returns ok immediately for m==0 or n==0. For a nonempty output it requires C and its extent; A/B are required only when k!=0 and alpha!=0. k==0 or alpha==0 scales/fills C, and beta==0 avoids reading old C. Every checked failure precedes output mutation. The inner product uses conversion to Acc and ordinary multiply/add, with no general output-overflow status for floating arithmetic.

Integer GEMM checks zero points before the empty-output early return. It rejects k>max_signed_accumulator/65025, using the worst-case 255*255 centered-product magnitude regardless of the actual data. All validation finishes before writing C. The successful output is an unscaled integer sum; requantization is a separate operation. quantize_i8's scale validation is not implemented: a nonpositive/nonfinite scale violates its precondition rather than returning a status.

Constraints

op::op_tag accepts exactly these types. Tags own no matrix, allocate nothing and select branches at compilation; they do not rearrange the underlying data.

micron::math::blas::side::left

Defined in header <micron/math/blas/tags.hpp>.

Empty tag selecting a structured matrix factor on the left of a matrix product or solve.

Related tag

side::right selects the right factor. side::side_tag accepts exactly left/right. The tag changes the logical square factor dimension and traversal, without storing state or validating operand sizes.

micron::math::blas::uplo::lower

Defined in header <micron/math/blas/tags.hpp>.

Empty tag selecting lower-triangle storage/update in structured kernels.

Related tag

uplo::upper selects the upper triangle; uplo::uplo_tag accepts exactly those two types. Symmetric kernels reconstruct the opposite triangle mathematically, while triangular kernels ignore it and symmetric rank updates leave it unchanged. An ordinary view's at() does not interpret these tags.

micron::math::blas::diag::unit

Defined in header <micron/math/blas/tags.hpp>.

Empty tag selecting an assumed unit diagonal in triangular multiplication and solves.

Related tag

diag::non_unit reads/divides by stored diagonal coefficients. diag::diag_tag accepts exactly these two types. Nonunit mode does not add a zero-pivot status check; callers supply a valid nonsingular factor for triangular solves.

micron::math::blas::mixed::status

Defined in header <micron/math/blas/mixed.hpp>.

Validation result enumeration for mixed floating-input and centered int8 row-major GEMM.

Values and guarantees

ok means the output operation completed or its empty case required no work. bad_dimension reports pointer/leading-dimension/address-overflow validation failure; bad_zero_point reports an int8 zero point outside [-128,127]; accumulator_overflow reports the conservative centered-integer term bound. These checks precede output writes. Ordinary level1/2/3 kernels do not return this enumeration.

micron::math::blas::level1::vec_view

Defined in header <micron/math/blas/level1.hpp>.

Using-declaration exposing the borrowed quants::vec_view in the level-1 kernel namespace.

Shared view interfaces

vec_view<T> refers to an existing pointer, logical count n and signed element increment inc; it owns no coefficients. Level1, level2, ext and identities expose this same quants view through using-declarations. Matrix row_view/col_view imports in level2, level3, ext and identities likewise name the matrix view types described in the matrix reference; level2/level3 also import their symmetric/triangular variants. These declarations create no converted storage, validation, ownership or different indexing convention.

micron::math::blas::level1::axpy

Adds alpha*x into caller-provided y over a contiguous range or explicit strided count; O(n), with valid lengths and nonaliasing where restricted pointers are used.

Defined in header <micron/math/blas/level1.hpp>.

template<typename T>
constexpr void axpy(T alpha, const T* x, const T* x_end, T* y) noexcept;

Parameters

alphaScale factor for the input values.
x, x_endThe half-open input range.
yOutput range with at least x_end - x elements.

Return value

None. For each element, assigns y[i] + alpha * x[i] to y[i].

Notes

The pointer parameters are restricted; use non-overlapping input and output ranges.

micron::math::blas::level1::scal

Multiplies a contiguous or strided vector's selected coefficients by alpha in place in O(n), without resizing or allocating.

micron::math::blas::level3::gemm

Example

#include <micron/math/blas/level1.hpp>

int main()
{
  const double x[]{ 1, 2, 3 };
  double y[]{ 10, 20, 30 };
  micron::math::blas::level1::axpy(2.0, x, x + 3, y);
  return y[0] == 12 && y[1] == 24 && y[2] == 36 ? 0 : 1;
}
