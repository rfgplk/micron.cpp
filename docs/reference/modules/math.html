Mathematical functions

From micron reference
micron reference › Numerics and mathematics

Scalar arithmetic policies, floating-point elementary/special functions, compensated reductions, numerical array operations, activations, and compile-time constants. Specialized numeric containers have their own module pages.

Floating implementation and policies

The main scalar kernels use exponent/significand decomposition, range reduction, fixed tables, and polynomial/rational approximations. Exp uses 16-entry binary32 and 32-entry binary64 tables; log uses reduced mantissas and split ln(2). Trigonometric reduction selects Cody–Waite, double-double reduction, or a bounded Payne–Hanek table path according to input magnitude, then evaluates reduced polynomials. CORDIC uses 28 binary32 or 62 binary64 shift/add iterations after reduction.

Hyperbolic functions choose expm1/log1p-based forms near sensitive regions. Error functions use piecewise rational approximations; gamma uses Lanczos/reflection; Bessel routines combine truncated series with asymptotic forms. These implementations return numeric NaN/infinity/domain results rather than an error object or a uniform errno-setting contract. Output parameters such as frexp's exponent and remquo's quotient require valid writable pointers.

policy names express intended accuracy tiers, but most scalar wrappers do not select distinct code for every tag. cr_tag selects double-double paths for sin/cos/exp/log; fast_tag changes the binary32 reciprocal-square-root path. Many other tagged functions use the same kernel for all accepted tags. The CR driver returns its last approximation even when its rounding test is inconclusive; it has no arbitrary-precision retry or failure status. No uniform correctly-rounded or ULP bound follows from choosing a tag alone.

Constant evaluation of many mk interfaces uses compiler builtins, while runtime calls use micron kernels. Availability of a constant expression therefore depends on compiler support and argument; constexpr does not guarantee every invocation is evaluable at compile time. Runtime hardware/ISA selection follows build definitions. FMA may be nonfused on ARM VFPv3, and Clang constant-evaluation fallbacks use multiply-plus-add. Do not infer identical rounding across those paths.

Native wrappers commonly narrow long double/extended inputs through f64, and some legacy convenience overloads select a different path from the qualified kernel. In particular the non-template f32 cbrt overload in sqrt.hpp computes power(x,1/3), while mk::pow_ns::cbrt uses a sign-preserving, scaled Halley iteration. Integer fsqrt converts through f64, returns zero for negative signed input, and truncates the floating result; it is not an exact full-width integer-root algorithm.

Arithmetic and scalar preconditions

checked add/sub/mul use compiler overflow builtins and return the computed value with an overflow flag. checked div detects signed minimum divided by -1, but does not check a zero divisor. saturating arithmetic clamps on its detected overflow. Wrapping arithmetic converts through unsigned types; ordinary C++ integer promotions still apply to small unsigned operands, notably multiplication. Widening only participates when a wider mapped type exists.

Integer gcd uses binary subtraction/shift reduction; power/pow use exponentiation by squaring and return zero for a negative exponent, while power_loop takes linear exponent work. Factorial/permutation and lcm use ordinary representation arithmetic without a general overflow result. Signed absolute-magnitude operations need care at the minimum value, which has no positive counterpart in the same signed type. nearest_pow2 variants narrow to their named working width and do not guard a shift by the full width at the largest inputs.

Rounding/remainder helpers follow their individual formulas. rint uses a magic-add/subtract path natively and nearbyint delegates to it; they do not separately manage floating exception flags or provide a full floating-environment API. fmod uses truncating quotient semantics; remainder uses nearest/ties-even adjustment; remquo returns selected low quotient bits. Native work can scale with the exponent difference, bounded by the chosen format. Generic floor/ceil fallback for wider types casts through i64 and needs representable finite input.

Reductions and statistics

Pointer ranges are half-open. Container overloads generally assume contiguous pointer-compatible begin/end access and do not resize output. Selection preserves allocated storage but changes element values/order; existing pointers refer to potentially different values afterward. Integral overflow, NaNs, infinities, and an invalid quantile argument are not reported through a shared status. Use finite ordered data and suitable representations when that is required.

Numerical arrays

Bulk pointer operations marked restrict require nonoverlapping input/output storage unless using a dedicated in-place overload. Container destinations must already contain enough writable elements; these overloads do not infer or allocate the needed result size. Ordinary scalar operations and these array loops allocate no heap storage.

Logarithmic helpers and activations

log_sum_exp/log_sum_exp_n subtract a maximum before exponentiation; log_softmax subtracts the log sum; softmax writes normalized exponentials. Empty log-sum input returns negative infinity and empty bulk transforms do nothing. Inputs containing positive infinity or all negative infinity can still create indeterminate infinity subtraction in some paths; this is not a fully masked probability engine.

log1mexp selects a cancellation-resistant branch for log(1−exp(x)), requiring x<=0; log_diff_exp requires the corresponding ordered exponentials. logistic/log_logistic and softplus choose sign/size branches to avoid common overflows. xlogx/xlogy return zero when the multiplying x is zero.

Activations include ReLU, leaky ReLU, ELU, exact-erf/tanh-approximate GELU forms, SiLU/swish, mish, hard-tanh, softsign, hardswish, and threshold. Scalar forms compose the math kernels; supplied bulk overloads loop in O(n), using existing output or modifying input. Their treatment of NaNs follows the actual comparisons/formulas; there is no common propagation policy. Multiple-container overloads independently transform each supplied container.

Constants and runtime support

constant_* variable templates cast long-double literals to the requested floating type. Named double/float constants and pi_t/default_eps specializations provide convenient spellings; default_eps is an algorithm default tolerance, not numeric_limits<T>::epsilon or a universal error bound. micron::ratio stores an unsigned reduced compile-time fraction and supplies SI scale aliases.

The __gcc_* headers provide compiler runtime/link symbols for a freestanding CRT and are not ordinary application headers. Their native long-double math shims often narrow to double; the binary128 arithmetic shims implement fixed software arithmetic with subnormal output flush-to-zero limitations. Their existence does not upgrade scalar transcendental wrapper precision. Include public math headers for application calls.

For a fixed binary format the elementary kernels use bounded scalar work and constant storage, but their costs differ substantially: a hardware root, short polynomial, long argument reduction, CORDIC loop, and special-function composition are not interchangeable performance promises. No benchmark comparison is implied by fast or branchless naming.

micron::math::arith::checked_result

Defined in header <micron/math/arith.hpp>.

Arithmetic value and overflow flag returned by checked integer operations.

Result handling

Explicit Boolean conversion is true when overflow is false. Inspect overflow before treating the computed value as an exact mathematical result. Division by zero is not represented by this flag. arith_integral accepts integral types other than bool; result storage is inline and performs no allocation.

micron::math::arith::widen

Defined in header <micron/math/arith.hpp>.

Type mapping to the next wider fixed-width integer where a specialization is supplied.

Mappings

i8/u8 map to i16/u16, then to i32/u32, then i64/u64. On pointer-width-64 targets i64/u64 map to i128/u128. Other types map to themselves; widening operations require a changed type. widen_t names type. Carrying adc/sbb instead return tuple<T,T> with result and an OR-combined carry/borrow indicator; mul64 returns low and high halves of a u64 product.

micron::math::policy::ieee_tag

Defined in header <micron/math/policy.hpp>.

Empty type selecting the named IEEE policy in interfaces that accept a math policy.

Policy family

cr_tag, faithful_tag, and fast_tag are the other native tags. ieee/cr/faithful/fast are constexpr tag objects; default_tag<F> is faithful_tag natively. policy_tag recognizes these types. Tags carry no runtime state and do not themselves measure or certify rounding error; consult the selected function's actual policy branch.

micron::math::cr::ziv_result

Defined in header <micron/math/cr.hpp>.

Double-double approximation y and asserted absolute-error bound abs_err for a rounding-test stage.

Driver behavior

drive_f64/drive_f64_2arg run a first stage, test, then a second stage if needed and return that stage even if its test remains inconclusive. Binary32 drivers round the supplied double-double stage through a round-to-odd helper. Specific sin/cos/log/exp CR routines use bounded double-double kernels rather than an extensible precision ladder. This record is useful for the stage protocol, not an independent proof that an arbitrary supplied error bound is valid.

micron::math::poly_coeffs

Defined in header <micron/math/bits/impl.hpp>.

Inline array of degree Dg plus one floating coefficients, ordered from constant term upward.

Members and cost

value_type is F, degree is Dg, and size is Dg+1. Indexing is unchecked; begin/end expose a const pointer range. horner evaluates with Dg multiply-add steps, O(Dg) time and constant scratch. horner_p's n is a degree index (it reads c[n]), unlike numeric.hpp's polyval count. The array is embedded and pointer validity follows the object's lifetime.

micron::math::moments

Defined in header <micron/math/reduce.hpp>.

Floating population mean/variance and sample count returned by Welford reduction.

Interpretation

mean and var are F and n is usize. welford updates both statistics online and divides variance accumulation by n, not n−1. Empty input returns all zeros. This is a result snapshot without retained input or incremental-update member functions.

micron::math::divmod_result

Defined in header <micron/math/numeric.hpp>.

Integral quotient quot and remainder rem from floor-style division.

Division semantics

divmod first uses C++ quotient/remainder arithmetic, then adjusts a nonzero signed remainder to have the divisor's sign. The quotient is therefore floor division for signed operands. Zero divisors and signed minimum divided by -1 remain invalid arithmetic; no error field is returned. The pair uses constant scalar work.

micron::ratio

Defined in header <micron/math/ratios.hpp>.

Compile-time unsigned numerator/denominator ratio reduced by Euclid's GCD.

Members and aliases

N and D are uintmax_t and D must be nonzero. num and denom are the reduced static constants; the type has no stored value or arithmetic/comparison operators. SI aliases range from exa through atto with base_ratio for unity. Negative ratios are not represented. Template reduction takes O(log(min(N,D))) remainder steps; using the constants has no runtime storage cost.

micron::math::mkbits::cordic_ns::atan_q62_table_t

Defined in header <micron/math/bits/cordic.hpp>.

Inline precomputed CORDIC table wrapper for 63 Q2.62 angle values.

Related tables
