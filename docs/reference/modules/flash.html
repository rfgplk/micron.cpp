Asynchronous file I/O

From micron reference
micron reference › Input and output

An io_uring engine, completion-waiting descriptor/file operations, linked SQE chains, and bounded-concurrency path batches. Ordinary flash read/write/file helpers wait for completion before returning; queue_* plus explicit submit/reap/wait expose the asynchronous protocol. One engine requires exclusive, coordinated use of its submission and completion queues.

Counts and completion results

The templated pointer read/write/pread/pwrite count is an element count, multiplied by sizeof(T); the returned max_t is bytes. This differs from io::read/write's explicit byte count. Multiplication, offset addition, pointer extent, and nullness are not checked. The implementation splits requests into at most 1-GiB SQEs and waits after each chunk. It retries EINTR; a later error can return previous positive progress rather than that error. A zero completion ends the loop. Nonpositional calls use the all-ones offset sentinel; positional calls advance the explicit u64 offset.

One-shot metadata/fixed operations submit one SQE and return its i32 completion result widened to max_t. Submission-wait return values are ignored before await, so a failed submission is not uniformly surfaced at its original site. There is no automatic fallback to ordinary blocking syscalls when the ring is unavailable or an opcode is unsupported. A dead engine returns -ENOSYS through the guard.

Successful queue_* returns 0 for staging, not completed I/O. Buffers, path characters, stat output records, descriptors, and any linked SQEs must remain valid until their CQEs have been consumed. reap consumes one ready completion; wait consumes one after waiting; drain invokes the callback for exactly n completions or returns a wait error. The callback receives user_data and the raw completion result. Callback exceptions propagate; the helpers do not own the borrowed payloads or cancel them at scope exit.

Completion ownership and isolation

engine::await discards every consumed CQE whose user_data does not match its one requested id. Internal batch waves likewise consume all visible completions but dispatch only the selected tag/generation. Other requests' completions are not retained for a later consumer. Do not interleave independent synchronous, chain, batch, coroutine, or user-managed consumers on the same ring. The raw ring accessor does not create separate queues or an ownership boundary.

Internal user_data packs one-shot, wave, chain, or reclaim tags, a 16-bit generation for waves/chains, a 24-bit item index, and step identifiers. Generation wrap is not a proof against arbitrarily old outstanding requests. Custom queue user_data is unrestricted but can collide with that namespace. Keep all internal waves drained and use a dedicated engine when manually managing unrelated completion ids.

Internal wave submission tracks published versus still-unsubmitted SQEs, then drains presumed in-flight completions. Errors/short submission can leave requests or completions unaccounted for; callers of the wave helper ignore its status. No public timeout, cancellation, completion stash, or general drain-on-error guarantee is provided. Storage referenced by an actually outstanding request must not be freed merely because a higher-level error path returned.

Whole-file helpers

read_file<T> supports one-byte string/contiguous targets. It first reads a 64-KiB probe at offset zero, returning directly when short. A full probe triggers statx; a positive larger reported size is reserved/read, otherwise capacity grows by a factor of four while fills remain full. Allocation/size multiplication and growth overflow are not globally guarded. The value form returns option<T,error_t>; the resizable target form resets length to zero on an explicit read error, while fixed-capacity targets use a one-byte overflow probe and return EFBIG if more data is detected. Failure of that final probe is not separately reported.

write_file creates/truncates and returns its write count without fsync. write_file_sync additionally checks a completed sync; append_file opens O_APPEND. create_file uses truncating modes::write rather than an exclusive-create contract. read_file/path helpers require available() (basic/fixed), while file construction itself mainly checks ring liveness and can attempt an unsupported opcode. file_size returns -1 and exists false on stat failure.

copy opens/truncates the destination, uses a pool slab or a 16-KiB stack fallback, and loops positional reads/writes without final fsync or a same-inode guard. Source and destination must not be the same inode, including through a hardlink, because destination truncation occurs before reading. move uses rename, then this copy + remove on EXDEV; it is not atomic across filesystems and a short positive copy is not independently verified against a source snapshot.

with_file invokes a callback with a scoped flash::file&, returns its value/unit_t in option, and propagates callback exceptions. map_files first loads all inputs then calls the transform on successful values in order; fold_files also loads all inputs before its ordered fold and stops at the first result error. These operations retain all loaded contents, not one streaming file at a time. Curried forms capture path/callback state and use the thread's default engine when invoked.

Batch behavior and limits

read_files/write_files/stat_many process windows of min(remaining,64,ring_entries-8), with one item when the depth is at most eight. A wave stages only currently available SQ room. The outer loop nevertheless advances over the whole item window; an occupied ring can therefore cause unstaged items to fail or be omitted from a cleanup wave. Use a dedicated otherwise-empty ring, with sufficient room, and treat per-item results as authoritative rather than assuming every request was submitted.

read_files issues statx-size and open waves, allocates reported sizes, then performs at most sixteen read rounds per window. Each item requests up to 1 GiB in a round; interruptions also consume rounds. A positive-size item still incomplete after the cap becomes EIO. A reported zero-size item is retried through the one-file growth helper after the batch close. Open flags here are O_RDONLY without the normal open_opts close-on-exec default.

write_files opens O_WRONLY|O_CREAT|O_TRUNC, then uses the same sixteen-round/1-GiB-per-item cap. A zero write changes the desired count to progress already made and can yield a successful short count. Neither writer nor close wave fsyncs or reports close errors. A cleanup wave that cannot stage every close can leave an fd unclosed even though bookkeeping is reset. Earlier successful/partial outputs are not rolled back on another item's error.

Results preserve input order and use first=success, second=error. The target overload of read_files appends results to an existing vector and returns the number of successful alternatives, not bytes. stat_many returns per-item stat/error. Value vectors and per-file buffers require memory proportional to item count plus all retained file contents; bounded in-flight concurrency does not bound total result storage.

Alignment, capability, and tuning

Engine configuration can request SQPOLL, IOPOLL, registered buffers/files, and a registered ring fd. SQPOLL requests a kernel polling thread; IOPOLL is for appropriately opened direct-I/O files/devices. These are opt-in operation modes with kernel/device requirements, not measured speed guarantees. Direct I/O still requires suitable address, length, and offset alignment; enabling a pool does not validate a particular device request.

dio_align returns 4096 when its feature/query/field check fails. Its stat helper requests STATX_BASIC_STATS rather than explicitly requesting the DIOALIGN mask, and it does not verify that result's validity mask. Thus the return is a fallback hint, not a comprehensive device alignment certificate. Engine pool slab size is not rounded to pages; only mmap's initial base is page-aligned, so later slabs need a suitably aligned configured stride.

Batching reduces the number of separately awaited submissions by staging independent items together; linked chains express ordering without user-space sequencing between their steps. Actual throughput/latency depends on workload, storage, kernel, ring depth, and selected modes. No performance comparison follows from tier names alone. Kernel I/O and waits have no finite worst-case completion-time bound.

micron::io::flash::tier

Defined in header <micron/io/flash.hpp>.

The engine's selected ring/path-operation capability level.

Values

ValueSelection and usable interpretation
noneRing initialization failed or shutdown occurred; guarded operations return -ENOSYS.
plumbingRing initialized but the feature table lacks ordinary op_read. available() is false, so high-level path helpers refuse it.
basicop_read feature is reported; ordinary path/file SQEs are attempted, subject to opcode-specific support.
fixedBasic plus successful sparse fixed-file registration, enabling direct-open chains.

Limits

The implementation's plumbing tier does not automatically substitute READV/WRITEV for the ordinary pointer read/write wrappers: they still prepare READ/WRITE. A live plumbing ring therefore does not promise those helpers succeed. Tier fixed does not route ordinary whole-file helpers through a linked fixed-file chain automatically. Optional operations such as ftruncate/rename/mkdir also test their individual feature gates. live means a ring exists; available means basic or fixed.

Sizing

Pool byte size is count*slab_size with no overflow or page-stride rounding check. Sparse file slots and buffer slots are finite borrowed resources, not elastic queues. These values are read at init; changing an options object after initialization has no effect. init on an already live engine returns 0 without applying new options.

micron::io::flash::engine

Defined in header <micron/io/flash.hpp>.

An immovable, unsynchronized io_uring owner with lazy registered-buffer storage and sparse fixed-file slot bookkeeping.

Initialization and lifetime

Default construction leaves a dead engine; the options constructor calls init and discards its returned status. Inspect init/live/level. init chooses SINGLE_ISSUER|DEFER_TASKRUN or COOP_TASKRUN where feature-gated, unless SQPOLL was requested, and uses ring::init_best to retry selected unsupported setup flags on EINVAL. Such issuer modes require the appropriate single-issuer use; the class adds no cross-thread locking.

Buffer geometry is recorded at init but mmap/registration occurs on first acquire. Sparse fixed-file registration is attempted eagerly; success promotes basic to fixed. Shutdown unregisters buffers/files, shuts down ring mappings, frees pool storage, and sets counts/level to none. It does not wait through a public all-requests ownership protocol or invalidate external C++ handles safely; finish all operations and destroy leases/files/chains before destroying the engine.

The four fixed-file free bitmaps are not cleared by shutdown. Reinitializing the same object with fewer slots can leave old free bits outside the new registered count, and acquire_slot can return such a stale index. Prefer a fresh engine for a new configuration rather than assuming shutdown/init resets every resource bit. Pool configuration also remains recorded after shutdown, so has_pool/nbufs can describe configured geometry even while the ring is dead. Sequence/generation counters retain their prior values.

default_engine is a function-local thread_local engine initialized with defaults; no thread-safety is added to a borrowed reference crossing threads. Files and leases using it must be destroyed before that thread-local engine. The thread's first access can perform kernel feature probing and ring setup; failure remains a dead engine rather than falling back to ordinary I/O.

Submission, resources, and results

sqe gets a writable SQE and tries an enter(0) once when no SQE is available. advance/publish make SQ entries visible; stage(k) peeks at unpublished positions without reserving them against another builder. submit/submit_wait expose ring results. await consumes unmatched CQEs as described above. ring() grants direct mutable access and can violate engine assumptions if independently used.

acquire_buf realizes the pool and returns a slab pointer/capacity/u16 index, or EAGAIN for pool failure/exhaustion. Realization mmap's count*stride, allocates an iovec vector, registers it, and disables later pool realization after mmap/registration failure. Its noexcept body can still reach allocation failure policy. release_buf simply sets the free bit for an in-range index; duplicate release or release during in-flight I/O is not detected.

acquire_slot scans four u64 words for a free bit and clears it; release_slot marks an in-range slot free but does not close/unregister a file occupying it. These methods form bookkeeping only. Callers must close the fixed file and complete its requests before returning the slot. No generation/refcount validates stale slot/lease users. Setup/teardown costs include ring/resource syscalls and mappings; ordinary slot acquisition/release takes bounded constant work, while CQ waits depend on completion traffic.

micron::io::flash::pool_buf

Defined in header <micron/io/flash.hpp>.

A move-only lease returning one registered-buffer index to its borrowed engine on destruction.

Fields and ownership

Public data, cap, index, and __e describe a slab; valid tests only __e != null. acquire_buf returns this lease in the first option alternative or error_t in the second. Moving transfers the release responsibility and nulls the source's engine/data, leaving other scalar metadata potentially unchanged. Move assignment first releases a previous lease. Destruction returns the bit; it does not wait for outstanding requests or unmap memory.

The engine and registration must remain alive through every use and the lease destructor. Do not shutdown/reinitialize the engine while leases exist; an old lease can release a newly reused index or refer to unmapped storage. Pointers are invalidated by pool teardown, and returned slab contents are not automatically cleared between acquisitions. The lease owns exclusive bookkeeping for the slot, not a separate heap allocation.

read_fixed/write_fixed take byte counts, cast them to u32, and check only b.valid. They do not enforce count <= cap, count <= UINT32_MAX, suitable alignment, or that the supplied/default engine is the same engine that registered b. Supply that exact engine explicitly when necessary and retain the lease until completion. A fixed one-shot can be short and supplies no complete-transfer loop.

micron::io::flash::chain

Defined in header <micron/io/flash.hpp>.

An immovable builder of at most eight linked SQEs over a borrowed engine.

Build protocol

Construction obtains a generation and initializes eight results to -1. Explicit-fd read/write/fsync/close work without a fixed-file slot. open requires tier fixed, borrows one slot, and prepares a direct open; subsequent no-fd operations address that slot. Every added step marks its predecessor IO_LINK. Payload/path storage remains borrowed. More than eight steps sets EINVAL; unavailable staging/slots sets EAGAIN; subsequent additions retain that build error.

Build on an otherwise exclusive engine and call run once. Staging does not reserve queue positions against other engine operations, so interleaving builders/submissions can overwrite or link the wrong SQE. The object is neither copyable nor movable and retains its engine reference. It has no reset/rebuild protocol; run does not clear the staged count or results before a later run. Use at most one open per chain: a second open overwrites the tracked slot id without returning the first slot's bookkeeping.

Destruction returns the tracked slot's free bit but does not submit an abandoned chain or wait/cancel in-flight work. A failed build can retain its slot until destruction. Do not destroy the engine first, and do not release a chain whose requests are still using its slot or payload.

Run results and cleanup

run publishes the built count and uses one matching-generation wave to collect results. res(i) returns a step result, or -1 outside the built range; missing results also remain -1. run returns the first observed non-cancellation error and ignores ECANCELED. It does not establish that every step was observed: the wave status is ignored, so zero can accompany canceled or missing completions. Inspect per-step results and the operation's expected byte counts.

If an observed open succeeded but no observed successful close exists, run attempts an extra direct close. Its cleanup wait consumes one CQE without verifying its id and ignores that result. Cleanup failure can leave a file occupying a slot that destruction later marks free. Linked operations also obey the kernel's short-I/O/link-cancellation rules; adding read/write/fsync/close does not make a multi-step transaction or promise rollback. User-space builder work is O(number of steps), bounded by eight, with fixed inline metadata; kernel I/O and waits remain unbounded in latency.

micron::io::flash::file

Defined in header <micron/io/flash.hpp>.

A move-only descriptor owner using a borrowed engine and an independent u64 byte cursor.

Opening and ownership

Path construction submits openat with modes/open_opts and stores its descriptor/error without an inode-type validation. The name is only a suffix of at most name_cap-1 (127) characters, not necessarily the full path. Adoption takes fd ownership and records that shortened text without dup/stat. Default construction is invalid. valid requires nonnegative fd and a nonnull engine pointer, but does not check that the engine is still live.

Move transfers fd/engine/cursor/name and disarms the source. close submits a ring close while the engine is live, ignores its completion status, and invalidates the handle; if the engine pointer is null/dead it uses raw SYS_close. The engine object itself must still exist to test live. An ignored ring-close failure can lose the descriptor value without a successful close. fd/raw_fd are borrowed; no release member transfers ownership. Destructor closes but does not automatically fsync.

The logical cursor starts zero for every mode, including append. seek/rewind only change that number, not the kernel fd position. read/write use positional flash calls and advance cursor by positive byte results; read_at/write_at leave it unchanged. O_APPEND can determine actual kernel write placement independently, so cursor does not then represent physical EOF. Cursor arithmetic/offset validity is unchecked and unsynchronized.

Data and transforms

String/trivial-contiguous writes use string_len(c)*sizeof(value_type); plain trivial objects use native sizeof(T) bytes; literals omit the final slot and pointer strings scan to NUL without a null check. No generic node-container framing tier is supplied here. read(out) fills its current element extent without resizing. read<T>() reserves from statx size when positive, otherwise grows one-byte push_back targets until a nonpositive read; its result has no error alternative and can be empty/partial after failure.

read(fn) invokes a string consumer and returns its result/unit_t in option, but it checks only the initial file guard before calling the value-returning read. A later read failure can therefore still invoke the callback with empty/partial data as a successful alternative. modify reads from the current logical cursor (it does not first rewind), transforms that string, truncates the entire file to zero, resets cursor, then writes. It is not a whole-original-file transform when cursor was advanced, and is not atomic or automatically synced.

size/stat use statx through the ring. sync/datasync/allocate/advise/truncate expose completion results; truncate has an individual feature gate. fadvise's length narrows to u32 in the prepared SQE. No synchronous syscall fallback, cached stat, record lock, cancellation token, or concurrent method safety is added. Returned name references borrow the object; moved/replaced/destroyed descriptors and engine teardown invalidate dependent uses. Whole-value reads/transforms allocate proportional to content; raw transfer state is constant apart from ring resources.

micron::io::flash::write_spec

Defined in header <micron/io/flash.hpp>.

An owned path plus a borrowed byte span for one batch write.

Fields and lifetime

path is path_t, data is const byte*, and len is bytes. Copying copies the fixed path and pointer/count without copying payload. write_files opens/truncates every selected destination, then reads this span during its completion waves. The vector, paths, and all payload spans must remain stable through the call and any outstanding requests after an abnormal completion path. Empty len needs no payload bytes; nonempty null/undersized storage is not validated. Batch status, partial output, sixteen-round limits, and absent fsync are described above.
