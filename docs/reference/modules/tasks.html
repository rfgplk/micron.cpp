Tasks and coroutines

From micron reference
micron reference › Concurrency

Lazy C++ coroutine tasks, continuation-stealing scheduling, manually resumed stackful routines, and asynchronous synchronization share frame/lifetime support but have distinct execution and ownership protocols.

Entry headers and runtime lifecycle

Include <micron/stdcoro.hpp> before other task headers to select the io_uring reactor by default; define MICRON_CORO_NO_URING first to disable that default. Including a task/reactor header before the entry header can compile out the reactor and is diagnosed by the entry header. <micron/coroio.hpp> additionally includes the I/O umbrellas; it does not introduce another task type. Native stack switching and the task-based engine reject wasm.

start_coroutine_runtime(nworkers) lazily initializes a global engine once, selecting cpu_count() for zero and clamping to 1 through 32 workers. Each worker is an owning auto_thread, with a private work deque, overflow list, and resident dispatch fiber. External roots enter a bounded 256-entry MPMC inbox; submission yields until it can insert. Default deques are growable from MICRON_CORO_DEQUE_CAP (1024); MICRON_CORO_FIXED_DEQUE uses the fixed variant.

A worker pops local continuations LIFO, polls the inbox first every 64 searches, checks completions when enabled, and steals from other workers with a bounded randomized scan. Before parking it performs bounded CPU-pause searches, announces its park bit, and rechecks for work. Per-worker epoch futexes are the default; MICRON_CORO_GLOBAL_SIGNAL selects a shared signal word and is incompatible with the reactor. These heuristics do not guarantee FIFO scheduling or progress for a blocking callback.

stop_coroutine_runtime() waits for repeated quiet observations, applies configurable no-progress grace periods to timers and I/O, wakes/join workers, shuts down rings and pooled segments, and clears global state. It is not a general cancellation/join of arbitrary tasks suspended on user synchronization. Timer waits can be cut and their list discarded after the grace period. Stop must run from an external coordinated owner without concurrent submission, restart, or outstanding borrowed engine/executor use; calling it from one of its workers can wait on or join itself. The runtime reaper calls stop during normal teardown.

Fork, call, join, and result binding

co_await fork(eventual, fn, args...) constructs a child and binds its result to the supplied eventual. fork(&slot, fn)(args...) binds an existing assignable value; fork(discard, fn)(args...) discards the result. The bracket forms select the same binders. The current worker publishes the parent continuation before immediately transferring into the child. If publication is unavailable or a fixed deque is full, the child completes serially back to the parent.

Forked callable parameters must be passed by value: reference parameters could refer to the binder's argument copy after a continuation is stolen. The source checks ordinary function and non-overloaded call-operator signatures; generic/overloaded callables may evade that check and still must obey the lifetime requirement. Capturing a pointer does not copy the pointed-to object. Result destinations and parent locals must remain live until co_await join completes.

co_await join waits for detached/stolen child completions, destroys the parent's linked child frames, clears the join epoch, and surfaces the first recorded child error. At most 32767 outstanding steals fit one join epoch; exceeding that packed count traps. The first-child-error pointer is ordinary shared storage: simultaneous failures in separate children can race while recording it, so this is not a general synchronized exception-aggregation mechanism. No destructor implicitly joins forked children. Returning, unwinding, or destroying a parent before the join can leave children referencing dead parent/result storage.

Unbound call(fn, args...) simply invokes the callable and returns its task for ordinary co_await. Result-bound call(&slot, fn)(args...) uses a serial symmetric-transfer child and destroys its frame with its awaitable. A bound child's runtime exception is not automatically surfaced by that awaitable's empty await_resume; an eventual binding records it, while raw/discard binding may leave no value/error indication. Fork construction/allocation failures are recorded for join, while call construction failure records an eventual error only when that binding is used.

Root submission, yielding, and timed waits

sync_wait(task&&) starts the runtime, moves the root into a bridge, submits it, briefly CPU-spins, then futex-waits for a release-published done flag. schedule(task&&) returns futex_future<T> and completes its promise from a detached bridge. detach(task&&) supplies no result. The bridge unhandled-exception path traps; these APIs do not preserve and rethrow an arbitrary task exception as the original exception object. sync_wait does not check a null bridge allocation result before accessing it.

co_await futex_future uses its state's single coroutine-waiter slot and returns get(). The future/state and engine must remain live. Only one pending coroutine waiter may register on a state. coro::when_any(futures, n) allocates a selection state and one node per future, returning the first observed ready index without consuming a result. Losing registrations remain until their producers complete; their futures/states must be retained. n == 0 has no winner and suspends indefinitely, and overlapping registrations on the same state are unsupported.

reschedule() republishes locally LIFO and may return inline off-engine or on deque failure. reschedule_fair() first tries the external inbox and drains some I/O, then falls back to the local route. Neither is a strict fairness or I/O-completion guarantee. sleep_until uses an absolute monotonic timespec; sleep_for counts nanoseconds and sleep_for_ms multiplies milliseconds without overflow checking. Sleep uses a ring timeout when available, otherwise a lazily created native timer thread scanning an intrusive list. Retain a sleeping frame until wake; the timer registration has no destructor unlink.

Bulk task creation

spawn_many(n, fn) forks fn(i) into a vector of n already default-constructed slots, joins, and returns it. The result must be a nonvoid default-constructible, assignable element type; the slots stay stable during the loop. spawn_tuple(tasks...) and when_all similarly default-construct a heterogeneous tuple, fork each already-built task into its slot, and join. Void and nonassignable results are not supported by these aggregate result containers.

fork_task(&slot, task&&) transfers an already constructed task into a fork awaitable and selects eventual or lvalue binding from the destination type. It does not by itself run a task; the returned awaitable must be awaited. Aggregate spawning allocates result storage and coroutine frames and uses linear setup/collection work plus the children. It inherits the per-join epoch and destination-lifetime bounds.

Coroutine synchronization and cancellation

Async mutex/event/semaphore/barrier/latch/rwlock/condition-variable waits require promises derived from the scheduler's frame base. They store nodes in suspended frames and generally wake by engine submission or inline resume. They do not interoperate with an arbitrary foreign coroutine promise merely because it has a coroutine handle.

Cancellation is cooperative. cancellation_source::bind(task) records a borrowed flag in that frame; structured fork and result-bound call inherit it. co_await cancelpoint() returns a boolean and neither throws nor automatically stops the task. Ordinary direct co_await of another task does not copy the parent's flag into that task. Mutex, condition, channel, and timer waits do not automatically unlink or complete on source cancellation.

With the reactor, a source cancel also scans registered one-shot I/O operations and requests kernel cancellation by user_data. Group request-cancel only sets its own flag and does not call that source hook. Neither form permits destroying an in-flight awaitable or buffer before completion has been observed.

Fiber storage and ABI

Fibers choose the first size class at least as large as the requested segment: 256 KiB, 512 KiB, 1 MiB, or 4 MiB, clamping larger requests to 4 MiB. Roughly three quarters are reserved for upward-growing coroutine frames and one quarter for the downward-growing C stack, with two guard pages; VA-granule rounding can add frame slack. The control block occupies the high end of the C stack, reducing usable call-stack bytes. routine::stack_size() reports that C-stack region, not the requested combined class size.

Segments first carve from abcmalloc's VA reservation and commit frame/stack spans, then fall back to ordinary mapping. Fallback guard mprotect errors are ignored. Same-thread released segments enter a TLS freelist; cross-thread releases use a bounded per-class 64-entry pool or return the region. Coroutine frames use an aligned bump arena when a fiber is current and fall back to aligned heap allocation otherwise or on arena exhaustion. Each arena frame retains a segment reference; only the topmost current frame can rewind the bump cursor individually.

Context switching has explicit amd64, i386, arm32, and arm64 register layouts. Native thread TLS is not switched per fiber. The default does not save x86 floating-point control modes; MICRON_FIBER_FPENV adds x86 control-word handling and masks sticky SSE status bits on save. ARM code saves ABI callee-saved floating registers, not an independent complete per-fiber floating environment. Code must not assume thread-local state or a changed FP environment belongs to a migrating coroutine.

Reactor and one-shot I/O

With MICRON_CORO_URING, each worker owns a ring initialized on that worker and a separate 64-entry fallback ring accepts off-worker submission under a lock. Worker ring entries default to 256 (MICRON_CORO_URING_ENTRIES). Submission remains single-producer per worker ring; completion reaping is serialized per ring and may be performed by another worker. The setup uses no-SQ-array intent and the ring's compatible initialization path, rather than assuming every kernel supports the newest flags.

The coro::io read/write/readv/writev, open/close/metadata, allocation/advice, splice/tee, socket, poll, and nop builders copy an SQE into a one-shot awaitable. Awaiting returns the kernel completion's signed 32-bit result: byte count/descriptor/mask or negative errno, depending on the operation. Read/write offset u64(-1) uses and advances the descriptor position. Paths, iovecs, address buffers, and data buffers are borrowed until completion, and the wrapper does not retry partial transfers.

A submitted/suspended/done-early handshake prevents completion from resuming a frame before suspension commits. Missing rings produce -38, refused fixed-buffer registration -95, a pre-cancelled frame -125, and exhausted submission room after retry -105. operation | after(ns) submits the operation linked to a relative timeout SQE and reports the operation completion result; it does not return a separate timeout enum. The awaitable destructor removes its cancellation-registry link but does not make destruction before kernel completion safe.

Fixed data uses a shared slab of eight 256-KiB slots. acquire_fixed returns a slot or -1, fixed_ptr/size expose its buffer and byte capacity, and release_fixed only returns its bitmap slot. Retain the slot until all using operations complete. Slab registration is lazy per ring and can be refused, for example by memlock limits. Sparse direct-file tables default to 256 slots per ring (MICRON_CORO_FILE_SLOTS, a nonzero multiple of 64); wave helpers keep ring id and slot ownership paired.

MICRON_CORO_STAGED_SUBMIT batches worker submissions up to 16 SQEs before entering and flushes on progress/parking paths. MICRON_CORO_STATS enables counters; io_stats() otherwise returns zeros. Registered-buffer and ring sizes are tuning/storage choices, not throughput guarantees. They also do not validate an arbitrary pointer as belonging to a chosen fixed buffer.

Multishot and wave protocols

coro::io::mrecv_t retains one multishot receive operation on its worker ring. Each event has a result, originating ring, optional provided-buffer id, and more-events flag. The provided pool defaults to 256 buffers of 8192 bytes per participating ring; MICRON_CORO_PBUF_ENTRIES is a power-of-two setting and MICRON_CORO_PBUF_SZ is the per-buffer byte size. A single consumer calls mrecv_next, inspects/uses data, then recycles each provided buffer exactly once after use.

The event queue has twice the provided-buffer entry count and traps on overflow. Not returning buffers prevents their reuse; retaining a data pointer after recycle allows subsequent kernel writes to overwrite it. mrecv_cancel requests synchronous cancellation, drains completion events until no more are promised, recycles queued buffers, and resets the operation; the destructor calls it while live. Keep the operation alive until that drain finishes. Cancellation can wait and is not a bounded-step destructor.

wave.hpp supplies lower-level ring/slot and batch-await support rather than an owning public wave container. The owner supplies the SQE array, completion-node array, and wave state and must keep them alive while any completion is outstanding. One batch completion resumes its owner after the last SQE; individual results remain in nodes. Waves do not register with the task cancellation source, so cancelling a source does not cut a batch short. Batch construction/destruction and result extraction belong to the higher I/O wrapper contract.

micron::task

Defined in header <micron/tasks/task.hpp>.

A lazy move-only coroutine owner storing its result in a promise or a caller-bound destination.

Ownership and result

promise_type aliases __task_promise<T>; its void specialization stores completion without a value. Construction from a coroutine handle owns that frame. release() transfers the handle and empties the owner; handle() merely borrows it. Move transfers ownership, destroying the destination's old frame on assignment. Destruction immediately destroys an owned frame rather than running or joining it.

valid() tests a nonnull frame and done() tests completed final suspension. result() requires both and reports a library error otherwise. It moves the inline result without clearing the value-state flag; repeated calls move again from the retained object. An empty/allocation-failed task is invalid. Reference-result instantiations are not provided by the union-based value storage.

Rvalue operator co_await creates a non-owning awaiter that sets a continuation and symmetrically transfers into the child. The task object still owns the frame and must survive the await; temporary task lifetime normally supplies that. Unhandled exceptions are reduced to a fixed diagnostic string and surfaced through the library error path; the original exception object is not retained. Bound promise completion constructs an eventual, assigns a raw lvalue, or discards according to the binding mode.

Frame allocation uses the current fiber's aligned arena or heap fallback. Handle operations are constant work; creating/destroying a frame includes parameter/local/result lifetimes. A frame suspended in a registered wait or with unfinished fork children cannot safely be destroyed merely because an owner handle is available.

micron::coro::eventual

Defined in header <micron/tasks/frame.hpp>.

An immovable construct-once result slot for a structured child task.

Value lifetime

The primary template contains uninitialized union storage, a has-value flag, and an error-string pointer. Successful child return constructs T directly in that storage; destruction destroys it only if constructed. get() & returns its protected-by-join reference; rvalue dereference moves a result by value but leaves the stored object alive. Reading an error or reading a nonvoid slot before production reports a library error.

The slot has no atomic readiness wait and does not retain a producing frame. Read only after the corresponding join/call completion, and do not overwrite a live constructed result with another child. The void specialization stores only error state; its successful dereference performs no readiness check. Copy and move are not available.

micron::coro::discard_t

Defined in header <micron/tasks/quasi_pointer.hpp>.

An empty tag selecting evaluation without result storage for a bound fork or call.

Use

The inline constant coro::discard is passed to the fork/call binder. It suppresses destination storage, not execution, lifetime obligations, child joining, or error recording for structured forks. It allocates no memory and carries no cancellation state.

micron::coro::manual_lifetime

Defined in header <micron/tasks/manual_lifetime.hpp>.

Aligned inline union storage with explicit construction and destruction of T.

Protocol

construct(args...) placement-constructs the object and returns its address. destroy() explicitly invokes the destructor. get, ptr, and arrow access storage without checking whether an object is live; cv/ref-qualified get preserves value category. The wrapper destructor intentionally does not destroy T. The caller must balance construction/destruction and never read inactive storage. Copying is deleted and no move is provided.

The void specialization makes construct/destroy/get no-ops. The wrapper performs no allocation or synchronization. Costs are those of the chosen T operation; double construction, double destruction, and using inactive storage are unsupported.

micron::coro::worker

Defined in header <micron/tasks/coro_core.hpp>.

A cache-line-aligned scheduler record holding one worker's continuation deque and dispatch state.

Storage and constraints

The record contains a fixed or growable Chase-Lev deque, an owner-private overflow list, an active flag, resident fiber pointer, id, and inbox-poll cadence counter. Deque bottom operations belong to its worker; thieves use the steal interface. Direct field manipulation is scheduler-internal and does not transfer frame ownership. current_worker() returns the native thread's TLS record or null off-engine.

The engine owns the worker array and destroys it after joining workers. A borrowed record becomes invalid when runtime stop releases that array. Initial deque allocation and growth follow the selected queue's contracts; the worker object is not a user-level task handle.

micron::coro::engine

Defined in header <micron/tasks/coroutine/cl_sched.hpp>.

The native-worker continuation-stealing scheduler and externally submitted root inbox.

Submission and ownership

submit(frame) requires a live resumable scheduler frame and can yield indefinitely while its 256-entry inbox is full. It does not clone, reference-count, or destroy an arbitrary submitted frame. Bridge/task protocols determine frame ownership. The global start/stop functions initialize workers, join them, drain supported runtime resources, and destroy the engine in the required order; directly destroying an active engine is unsupported.

The engine's public fields are implementation state, not a thread-safe reconfiguration interface. A noexcept worker activation traps if an exception escapes its coroutine chain. Waiting on a blocking native syscall or native mutex inside a task blocks that worker; having a separate fiber stack does not automatically turn ordinary blocking code into an asynchronous operation. Runtime lifecycle and tuning are described above.

micron::coro::fork_group

Defined in header <micron/tasks/fork_group.hpp>.

An immovable dynamic group of independently scheduled roots, with an outstanding count and coroutine joiners.

Spawn and join

spawn(fn, args...) increments its count, builds a heap bridge, invokes the task-producing callable from that bridge, and submits an independent root. It discards the child's result and decrements the count after successful co_await completion. Bridge allocation failure undoes the count, with no returned failure indication. The bridge unhandled-exception path traps rather than propagating a stored group result.

join() returns an awaiter that registers until the outstanding count is nonpositive; multiple joiners may register. No destructor joins or cancels members. The group must outlive all children, its cancellation tokens, and joiners. A join that observes zero does not prevent a concurrent later spawn; externally define the end of group submission.

request_cancel() sets the group's flag. Children bind that flag and inherit it through structured forks, but request-cancel does not call the general source's I/O cancellation hook. It never decrements outstanding merely because cancellation was requested. Count arithmetic overflow and arbitrary destruction during active work are unsupported. Per-child setup uses constant bookkeeping plus frame/argument costs; waking all joiners is linear in their number.

Lifetime and resumption

Suspended operations retain pointers to waiter nodes inside coroutine frames. The primitive, frame, and any referenced data must remain live at stable addresses until the operation completes. These primitives have no general cancellation registration or destructor that removes a queued waiter. Destroying a waiting task can therefore leave a dangling registration.

Wakeup submits a frame to the global engine when one exists, otherwise resumes it inline on the notifying thread. Callers must allow continuation execution and reentry around notification. Internal list locks spin briefly; suspending the coroutine does not eliminate all spinning from the implementation. No FIFO or starvation bound follows from an awaitable interface.

micron::coro::cancellation_token

Defined in header <micron/tasks/cancellation.hpp>.

A copyable non-owning view of a cooperative cancellation flag.

Observation

Default construction is unbound and never cancelled. Boolean conversion tests whether a source is bound, not whether cancellation was requested. cancelled() relaxed-loads the flag. It does not wait, register a callback, retain the source, or supply an acquire publication edge for unrelated source data. The source flag must outlive every token/frame using it.

micron::coro::cancellation_source

Defined in header <micron/tasks/cancellation.hpp>.

An address-stable cancellation flag that can be borrowed by tasks and tokens.

Operations

cancel() release-sets the flag and calls the current I/O cancellation hook if installed. token() returns a borrowed observer. bind(task&) assigns the flag address to an existing valid task frame; bind before concurrent execution. The source is noncopyable and no move operation is provided.

Cancellation is permanent for the source; there is no reset. Polling itself is constant work, while cancel with the reactor scans registered I/O operations and performs cancellation syscalls for matching entries. The source must remain live until bound frames and registered operations finish. cancelpoint() returns a bool in the current frame and does not stop execution automatically.

micron::generator

Defined in header <micron/tasks/generator.hpp>.

A lazy move-only synchronous single-pass coroutine range.

Iteration and values

The nested promise_type stores a pointer to the currently yielded value and a diagnostic string. begin() resumes to the next yield; every additional begin advances again rather than creating an independent iterator. Prefix/postfix increment resume the same frame, and comparison with sentinel tests null or done. Postfix increment returns void. There is no random access, size cache, or multipass guarantee.

iterator::operator* and arrow borrow the object passed to co_yield. Advancing or destroying the generator can end that object's lifetime. Reference-like yielded expressions still require an appropriately surviving referent; no copied yield buffer is provided. The arrow declaration is T*, so a reference T cannot form that return type and is not a supported general reference-generator specialization.

Move transfers the coroutine handle; destruction destroys it and all live coroutine locals without completing iteration. Escaped exceptions become a fixed library-error diagnostic when advancement reaches done. No scheduler or worker thread is started by iteration. Iterator copies refer to the same frame and concurrent iteration is unsupported.

micron::coro::routine

Defined in header <micron/tasks/coroutine/routine.hpp>.

A movable manually resumed stackful coroutine with yield type Y and final result type R.

Creation and transfer

spin<Y, Stack>(fn, args...) decay-stores the callable/arguments in its fiber frame arena and returns a fresh lazy routine. Its callable consumes stored arguments as rvalues. launch additionally jumps to the first yield or completion. yield_type is Y and result_type is the callable result R. No global scheduler is required for manual jump.

jump() resumes until yield/completion and returns Y* for a value-yielding routine, or a boolean for Y = void; completion returns null/false. A value routine that calls argument-free yield can also return null while still alive, so use done/alive for completion state. yield(v) retains the address of its argument on the suspended stack rather than copying it. The yielded expression's type is not checked against Y; mismatch leads to type-confused access.

A yielded pointer remains valid only until the routine advances, is dismissed, or destroys that object. finish() repeatedly jumps and discards yields until done. result() finishes, moves the final nonvoid result, destroys its stored object, and permits only one successful extraction. It marks the result consumed before moving; a throwing move can leave no retryable result cleanup.

Copying is deleted. Move transfers the fiber/control pointers. Destruction or dismiss() releases a fresh or completed routine with appropriate launch/result cleanup, but a suspended routine is abandoned without unwinding its ordinary function stack or destroying suspended callable locals. Destruction of a running activation traps. Cross-thread jump or destruction must be externally serialized; the plain pointer state is not a concurrent owner protocol.

native_handle() borrows its fiber and stack_size() reports the C-stack portion. done, started, and alive are observations. Setup costs include a segment and callable construction; each jump adds constant context-switch work plus user work until the next yield. A routine can run or yield forever.

micron::fiber::fiber

Defined in header <micron/tasks/coroutine/fiber.hpp>.

A stack-resident execution-context control block retaining its stack segment and coroutine-frame arena.

Execution protocol

create_fiber(entry, arg, requested_size, parent) returns a fresh/recycled fiber or null on segment failure. The control block is embedded at the highest stack address and is not independently allocated. resume(f, host) switches into its saved context; suspend_to_scheduler() switches back through its current link. The entry trampoline marks running, calls entry, records an escaped exception when enabled, marks done, and returns to the scheduler context.

fiber_state contains fresh, running, suspended, and done. Direct resume of a completed fiber or concurrent resumes are unsupported. current() is a native-thread TLS pointer. The refcount covers execution plus arena-backed coroutine frames; destroy_fiber drops the execution reference and recycles the segment only after all retained frames are freed. It does not unwind a suspended entry stack.

Same-thread freelist reuse and cross-thread segment-pool routing reduce repeated mapping operations while retaining memory. drain_freelist applies to the calling thread; drain_seg_pool requires coordinated shutdown. The storage split, size-class clamp, alignment, and per-architecture context restrictions are described above.

micron::coro::waiter_node

Defined in header <micron/tasks/waiter_list.hpp>.

A borrowed intrusive node containing a scheduler-frame pointer and next link.

Use

Nodes are ordinarily embedded in suspended awaiters. A node may be linked in only one waiter list at a time and must remain live until removed. Linking does not retain a coroutine handle or arrange automatic destruction cancellation. Resumption can invalidate the node immediately, so wake walkers read its next link before submitting it.

micron::coro::waiter_list

Defined in header <micron/tasks/waiter_list.hpp>.

A spinlock-protected intrusive LIFO list of borrowed coroutine waiter nodes.

Operations

push prepends; pop removes the head; pop_blocking spins until one exists; swap_all detaches the complete list. push_unless(node, open) tests its predicate under the same lock as registration, closing the check/register race. swap_all_under(fn) runs a callback under the lock and detaches all only if it returns true. Those callbacks must not block or resume a coroutine.

List methods do not themselves resume or destroy detached nodes. Wake helpers submit/resume their frames. Empty checking and individual link changes take constant work plus spin contention; waking a complete list is linear in its length. Copying is deleted; list lifetime must cover all linked nodes.

micron::coro::async_mutex

Defined in header <micron/tasks/async_sync.hpp>.

A nonrecursive coroutine mutex storing unlocked/held sentinels or a stack of waiting awaiters in one atomic word.

Acquisition and release

co_await lock() acquire-claims the unlocked sentinel or links the awaiter and suspends. try_lock() makes one strong attempt. Unlock either publishes unlocked or removes the newest waiter and hands it ownership before resuming it. Waiting is LIFO, so older waiters can starve. Unlocking an unlocked mutex is unsupported and interprets the sentinel as an invalid waiter pointer.

There is no native-thread owner check, recursive count, timed acquisition, or automatic cancellation. Uncontended operations have constant atomic work; CAS retries and scheduler submission can wait. Use co_await coro::scoped_lock(m) for an owning guard after acquisition.
