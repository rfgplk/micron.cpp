Input devices

From micron reference
micron reference › Input and output

Input support separates raw evdev device ownership and callback polling from keymap translation and Wayland seat events. Raw devices expose kernel events; translation requires a selected keymap and modifier-state protocol.

Discovery and binding

get_devices() enumerates /sys/class/input entries containing event, reads each device/uevent file, and classifies supported devices from EV, PROP, and KEY capabilities. Keyboard detection requires key/repeat capability and at least 30 recognized alphanumeric keys; relative key devices become mouse/pointing-stick before the absolute-axis classifications. Pen/stylus, direct positioning, finger tools, and gamepad/joystick bits select the remaining categories. Unknown devices are omitted.

KEY capability text is parsed as at most sixteen 64-bit words, with the low word at the end. The text format must match that assumption. Classification is a capability heuristic, not a complete input-driver identity check. Discovery allocates strings/vector records and depends on sysfs access.

bind_device opens read-only; nonblock_bind_device additionally selects nonblocking. On success they close a previous binding and retain the new fd; failure returns the negative open result while retaining any previous binding. unbind_device closes and resets. The high-level open/open_first variants select by type but ignore the binding return, so a discovered result can still be unbound. Inspect the fd before use. The required access comes from permissions on the device node and environment; the wrapper does not arrange privileges.

Raw event and polling protocol

read_raw(device, event) performs one read of sizeof(input_event) and returns true only for a complete record. It does not accumulate a partial read, retry interruptions, or distinguish EOF, EAGAIN, and other errors. get_event returns a zero-initialized event on any such failure. Raw event time and codes retain their Linux ABI meaning.

A packet first matches event type, then linearly scans selected codes. For every match it calls the general callback, then the actuate callback when value is nonzero or release callback when zero. Thus repeat value 2, negative relative motion, and arbitrary nonzero axis values use the actuate branch; axis value zero uses release. Duplicate selected codes/packets can dispatch and append history more than once for the same event.

poll loops forever until descriptor/poll failure and returns -1 for such failure, using a default 250-ms poll timeout. Timeout simply retries. poll_pack polls each descriptor separately in index order with default 1 ms, rather than one combined readiness syscall; idle-device delays can add. poll_pack_rt repeatedly reads each device with no poll wait, and poll_pack_once makes one such pass. Use nonblocking devices for those pack readers to prevent one quiet device from blocking the rest.

The high-level read, read_rt, and read_once validate loaded/bound state then forward these loops, discarding the integer poll result. No stop token, callback exception boundary, automatic history bound, or synchronized concurrent access is supplied. Event dispatch costs are linear in the total selected codes plus callback/history costs; continuous polling has no finite iteration bound.

Listener selection and legacy translation

prepare_listener(type) chooses one sensor packet for mouse/pointing-stick, touchpad/touchscreen, joystick, or tablet, and a keyboard-code packet for keyboard. It does not automatically combine motion with that device's button packet. The legacy __ev_code_to_integral<T> is a fixed switch with approximate US character/special-key values, no modifier state, and collisions between some function/navigation values and characters. It is not a Unicode or layout-aware decoder.

First-party keymap subset

The keymap parser accepts a complete xkb_keymap document containing keycodes, types, compatibility, symbols, and skipped geometry sections. It handles aliases, eight real modifiers, virtual modifiers, type maps/preserves, interpretation rules, up to four symbol groups, level selection, group wrap/clamp/redirect, and repeat metadata. Includes are rejected as unsupported; unresolved include names are not loaded from system files. Actions/geometry are skipped rather than executed; modifier state is supplied by the compositor.

Limits are 4 MiB of source bytes, 8192 key definitions, 8192 aliases, 24 virtual modifiers, 256 types, 256 entries per type, 4096 interpretations, 8192 modifier-map entries, four groups per key, 32 symbols/levels per group, and 32 levels of skipped nested syntax. Key/alias names fit 31 characters; type/virtual names fit 63. The accepted keysym table is finite, with explicit U-hex Unicode and F1-F35/keypad forms; it is not a complete XKB implementation or compose/input-method engine.

Loading builds a candidate and replaces the active map only on success. It reports negative invalid-argument, unsupported-operation, overflow, message-too-long, or caught-allocation error. load_map contains a try/catch allocation boundary; its instantiation requires exception syntax support in the selected build. The accelerated policy changes newline scanning in comments using the selected SIMD string helper; it does not establish a measured translation speed advantage over the scalar policy.

Virtual input setup

make_uinput() opens /dev/uinput nonblocking/write-only and returns a raw fd_t, setting a generic errno on open failure. That descriptor has no automatic-close ownership. set_events and set_keys accept packs whose deduced types are exactly byte; higher evdev codes cannot be represented through that byte-only interface. Their comma fold examines only the final ioctl result, so earlier failures can be hidden by a later success.

start_device issues setup then create, records errno on failure, and continues to the create call even after setup failure. The name overload truncates to the fixed setup name buffer. No helper here implements event emission, SYN framing, device-destroy ioctl, or a scoped close/destroy owner; uxin::write() is empty. The caller must supply those parts of a complete virtual-device protocol.

micron::uxin::type_t

Defined in header <micron/io/uxin/devices.hpp>.

Classifies discovered input devices as unknown, keyboard, mouse, touchpad, touchscreen, joystick, tablet, or pointing_stick.

Use

This char-backed enum selects discovery/filter/listener behavior. It is not a kernel event type, bitmask, or guarantee of a specific driver interface. Unknown devices are omitted by the discovery helper and rejected by the high-level open/listener functions.

micron::uxin::device_t

Defined in header <micron/io/uxin/devices.hpp>.

A move-only owner of an optionally bound evdev descriptor and its discovery strings.

Fields and ownership

i_path is the /dev/input path, path its sysfs path, and name/phys are parsed metadata strings. type defaults to unknown and bound_fd to -1. Destruction closes a nonnegative descriptor. Move transfers strings/type/fd and sets only the source fd to -1; move assignment first closes the old destination binding. Copying is deleted.

is_loaded checks only that both paths are nonempty. is_bound checks !fd.closed(), where closed means exactly -1; a manually assigned different negative error can therefore be misclassified as bound. A nonnegative numeric fd remains a borrowed OS handle for external calls and can be invalidated if closed outside this owner. Discovery strings and binding operations require no concurrent mutation.

micron::uxin::input_t

Defined in header <micron/io/uxin/bits.hpp>.

An input-device owner paired with an allocated stack of event history.

History and lifetime

Public device owns the fd; history is stack<input_event>. The polling overloads append only events matching a supplied packet code, potentially once per matching packet/code. No automatic maximum, pruning, or synchronization is applied. Stack allocation/growth and invalidation follow stack rather than the kernel event queue. Copying is unavailable through the device member; moving transfers device/history ownership when those member operations are used.

micron::uxin::input_packet_t

Defined in header <micron/io/uxin/bits.hpp>.

A selected event type, an owning code slice, and three synchronous callback pointers.

Fields and callbacks

mask_type is the Linux event type; button_mask is a slice<button_t> with button_t = i32. callback, actuate_callback, and release_callback receive (const timeval_t&, u16 code, i32 value) and may be null. Prepared builders allocate and fill the slice, then store callback pointers; they do not register a device or start reading.

Callbacks run inline in the polling caller and borrow the current event timestamp only for that call. Packet mutation/destruction cannot race a polling loop using it. Copy/move behavior follows the owning slice; callback addresses are copied without managing an external callable lifetime. Per-event scanning is linear in selected codes.

micron::uxin::keymap::translation

Defined in header <micron/io/uxin/keymap.hpp>.

The first-party decoder's symbol, Unicode, consumed-modifier, and repeat result.

Fields

symbol is the selected XKB-style keysym, codepoint its supported Unicode scalar or zero, consumed the expanded modifier mask used by level selection, and repeat the key's repeat permission. supported is false for an unresolved/unsupported noncharacter symbol; it is not a general valid-map/key-presence flag. Missing/invalid map or missing key returns the default record, whose supported field is true but symbol/codepoint are zero. Zero codepoint also covers nontext keys.

micron::uxin::keymap::basic_state

Defined in header <micron/io/uxin/keymap.hpp>.

A move-only owned first-party keymap plus externally supplied modifier and group state.

Loading and translation

state aliases basic_state<true>; scalar_state selects false. prepare() returns true without external setup. load_map(raw_slice<const char>) borrows source bytes only during parsing and retains owned parsed data after success; the source span must be valid, and null nonempty storage is not checked. Failed parsing leaves the previous map/state intact. reset() releases map data and invalidates translation.

update_mods(depressed, latched, locked, group) ORs the three modifier masks and stores the group. update_key is a no-op: key presses/releases do not independently update state. translate(evdev_code) looks up code + 8, selects a group according to policy, applies a named type map or two-level shift/lock fallback, then translates its symbol. translate_key and translate_utf32 return individual fields, each recomputing translation. There is no UTF-8 output, dead-key compose, auto-repeat timer, or action execution.

modifier_mask(name) recognizes real and parsed virtual names; modifiers() expands the current mask with virtual bindings. It returns value snapshots without locking. A moved-from state has moved map containers but defaulted scalar flags can still indicate the old valid state; reset before reuse when an explicitly invalid state is required.

Complexity

Code lookup uses a sorted index and binary search in the key count. Translation then linearly searches type names/entries and virtual modifiers, plus the finite symbol conversion table. Parsing contains linear duplicate/name scans and nested binding/interpretation scans; it is not generally linear in source bytes. Owned vectors/strings allocate during loading; translation itself does not allocate. Concurrent load/reset/update/translation on one state requires external synchronization.

micron::uxin::keymap::named_symbol

Defined in header <micron/io/uxin/keymap_symbols.hpp>.

A static name-to-keysym record used by the first-party decoder's finite symbol table.

Tables and conversions

Fields are borrowed const char* name and u32 value. legacy_symbol adds separate symbol and Unicode values for the supported Latin extension table. Both arrays have static storage; records allocate nothing. symbol_from_name recognizes a single byte, U-hex Unicode, F1-F35, keypad digits, then linearly scans the tables, returning unknown_symbol (0xFFFFFFFF) on failure.

unicode_symbol(cp) maps supported Unicode scalar values to direct/Unicode-prefixed keysyms and rejects surrogate/out-of-range values. symbol_unicode handles printable ASCII/Latin-1, the Unicode prefix, keypad symbols, selected extra symbols, and the Latin table, returning zero for unsupported/nontext cases. These functions do not perform normalization, case folding, compose, or a general locale conversion.

micron::uxin::basic_wayland_source

Defined in header <micron/io/uxin/sources/basic_wayland_source.hpp>.

An immovable Wayland seat/input proxy owner parameterized by a keymap decoder.

Binding and borrowed environment

bind(display, surface, synchronous) requires a Wayland display and borrows its display/library plus optional surface. It creates its own registry, binds the first advertised seat at at most version 7, and creates pointer/keyboard proxies when capabilities arrive. Default synchronous binding performs two roundtrips and reports an error if no seat was advertised. Asynchronous binding requires later event dispatch to discover the seat. Release an existing binding before rebinding; bind does not first tear down its previous proxies.

The decoder protocol is prepare, load_map(byte span), reset, valid, update_key, update_mods, translate_key, and translate_utf32. The source owns that decoder and exposes it by reference. A received keymap fd is read into owned bytes with EINTR retry, capped at 4 MiB and format 1, then closed. A failed/truncated load resets the decoder and stores a negative error. take_error() returns and clears that one stored error; later errors overwrite earlier ones.

poll() forwards display event dispatch; it does not create a thread or retain a display owner. release() destroys keyboard/pointer/seat/registry proxies and resets decoder/focus state without closing the display. The borrowed display, library, surface, user context, and object address must remain valid for all registered callbacks. Callback execution and release require external serialization; callbacks must not destroy/rebind this source during its active dispatch.

Event semantics

A selected surface filters pointer/keyboard focus; null accepts all surfaces. on_position receives fractional surface coordinates. The legacy on_motion emits EV_REL X/Y codes containing truncated absolute surface coordinates, not relative deltas. Scroll callbacks receive float axes while legacy on_axis emits truncated wheel values. Wayland millisecond times are converted to seconds/microseconds; these are protocol times, not a wall-clock epoch.

Key/button events use evdev codes and pressed 1/released 0; keysym/UTF32 callbacks run only with a valid decoder. Modifier and repeat-info callbacks expose compositor data, but the source implements no repeat timer. Keyboard enter ignores its already-held-key array. Touch capability/metadata exists but no touch proxy/listeners are acquired by this source. Pointer frame/source/stop/discrete/v120/relative-direction callbacks are present as no-ops; seat binding's version cap also excludes newer pointer event tiers.

Aliases and cost

wayland_source is basic_wayland_source<system_keymap_decoder>; first_party_wayland_source selects keymap::state. Callback fields and user are public borrowed function/context pointers. Event forwarding has constant wrapper work apart from decoding and user callbacks; setup/keymap allocation and display roundtrips have environment-dependent costs. No general thread safety or reentrant dispatch guarantee is supplied.

micron::uxin::system_keymap_decoder

Defined in header <micron/io/uxin/sources/wayland_source.hpp>.

A decoder-policy adapter around the host libxkbcommon keymap-state owner.

Preparation and map load

prepare() forces host-library initialization, returning false for a caught setup exception in exception-enabled builds. Without that catch path, library setup failure follows the library error behavior. load_map(span) requires a nonempty span with a trailing zero byte, then calls inherited load; caught parsing errors return negative invalid-argument. A null nonempty span is not validated before its final byte is read.

All update/translation/reset/valid behavior comes from xkb::keymap_state; a failed host reload discards the previous keymap rather than preserving it like the first-party candidate loader. It is the policy used by the wayland_source alias and depends on the host dynamic-library boundary.

micron::uxin::xkb::keymap_state

Defined in header <micron/io/uxin/xkbcommon.hpp>.

An immovable RAII owner of one host XKB context, compiled map, and key state.

Ownership and calls

load(nul_terminated_text) resets the previous objects, creates a context/map/state through the loaded function table, and cleans already-created objects on the explicit failure paths. Destructor/reset unreference state, map, then context. Copying is deleted and no move is provided. The input text is borrowed for compilation only; subsequent storage and translation costs belong to the host implementation.

update_key adds 8 to evdev code and updates press/release state; update_mods applies depressed/latched/locked masks and the compositor group as locked layout. The code + 8 arithmetic is unchecked here. translate_key returns NoSymbol when invalid and translate_utf32 returns zero; valid calls forward to the host table. valid and bool test state presence. One instance has no concurrent-call protection.

micron::uxin::xkb::lib_t

Defined in header <micron/io/uxin/xkbcommon.hpp>.

A host DSO owner and public function table for libxkbcommon.so.0.

Loading and ABI types

Construction opens the host library and resolves context/map/state lifetime, key/mask update, keysym/UTF conversion, and symbol-name functions. xkb_lib() returns a function-local singleton. Its explicit required-symbol check covers only a subset: unref functions and UTF32/UTF8/name conversion pointers are not all checked before later callers may use them. A missing unchecked entry can therefore be called through null.

context_t, keymap_t, and state_t alias opaque host records. keysym_t, keycode_t, layout_index_t, mod_index_t, mod_mask_t, and level_index_t are u32 ABI aliases. The PFN aliases match the named host function signatures; they do not own the pointed-to host objects.

micron::uxin::wl_seat_listener_t

Defined in header <micron/io/uxin/wayland_seat.hpp>.

A Wayland seat listener record containing capability and name callback pointers.

Related listener records

wl_pointer_listener_t contains enter/leave/motion/button/axis plus frame, source, stop, discrete, value120, and relative-direction callbacks. wl_keyboard_listener_t contains keymap, enter/leave, key, modifier-mask, and repeat-info callbacks. All receive a borrowed user pointer and protocol proxy. These records are ABI callback tables, not owning subscriptions.

The same header supplies seat/pointer/keyboard/touch interface descriptors, method/event signatures, opcodes, capability flags, and key/button-state values. Descriptors advertise version 9, but the high-level source negotiates seat versions only through 7. The touch interface is metadata only in that source. Listener storage and user context must outlive the registered proxy use, and direct registration must match the negotiated protocol version.
