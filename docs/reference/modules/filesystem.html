Files and filesystem

From micron reference
micron reference › Input and output

File descriptor owners, whole-file and windowed processing, lexical paths, directory traversal, and caches of open handles. Most path queries return sentinels on metadata failure; opening constructors and selected convenience reads can throw. These interfaces operate on trusted Linux pathnames and do not provide a confined path-resolution policy.

Open and error protocols

An os_file/file path constructor verifies nonempty text, opens, and throws on open failure. Most modes then fstat the opened fd and accept regular or character nodes by default; append, create, and readwritecreate skip that post-open type check. Creation/truncation can already have happened before a later type rejection. The free open_file instead adopts a negative error into its returned file and is tested with valid/raw_fd; it performs the corresponding type check without throwing for the open result. Allocation or metadata convenience methods may still throw.

Recorded names are bookkeeping, not stable inode identities. Path operations such as rename/unlink/readable/fullpath use the stored name and can address a different object after outside renames or cwd changes. Descriptor operations continue to address the opened inode. Copying an os_file/file dup's its descriptor: each copy closes its own number, but they share a kernel file offset and status flags; dup failure is retained as a negative handle. Dup does not preserve FD_CLOEXEC. Moves transfer ownership and invalidate the source.

Raw metadata predicates commonly conflate absence, denied access, malformed paths, and other failures. file_size/get_size return -1; time queries often return 0; uid/gid return cast -1. Error-carrying descriptor results preserve a negative errno, whereas several older node/window helpers return -1 or ignore an error. Inspect each operation's result instead of assuming a uniform exception or status policy.

Whole-file and callback helpers

read_file<T> is constrained to a string/contiguous container with one-byte elements. The value-returning overload also needs reserve/set_size for the positive reported-size branch. It sizes a destination to the stat size, reads from offset 0, trims to actual bytes, and returns option<T,error_t>. A zero reported size uses repeated 4096-byte reads and push_back when available, supporting proc/sysfs-style files; other targets do not automatically grow. The target overload clears/grows where its available members permit, but can retain partial data after an error. A changing file is not a snapshot.

write_file/append_file open a scoped fd and use file's marshalling dispatch. A nonnegative write is followed by flush, whose result is ignored, so the returned byte count is not a checked durability result. with_file opens a scoped file, invokes a callback by borrowed file&, and returns a decayed result or unit_t in option; callback exceptions propagate. Returning a pointer/view to that file or its transient contents does not extend lifetime. Curried write/append/modify helpers capture the path and callback by value.

read_lines builds strings using file::each_line; the value overload discards its local accumulated collection on error, while the target overload clears then can retain a partial collection. modify(path,fn) performs the in-place transformation and ignores a later flush result. interact reads stdin to EOF into an unbounded string, calls the transform once, then writes the result's native code-unit bytes; it is not a streaming per-line filter.

Copying and mutation

Free io::copy first rejects a destination with the same device/inode, then creates/truncates it with the source's ordinary permission bits. It tries copy_file_range, then sendfile on selected unsupported/cross-device errors, then read/write_all with a 64-KiB stack window. It retries interruptions and checks final destination fsync, while close results are ignored. A failed copy leaves a created or partial destination. The fallback can lose unread source suffix bytes if write_all makes a nonnegative short transfer. Metadata beyond the ordinary mode bits is not copied.

basic_filesystem::copy has a similar sequence but its explicit buffered writer treats zero progress as EIO; its final fsync is ignored. move first tries rename, then copy + unlink only on EXDEV, with no cross-filesystem atomicity. copy_list starts all destination copies in pack order before examining the collected results, so an earlier failure does not prevent later destinations from being attempted. remove is an unlink alias and does not remove directories; rmdir is separate.

mkdir_p uses a fixed path_max character buffer, creates each prefix, and tolerates EEXIST without checking that an existing component is a directory. Overlong input is clipped to that buffer by the underlying helper. touch probes existence then creates or applies current timestamps; these separate path operations do not eliminate check/open races. Path-based helpers generally follow symlinks unless an explicit l*/nofollow operation is selected.

Lexical paths and canonical resolution

Free prune collapses repeated slash text, changes runs of ... through a ... -> .. replacement, and removes trailing slashes except root. path::prune only handles slashes; the two normalization functions therefore differ. collapse also removes . and cancels preceding components for ..; leading relative .. is discarded rather than preserved. These transformations are lexical and can change the meaning of paths containing symlinks or unusual literal components. They are not a secure resolution step.

trim removes edge space/tab/CR/LF then prunes. valid only checks nonempty text; well_formed additionally checks total and component lengths, not existence or encoding. basename/dirname split the final component, extension includes the final dot suffix but treats every leading-dot basename as extensionless, and stem removes that suffix. Join discards the base for an absolute right operand. relative_to compares the supplied text without first canonicalizing or resolving dots. None of these operations establishes that two names identify the same inode.

realpath_into opens O_PATH, reads /proc/self/fd/<number>, closes the fd, and terminates the result. It requires the object to open and procfs to expose that link; failure returns null without a precise error object. A result filling cap-1 is rejected as potentially truncated. The pointer realpath overload with null destination allocates path_max bytes with mmap; the caller must munmap that exact mapping rather than use heap free. A supplied raw destination is assumed to have path_max capacity; prefer the capacity-taking/string overloads when it is smaller. resolve maps every resolution failure to error::no_entry.

Tree traversal

ftw collects directory paths, ftw_files regular-file paths, and ftw_all all child entries. The root itself is not yielded. At each level all selected children are visited before recursive descent into the subdirectory list. Symbolic-link directories can be reported, but descent skips them after an lstat-based check. A chain of device/inode pairs prevents ancestor cycles; a depth limit of 100 silently stops deeper descent. This is a path-based traversal and does not defend against a child being swapped between checks/open.

An unreadable root raises io_error; unreadable subdirectories are skipped through error-returning try-list operations. Directory read failures can also be conflated with end by the underlying iterator, so traversal completion is not a detailed per-node error report. Visitor overloads count each invocation, including the one returning false, and stop when a bool-convertible result is false; void/non-bool results continue. ftw_fold visits the all-entry set and returns the final accumulator.

Traversal allocates lists for selected children and subdirectories at each recursion level and can enumerate a directory twice. Work includes entry scans, path copying, stat calls, linear ancestor checks up to the depth cap, and user callback/fold work. Collection variants additionally retain every result. Mutation during traversal has no stable-snapshot guarantee.

micron::io::ipermissions

Defined in header <micron/io/os/os_file.hpp>.

A value record of read, write, and execute permissions for one identity class.

Operations

Factories none/all/ro/rw/rx/wo/wx/xo initialize the three booleans. with_*/without_* return modified copies; any/full test OR/AND. to_octal uses bits 4/2/1; from_octal masks those bits. The record neither queries nor changes the filesystem; all operations take constant work and allocate nothing.

micron::io::linux_permissions

Defined in header <micron/io/os/os_file.hpp>.

Owner/group/others permission triplets with separate setuid, setgid, and sticky flags.

Mode conversion

from_mode extracts only the ordinary nine permission bits and leaves special flags false; callers preserving special bits must populate them separately. to_mode, to_posix_mode, and the explicit mode_t conversion omit special flags. full_mode includes all three. The with_owner/group/others/special-bit methods preserve other fields in a returned copy. Equality compares ordinary and special bits.

Factories provide none, all, 0644 file, 0755 executable/directory, 0600 private-file, and 0700 private-executable forms, plus corresponding perm_* constants. Passing to_mode into a create/chmod helper intentionally omits special bits even if the record contains them; helpers using full_mode preserve them subject to kernel policy. No permission change occurs until an operation applies the value.

micron::io::open_opts

Defined in header <micron/io/os/os_file.hpp>.

Per-open options applied in addition to the selected modes flags.

Defaults

sync, direct, nonblock, and noatime default false; cloexec defaults true; perms defaults 0644. compose_open_flags ORs enabled options with the mode's base flags. Setting an option false does not remove a flag intrinsically selected by a mode. perms is passed at creation and remains subject to the process umask. These are open-time requests, not a mutable live descriptor policy.

openmode is a compatibility record containing static r/r+/w/w+/a/a+ strings and an int md. The mode composer accepts modes, not those strings or md; the record performs no parsing and md is uninitialized by default aggregate construction. permission_types names each owner/group/others read/write/execute position and supplies no bitmask conversion itself.

micron::io::stat_existing

Defined in header <micron/io/os/os_file.hpp>.

Selects reuse or refresh of an os_file-compatible cached stat record.

Cache policy

STAT_OVERRIDE is 0 and STAT_EXISTING is 1, used as bool template arguments. stat<STAT_EXISTING> returns cached nonzero sd without another fstat. stat<STAT_OVERRIDE> always queries. A zeroed record is the invalid-cache marker; stat failure zeroes os_file's cache and returns the negative result. External writers, shared descriptors, and several raw inherited transfer paths do not automatically invalidate it. Use explicit refresh when current metadata is required.

micron::io::os_file

Defined in header <micron/io/os/os_file.hpp>.

A copyable scoped descriptor owner with a fixed recorded name and lazy stat cache.

Ownership and open behavior

Public fname is sstr<path_max>, __handle is the owned fd_t, and mutable sd is the stat cache. Default construction is invalid. Adopting (fd_t, recorded_name) takes close ownership without opening, duplicating, type-checking, or stat. Path constructors open according to modes/open_opts and normally accept regular/character nodes. close ignores errors; try_close resets the stored fd before returning the close result. Negative adopted errors other than -1 can still be passed to close by that path. is_owned always returns true.

Copy duplicates a nonnegative descriptor and copies the name/cache; dup failure is stored rather than thrown. Its open-file-description offset/status remain shared, while close-on-exec is not copied. Move transfers and disarms. Assignment closes the old resource first. Name assignment closes then reopens read-only; reopen also closes before attempting its open, zeroes stat, and does not repeat the constructor's inode-type validation. Failed reopen therefore loses the old descriptor.

fd(), raw_fd(), conversion, and dup results expose borrowed/non-owning numbers. Closing them externally or manually changing public fields can cause stale metadata or double-close after reuse. Name/stat references live in the owner and are changed by assignment/reopen/rename/refresh. No automatic synchronization is supplied.

Data and metadata operations

Container read/read_all expose max_size()*sizeof(value_type) writable bytes without constructing elements or updating logical size. Container write uses size()*sizeof(value_type). Explicit length, pread/pwrite, and reference overloads take byte counts and do not prove source/destination extent. Single read/write/pread/pwrite can be partial; all variants use the corresponding complete-transfer helpers. Insertion/extraction operators discard status, with extraction first rewinding. These are raw representation operations, not element serialization.

size validates the fd and throws on stat failure. Many other accessors ignore stat's status and return fields from the zeroed cache after failure. refresh_stat forces a query but returns sd regardless of its result. Flag setters use F_GET*/F_SET* pairs, so concurrent changes can be lost. truncate/chmod/chown/allocation paths invalidate cache on their checked success; basic raw writes and some transfer paths do not. seek_end(off) means EOF minus off, not EOF plus off.

Shared/exclusive locks are whole-file fcntl record locks; range helpers pass their second parameter directly as l_len, despite its end_pos name. It is a length, not an absolute ending offset. The wrappers add no scoped unlock owner. dup/copy/process lock behavior remains the Linux record-lock protocol. Allocation helpers call fallocate with explicit punch-hole/zero-range flags and do not emulate unsupported filesystems. Splice/copy_range are single possibly partial calls; copy_to/copy_from use sendfile loops. Metadata, xattr, pathname mutation, and sync methods expose their own kernel results or documented ignored results.

Complexity

The owner has constant fixed user-space storage and no data buffer. Copy performs dup plus fixed-name/cache copying; move copies/transfers the same bounded state. A cached metadata access is constant; refresh and descriptor/path operations incur syscalls with kernel-dependent costs. Raw data transfer is proportional to bytes plus syscall work, with no bound on blocking time. Do not concurrently mutate lifetime, offset, flags, cache, or referenced contents without an external protocol.

Read and write results

The internal loops retry EINTR, retry EAGAIN only when status does not indicate nonblocking, and otherwise return previous progress instead of a later error. A partial read/write can therefore look like a clean shorter result. Successful normal writes invalidate stat, but an error after partial output returns before that final invalidation. No whole-operation atomicity follows from the loop.

read<T>() for trivial strings/containers allocates/reserves from the remaining stat size and floor-divides by element width, leaving trailing incomplete-element bytes unread. If reported remainder is zero and one-byte push_back is available, it reads to EOF and appends; that branch silently stops on errors. A fixed target too small raises io_error. read(out) instead fills out.size() elements without resizing. Plain-object read(out) returns a possibly short byte count and can leave a partially overwritten representation. The internal callback-value reader requires sizeof(T) for such an object and reports EIO when short.

Framed read(out) allocates the entire reported remainder, consumes it through the descriptor, and returns the decoder's consumed count. Trailing frames/bytes have already been read even if the decoder uses only a prefix. Value-returning framed read ignores its status and returns a possibly partial default/decoded value. Use an explicit result-bearing path when an error must be distinguished.

Functional and line operations

write(fn) calls a nullary producer once and marshals its result. read(fn) deduces one callback argument, reads that value, and returns the callback result or unit_t in option; callback exceptions propagate. read_with uses a reusable 16384-byte window and write_with requests bytes from a producer, rejects a produced length beyond the window, and checks complete writes. read_with inherits the loop's possibility of hiding an error after progress within one window. Borrowed callback spans expire on the next fill.

each_line returns a line count, not a byte count; fold_lines returns an accumulator/error option. Raw line callbacks take pointer/byte count, otherwise const string&. The line range uses the LF/CR and prefetch-restoration policy described for lines_range. lines() borrows the descriptor without checking validity at construction, so retain this file and avoid conflicting offset operations while the range is live. operator>> rewinds and assigns read<T>(); operator<< ignores write status.

In-place and replacement transformations

modify seeks to zero, reads a value, invokes a pure T->T or in-place void(T&) callback, seeks to zero again, checks its full marshalled write, and truncates if the new representation is shorter. It rejects O_APPEND. It can leave partial new content after a failure and neither locks outside writers nor fsyncs automatically.

modify_atomic transforms in memory then delegates to atomic_replace. atomic_replace uses the deterministic sibling path <name>.tmp.<pid>, opened O_TRUNC|O_NOFOLLOW without O_EXCL, writes it completely, attempts ordinary permission preservation, fsyncs/closes it, renames over the destination, attempts parent-directory fsync, then reopens this handle onto the new inode. fchmod and parent open/fsync/close errors are ignored. Thus rename replacement is used, but successful return does not certify directory durability or exact mode preservation. A failure during rebind can occur after replacement already happened. The temporary pathname must not be concurrently reused or preplanted; no locking, unique-name retry, ownership/xattr preservation, or rollback is implemented.

Encoding, bridges, and cost

write_encoded allocates source_bytes*4+64 scratch without overflow/expansion checks, trusts the encoder's returned length, then writes it. The encoder must obey capacity and initialize every returned byte. append_encoded seeks to EOF before this operation and has no atomic append guarantee unless the fd also has O_APPEND. to_stream returns the stream's resulting total size rather than newly read bytes; from_stream rewinds the stream after its write attempt, including failure/short output.

Raw reads/writes use constant local transfer state; whole-value reads/framing/modify allocate proportional to file/value size, and encoded output uses the named scratch bound. Line traversal additionally stores the longest line. Work is linear in bytes plus serialization/element/callback/allocation work. Copy/move and descriptor/reference lifetime follow os_file. Concurrent operations on this mutable owner or its shared open-file-description offset require external coordination.

micron::io::cached_file

Defined in header <micron/io/cached_file.hpp>.

A file owner with an explicitly loaded resident string and independent byte cursor.

Resident state and persistence

Template T defaults to string and must satisfy the specific reserve/data/_buf_set_length/push/append operations used. Opening does not load content. Resident data starts empty; the logical cursor starts zero, or stat size in append modes. A legacy buffer-size constructor/reopen argument is accepted and ignored. Destruction closes the file through its base and discards resident edits without writing them.

load refreshes stat, reserves from reported bytes, preads from offset zero, and updates resident length to complete elements; it does not move the logical cursor or fd offset. A zero reported size clears resident length; load_kernel separately grows from pread until EOF, appending one converted element per byte. load_and_pull chooses that path from the device-major heuristic, ignores load errors, and returns whatever data was obtained.

push/push_copy replace resident content; get borrows it, pull moves it out, and modify affects memory only. clear clears resident content without truncating the file or resetting the cursor. write() pwrite's all resident bytes at the logical cursor, advances by written bytes, and retains content. It does not replace/truncate the whole file. A second write repeats that data at the next cursor. flush calls write and clears content after any nonnegative result, including short output; it is not fsync. sync separately ignores fsync's result and returns syncfs's result. Reopen syncs but does not persist resident edits before discarding them.

Position, append, and copying

set/set_start/set_end change only the logical byte cursor; read_bytes appends bytes from that cursor and advances it. O_APPEND can override the intended pwrite position on Linux, so append-mode behavior depends on the fd flag as well. append_raw/append_file find a destination size then issue explicit-offset writes without updating the logical cursor; outside appenders can race that size probe. truncate clamps cursor and changes file length but does not trim resident data.

copy_to copies on-disk bytes with a window, not resident edits, and opens/truncates its destination without a same-inode guard. Do not use the source itself or a hardlink as destination. compare_to returns -1/0/1, with errors normalized below -1; it compares reported sizes after window scans and assumes files stay stable. Zero chunk size prevents comparison progress, so use a positive chunk size. load_intercepted appends to existing resident data, allows callback mutation of each window, and silently stops on a non-EINTR read error. flush_to_stream returns resident element count and retains data even if the stream clips its append.

Copy duplicates the base descriptor and copies resident data/cursor; move transfers them and zeroes the source cursor. Equality compares numeric fds rather than content/inode, so a duplicated copy normally compares unequal. Memory/reference invalidation follows T; file/cursor and resident changes are unsynchronized. Whole loads/edits require memory proportional to resident content; window copies/comparisons add one/two chunk buffers. Costs are linear in bytes plus callback/string growth work and kernel I/O.

Offsets

Explicit bool tests found; no_match is false with zero offset/length. micron::io::bin_range_t

Defined in header <micron/io/bin.hpp>.

A borrowed constant byte span used by binary windows and callbacks.

Lifetime

ptr/len, begin/end, size, empty, and unchecked indexing expose the span. bool requires both nonnull ptr and nonzero len; a valid empty span converts false. micron::io::bin_stats_t

Fields

micron::io::binary

Defined in header <micron/io/bin.hpp>.

A binary file owner with a nullable shared window, explicit endian readers, searches, and statistics.

Storage, copies, and positions

Path construction allocates a 65536-byte window by default; default construction has no buffer. resize__buf replaces it and resets valid/offset metadata. Copy dup's the file descriptor but shares the same mutable buffer through shared<buffer>, while copying valid-byte/offset/cursor metadata independently. A fill through one copy overwrites the other's bytes without updating its metadata. Move transfers ownership and zeroes source window metadata; self-move is not specially guarded in binary's assignment body.

set/skip/rewind/set_end affect a logical __seek used as a position value; the explicit fill/read/write/search operations generally use their own supplied offsets rather than consuming that cursor. fill seeks the shared descriptor then performs one checked read into the window, ignoring seek failure. advance uses old offset plus valid bytes (or capacity when empty), but reaching the reported file end returns zero without clearing the prior window. Most offsets and buffer offsets are off_t, with the selected ABI's width, rather than uniformly off64_t.

buf_data/window/window_at/as_range borrow initialized window bytes; window offset and endian-read offsets are relative to the current window, while _at scalar readers use absolute file offsets. Reads require an allocated populated window or throw. Endian readers explicitly assemble bytes for 8/16/32/64-bit signed/unsigned forms, avoiding alignment dependence. Absolute scalar helpers return zero on any incomplete/error read, conflating that with a stored zero. hex_string writes exactly three characters per byte with trailing spaces and no terminator; destination extent is caller supplied.

Transfer and search behavior

read_into/write_at are single pread/pwrite calls. read_exact loops until full, EOF, or error but does not retry EINTR and can return an error after partial writes to the destination. slice/slice_into allocate/grow and throw on a short range; try_slice returns an error. read__buffered serves an existing covering window or fills one window and copies a prefix; it is not an arbitrary-length complete read. write_at and inherited writes do not refresh the window or its metadata.

Forward window search builds an allocated KMP table and has linear worst-case work in window plus pattern length. Backward search compares at every candidate and is worst-case O(window_bytes*pattern_bytes). Whole-file searches allocate KMP plus window/pattern carry storage, stop on any nonpositive pread, and return no detailed read error. The carry scheme reserves pattern_length-1 bytes and assumes sufficient real carry bytes; patterns larger than the actual preceding chunk can include unwritten carry bytes. Use pattern/window sizes compatible with the observed chunk lengths. find_all skips a matched pattern within each work window, but restarting across carry boundaries can still report overlaps with a prior window's match.

count_byte_file/file_entropy/analyse_file overwrite the shared window directly without updating its offset/valid metadata. Refill before interpreting a prior window after these operations. Public analyse() on no explicit argument analyzes the current window; the explicit bin_range argument collides with a better-matching private nonconst overload on a nonconst binary object, so use the public const interface for explicit ranges. The private nonconst analyse helpers recursively delegate to each other and do not provide an independent public free-range analyzer.

Complexity and invalidation

A window bounds retained bytes, not total file size or logical cursor. Streaming search has per-window carry work, KMP scans, and allocation proportional to pattern plus window; find_all additionally retains matches. Statistics scan visited bytes plus 256 frequency slots; longest_run returns run_t with val, off, and len for the first longest equal-byte run in the current window. each_window returns prior progress instead of a later error, whereas fold returns an error option. Both reuse borrowed ranges. Buffer refill/analysis/copies, resize, move/reopen, and destruction invalidate range content or ownership assumptions. No thread safety, snapshotting, or copy-on-write isolation is implemented.

micron::io::block

Defined in header <micron/io/os/block.hpp>.

A scoped block-device descriptor with an owned mutable window and explicit dirty tracking.

Open, buffer, and writeback

Construction allocates the named buffer, default 64 KiB, then verifies the path exists and names a block device before opening. Those path probes can race replacement. Read/write mode adds O_SYNC; direct modes use O_DIRECT/O_LARGEFILE, with alignment constraints left to the caller. Default construction is deleted. Copy duplicates fd and deep-copies the window/info but sets the new dirty flag false; move transfers dirty state. Assignment attempts to flush an old dirty window but ignores its result before replacing it.

fill attempts old writeback then performs one pread. write_buf changes only an already covered byte range and sets dirty; a mutable view() change does not itself mark dirty. flush_buf makes one pwrite and clears dirty on any nonnegative result, including short output; commit narrows that result to i32. Destruction attempts writeback but ignores errors. A caller requiring verified persistence must check full transfer and a separate fsync/fdatasync. invalidate_buf/rewind_view discard dirty state without writing it.

read_block fills the whole existing buffer at the block address; read_blocks only grows capacity to at least count*block_size then fills the whole capacity, so a prior larger buffer can read beyond the requested block count. read_*_into/write_*_from take caller spans; block numbers multiply logical block size. read_all_into checks capacity then reads from the current sequential fd position, not an explicit zero offset. Arithmetic overflow, device-range validity, and direct-I/O alignment are not automatically checked. in_range(offset,len) itself uses an unchecked addition.

Device controls and lifetime

Metadata methods lazily query block_info_t. Readahead/fadvise, discard/secure-discard/zero-out, partition reread, read-only settings, cache flush, vector transfer, and seek helpers forward Linux ioctls/syscalls without emulating unavailable operations. Their success and blocking cost depend on the device/kernel. Some return zero/default metadata after an ignored ioctl error. writeback does not invalidate/requery device information automatically.

view() and info() borrow member storage; resize/move/assignment/destruction invalidate storage references or their interpretation, and fill changes bytes in place. Copy/window operations are linear in capacity; buffer transfer is linear in requested bytes plus kernel work. All state and dirty flags are ordinary mutable fields. Concurrent use, external closes, and direct mutable-window edits require an explicit synchronization/writeback protocol.

micron::io::volatile_t

Defined in header <micron/io/os/volatile.hpp>.

An owner of an anonymous memfd file and one optional tracked shared mapping.

Creation, cloning, and ownership

Default construction creates a close-on-exec memfd named micron_volatile. Name/flags and initial-size constructors create another memfd; initial ftruncate status is ignored. Copy/clone/from_file/from_fd create a new memfd and attempt to copy source bytes, unlike os_file's dup copy. Known-size cloning tries copy_file_range and a buffered fallback on EXDEV/ENOSYS/EINVAL; unknown-size cloning uses a temporary pipe and splice. Copy/clone do not return transfer errors, can leave zero-filled/truncated copies, and do not robustly drain/retry every short/error operation. Unknown-size splice consumes the source's sequential offset.

Move transfers fd and tracked mapping. Move assignment first closes its own resources and has no self-assignment guard; self-move therefore discards its resource. Close unmaps the tracked exact length then closes/reset fd, ignoring errors. valid only tests fd != -1, so a manually stored other negative error can be classified valid. Public name/fd/stat/map fields expose bookkeeping and can violate invariants if altered. Dup results are raw non-owning descriptors and share the underlying file; copied clones are separate files.

Data, mapping, and seals

Read/write/count/pread/pwrite are raw byte operations with simplified -1 invalid/null checks in several overloads. Container operations use size/max_size directly as bytes without multiplying element width or setting logical size. Normal writes and several transfer paths do not invalidate the stat cache; refresh before relying on current size. reserve grows the file length, rather than only reserving physical allocation, and truncate/clear affect file content without rebuilding existing mappings.

map_ro/map_rw refresh size and map the entire nonempty file MAP_SHARED. Successful remap releases the previous tracked mapping; empty-size or failed map leaves the old mapping in place while returning null. unmap() uses the stored exact length; unmap(addr,len) uses that exact tracked length when addr matches, otherwise unmaps the caller's span. Returned pointers are invalidated by successful replacement, unmap, move-assignment/close, or destruction. Shrinking the file can make an otherwise mapped address fault; mapping length is not automatically adjusted.

Sealing is enabled only when created with MFD_ALLOW_SEALING, such as sealable/make_volatile_sealable. seal_write adds WRITE|GROW|SHRINK; seal_all additionally seals the seal set. Kernel conditions, including existing writable mappings, can reject seals. sendfile_all_to is one sendfile call despite its name and can be partial. Copy-range/splice/sendfile methods are single calls with kernel constraints, no general fallback, and no automatic mapping refresh. Memfd storage is kernel-backed file storage, not C++ volatile or a promise of secure erasure.

Complexity

The owner retains fixed name/cache state and optional kernel mapping; cloning is linear in copied bytes with kernel or fixed-window transfer costs. Mapping does not copy every file byte at the wrapper level; subsequent page faults and residency depend on the kernel. No wrapper lock coordinates offsets, cache, seals, mapped accesses, or lifetime.

micron::io::path

Defined in header <micron/io/paths.hpp>.

Construction and representation

The sole retained value is path_t = sstr<posix::path_max>; no descriptor is owned. Text construction prunes slashes and uses . for a null pointer, without opening that path. Default construction does resolve . through realpath and falls back to . on failure, so it can perform filesystem/procfs operations. micron::io::dir

Defined in header <micron/io/os/dir.hpp>.

A directory descriptor owner with a per-object read cursor and an allocated cache of entry values.

Opening and traversal

Path construction performs existence/type probes then opens O_DIRECTORY|O_CLOEXEC and throws on failure. try_open avoids pre-probes and returns an invalid negative-error handle, with no runtime read until requested. It is noexcept although assigning an overlong fixed name can invoke the string's failure policy. Copy dup's fd and deep-copies cached entries while resetting cursor state; copies still share kernel offset. Move transfers fd/cache/cursor. Destruction closes through os_file.

next reads through the object's 8192-byte readdir_ctx and includes dot entries; it conflates end/error. rewind seeks to zero and resets that cursor. get_children lazily populates _entries only while empty; an actually empty directory is therefore reread on each call. list/refresh clear and rebuild from offset zero, skipping . and ... begin/end/count/empty/operator[] access only the current cache and do not trigger a fill. for_each opens another scoped traversal by stored pathname; for_each_entry/while/fold use the cached values.

Name/extension matches are case-sensitive byte tests. Cached entry values can become stale after outside mutations. A successful child create/remove/rename/link/symlink calls refresh, invalidating every previous cache reference/iterator. Child operations and invalidation

Up/down/root navigation returns newly opened directories from recorded path text. create/create_all ignore mkdir status then open, so they can succeed on an existing directory. Child chmod/chown forward their status without a cache rebuild. chdir changes global cwd.

Cache growth/rebuild/clear/assignment/move/destruction invalidate references as dictated by vector; a copied entry value owns its fixed name. Per-object next state avoids ordinary readdir's global cursor but remains unsynchronized. Reading/building a cache takes linear entry/byte work and allocation; matching is linear in cached entries plus predicate/stat costs, while contains/name operations additionally compare name bytes. micron::io::basic_filesystem

Defined in header <micron/io/filesystem.hpp>.

A policy-locked cache of stable-address file owners keyed by pruned path text.

Policies and storage

Template axes are DefaultMode=read, Lock=null_lock, and Cap=0. filesystem aliases the null-lock specialization; concurrent_filesystem selects mutex. The cache is a heap_swiss_map<string,entry>; each file is separately allocated through unique_pointer, preserving its address across table rehash. Cap=0 is unbounded. Positive Cap tracks recency in a vector and flushes/erases the oldest key after a touch exceeds the cap. Copy is deleted; move transfers cache/recency with a fresh lock, and must not race another operation.

Unprotected reference-returning operator[]/open/create/at exist only for the exact null_lock policy. apply acquires the policy lock, opens/reuses a file, and runs the callback while locked; it returns auto, so an ordinary returned reference is decayed unless a pointer/reference wrapper is explicitly returned. A returned borrowed pointer can outlive the lock and later be invalidated by eviction. Reentrant apply or another locking method on the same mutex specialization deadlocks. Locking does not coordinate external fd users or process cwd.

Keys use free prune, including its ... replacement, without canonicalization or inode identity resolution. Aliases/hardlinks/relative cwd variants can occupy separate entries. A cache hit is reopened when the stored mode cannot service the request: truncate/exclusive modes always reopen, and direct/noatime/access/append properties are compared. An append request can reuse a writable non-O_APPEND handle; append then seeks EOF, so concurrent outside appenders are not protected by kernel append positioning.

Operations and invalidation

Queries use path syscalls without inserting a handle. Data operations may implicitly open and throw even though their successful/error return type is max_t. read rewinds; trivial values use file::read<T>() and may throw. write opens a truncating mode, writes, then ignores truncate status. Close/evict/clear/destruction attempt data sync but ignore it before releasing owners. sync(path) reports one status; global sync ignores all statuses. Rename/unlink invalidate cached source/destination before the path syscall, even when it subsequently fails.

Rehash preserves a file's address, but erase/clear/eviction/destruction invalidates all references to that owner. Mode reopen keeps its allocated address but replaces its fd/cache, so previously borrowed fd values no longer identify its resource. The cache supplies no pin/lease against LRU eviction. Root/path mutation and independent file changes are not automatically reflected in cached stat. Cap is a count of retained handles, not a byte/file-size budget.

Hash lookup has the underlying map's expected/worst-case behavior and name hashing/comparison cost. Positive-cap touch/drop scans and shifts recency linearly in retained keys; insertion may rehash/allocate and open. list/clear/sync scan all entries. Blocking I/O and user callbacks execute while the selected lock is held. A default instance performs no filesystem syscall until an explicit query/open action, but allocates according to the map's storage policy.

micron::io::rooted_filesystem

Defined in header <micron/io/filesystem.hpp>.

An unsynchronized path-keyed file cache anchored by an owned O_PATH directory descriptor.

Resolution and ownership

Construction prunes and opens the root with O_PATH|O_DIRECTORY|O_CLOEXEC; failure throws. Copy is deleted; moves transfer root/cache and disarm the source. Queries and child mutations use *at operations relative to that fd, so renaming the root directory does not replace the pinned identity.
