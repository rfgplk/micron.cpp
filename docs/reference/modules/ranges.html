Ranges, iterators, and views

From micron reference
micron reference › Language support

Arithmetic ranges, iterator adapters, owning contiguous sequences, and non-owning pointer descriptors. Storage ownership is specific to each type: slice owns heap storage and span owns embedded elements.

Contiguous sequence operations

slice and span share many operations, but their constructors, lengths, and lifetime responsibilities differ. Their iterator types are raw T pointers. Neither an overloaded address-of operator nor a pointer result retains the owner.

Borrowing and constness

A raw descriptor becomes invalid when the owning allocation/object is destroyed, replaced, or moved to a different address. Insertion, erasure, rotation, and length changes can change which logical element occupies an otherwise unchanged address.

Several const split, strip, trim, and align_to members on both owning sequences return raw_slice<T> rather than raw_slice<const T>. raw_slice's constructor accepts const T* and removes constness. Consequently the const qualifier of the parent does not enforce read-only access through these results. Mutation of an actually const object remains invalid. Prefer an explicitly const element descriptor for read-only borrowing.

Reinterpreting bytes as U does not establish U object lifetimes or validate representation, aliasing, alignment, or complete element coverage. align_to calculates an aligned middle address, but converts leftover byte counts to T counts by integer division. These functions expose memory; they are not type-safe conversions.

Split return values and lifetime

The regular split functions report callback count, including an empty trailing run; splitting an empty sequence invokes one callback. splitn/rsplitn with n=0 perform no callbacks. The inclusive implementation always returns delimiter_count+1, but invokes a final callback only for a nonempty tail. Its return value therefore exceeds actual callback count when the input ends in a delimiter or is empty.

The _mut suffix does not imply a separate allocation or a borrow-checking mechanism. split_off_mut and related methods can lower the tracked length while returning storage outside the new live prefix. That storage is no longer covered by normal destruction of the prefix. For nontrivial T, manual lifetime management is required before reuse or owner destruction.

Thread safety

These types contain no locks or atomic lifetime management. Descriptor copies do not extend storage lifetime. Concurrent read access requires stable backing objects, and mutation must be synchronized according to the element and container operations involved.

micron::slice

Defined in header <micron/slice.hpp>.

A move-only owning heap sequence with an independently tracked live length and allocation capacity.

Template parameters and construction

T satisfies is_movable_object. Storage uses allocator_serial<>; the class no longer accepts a custom allocator parameter. Its public memory-resource base owns the allocation. Despite historical comments describing a view, both mutable and const pointer-pair constructors allocate and copy the half-open source range.

Default and count-only construction set length to the allocator-reported capacity, which can exceed the requested count. Trivially copyable elements are left uninitialized in these constructors; nontrivial elements are constructed from T{}. Count-and-value construction records the requested count. Null constructors create an unallocated zero-length slice. The (function,range) constructor copies transformed results into new storage.

Copy construction/assignment are deleted. Movement transfers the allocation and leaves the source empty; move assignment first destroys and releases its destination. Slice subscripting with two bounds, no-argument subscript, and to_vec all return another owning slice by copying. They do not return borrowed views or a vector type.

Length and access

size()/len() return tracked length and max_size() returns allocation capacity. mark(n) changes only length when n fits, silently ignores excessive n, and neither constructs nor destroys elements. It is an unchecked lifetime-management operation for nontrivial T. reset rebuilds/resets the whole capacity and sets length to capacity.

Single-element subscript is unchecked. get and last test live length; first tests capacity instead, so it can return allocated storage even when length is zero. get_disjoint_mut returns two null pointers if either index is invalid or they coincide. element_offset returns size_t(-1) outside the live interval and expects a pointer whose comparison to that storage is valid.

data, addr, as_ptr, begin/end, iter/iter_mut, and pointer-range records expose borrowed storage. Dereferencing the slice with unary * returns the memory-resource byte chunk; address-of is overloaded to expose a byte pointer. Use micron::addressof when the slice object's address is required. The declared immutable_tag describes the allocation model, not const element access: mutation methods are provided.

Splitting and transformations

split_at clamps an oversized midpoint; split_at_checked instead returns an invalid pair; unchecked variants trust the caller. split_first/last and chunk variants return pointer-plus-remainder records or invalid records when insufficient elements exist. Callback splitting and prefix/suffix/ASCII operations follow the shared table above.

split_off(mid) allocates a copied tail and destroys removed nontrivial tail objects, then shortens the source. When mid>=length it returns a count-zero slice. split_off_first/last move a value out, return T{} on empty input, and destroy the removed tail slot; removing the first shifts the remainder.

split_off_first_mut returns a descriptor to slot zero after shifting later values into it, so it does not preserve the original first value. It also lowers length without destroying the trailing object. split_off_last_mut and split_off_mut similarly remove storage from the tracked prefix without destroying its objects.

repeat allocates repeated copies; concat allocates the concatenated sequences; join/connect inserts one separator between them, even when a side is empty. These length calculations use unchecked multiplication/addition in the slice body. set/fill assign values, byte assignment fills the live byte representation for trivially copyable T, and swap_with_slice swaps only the shorter prefix rather than exchanging ownership.

Complexity and invalidation

Pointer access and borrowed splits are O(1). Owning subranges, cloning, split_off, and concatenation are linear in copied elements, plus allocation and element construction. repeat is O(repetitions*length). Prefix removal is O(length); suffix removal is O(1) plus destruction. Predicate operations add their predicate/callback costs.

There is no ordinary growable append API in this class. Moving transfers pointer ownership, while destruction or replacement invalidates all descriptors. Length marking and raw-tail extraction can make formerly live references refer to unmanaged or unconstructed storage. Prefer raw_slice for a non-owning interval and span for bounded embedded storage.

micron::span

Defined in header <micron/span.hpp>.

An owning fixed-capacity contiguous sequence with raw embedded storage for N elements and a variable live prefix.

Template parameters and ownership

T satisfies is_regular_object and N defaults to 64. The element array is inside a union so default construction leaves length zero without constructing N objects. This is not the standard-library non-owning span model. Container storage does not allocate, although T operations and constructing other returned containers may do so.

Count, fill, initializer-list, pointer-range, raw_slice, and generator constructors construct owned elements and report a library error when their input exceeds N. Pointer/raw-slice construction copies rather than borrows. Copying constructs independent elements. Same- and cross-capacity moves move the live prefix and set source length to zero; a cross-capacity move checks fit.

Capacity and modifiers

size/len return length, max_size returns N, and full tests length==N. overflowed() tests length+1>N, so it is also true for an ordinarily full span. mark(n) edits length only when n<=N and does not construct or destroy objects; __set_size edits it without a capacity check. These are lifetime-sensitive internal-style operations despite being public.

push_back, move_back, and emplace_back construct one element and return span&; excess capacity reports a runtime_error. Insert shifts the suffix and accepts an index through length. Erase shifts left and reports an invalid index; pop_back is a no-op on empty input. Clear destroys the live prefix. Fast_clear skips destruction only for nonclass T. Reset destroys the live prefix, constructs N default values, and makes the span full.

Single-element subscript is unchecked even though the class is tagged safe. A two-bound subscript checks a nonempty in-range interval and returns an owned copied span with the same N capacity. The no-argument subscript copies the complete live prefix. Front/back return pointers and do not check emptiness; first/last/get instead return null when unavailable.

Borrowed results

iter, pointer-range, callback split, strip/trim, byte, flattening, and alignment operations return borrowed descriptors. Their shared semantics and constness limitations are described above. span does not expose slice's split_at, split_first/last record methods, repeat, concat, or join APIs.

split_off_first/last return moved values, with T{} for empty input. split_off_first_mut stores the removed value just beyond the new live prefix and returns a descriptor to it. split_off_last_mut and split_off_mut similarly retain objects outside the tracked prefix. Those removed objects are not destroyed by normal span destruction and can be overwritten by later insertion unless their lifetimes are managed explicitly.

swap_with_span exchanges only the shorter live prefix, not lengths or complete container contents. is_pod/is_class_type/is_trivial are static queries about T. Address-of returns the embedded element bytes, not the span object's address.

Complexity and invalidation

Construction, copying, movement, assignment, clear, and reset perform work proportional to their constructed/destroyed element counts. End insertion/removal is O(1) element work; interior insert/erase and first removal are O(length). Shared sequence transformations have the costs in the family table.

No container reallocation occurs, so unaffected addresses remain within the same object. Shifts, rotations, reset, and replacement can change element identity or lifetime at those addresses. Moving a span constructs elements at the destination's embedded addresses and does not redirect existing pointers there. Choose it when a fixed object-local capacity is suitable.

micron::raw_slice

Defined in header <micron/slice.hpp>.

A non-owning contiguous descriptor with public T* ptr and size_t len members.

Construction and access

Default construction gives {nullptr,0}. The pointer/count constructor accepts const T* and removes constness; use raw_slice<const T> to express read-only elements. Copying a descriptor copies the address and count only. It neither frees storage nor destroys elements.

Begin/end are raw pointers; const access returns const T pointers/references. Size returns len, is_empty tests len==0, and valid tests only ptr!=nullptr. A valid zero-length descriptor is possible. Subscript is unchecked; get(i) returns null unless i<len. The caller must ensure the whole described interval is valid.

Complexity and lifetime

All descriptor operations are O(1). Retaining or copying the descriptor does not extend the allocation's lifetime. It is the direct borrowed-storage choice among these types.

micron::range

Defined in header <micron/range.hpp>.

A compile-time half-open unit-step range of umax_t values with From<To.

Operations

The range object stores no generated values. Static begin/end create counting iterators at From and To; reverse access wraps those endpoints. size and ssize cast To-From into the selected unsigned/signed types, and empty always returns false. Copy/move construction is defaulted, but assignment is deleted.

Unlike count_range::perform, range::perform(f) invokes a nullary callback To-From times and does not pass the counter. Its member-function overload repeatedly invokes the selected member with the same argument pack.

Complexity

Endpoint and size operations are O(1), with no allocation. Complete iteration and perform cost O(To-From) increments/calls plus callback cost. Endpoint conversions and signed-size representability remain the caller's responsibility.

micron::count_range

Defined in header <micron/range.hpp>.

A compile-time arithmetic unit-step counting range, parameterized by value type T and endpoints From and To.

Representation and aliases

The declaration requires arithmetic T, a To convertible to T, and From<To. Iterators yield values rather than references to stored elements. Copy/move construction is supported; assignment is deleted. Perform invokes f(value), with member-function overloads taking a value, const reference, or rvalue reference.

Floating endpoints

Floating counting_iter stores an anchor and an integer step counter. Count_range's floating end uses the same From anchor and counter max_t(T(To)-From). This truncates a fractional distance rather than rounding up. For example, a positive distance below one yields equal begin/end even though empty() remains false. size also truncates the arithmetic distance to usize, while ssize retains the floating difference_type.

Incrementing the integer counter avoids an iterator-position stall at large floating values, but distinct counter positions can still produce equal rounded floating values. Arithmetic offsets are converted to max_t for floating iterator movement. These ranges represent unit steps, not arbitrary floating strides.

Complexity

Construction and endpoint arithmetic are O(1). Enumeration costs one value computation per step, plus callback work. Choose integral endpoints or deliberately integral floating step counts when conventional half-open counting is required.

micron::counting_iter

Defined in header <micron/range.hpp>.

An arithmetic cursor yielding its current value by value; it owns no sequence elements.

Variants and member types

The primary template stores T val__ and increments/decrements it directly. Its value_type is T, reference is T, pointer is const T*, difference_type is iter_difference_t<T>. The floating specialization stores T val__ plus max_t cnt__ and yields val__+T(cnt__). Equal anchors compare integer counters; different anchors compare computed floating values.

iter_difference_t<T> selects make_signed_t<T> for nonfloating types and T for floating types. iter_size_t<T> selects make_unsigned_t<T> for nonfloating types and usize for floating types. The underlying _iter_difference and _iter_size structs expose these selections through type.

The cursor supports pre/post increment/decrement, arithmetic, indexing by offset, subtraction, and ordering. const_counting_iter inherits these operations but deletes copy/move assignment; it does not freeze its position, and dereference still yields a value. No real element address is associated with pointer/reference typedefs.

Complexity

Cursor operations are O(1) arithmetic work. Unsigned wrap, signed overflow, integer counter overflow, and floating precision limits are not checked.

micron::reverse_iter

Defined in header <micron/range.hpp>.

An adapter whose base points one position past the element yielded by dereference.

Operations and requirements

Dereference copies the base and returns *--copy. Increment moves the base backward; decrement moves it forward; arithmetic and ordering reverse their base direction. base() returns the stored iterator. Endpoints use {end,begin} without forming a pointer before the start of an array.

_iter_traits obtains value_type, difference_type, pointer, and reference from iterator member types, with a raw-pointer specialization using ssize_t and element references. Instantiating an operation requires the corresponding decrement/arithmetic/comparison support of Iter. There is no arrow operator in this adapter.

Complexity and lifetime

Adapter overhead is constant; underlying operations determine total cost. It borrows whatever its base iterator borrows and is invalidated by the same storage or position changes.

micron::range_of

Defined in header <micron/range.hpp>.

A fixed-count prefix utility whose nested view stores a reference to a container rather than copying its elements.

Template parameters and binding

Cnt is a compile-time count convertible to size_t. Static perform uses T::iterator and T::size_type to walk the first Cnt entries of its supplied object. bind(c) returns view<C>; a const overload returns view<const C>.

The nested view stores C& c__. Begin/data/subscript forward to the current container, and end is current begin+Cnt. Size is always Cnt and does not inspect the container's actual length. The view requires the relevant container aliases, random-access addition/subtraction, and data/index operations when used. No fit check verifies Cnt<=c.size().

Complexity and invalidation

Binding and forwarding accessors are O(1) plus the container operation. Perform executes Cnt callbacks. The container object must outlive its bound view. Reallocation invalidates previously obtained iterators, while a fresh begin call obtains the container's current storage; destroying the referenced container invalidates the view itself.

micron::view

Defined in header <micron/view.hpp>.

A non-owning interval of pointer values with deleted copy and move operations.

Template parameters and access

T must itself be a pointer type and defaults to byte*. Constructors store one pointer with a null end, two endpoints, or reinterpret a container's begin/end as T. The endpoint fields are const pointer values, not necessarily pointers to const elements.

Begin/end return those stored pointers. operator[](n) checks n against end-start and returns &start[n], an element pointer rather than an element reference. A one-pointer view has no valid bounded interval for that subtraction and must not be indexed as though its extent were known. The class has no size or empty observer.

view_ptr is only a declaration returning add_pointer<T>::type and is suitable for unevaluated type inspection, not a defined runtime helper. view_type(T&) returns a default-constructed remove_reference<T> object; it does not return the argument or a view of it.

Complexity and lifetime

Construction and access are O(1). The original storage must remain valid; no ownership or lifetime extension occurs. This type differs from the ranges::view concept and from slice/span owners.

micron::iterator

Defined in header <micron/iterator.hpp>.

A non-owning mutable cursor over fundamental P objects, storing a current pointer and an end pointer.

Construction and operations

The explicit pointer-pair constructor records a conventional half-open interval. A container constructor reinterprets its begin/end addresses as P pointers. Other forwarding constructors accept fundamental/pointer forms under conversion constraints; their end calculation uses the address of the constructor argument plus rng, so they should not be assumed to describe the pointee array.

Copying duplicates cursor state; moving clears the source pointers. Dereference, arrow, peek, and call expose the current element/address. Advance/retreat move by n, next/prev by one; nth calls next n times. Equality compares current pointers only and ignores end. operator! tests a null current pointer, not exhaustion.

Count advances before checking the end and consumes the cursor. For a valid nonempty interval it counts the steps after the current element, not the full remaining length; on an empty interval it moves past the end and cannot be used as a safe size operation. size_hint returns end-current without advancing. For_each transforms the current value first and then advances until end; its do/while body requires nonempty valid input. Skip advances by one only when its predicate accepts the current value.

Complexity and notes

Pointer movement is O(1), nth is O(n), and consuming count/for_each are linear in traversed elements plus callback work. No bounds checks stop manual advancement. Its value/pointer/reference/category aliases are private, and regular_iterator_tag is a local marker rather than proof of standard iterator conformance. Prefer direct container iterators when the extra consuming operations are unnecessary.

Concept inventory

The range concept checks begin/end plus sentinel_for. Sized_range adds size; input_range, forward_range, bidirectional_range, random_access_range, and contiguous_range combine the corresponding micron iterator concepts. view additionally requires move construction and a nested __lazy_view_tag. viewable_range accepts either such a view or a range after removing references; it does not itself reject every dangling temporary scenario. borrowed_range accepts an lvalue reference range or a range with __borrowed_tag.

range_size_t<F,T> outside the ranges namespace is simply convertible_to<T,F>. None of these constraints provides a runtime length check or lifetime tracking. Accessor complexity and exceptions follow the selected member; array access is O(1).

micron::view_interface

Defined in header <micron/range.hpp>.

A storage-free CRTP base deriving convenience accessors from a range type D.

Operations

Empty compares the derived const begin/end, explicit bool negates empty, and front dereferences begin without an empty check. Size and ssize are available only when the derived type supplies __size_exact. Subscript requires a random-access const range and indexes its begin cursor without a bounds check.

The base does not by itself mark D as a ranges::view or borrowed_range and does not own the derived range's elements. Runtime cost and invalidation follow the derived accessors/iterators; front and subscript require valid positions.
