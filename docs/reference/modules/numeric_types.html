Numeric types

From micron reference
micron reference › Numerics and mathematics

Numeric limits, complex and rational values, compact floating-point storage, double-double arithmetic, and decimal conversion results.

Choosing a representation

These facilities have different error conventions. Rational and decimal functions return structures with an explicit error field and Boolean success conversion. Complex and double-double operations use ordinary floating-point results and do not return those error structures.

micron::numeric_limits

Defined in header <micron/numerics.hpp>.

Reports numeric properties for a supported type. The primary template is unspecialized and returns T{} from its value-producing functions.

Specializations

Explicit specializations cover bool, the ordinary character and integer types through unsigned long long, float, double, long double, and object pointers. Top-level const, volatile, and const volatile specializations inherit the unqualified specialization. Aliases use the specialization of the type they actually name. There is no explicit native/emulated 128-bit integer, _Float16, _Float32, _Float64, or _Float128 specialization in this header.

Notes

Several specializations retain literal metadata that differs from the target type. Plain char reports a range of 0–127 and is_signed = false, regardless of target signedness. wchar_t reports zero as its minimum even though it reports signedness. unsigned long uses the signed-long values for digits and digits10. These fields must not be used to derive a complete portable encoding range.

The long double value bounds and smallest subnormal use compiler target macros, but its precision, epsilon, and exponent metadata remain the x87 values. They do not describe aarch64 binary128 or armv7-a binary64 in full. A compiler-specific f128 alias may select either this specialization or the unspecialized primary template.

The pointer specialization returns null for min() and lowest() and an all-one address representation for max(). That maximum is not a valid allocation or a dereferenceable sentinel. Its max() is not constexpr, and the pointer specialization supplies only its reduced set of members, without the floating-value functions.

All value queries perform constant work and allocate no storage. The header also defines maximum::{u8bit,u16bit,u32bit,u64bit,maxbit,i8bit,i16bit,i32bit,i64bit,f32bit,f64bit}, corresponding signed/floating minimum constants, and the approximate pi, half_pi, pi64, and half_pi64 constants.

micron::math::complex

Defined in header <micron/math/complex.hpp>.

A complex value with public components F real and F imag. F must satisfy complex_scalar, which tests is_floating_point_v<F>.

Construction and operations

Default construction initializes both components to zero. Construction from one scalar sets the imaginary component to zero; the two-scalar constructor supplies both. Conversion from another complex<G> is explicit and converts each component. Copy and move have ordinary value semantics.

Unary signs, complex addition/subtraction/multiplication/division, scalar multiplication/division, compound assignment, and exact component-wise equality are provided. conj(z) negates the imaginary component; norm(z) returns real*real + imag*imag, the squared magnitude. There is no ordering operation or implicit scalar conversion.

Implementation and complexity

Each operation uses a fixed number of component operations and no heap storage. Division of two-byte and four-byte components widens intermediates to float or double. Wider division uses a direct reciprocal formula within a checked magnitude interval and a scaled Smith-style calculation outside it, reducing avoidable finite overflow and underflow.

The operations are noexcept and supply no domain-error result. Zero denominators and nonfinite values follow the selected floating computations; the type does not establish a complete exceptional-value recovery policy. norm uses the direct sum of squares and can overflow even when a separately scaled magnitude calculation would be representable.

micron::math::rational

Defined in header <micron/math/rational.hpp>.

Canonical exact fraction stored as an owned arbint<> numerator and arbuint<> denominator. The default value is zero over one.

Construction and operations

make_rational(numerator,denominator,limits) accepts arbitrary-precision signed inputs or i64 values, transfers the denominator sign to the numerator, divides by their greatest common divisor, and returns a rational_result. Zero denominators are rejected. A zero numerator is normalized to the default zero value.

numerator() and denominator() return const references. sign(), is_zero(), and is_integer() inspect the canonical components. Free rational_negate, rational_add, rational_subtract, rational_multiply, rational_divide, and rational_power return checked results; equality compares the canonical components directly. rational_compare returns a checked ordering instead of a Boolean less-than operation.

Addition reduces a shared denominator factor before forming products. Multiplication cancels numerator/denominator cross factors before multiplying. Division forms the reciprocal of the divisor and uses multiplication. Power uses repeated squaring, supports negative exponents, and rejects zero to a nonpositive exponent, including 0^0.

Storage, complexity, and lifetime

Arithmetic can allocate arbitrary-precision component and temporary storage. Its cost depends on limb lengths, greatest-common-divisor calculations, multiplication, and division. It is not constant-time scalar arithmetic. Power performs O(log |exponent|) checked multiplications, whose operand sizes can grow. Equal-denominator comparison avoids cross products; a general comparison forms reduced cross products.

Copies duplicate the component values; moves use the component move operations. References returned by component accessors belong to the rational object and must not outlive it or be retained across replacement of its state. Operations produce new values and preserve the input fractions.

Parameters and result types

micron::math::float16

Defined in header <micron/math/float16.hpp>.

Two-byte binary16 storage with public u16 bits. It is distinct from the compiler-dependent global alias f16.

Construction and conversion

Default construction gives positive zero. The explicit converting constructor accepts only a floating-point type occupying four bytes. It rounds to nearest with ties to even, preserves signed zero and representable subnormals, overflows to signed infinity, and canonicalizes NaNs to signed quiet NaNs. Wider source values must first be explicitly narrowed by the caller.

from_bits(u16) stores the supplied representation unchanged. to_float() decodes to f32; to_double() directly decodes to f64, including subnormals and special values. is_finite() tests the exponent bits. Size is exactly two bytes and alignment is alignof(u16).

Usage and complexity

The type supplies storage and conversion, without arithmetic operators or a numeric-limits specialization in this header. Convert to a working scalar type, compute, and explicitly convert back when compact storage is required. Conversions use bounded integer/bit operations with no allocation and do not consult a floating-point rounding mode.

micron::math::bfloat16

Defined in header <micron/math/float16.hpp>.

Two-byte bfloat16 storage: one sign bit, eight exponent bits, and seven explicit fraction bits.

Construction and conversion

The explicit constructor accepts a four-byte floating-point value and rounds its representation to nearest with ties to even. NaNs become signed canonical quiet NaNs. from_bits retains any supplied 16-bit pattern; to_float restores the high 16 bits of binary32 and quiets NaNs, while to_double decodes directly into binary64. Default construction yields positive zero; is_finite tests the exponent field.

Size is two bytes with u16 alignment. The exponent range and fraction precision differ from binary16. Use bfloat16 when its wider exponent field is appropriate; use float16 when its larger fraction field and smaller exponent range are appropriate. Both are storage types with bounded-cost conversions and no heap ownership.

micron::math::dd64

Defined in header <micron/math/dd64.hpp>.

A double-double value stored in public binary64 components hi and lo, interpreted as their sum.

Representation and operations

The object occupies 16 bytes. Constructors accept zero, one f64 value with zero low part, or an arbitrary high/low pair. Construction does not normalize a supplied pair. to_double() and explicit conversion to f64 return hi + lo, rounding back to one component's precision.

The math::dd functions provide two_sum, fast_two_sum, two_prod, add, sub, mul, and div. The first three return a leading result with its rounding residual when the floating assumptions hold. fast_two_sum(a,b) requires abs(a) >= abs(b). Runtime two_prod uses FMA for the residual; Clang constant evaluation uses a scaled split-product calculation.

Addition combines component sums, multiplication retains the leading product residual and cross terms, and division computes one quotient and one correction. Arithmetic is provided by these functions rather than member operators. The representation extends precision, not the range of each underlying binary64 component.

Complexity and notes

Operations use a fixed number of scalar computations and allocate no storage. Error-free transformation properties require suitable finite values, rounding behavior, and preservation of the operation sequence; overflow, underflow, nonfinite inputs, and reassociation can invalidate them. Arbitrary high/low constructor inputs do not establish a normalized expansion.

micron::math::decimal_result

Defined in header <micron/math/decimal.hpp>.

Result of binary64 decimal formatting, containing the number of bytes written and a decimal_error.

Formatting contract

binary64_to_decimal(destination,capacity,value) formats the exact finite binary64 value. The overload with significant_digits accepts 1–17 digits and rounds to nearest with ties to even. Both choose fixed or scientific spelling from the resulting decimal point and digit count, preserve negative zero, and omit a terminating null character.

The result's size is the output byte count on success; explicit Boolean conversion tests error == none. Errors are nonfinite, short_output, internal_capacity, and invalid_precision. Formatting builds a local result and writes only after checking the destination and capacity. These errors return size zero and leave the caller's destination unchanged.

binary64_decimal_capacity is 800 bytes for the exact-output buffer; binary64_significant_decimal_capacity is 32 for the significant-digit form. The implementation expands powers into fixed base-10^9 working limbs and rounds decimal digits; it performs bounded work for binary64 and allocates no heap memory. It is a conversion facility, not an owning decimal arithmetic class.

micron::math::ieee::traits

Defined in header <micron/math/ieee.hpp>.

Format metadata selected by the size of a floating-point type. The ordinary implementations describe four-byte binary32 and eight-byte binary64.

Member types and constants

traits_n<Size> is the size-specific template and traits<F> inherits traits_n<sizeof(F)>. A wasm build additionally includes its binary128 specialization. The ieee754_floating concept itself only tests is_floating_point_v; that test alone does not establish that traits<F> supplies the members an operation needs.

MemberMeaning
uint_typeUnsigned integer representation: u32 for four bytes or u64 for eight bytes.
bits, mant_bits, exp_bits, exp_biasFormat width, explicit fraction width, exponent width, and exponent bias.
sign_mask, exp_mask, mant_maskMasks for the sign, exponent, and explicit fraction fields.
implicit_one, quiet_nan_bitImplicit leading fraction bit and quiet-NaN bit.

Operations and notes

The associated functions extract or construct bit patterns, classify values, compute adjacent representations and ULP distance, and inspect raw sign/exponent/fraction fields. pack masks the supplied fields without validating a numerical exponent range. exponent_of subtracts the bias even for a zero exponent field; it is not a complete decomposition of zero or subnormal values.

Classification of four-byte and eight-byte values uses integer bit tests. Several other floating classifications fall back to compiler built-ins, while representation-based functions require a supported traits specialization. Most non-wasm 16-byte long double representations therefore cannot use the size-based bit API. These functions perform fixed work without allocating storage.
