Arrays

From micron reference
micron reference › Containers and strings

Array containers provide fixed extents, sorted bounded sequences, persistent indexed values, multidimensional storage, and separate typed columns. Their storage and update models differ; an array-family tag does not imply inline storage or a fixed logical size.

Container types

<micron/array.hpp> includes array, bisect_array, carray, conarray, and farray. The other types require their individual headers. constarray.hpp includes constexprarray.hpp and introduces no additional class.

Extent and element lifetime

For array, farray, carray, constexpr_array, iarray, and conarray, size() and max_size() both return N; clearing resets values without making the array empty. These templates require N > 0 and N * sizeof(T) < 2^22. Their storage belongs to the container object, regardless of whether that object itself is placed on the stack or heap.

bisect_array reports an active prefix through size(), although all N slots are constructed. mdarray::max_size() is the current total element count. soa::max_size() is its current row capacity. parray::max_size() is its compile-time logical extent.

Arithmetic and synchronization

For the fixed inline numeric interfaces, a scalar operation visits every element. Same-family array overloads are declared for M <= N and operate on a prefix. However, the different-extent overloads in array, farray, carray, iarray, and conarray access the other specialization's private storage without friendship, so those instantiations are ill-formed. constexpr_array has public storage and permits the declared different-extent operations. Arithmetic overflow, division by zero, and invalid element operations are governed by T; the containers add no numeric checks.

The array families other than conarray do not serialize mutations. Const access is safe for simultaneous readers only while the owning object and any shared element state are not modified. The immutable_tag on a type does not prohibit assignment to the container object.

Construction and assignment

Default construction initializes all elements from T{}. A value constructor fills all elements. Initializer-list construction rejects lists longer than N and value-initializes the omitted suffix. A slice copies its available prefix and fills the remainder with T{}. Construction from another generic container requires at least N source elements and consumes the first N.

Copy construction copies every element. Move construction and move assignment move elements while retaining the source array's extent and element lifetimes. Assignment from a shorter C array or container updates only the overlapping prefix; it leaves the destination suffix unchanged.

Complexity and iterator invalidation

Element access, size queries, and obtaining an iterator take constant time. Construction, copying, moving, clearing, filling, and a complete arithmetic operation take linear time in N, excluding the cost of the element operations. A reduction or an unsuccessful any/all query also examines N elements.

Storage never reallocates. Assignment and arithmetic retain element addresses; a move constructs or assigns elements in a different array rather than transferring storage. Clearing destroys and reconstructs elements at the same addresses. Pointers and iterators must not outlive the owning array. A member returning slice<T> constructs a separately allocated copy in linear time in the selected count; that result owns its copied elements.

Notes

Unary operator& returns a byte pointer to element storage. addr() returns the container object's address. Arithmetic is available only when the selected element operations are well-formed. The variadic compound-assignment helpers apply each argument in order; a container argument affects its overlapping prefix.

Storage and arithmetic

Construction, copying, moving, fixed size, and prefix assignment follow the ordinary array's model. Destruction calls element destructors without the ordinary array's final storage zeroing. clear() still destroys, zeroes, and reconstructs all elements. length and static_size equal N.

Selected addition, subtraction, multiplication, and scalar division use AVX/AVX2, SSE, or NEON code according to the enabled features and element size. Scalar work of at most 32 elements may be expanded with an index sequence. Other paths use loops, and scalar tails process elements outside a complete SIMD block. Integer division and modulo use scalar operations. Prefetching is used in selected loops when element storage exceeds 4096 bytes.

Element access

at(i) checks i < N. operator[], get, cget, and both slice endpoints are unchecked. A range supplied to operator[](from, to) must delimit valid element storage. data() and iterators expose the fixed buffer. operator& returns its byte address; addr() returns the object address.

Complexity and iterator invalidation

Element access, size queries, and obtaining an iterator take constant time. Construction, copying, moving, clearing, filling, and a complete arithmetic operation take linear time in N, excluding the cost of the element operations. A reduction or an unsuccessful any/all query also examines N elements.

Storage never reallocates. Assignment and arithmetic retain element addresses; a move constructs or assigns elements in a different array rather than transferring storage. Clearing destroys and reconstructs elements at the same addresses. Pointers and iterators must not outlive the owning array. A member returning slice<T> constructs a separately allocated copy in linear time in the selected count; that result owns its copied elements.

Notes

The current SIMD eligibility calculation includes 16-bit integers, but the addition and subtraction SIMD bodies contain no 16-bit bulk branch. A selected SIMD path can therefore leave the bulk unchanged while processing only a tail for that element size.

The scalar loop fallback in the value-returning operator+, operator-, and operator* refers to the const source buffer rather than the result buffer. Instantiations that reach that fallback with M > 32, such as carray<long, 33> addition on an SSE2 build, are ill-formed. These limitations do not apply to the ordinary array arithmetic loops.

Storage and construction

Requires is_constexpr_valid<T>. The public member stack is a 64-byte-aligned T[N], initialized with {}. Default construction retains those initialized values. Value construction assigns every slot. Initializer-list construction copies at most N values and value-initializes the remaining slots; excess values are silently ignored.

Copy and move operations process every element. A move retains the source's fixed extent. length and static_size equal N. The generator constructors appearing in a source comment are not part of the compiled interface.

Operations and complexity

at(i) checks its index; subscript is unchecked. Iterators and data() are raw pointers. fill, scalar compound arithmetic, array arithmetic on a prefix of extent M <= N, sum, mul, sqrt, all, and any use constexpr loops. Access and size queries are constant time; complete copies, fills, transforms, and reductions are linear in N.

Operations do not relocate the inline storage. Constant evaluation additionally requires every invoked element and math operation to be valid in a constant expression.

Storage and value operations

Stores all N elements inline with alignof(T) alignment. Constructors support defaults, a repeated value, a list, a slice, generators, and sufficiently large containers. A list longer than N is rejected. A slice pads its short suffix with T{}; a generic container must supply at least N elements.

Copy and move operations process every element. begin, end, data, front, back, and subscript expose const elements. at, get, and cget check their indices. length and static_size equal N. The mutable iterator, pointer, reference, and ref aliases describe types and do not change the const return types of the ordinary accessors.

Transformations

Binary arithmetic, compound arithmetic such as operator+=, named arithmetic, sqrt, fill, and clear return an independent iarray; they leave the original's elements unchanged. The result must be retained to use the transformation. Reductions and equality queries inspect the complete extent. The source's two-index slice overload has an additional template parameter C that is not deducible from the indices.

Complexity and iterator invalidation

Element access, size queries, and obtaining an iterator take constant time. Construction, copying, moving, clearing, filling, and a complete arithmetic operation take linear time in N, excluding the cost of the element operations. A reduction or an unsuccessful any/all query also examines N elements.

Storage never reallocates. Assignment and arithmetic retain element addresses; a move constructs or assigns elements in a different array rather than transferring storage. Clearing destroys and reconstructs elements at the same addresses. Pointers and iterators must not outlive the owning array. A member returning slice<T> constructs a separately allocated copy in linear time in the selected count; that result owns its copied elements.

Notes

mut(i) returns an unchecked mutable reference. Copy, move, scalar, C-array, and generic-container assignment also modify the object. These operations require external synchronization when an object is shared with readers. The class provides value-oriented arithmetic rather than enforced physical immutability.

Synchronized access

Stores N regular objects in 64-byte-aligned inline storage and owns a fast_mutex. at(i) returns a copied value under the lock; at(i, value) writes under the lock. front() and back() return copied values. Fill, clear, reductions, scalar arithmetic, and equality queries hold the mutex during the complete operation. length and static_size equal N.

locked() returns a noncopyable scope that holds the mutex for its lifetime and provides mutable data() and subscript access. The parameterless get() instead locks manually and returns the first element pointer; every successful call must be paired with release(), including on exceptional exits.

Unsynchronized access and thread safety

Iterators, data, view, indexed get/cget, subscript, and byte-address operator& do not retain the lock. Reads or writes through them require external exclusion from conflicting access. Slice construction also reads the source without a lock, then owns an independent copy. Array-operand compound arithmetic locks the destination only; concurrent modification of the source requires separate exclusion.

The scope mutex is not recursive. Calling another locking member while a scope or manual get() lock is held can deadlock. Destruction requires exclusive ownership of the container lifetime.

Complexity and iterator invalidation

Apart from mutex waiting, individual reads and writes take constant time. Copy/move construction and complete array operations are linear in N. Element addresses remain fixed for the object's lifetime. A pointer's stable address does not synchronize later accesses.

Notes

Two-index slicing checks a half-open range, then obtains each endpoint with checked get; consequently to == N is rejected by get(N). Binary arithmetic initializes a fresh default array and computes the first M results; its suffix remains default-initialized rather than copying the left operand's suffix.

The current copy and move assignment bodies compare this with &o, where operator& returns a byte pointer. These instantiations are ill-formed. Two-object binary arithmetic also depends on the deferred-lock helper and on access between different extents; declarations alone do not establish that every combination is usable.

Lifetime and access

Construction locks the referenced container; destruction unlocks it. Copy construction and copy assignment are deleted. data() returns the mutable first-element pointer, unchecked subscript returns T&, and size() returns N. Access is constant time after acquiring the lock. The container must outlive the scope, and pointers obtained from the scope are no longer protected after it is destroyed.

Storage and ordering

Requires a regular object type and the same positive extent and storage-size bound as array. Construction creates all N elements from T{} and starts with logical size zero. Container construction inserts each source value; the source need not be sorted. static_size and the public constant __length equal N; there is no max_size() member.

insert(value) uses right bisection with operator<, then shifts the suffix by assignment. A new value follows equivalent values. It rejects insertion when full. erase(i) checks the active index and shifts later values left. It decreases logical size without destroying the now-unused final slot. All N objects remain alive until array destruction.

Copy and move operations process the complete underlying extent and copy the logical size. A move resets the source logical size to zero.

Complexity and iterator invalidation

Index access and size/full/empty queries are constant time. Bisection uses logarithmically many comparisons, followed by up to size() assignments, so insertion and erasure are linear in the active suffix. Building from an arbitrary n-element container by repeated insertion is quadratic in the worst case. Copying, moving, and destruction are linear in N.

Storage does not relocate. Insertion and erasure change the values represented by positions at and after the changed index. The old end position no longer marks the logical end after a size change.

Notes

Const subscript checks the active size. get/cget check capacity N instead, and mutable data and iterators allow direct edits that can break sorted order. front/back require a nonempty logical sequence. The mutable range has begin/end; const traversal is provided through cbegin/cend. There is no public search or bisection member.

micron::parray

Defined in header <micron/array/parray.hpp>.

A persistent fixed-size indexed value implemented by an atomically reference-counted branching trie.

Template parameters and storage

T satisfies is_movable_object; operations that copy leaves additionally require copying and assignment. K is 1 through 6, H is 1 through 8, and branching is B = 2^K. The fixed logical length is B^H, or 32768 with the defaults. The capacity must be representable in usize; the source additionally asserts K * H < 64.

The object stores one root pointer. Internal nodes hold B child pointers; leaves hold B constructed elements. Null subtrees represent default T{} values without allocating them. Default construction allocates no trie nodes. A repeated-value constructor builds one subtree per level and shares it across all equal branches. Initializer lists and contiguous sources materialize the occupied prefix and pad its final leaf.

Value operations and complexity

Copy construction retains the root in constant time; move construction transfers it. Assignment also releases the destination's previous tree, which may destroy its uniquely owned nodes. size() and max_size() always return the fixed length, and empty() always returns false, including for a default-constructed array.

set and update return a new version by copying the root-to-leaf path and retaining untouched branches. A lookup traverses H levels; a point update allocates H nodes and copies or initializes one leaf of B elements and B child entries per internal level, for O(B * H) work. set_many repeats this operation for each pair of members a (index) and b (value). at, set, and update check the fixed extent; get and subscript do not.

Scalar arithmetic constructs a complete new tree and visits the complete logical extent. Elementwise array arithmetic iterates the materialized leaves of the right operand and performs a point update for every visited slot. identity() exposes root identity, not value equality. Equality skips identical subtrees; distinct trivially copyable leaves are compared bytewise, while nontrivial elements use operator==.

Traversal and reduction semantics

Ordinary iteration visits every logical index, including implicit defaults, with O(H) dereference cost. for_each(index, value) instead visits only allocated leaves, including default-padded slots within each leaf. It skips entire null subtrees.

sum, mul_reduce, all, and any use that sparse traversal. In particular, all(value) is true and any(value) is false for a completely unmaterialized array, although indexed reads return defaults. Elementwise multiplication and division likewise leave left-hand indices in null right-hand subtrees unchanged. These functions do not have dense-array semantics for every sparse representation.

Iterator invalidation and thread safety

Creating another version does not mutate the original's elements. References remain valid while a version retaining the referenced leaf exists; an implicit-default reference denotes the shared default object. Iterators store a pointer to the container object and do not retain its root independently. Assignment, movement, swap-like replacement, or destruction of that owner changes or ends what an iterator observes.

Atomic reference counts support independent published versions in different threads. They do not serialize assignment to the same container object or synchronize mutable state reachable from an element.

Shape and ownership

Owns one operator new allocation and stores R dimensions, R strides, and their product. Over-aligned element types use aligned new/delete. Default construction is empty. Construction from exactly R dimensions rejects zero dimensions and checks both the dimension product and element-byte product for overflow.

The last-axis stride is one; each preceding stride is the product of later dimensions. size() and max_size() return the total element count. rank equals R. shape(axis) and stride(axis) require axis < R and do not check it. There is no resizing or reshaping member.

Copy construction allocates and copies all values. Copy assignment frees the old buffer first. Move construction transfers the buffer, shape, and strides and resets the source to an empty shape. swap exchanges all storage and shape metadata.

Element access and operations

operator()(indices...) computes the row-major offset without checking coordinates. Flat at(i) checks the total element count; for rank at least two, at(indices...) checks each coordinate. front and back require nonempty storage. Iterators and data() expose the flat contiguous sequence.

fill, clear, +=, -=, scalar *=, and sum visit the flat elements. clear() writes defaults and retains the shape and allocation. Binary arithmetic checks equal total counts only: shapes such as 2 x 6 and 3 x 4 are accepted together and combined in flat order. Selected float operations use AVX2 or NEON loops; other cases use scalar loops.

Complexity and iterator invalidation

Flat access is constant time; coordinate access performs R multiply-add steps. Construction, copying, clearing, arithmetic, and reduction are linear in the total count. Move construction and storage exchange are linear in R. In-place arithmetic retains addresses; copy assignment invalidates the old allocation. Moving and swapping transfer existing pointers to the new owner.

Notes

Copying from an empty source frees the destination buffer but returns before resetting its old shape and stride arrays. Thus size() == 0 need not imply zero values from shape() after that assignment. No synchronization is provided.

micron::soa

Defined in header <micron/array/soa.hpp>.

A move-only structure-of-arrays container with one independently allocated contiguous column for each type in Ts....

Storage and member types

Requires at least one column type. Column I stores the corresponding type from Ts...; all columns share the same row count and capacity. The container declares category_type = array_tag, mutability_type = mutable_tag, and memory_type = heap_tag. column_count is sizeof...(Ts). It provides no general row value_type, row iterator, or row reference type.

Default construction starts without storage. The capacity constructor allocates raw space for every column without constructing rows. Copy operations are deleted; moving transfers the column allocations. Destruction destroys live rows in each column and frees every allocation, using aligned allocation for over-aligned column types.

Capacity and row operations

reserve(cap) grows every column to at least the requested row capacity. emplace_back(Ts... values) accepts one value per column by value and constructs a row. Automatic growth starts at 16 rows and doubles. capacity() and max_size() report the allocated row capacity; size() reports constructed rows.

Growth byte-copies trivially copyable columns. Other column types must be nothrow move-constructible; growth move-constructs their elements and destroys their old instances. Row construction unwinds already-constructed columns if a later column throws. pop_back() rejects an empty container and destroys the final row. clear() destroys all rows while retaining column buffers.

Column access and complexity

column<I>() returns a raw typed column pointer; at<I>(row) checks the live row count. front<I>() and back<I>() require a live row. The column index is a compile-time index into the type pack.

Column access is constant time. Appending without growth and popping perform one element operation per column; growth moves every live element in every column. With a fixed column count and ordinary bounded-cost element moves, automatic doubling gives amortized constant-time append. reserve and clear are linear in the total number of live column elements. A growth operation invalidates pointers into every column; appending within capacity leaves existing element addresses unchanged.

Notes

Columns are contiguous individually; rows are not stored as adjacent tuples. This layout permits a loop to read one field without reading other columns, at the cost of multiple allocations and separate accesses for a whole row. It provides no internal synchronization. Allocation failure in the capacity constructor does not use the partial-allocation rollback present in reserve; no general strong exception guarantee is established for that constructor.

Interface notes

micron::array<T, N>

Stores N elements of T in the array object. N must be positive and the total storage must satisfy the class constraint.

Defined in header <micron/array/array.hpp>.

template<is_regular_object T, usize N = 64>
  requires (N > 0 and ((N * sizeof(T)) < (1 << 22)))
class array;

Parameters

TThe element type. It must satisfy is_regular_object.
NThe number of elements. It must be positive and the object's element storage must be less than 2²² bytes.

Notes

The elements are stored in the array object. Destruction destroys its elements. The initializer-list constructor fills omitted elements with T{} and reports an error if the list is too large.
