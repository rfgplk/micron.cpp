Vulkan

From micron reference
micron reference › Graphics

Vulkan instance/device and resource owners, borrowed queue/command/descriptor views, explicit GPU memory allocation, synchronization and Linux presentation. Generated typed ABI records and a 252-command dispatch table support lower-level native calls.

Setup and explicit capability decisions

Create an instance, enumerate and select a physical device, then choose queue families and requested features/extensions before logical-device creation. Create a surface before selecting presentation support when window-system presentation is needed. Convenience device selection prefers a discrete device but does not prove workload suitability; device construction can leave requested queue capabilities unsatisfied when some other family is usable.

The generated declaration surface includes selected core 1.0 through 1.3, WSI, debug-utils, synchronization2 aliases and diagnostic extension entries. Declared tokens/records do not enable features or guarantee a loaded function. The convenience path does not preserve an arbitrary feature chain in required_vk13_features. Use explicit raw records and procedure calls when complete extension chains, device-group settings, allocation flags, sharing indices or other omitted controls are required. micron::vk aliases micron::gfx::vk.

Resource storage and allocation choices

Creating a buffer/image allocates a native resource handle while leaving its memory unbound. Query requirements, choose a compatible memory type, allocate sufficient properly aligned VkDeviceMemory, then bind it. memory_allocation owns one allocation and optional mapping. memory_pool retains up to 64 pages, allocates aligned cursor ranges and reuses all ranges by bulk reset; it supplies no per-range free or compatibility search for each subsequently bound resource.

Use a dedicated memory_allocation when independent allocation lifetime/mapping is desired. A pool suits groups of compatible resources whose memory can be retired together after completion; retain the pool and stable device until every range is unused. Neither convenience allocator adds all possible dedicated/device-address/export allocation chains. CPU host callbacks serve the Vulkan driver's host allocations and cannot substitute for GPU memory selection/binding.

Recording, submission and invalidation

Command methods record explicit operations and dependencies; they do not infer transitions, track hazards, submit automatically or retain resource owners. Submit to a compatible queue, maintain host external synchronization and preserve referenced resources/pools/memory until completion. Fence waits, queue/device idle or another valid native completion protocol must precede affected reuse/reset/destruction.

Pool reset/free invalidates borrowed command-buffer/descriptor-set copies without clearing their stored nonzero handles. Swapchain reset/recreation/move invalidates image/view references. Memory-pool reset can overlap old suballocations with new ones while retaining the underlying pages. Device reset waits idle when available but does not destroy its children, and cannot make an invalid destruction order correct.

Results, limits and dispatch state

Creation/setup commonly throws through strict check_vk, which accepts only SUCCESS. Raw VkResult is retained for acquisition/presentation/query-result operations; waits translate TIMEOUT explicitly. Several optional commands/status helpers silently return empty/zero/false or do nothing when their entry is absent. Inspect the type's result contract when an absent operation must be distinguished from an ordinary empty/not-ready result.

Dispatch pointers are process-wide rather than per-device/thread state. Fixed inline capacities include 32 physical devices, 16 cached queue families, 32 extension/layer request pointers, command-buffer batches of 16, descriptor-set batches of 32, swapchain storage for eight images/views and 64 memory-pool pages. Native enumerations can throw on INCOMPLETE rather than expanding those arrays. The generated pointer representation of non-dispatchable handles additionally limits correct native ABI use on 32-bit targets, as described under VkBool32.

Cost and reuse

Fixed handle operations perform constant local work. Enumeration/name searches are linear in their bounded arrays, pool allocation scans O(p) retained pages and bulk wrapper initialization copies O(k) handles. Reusing pools/pages preserves allocations, but native memory, descriptor, command, shader/pipeline creation and GPU execution costs remain implementation-dependent. No measured relative performance or real-time bound is supplied.

Plain ABI records and borrowed views allocate no host containers. Dedicated native owners can allocate through the driver, shared ownership allocates one control block, and host callbacks retain their own headers/alignment padding. Swapchain/default feature choices are conveniences requiring surface/device validation, not an automatic rendering scheduler or frame graph.

micron::gfx::vk::vk_lib_t

Defined in header <micron/gfx/vk/loader.hpp>.

Owns libvulkan.so.1 and its vkGetInstanceProcAddr resolver.

Dispatch loading

Global, instance and device load operations traverse the 252-entry generated table and resolve entries of the corresponding dispatch kind into process-wide inline vk* pointer variables. Instance/device creation invokes those loading stages. The table is not stored per instance/device and is not thread-local; replacing its addresses and using multiple devices or loader instances require caller coordination.

Unavailable entries remain null. A declared API version, extension token or nonnull resolver does not establish that a feature is enabled on a device. Required entry points are checked by individual wrappers, while many command helpers silently do nothing when an entry is absent. Direct use of the internal noexcept load functions can terminate if their host-library access throws.

Extension probes

Instance extension and layer probes use inline capacities of 256 and 64 records and accept an INCOMPLETE prefix. Device extension probing uses 512 records and requires SUCCESS; an INCOMPLETE enumeration is reported as unsupported by that helper. Probe work is linear in the returned names plus driver enumeration cost, with no dynamically grown result list.

Raw command signatures

PFN_vk* aliases describe the selected core 1.0 through 1.3 commands, surface/swapchain Xlib/Wayland integration, debug-utils operations, synchronization2 KHR aliases and the selected AMD/NV diagnostic commands. Families cover instance/device discovery and creation; memory/resource allocation/binding; shader/pipeline/cache/descriptor objects; render-pass/framebuffer state; command allocation/recording; synchronization/query operations; submission and presentation. They are callable types, not a complete enabled-extension set or C++ resource owners.

The generated vk* variables retain nullable addresses. Raw commands use their declared VkResult/void/value conventions, native pointer/count ranges and native object synchronization/lifetimes. Symbol loading supplies no automatic conversion between legacy and synchronization2 descriptions and no fallback implementation for a missing extension command.

micron::gfx::vk::subset

Defined in header <micron/gfx/vk/loader.hpp>.

Stores an inline compile-time-selected set of Vulkan procedure addresses.

Loading and access

Indices select generated vk_table entries, commonly through MICRON_VK_SYM or sym_index_of. load_global, load_instance and load_device resolve every selected index with their corresponding resolver; they do not filter the pack by each entry's dispatch kind. The caller must choose a resolver valid for those commands. A missing device resolver leaves that load operation without populating the selected addresses.

raw returns a stored address; as casts it to a caller-selected function-pointer type without checking its signature or availability. Unknown symbol names produce u16(-1), which must not be used to index the table. The generated vk_entry_t records contain a name, u16 index and dispatch kind 0/1/2 for global/instance/device commands.

Cost and lifetime

A subset of N entries stores N pointers inline and performs N resolver calls when loaded. It owns neither a loader library nor an instance/device, retains null results, and provides no automatic refresh after parent destruction or dispatch changes. Lookup in the index pack is compile-time; calling a resolved function remains an indirect call.

micron::gfx::vk::flags

Defined in header <micron/gfx/vk/flags.hpp>.

Stores a strongly typed bit mask with the underlying representation of a Vulkan bit enum.

Parameters and operations

BitType supplies the enum and its underlying mask_type. bits_type names BitType. Construction from a bit or explicit mask stores that value; bitwise operators, equality, Boolean testing and mask conversion operate on the stored bits without validating device support. Cross-enum bit mixing does not occur through the typed operators.

flag_traits defaults is_bitmask to false. Generated specializations enable enum-enum bitwise operations and provide all_flags for the selected bit families. Complement is stored_mask XOR all_flags, not an unrestricted machine-word inversion; unknown stored bits are not cleared by that operation. An unspecialized trait has no all_flags member for complement.

ABI and cost

Most generated mask aliases use 32-bit storage. VkAccessFlags2, VkPipelineStageFlags2 and VkFormatFeatureFlags2 use 64-bit storage. Some reserved flag aliases are plain VkFlags rather than flags specializations. Reserved empty bit enums supply no usable nonzero bit merely because a flag field exists. All wrapper operations are constant work, allocate no storage and perform no Vulkan call.

micron::gfx::vk::structure_type_of

Defined in header <micron/gfx/vk/structure_type.hpp>.

Maps a supported raw Vulkan structure type to its generated VkStructureType constant.

Use and constraints

Generated specializations expose static value for the selected extensible structures. The unspecialized primary template is only declared. The mapping supplies a tag; it neither initializes a structure nor fills its pNext chain, counts, flags or nested pointers. Raw create-info overloads forward their input without repairing missing sType values.

Use the matching value or generated VK_STRUCTURE_TYPE_* constant while explicitly initializing a raw record. Correct extension-chain structure, enabled features and pointer lifetimes remain caller requirements. Mapping and constant access perform no allocation or runtime API work.

micron::gfx::vk::instance_hints

Defined in header <micron/gfx/vk/hints.hpp>.

Supplies application metadata, requested instance version, optional diagnostics and extension/layer names.

Members and selection

Defaults identify micron-app and micron, use version 0.1.0 for application/engine, request Vulkan 1.3, disable debug and enable surface integration. extra_extensions and extra_layers are borrowed arrays with explicit counts. Construction consumes their names; the hint record does not copy or own their backing strings.

Instance setup deduplicates appended names within fixed arrays of 32 layer/extension pointers, truncating additions at capacity. Debug requests add the debug-utils extension and add the validation layer only when discovered. Surface requests add the general surface extension and available Xlib/Wayland platform surface extensions. These requests do not choose a physical device or verify all later device features.

micron::gfx::vk::device_hints

Defined in header <micron/gfx/vk/hints.hpp>.

Specifies requested queue capabilities, core features, Vulkan 1.3 features and extra device extensions.

Members and actual use

graphics, compute, transfer and present default true; required_features and required_vk13_features default to zero. Extra extension names/count are borrowed. prefer_discrete=true and debug=false are present in this record but are not used to select a physical device or validation behavior by the device constructor that consumes it.

The constructor requests the supplied core feature bits directly. It copies the Vulkan 1.3 feature record, replaces sType and sets pNext to null, discarding a caller chain attached to that member. It does not query/intersect supported features and has no corresponding Vulkan 1.1/1.2 feature-chain convenience member. Timeline-semaphore and buffer-device-address use therefore require appropriate feature enablement through a suitable lower-level setup.

micron::gfx::vk::instance

Defined in header <micron/gfx/vk/instance.hpp>.

Owns a Vulkan instance and an optional debug-utils messenger.

Creation and enumeration

Construction loads global commands, builds the requested application/layer/extension records, creates the instance with host allocation callbacks, loads instance commands and optionally creates a debug messenger. debug_enabled reports the requested setting and does not certify validation-layer availability. If optional messenger creation throws after instance creation, construction does not provide a complete cleanup transaction for the already-created raw instance.

The nested physical_device_list stores up to 32 cached physical_device values inline, a count and unchecked indexed/iterator access. Enumeration caps the output array at 32 and passes the result to strict check_vk; an INCOMPLETE result throws rather than delivering an explicitly truncated success. pick_physical_device chooses the first discrete device when requested, otherwise the first entry, and returns an invalid wrapper for an empty list. It does not test presentation, requested features or queue suitability.

Ownership and cost

The object is move-only. reset destroys its debug messenger before the instance and clears owned handles; it does not retain or traverse surfaces, devices or borrowed physical-device wrappers. Destroy all dependants first. Enumeration performs O(n) cached-wrapper initialization for the retained devices, including their property queries, plus driver costs. Ordinary handle transfer and observers are constant work.

micron::gfx::vk::physical_device

Defined in header <micron/gfx/vk/physical_device.hpp>.

Borrows a physical-device handle and caches its core properties, features, memory properties and queue families.

Queries and selection

Construction queries the available property commands and stores at most 16 queue-family records inline. A missing query entry leaves the corresponding zero-initialized cache; valid tests the handle, not cache completeness. select_queue_family returns the first cached family whose flags contain the requested flags and whose optional surface-support query succeeds with support=true. Failure returns ~0u.

Device-extension checks use a fixed 512-entry array and accept only SUCCESS. More available extensions producing INCOMPLETE can therefore yield a false unsupported result. The wrapper does not enable any feature or extension, reserve queues or establish that a selected family can satisfy all later queue requests.

Lifetime and complexity

The wrapper is copyable and owns no instance/device. The originating instance must remain valid. Cache copying is fixed-size work; family selection is O(q) for q<=16 and extension-name testing is O(e) for e<=512 plus native query costs. Accessors return values or references into this wrapper's own cache and are invalidated by its replacement/destruction.

micron::gfx::vk::device

Defined in header <micron/gfx/vk/device.hpp>.

Owns a logical Vulkan device and caches borrowed queue wrappers and physical-device information.

Queues and feature requests

Construction independently chooses the first matching family for requested graphics, compute, transfer and, with a valid surface, presentation. It deduplicates up to four selected families and requests one queue at priority 1 from each. Missing individual capabilities do not fail setup if at least one family was selected; the corresponding queue accessor can remain empty. Queue-count and complete workload suitability are not established by this selection.

Core and Vulkan 1.3 requested feature bits are forwarded without supported-feature intersection. Swapchain extension setup is added for requested presentation with a valid surface; extra extension pointers fit a fixed 32-entry array and are not independently probed/deduplicated there. Device loading replaces the global device-command table. Raw queues are retrieved when the corresponding entry exists.

Lifetime, movement and destruction

The class is move-only. reset calls DeviceWaitIdle when available, ignores that result, then destroys the device and clears cached queues. It does not destroy child objects, so device-owned buffers, memory, views, pools, pipelines, synchronization objects and swapchains must be destroyed first. A wait does not repair a reversed native object-lifetime order.

Some children, including memory_pool and swapchain, store a pointer to this C++ device object. Keep that object alive at the same address; moving its handle does not update those pointers. Cache/handle movement is fixed-size work. Creation, wait-idle and destruction have implementation/device costs beyond local bookkeeping.

micron::gfx::vk::queue

Defined in header <micron/gfx/vk/queue.hpp>.

Borrows a device queue handle and records its family and queue index.

Submission and completion

submit and submit2 forward batches of VkSubmitInfo or VkSubmitInfo2 and an optional fence; missing submission entries throw and returned results pass through strict check_vk. wait_idle calls the native wait when available and otherwise does nothing. A successful submit enqueues work and does not imply completion.

The wrapper is copyable and retains no device, command pool, command buffers, semaphores or resource owners. All referenced objects must remain usable for their required GPU lifetime. Concurrent host use of the same native queue and synchronization of resource hazards remain application responsibilities. Fixed local work is O(1) per forwarded call, excluding native traversal of submitted arrays and GPU execution.

micron::gfx::vk::surface

Defined in header <micron/gfx/vk/surface.hpp>.

Owns a Vulkan presentation surface for a borrowed X11 or Wayland window.

Creation and lifetime

Construction chooses Xlib or Wayland creation from the platform window backend and requires its corresponding loaded extension entry. The owner records its raw instance and surface handle; it does not retain the C++ instance, window or display. Those native parents must outlive the surface and all presentation use.

The object is move-only. reset/destruction destroys the surface when its entry point is present. It does not wait for presentation or rebuild swapchains. Creation/destruction make native API calls with constant local bookkeeping; support, extent and format negotiation are separate queries.

micron::gfx::vk::buffer

Defined in header <micron/gfx/vk/buffer.hpp>.

Owns an unbound Vulkan buffer and caches its size and usage mask.

Usage, storage and binding

buffer_usage names none, transfer source/destination, uniform/storage texel buffer, uniform/storage buffer, index, vertex, indirect and shader-device-address uses; buffer_usage_mask is the underlying mask type. has tests whether any requested bit intersects the stored mask, not whether all requested bits are present. The wrapper's buffer creation allocates the resource handle but no VkDeviceMemory.

memory_requirements queries size, alignment and compatible type bits, or returns zero-initialized requirements when unavailable. bind forwards memory and byte offset without validating alignment, type compatibility or available allocation range. The convenience sharing-mode argument does not supply queue-family indices for concurrent mode; use a complete raw create-info path for such arrangements.

device_address returns zero when the entry is unavailable. A nonzero address additionally requires applicable feature enablement, usage and allocation flags; the memory-allocation convenience wrapper does not add a device-address allocation-flags chain automatically.

Lifetime and cost

The move-only owner borrows its raw device and memory binding. Destroy the buffer before its device and release/reuse memory only after all dependent GPU use. reset deletes the buffer without waiting for completion. Fixed local operations are O(1); resource allocation, binding and GPU access have native costs.

micron::gfx::vk::image

Defined in header <micron/gfx/vk/image.hpp>.

Owns a Vulkan image or wraps an externally owned image handle with cached format and extent.

Creation and external images

image_2d_request defaults to extent 1x1, R8G8B8A8_UNORM, sampled plus transfer-destination usage, one mip level, one array layer, one sample, optimal tiling, exclusive sharing and undefined initial layout. Resource creation leaves memory unbound. Requirements/bind operations follow native memory type, alignment and range rules without checking those constraints locally.

The external-handle constructor stores its supplied image/format/extent with ownership disabled and no device. It does not destroy the handle, returns zero requirements and cannot use the owning bind path. Swapchain images use this borrowed form. Declaring an initial layout does not record a transition or synchronize image access.

Lifetime

The wrapper is move-only. Owning reset destroys the native image without a GPU wait; external reset only clears the view. The device and bound memory must remain alive for owning images, and the external owner must remain alive for borrowed images. image_view objects do not extend either lifetime. Fixed local work is O(1), excluding native allocation and GPU operations.

micron::gfx::vk::image_view

Defined in header <micron/gfx/vk/image_view.hpp>.

Owns a Vulkan image view and borrows the image storage it interprets.

Parameters and lifetime

The convenience constructor selects the supplied view type, format and aspect range with identity component mapping. Remaining-mip/layer counts can be represented by ~0u. A raw create-info overload forwards the complete record. The wrapper does not validate format compatibility, aspect selection or the image's actual dimensions/mip/layer counts.

The move-only owner stores a raw device and view, not an image owner. Destroy views before their images and device, and after GPU use has completed. reset/destruction invokes native view destruction without waiting. Wrapper work is O(1); no CPU image data is allocated or retained.

micron::gfx::vk::memory_allocation

Defined in header <micron/gfx/vk/memory.hpp>.

Owns one VkDeviceMemory allocation and optionally caches a mapped host pointer.

Allocation and mapping

Construction chooses the first compatible physical-device memory type whose property flags contain the request, then allocates exactly the requested requirement size. The convenience path does not append dedicated-allocation, device-address or device-group allocation chains. Failure to find a type or a failed allocation throws.

map forwards the first requested range and caches its pointer. Calling map again while already mapped returns that same pointer without applying a new offset or size. unmap clears the cached mapping. Host visibility, mapping range and synchronization are caller requirements; mapping does not transfer or copy the entire allocation into a micron container.

Coherency and lifetime

flush and invalidate do nothing for coherent memory, an unmapped allocation or a missing entry point. Otherwise they forward the supplied mapped range and ignore its VkResult. They do not round to nonCoherentAtomSize; valid atom alignment/ranges remain caller requirements. A no-op return does not report that a failed native cache operation succeeded.

The move-only owner unmaps and frees on reset/destruction without waiting for GPU completion. Bound resources and mapped/suballocation pointers do not retain it. Memory-type search is O(t), with at most 32 native memory types; other local work is constant beyond native allocation/map/cache-operation costs.

micron::gfx::vk::memory_pool

Defined in header <micron/gfx/vk/memory_pool.hpp>.

Suballocates monotonically from up to 64 Vulkan memory pages using inline page records and cursors.

Allocation strategy

Construction borrows a stable device object, selects one memory type by requested properties and records a page size, default 4 MiB. Pages are allocated lazily. allocate scans existing pages for aligned remaining space, otherwise allocates a page at least max(page_size, requested_size+alignment). Alignment zero is treated as one; the bit-mask alignment calculation requires a power of two, and arithmetic overflow is not checked.

sub_allocation returns a borrowed memory handle, byte offset, byte size and optional mapped pointer. Persistent mapping requires an appropriate host-visible memory type. Suballocation validity tests only whether its memory handle is nonnull. Binding resources to returned handles/offsets remains an explicit native operation with the resource's memoryTypeBits and alignment constraints.

Reuse, invalidation and complexity

There is no individual free, free-list coalescing or recovery of earlier holes. reset rewinds page cursors without freeing or unmapping pages; existing suballocations can then overlap newly allocated ranges. release frees all pages. Both require completion of every affected GPU use. Mapped pointers remain tied to the corresponding allocation's lifetime and mapping.

Allocation scans O(p) pages for p<=64 and can make a native memory allocation; used includes cursor padding, while committed sums page allocation sizes. reset, release and move process O(p) page records. The pool stores a device pointer, so moving/destroying that device invalidates the association. Include memory_pool.hpp explicitly; the reviewed vk.hpp umbrella does not include it.

micron::gfx::vk::unique

Defined in header <micron/gfx/vk/pointers.hpp>.

Owns one native handle together with an inline deleter object.

Parameters and operations

Hnd is the handle carrier and Dlt supplies destruction, including any required raw parent handles and allocation callbacks. The owner is move-only and stores its deleter with no_unique_address. release returns the handle and disables destruction. reset invokes the deleter for the old nonnull handle before installing the new one; resetting to the same raw handle therefore destroys that handle and leaves a stale stored value.

value_type and element_type name Hnd; deleter_type names Dlt. pointer_type/category_type/mutability_type report owning-pointer, pointer and mutable tags. These aliases describe the handle wrapper and do not provide dereferenceable object storage. A default-constructed parent-bearing deleter is not automatically associated with a device or pool.

Cost and lifetime

No control block or host allocation is made. Transfer, release and observations are O(1); reset/destruction additionally incur the deleter's native cost. Deleter operations run under the wrapper's noexcept contracts. Parent handles are borrowed, and no GPU wait or parent reference count is implied.

micron::gfx::vk::shared

Defined in header <micron/gfx/vk/pointers.hpp>.

Shares ownership of a native handle through an allocated atomic-reference-counted control block.

Ownership and thread scope

A nonnull handle allocates one control block containing handle, deleter and atomic reference count. Copies increment using relaxed order; the final acquire-release decrement invokes the deleter and releases the control block. Empty handles have no control block. Moves transfer the block pointer, and release of one wrapper does not destroy a still-shared handle.

The counter permits separate wrappers to share lifetime; it does not synchronize mutation of the same wrapper, native object access, queue submission or GPU completion. use_count is an observation, not a lifetime barrier. There is no weak-owner, aliasing-owner or cycle-breaking interface.

Aliases and cost

The public value_type/element_type/deleter_type and pointer category aliases have the same handle-oriented meaning as unique. Copy/move/observations are O(1), with an atomic operation for ownership copies/releases. Initial ownership and final release incur allocator work. Captured raw device/instance/pool handles must outlive the final deleter invocation.

micron::gfx::vk::VkResult

Defined in header <micron/gfx/vk/__bits/__vk_types.hpp>.

Carries Vulkan success, progress and error status values as a signed enum.

Results and wrapper conventions

SUCCESS is zero. NOT_READY, TIMEOUT, EVENT_SET, EVENT_RESET, INCOMPLETE, PIPELINE_COMPILE_REQUIRED and SUBOPTIMAL_KHR are distinct nonzero statuses; negative values identify the declared host/device allocation, initialization, lost-device, feature/extension, pool, surface and other errors. A nonnegative result is not necessarily completion of the operation expected by a particular wrapper.

check_vk accepts only SUCCESS and throws for every other result, including positive progress/status values. Creation/enumeration wrappers using it can therefore reject INCOMPLETE or PIPELINE_COMPILE_REQUIRED. Fence/timeline waits explicitly translate TIMEOUT to false, while acquisition, presentation and query-result operations expose raw VkResult so the caller can handle their supported status set.

Status helpers that return a Boolean or zero can collapse errors with ordinary not-ready/zero outcomes; their type articles identify those cases. The signed-byte-count -errno convention used by operating-system I/O is not the result convention for raw Vulkan calls.

Semantics

VkFlags is u32 and VkFlags64 is u64. flags<BitEnum> aliases preserve the corresponding enum domain while retaining its underlying mask width. Aliases whose carrier is VkFlags are raw masks, including reserved fields with no currently selected bits. Mask construction does not check device support or make a reserved bit valid. All aliases store values inline and own no resource.

The combined-bit meaning follows the corresponding create-info, access/stage, format, descriptor, resource, synchronization, surface or external-handle field. The flags article describes typed bitwise operators and complement. A flags alias is neither an enabled-feature set nor a dynamically sized bit container.
