Trees

From micron reference
micron reference › Containers and strings

Ordered, hashed, prefix, and spatial tree containers. The family includes a red-black set, an ordered B+ map, a hash-byte adaptive radix map, a sequence-prefix trie, two fixed-universe point indexes, and an R*-style box index.

Container selection

trees.hpp includes the complete family and tree algorithms. The concrete headers can be included separately.

Storage and element lifetime

rb_tree, art, and radix_tree use block pools. Blocks grow without moving live nodes, and erased slots are reused. rb_tree::clear, art::clear, and radix_tree::clear release their blocks. Their pool-byte observers estimate the configured block growth sequence; they are not an allocator's exact accounting, especially after an explicit reserve.

b_tree, quadtree/octree, and rtree use the shared node_arena: a contiguous slab of raw slots addressed by u32 indices. Arena expansion byte-relocates the complete slab, including nontrivially copyable keys and values; it does not invoke their move constructors. Such payloads must tolerate relocation, and returned addresses cannot survive a slab move. Self-referential or address-sensitive objects are unsuitable for growth in this representation. Reserving sufficient nodes before insertion avoids expansion but not entry shifts or splits.

Arena slots are fixed at 64-byte alignment in these containers; the raw payload declarations alone do not provide support for types requiring greater alignment. Clear destroys live objects and resets slab usage while retaining allocation. Live-node counters walk free lists, whereas high-water counters report slots reached since the last reset.

Ordering and complexity

Ordered trees use strict comparison policies, not an injected callable instance: Less::lt or Compare::lt is invoked statically. Equivalence means neither value compares less. Modifying a stored value so its sort position changes breaks the search invariant.

Complexity statements count container work and exclude user comparison, copying, callbacks, and allocation. Ordered balanced trees provide logarithmic paths; spatial queries can visit every entry when regions overlap or subdivision does not separate the data. No source-independent performance ranking between these representations is implied.

Traversal controls

walk_ctl and traversal_order are declared in trees/__tree_walk.hpp. Traversal callbacks can return void to continue, walk_ctl for explicit control, or a bool-convertible result whose false value stops. Only traversals which expose internal structure can honor skip_children; element-only traversals generally inspect only stop.

rb_tree supports inorder, preorder, postorder, and level order. The B+ and spatial container traversals expose entries rather than internal nodes. Their cata members fold the physical tree shape, whereas map builds a new container by inserting transformed values. Allocation and insertion costs therefore remain part of mapping.

Thread safety

These mutable trees have no container-level lock. Read-only sharing requires stable storage and a callback that does not mutate it; structural mutation must be externally synchronized. Some const callback members currently expose mutable payloads, as identified in their notes. No callback may structurally mutate its tree while the traversal retains node pointers or references.

micron::rb_tree

Defined in header <micron/trees/rb.hpp>.

A unique-value ordered red-black tree with pointer-linked nodes allocated from growing blocks.

Template parameters and representation

T is copy- and move-constructible. Less defaults to default_less<T> and supplies static lt(a,b); Alloc defaults to allocator_serial<>. Each rb_node owns T, parent/left/right pointers, a red/black color, and a kind marker. Rotations and recoloring maintain red-black balance. New pool blocks do not relocate existing nodes.

Copy construction clones all nodes and preserves their shape and colors; move construction transfers the root and pool. Generated-value and builder constructors insert values, so equivalent generated values replace earlier ones rather than increasing population.

Member functions and types

insert, emplace, and insert_or_assign replace a comparison-equivalent value and return T&. update(key,fn) passes the current const T*, possibly null, to fn and inserts its result. find returns T* or null; find_by and erase_by accept the two heterogeneous comparison directions. Min/max return nullable pointers; extract_min moves out the least value and reports an error on an empty tree.

Both iterator aliases are const forward cursors, following parent links in ascending order. lower_bound, upper_bound, and equal_range return these cursors. They do not implement decrement or random access. node aliases rb_node<T>; value_type is T and category_type is tree_tag.

for_each walks inorder; map inserts transformed values into a new default rb_tree<U>, so it can merge equivalent results and does not retain a custom Less or Alloc. cata(empty,fn) combines left result, data, and right result. traverse<O> honors stop, and honors skip_children in preorder and level order. Level order allocates an fvector queue. Reserve adds pool capacity without constructing values.

Complexity

Find, insertion, erasure, min/max, and bounds are O(log n) comparisons under the red-black invariant. A single successor can climb O(log n) parent links; complete iteration is O(n). Copy and clear are O(n), plus block-release work; move construction and swap are O(1). Mapping by repeated insertion is O(n log n) comparison work.

Iterator invalidation

Insertion and rotations preserve addresses of existing node values. Erasure invalidates only the erased node; two-child erasure transplants the successor node rather than copying it into the erased slot. Clear and destruction invalidate all nodes. Swap/move transfer nodes to another owner; cursors hold node pointers and have no owner field.

Notes

The const for_each body passes root_ as a mutable node pointer, and template deduction can therefore give the callback T& even on a const tree. The const cata and traverse interfaces use const data. Mutable find/min/max and mutable callbacks must preserve the ordering relation. rb_node::kind is not recomputed by all tree rotations/link assignments, so it is not a reliable structural classification of a live tree.

micron::rb_node

Defined in header <micron/trees/rb.hpp>.

The public red-black node record owning T and holding non-owning parent, left, and right links.

Members and operations

data stores T; color is RBColor; kind_t is empty, leaf, or inner. Value construction makes a red leaf with null links. Default construction is deleted; emplace_tag constructs T in place. Copying a node copies its links rather than cloning a tree. Moving transfers the fields and clears source links/kind; it does not repair neighboring nodes.

grandparent, uncle, and sibling inspect links. set_left and set_right set a child's parent and mark the receiver inner when a non-null child is installed; removing a child does not necessarily restore a leaf marker. detach clears the receiver's links and kind without unlinking it from its former neighbors or changing a tree's size. These operations require manual invariant maintenance when used outside rb_tree.

micron::default_less

Defined in header <micron/trees/rb.hpp>.

The default rb_tree ordering policy, whose static lt(a,b) returns a < b.

Requirements

The result must describe a strict weak ordering consistent across all operations. Policies are types with a static comparison member; the tree does not store a comparator object.

micron::b_tree

Defined in header <micron/trees/b.hpp>.

An ordered B+ map with key/value entries in linked leaves and copied separator keys in internal nodes.

Template parameters and layout

K is copy-constructible and V move-constructible; Compare defaults to b_default_less<K>. DegreeOverride=0 chooses minimum degree T=16, 8, or 4 for combined key/value sizes at most 16, at most 64, or larger. A nonzero override must be at least two. Leaves hold up to 2*T-1 entries; internal nodes hold up to 2*T children. Counts are u16, so the override must fit their representation.

The tree uses a single 64-byte-aligned node arena with leaf next/prev indices. Insertion splits full children top-down. Erasure borrows from adjacent children or merges minimum-size siblings and collapses an empty internal root. Equivalence is defined by Compare::lt in both directions. Natural arithmetic/pointer ordering uses linear in-node scans; custom comparisons use a binary ladder, with an optional compiled vector-scan path.

Copying is deleted. Move and swap transfer the arena and root. reserve(n_entries) estimates a node count from desired entries and expected fill; it is not a strict no-further-growth capacity contract. nodes_used counts live slots and nodes_reserved reports slab capacity.

Member functions and types

insert and emplace preserve existing values and return whether a new key was inserted. insert_or_assign replaces existing values. operator[] supplies V{}; find returns null on absence; at reports a library error. Even a duplicate insertion can split full nodes before discovering the duplicate.

update calls fn(const V*), including null for an absent key, and stores its returned value. insert_or_modify invokes modify(V&) for an existing key or make() for a missing one; its missing path uses operator[] and thus additionally requires default-constructible V.

The non-const iterator returns kv_ref{const K&,V&} and advances in leaf order. Lower/upper bound are available on non-const trees; there is no const_iterator or const begin/end in this implementation. Const for_each supplies const V&. Map preserves keys and comparison/degree while inserting transformed values into a new tree. Cata gives leaves (keys,values,count) and internal nodes separator keys plus child accumulators; const cata currently passes mutable leaf pointers. Traverse visits ordered entries and honors stop.

Complexity

Height is O(log_T n). Lookup performs O(T) work per level for natural-order linear scans or O(log T) comparisons with the ladder search. Updates can shift O(T) entries or split/merge at each level, giving O(T*log_T n) structural work before arena growth. Arena expansion processes the allocated slab; complete leaf iteration is O(n + leaf_nodes).

Iterator invalidation

Arena expansion or expanding reserve invalidates every entry address. Insertion shifts entries and splits leaves; erasure shifts, borrows, or merges them, including on some unsuccessful searches. Iterator leaf/position coordinates are not stable element identities across these changes. The shared arena's byte-relocation restriction applies even when K/V have ordinary move constructors.

Notes

This is the key-ordered B+ tree. The separately named btree_map in the maps family hashes keys, buffers operations, and has different iteration and bounds contracts.

micron::b_default_less

Defined in header <micron/trees/b.hpp>.

The default B+ tree comparison policy, returning a < b through static lt.

Notes

Its __natural_order marker enables specialized in-node search selection for arithmetic and pointer keys. A custom policy must provide a consistent strict weak ordering; reproducing the marker asserts that the policy is the natural order expected by those specializations.

micron::art

Defined in header <micron/trees/art.hpp>.

An adaptive radix map over the bytes of a 64-bit hash, retaining original keys and values in stable pooled leaves.

Key requirements and representation

K is copy-constructible, and V copy- and move-constructible. Lookup hashes K and tests == after reaching a leaf. The trie consumes hash bytes least-significant first, at most eight levels; it does not inspect the key's character representation or implement lexicographic prefix order.

Internal nodes adapt from 4 to 16, 48, and 256 children. Small nodes scan byte-label arrays; the 48-way node has a 256-byte index into 48 child pointers; the 256-way node directly indexes children. Growth replaces internal nodes; erasure shrinks at 3, 12, and 37 remaining children. Equal full hashes form an unbounded leaf chain resolved by original-key equality. Separate block pools own each node shape.

Member functions and types

insert, insert_or_assign, and emplace all replace an existing mapped value and return true only for a new key. update passes a nullable const V* to fn and inserts its result. insert_or_modify calls make for absence or modify for presence. Find returns V* or null, contains/count test membership, and the non-const at reports absence.

max_size() returns current size; it is not a reserved capacity or implementation limit. node_bytes_live recursively sums current node shapes; block and pool observers describe retained pool storage. Copying is deleted; moving and swap transfer all five pools.

iterator aliases const_iterator, whose dereference is pair<const K&,const V&> and whose explicit ancestor stack holds traversal state. Its order follows physical child storage and collision chains; neither lexical K order nor sorted full-hash order is guaranteed. For_each has mutable and const value callbacks. Map preserves keys and rebuilds an art with transformed values.

Complexity

A lookup visits at most eight byte levels and a collision chain, O(8+c) with bounded node fanout; c can be n. Insertion and erasure also resize internal nodes or pools and scan collision chains. Enumeration and live-byte accounting are O(n + internal_nodes), including fixed child scans. Move construction and swap are O(1).

Iterator invalidation

Adding pool blocks preserves existing leaf addresses; internal growth/shrink does not move surviving values. An iterator stores internal-node pointers, so structural mutation can invalidate its traversal state even when its current value address survives. Erasure invalidates the removed leaf; clear/destruction release all nodes.

Use

Suitable for hash lookup where adaptive branching is desirable and original-key collision correctness is required. Sequence-prefix operations belong to radix_tree rather than this hash-byte trie.

micron::radix_tree

Defined in header <micron/trees/radix.hpp>.

A compressed radix trie owning nonempty sequence-key fragments and mapped values, with exact and longest-prefix lookup.

Key requirements and representation

Key and Value are constrained to be copy- and move-constructible. The implementation additionally default-constructs both, indexes and measures Key, takes substrings, appends fragments with +=, and assigns values. A string-like owning Key is the intended model; a non-owning Key carries its own backing-storage lifetime requirements.

Each pooled node owns an edge fragment, a default-constructed Value, child/sibling links, and a has_value flag. Sibling first elements are unique but unsorted. Insertion splits a partially matching fragment. Erasure clears the value and prunes empty terminal nodes; it does not merge remaining unary fragments. Empty keys are rejected by insert_or_assign, and find never returns a value for them.

Member functions

insert preserves existing values, while insert_or_assign replaces; both report whether a new key was added. find is nullable; at reports absence. longest_prefix_match(query) returns the value attached to the longest complete stored key prefix, not a pointer to the prefix text. operator[] inserts Value{} for nonempty absence; an empty argument cannot be inserted and its current body then dereferences null.

There are no begin/end iterators or ordered bounds. For_each reconstructs complete keys into a temporary accumulator and supplies (const Key&, Value&); key references must not escape the callback. Traverse accepts the same entry shape and supports stopping, but does not act on skip_children. Its const overload currently permits a mutable Value& callback. radix<Key,Value> aliases this class. Copying is deleted; move and swap transfer the pool.

Complexity

Let L be the query length and S the number of sibling edges inspected along its path. Lookup is O(L+S) element comparisons; S depends on fanout and can make lookup linear in the node population. Updates additionally copy substrings and allocate/split nodes. Enumeration reconstructs keys and can copy substantially more than n units of key data. Erasure records at most 64 path nodes for pruning; deeper searches still find values but may leave unused nodes unreclaimed until clear.

Reference invalidation and use

Pool growth does not relocate nodes, but splitting a fragment moves an existing Value into a new tail node, changing its logical address. Erasure resets a value and may free its node. No stable-value-address contract should be inferred from pooling. Use for actual sequence prefixes, with nonempty keys and callback-bounded reconstructed key lifetimes.

micron::quadtree

Defined in header <micron/trees/quadtree.hpp>.

A two-dimensional point-region bucket tree over a fixed universe box; an alias of the shared subdivision implementation.

Template parameters and layout

F defaults to float, Capacity to 8, and MaxDepth to 18. point_type is math::vec<F,2>; box_type is math::geometry::aligned_box<F,2>. Value is copy-constructible and is copied on public insertion. Each internal node has four child indices. A leaf holds up to Capacity point/value pairs and a chain link.

A full leaf subdivides at the box center until MaxDepth. At the depth limit, overflow leaves retain additional entries, including arbitrarily many coincident points. The default universe is [-1048576,1048576] on each axis; a constructor can supply another box. Insertions outside it return false rather than expanding the universe. The tree owns its values and uses the contiguous node arena.

Member functions and spatial semantics

Insert permits duplicate point/value entries. erase(point,value) removes one exact match, using exact point and value equality. It reclaims empty overflow nodes and empty internal subtrees; partially filled neighboring buckets are not merged. A point is a spatial key, not a unique map key.

query(box,fn) reports points contained by the query; query_radius(center,r,fn) uses squared Euclidean distance <= r*r. A negative radius is therefore treated like its magnitude. Const range/radius overloads provide const values. Nearest(p,k,fn) reports up to k entries in increasing squared distance and passes (const point_type&,const Value&,distance_squared); ties need not include every equidistant candidate. There is no const nearest overload.

For_each visits point/value pairs; map preserves points and universe while rebuilding transformed values. Cata folds values within each leaf/overflow chain, then all four child accumulators, including empty ones. Traverse exposes entries and honors stop. There are no iterators or exact-point find member. Reserve_nodes, nodes_used, nodes_high_water, nodes_reserved, node_bytes, and bounds expose storage/domain information.

Complexity

A normal insertion descends at most MaxDepth levels, with bounded bucket redistribution at splits. At maximum depth, locating overflow space or erasing can scan all entries in that region, worst O(n). Box/radius queries can inspect every entry, O(n + nodes). Nearest uses O(k) temporary result storage and a sorted candidate list; worst-case work includes O(n*k), plus child ordering and traversal. Callback and coordinate arithmetic costs are additional.

Reference invalidation and notes

Arena growth, subdivision, overflow changes, and bucket shifts can invalidate addresses or move logical entries. Reserve_nodes prevents slab growth only while the reserved count suffices. Nearest and non-const query callbacks are reached through noexcept functions; nearest allocates its temporary fvector despite being noexcept. Callbacks must not structurally mutate the tree. Capacity is stored as u16 internally and must fit that representation.

micron::octree

Defined in header <micron/trees/octree.hpp>.

A three-dimensional point-region bucket tree, sharing the quadtree API and storage implementation with eight children per internal node.

Template parameters and domain

F defaults to float, Capacity to 8, and MaxDepth to 12. Point and box types have dimension three. The default universe is [-1048576,1048576] on every axis; out-of-universe insertion returns false. MaxDepth stops subdivision, after which coincident or closely grouped points accumulate in overflow leaves.

Operations and ownership

The operations are the same as quadtree: copied-value insertion allowing duplicates; exact one-occurrence point/value erasure; box and radius queries; nearest with squared distances; enumeration, transformation, structural folding, stoppable traversal, and node reservation/accounting. No unique-key lookup or iterator is supplied. The shared arena owns values and byte-relocates them on expansion; copying is deleted and movement transfers storage.

Complexity and invalidation

The quadtree bounds apply with eight instead of four children. Descent is bounded by MaxDepth, while overflow chains and unpruned queries can be linear in population. Nearest maintains a sorted list of at most k results and can take O(n*k) work. Slab growth, subdivision, and erasure invalidate affected value addresses; shared callback and noexcept restrictions also apply.

micron::rtree

Defined in header <micron/trees/rtree.hpp>.

A growing spatial index of axis-aligned boxes, using R*-style subtree selection, split criteria, and limited forced leaf reinsertion.

Template parameters and representation

Value is copy-constructible; F defaults to float; Dim defaults to two and must be between two and sixteen. MaxOverride=0 chooses maximum fanout M=16; a nonzero override must be at least four and fit the u16 counts. A point is inserted as a degenerate min=max box.

Leaf nodes own up to M box/value entries, with one additional transient overflow slot. Internal nodes own bounding boxes and child indices. Minimum fill is max(2,floor(2*M/5)). Subtree choice minimizes overlap enlargement at leaf-parent level and area enlargement above it. Splits select an axis by summed margins and a distribution by overlap then area. At most one non-root leaf forced-reinsertion event occurs per top-level insertion, removing max(1,floor(3*M/10)) farthest-center entries; internal overflows split directly.

The contiguous node arena and a pending-entry fvector own storage. No fixed universe is required. Duplicate boxes and values are allowed; boxes and coordinates must have meaningful geometry, with valid corners and arithmetic sufficient for areas and squared distances. Copying is deleted; movement transfers the arena.

Member functions

Insert copies a value and returns void. Erase removes one entry with exactly matching box corners and value. Underfilled subtrees are collected, destroyed, and their surviving data entries reinserted. Root compression reduces a single-child root. Clear destroys live entries and retains arena capacity.

Query(q,fn) visits every leaf box intersecting q and supplies (const box_type&,Value&); there is no const query overload. Nearest(point,k,fn) ranks by squared minimum distance from the point to each box, zero for a point inside it, and supplies const values and squared distances in ascending order. It has no const overload. For_each does provide const and mutable value callbacks. Map preserves boxes while rebuilding transformed values; cata combines leaf entries then child accumulators; traverse visits entries and honors stop.

The public aliases are box_type, point_type, mapped_type, spatial_key_type=box_type, and size_type, plus the tree/mutable/heap tags. There are no begin/end iterators, unique-key find operation, or ordering bounds. Node observers distinguish live count, high-water count, reserved slots, and slot bytes.

Complexity

For fixed fanout/dimension, insertion descends a balanced hierarchy and may split a path; split selection scans candidate partitions and uses quadratic in-node sorting rather than a constant-cost primitive. Spatial overlap can make range search or erase visit O(n + nodes). Erase can collect and reinsert a large subtree, so it does not have a simple logarithmic worst-case bound. Nearest uses O(k) temporary result storage and sorted candidate maintenance, with O(n*k) candidate work in the worst case, plus node-child ordering. Mapping performs repeated spatial insertions.

Reference invalidation and notes

Slab growth invalidates every returned payload address. Leaf split, reinsertion, and erase can move existing values even without slab growth. Query callbacks cannot structurally modify the tree. Query, enumeration, and nearest are noexcept paths; nearest still allocates a temporary result vector. These contracts do not provide concurrent mutation safety or strong exception rollback for arbitrary throwing value operations.

micron::walk_ctl

Defined in header <micron/trees/__tree_walk.hpp>.

Traversal control enumeration with continue_, skip_children, and stop values.

Effects

Continue_ continues traversal; stop terminates the traversal and propagates to its caller. Skip_children suppresses descendants in rb_tree preorder and level-order traversal. Element-only traversal in b_tree, radix_tree, quadtree, octree, and rtree checks stop but does not prune a subtree for skip_children. A void callback is treated as continue_; any other non-walk_ctl result is interpreted as a boolean continuation test.

micron::traversal_order

Defined in header <micron/trees/__tree_walk.hpp>.

The rb_tree traversal-order enumeration: inorder, preorder, postorder, and level.

Order and storage

Inorder visits left subtree, node, right subtree; preorder visits node before children; postorder visits after children. Level uses a growing vector queue for breadth-first order. Recursive traversals use the call stack. The default rb_tree traversal is inorder; the other tree containers do not accept this order parameter.
