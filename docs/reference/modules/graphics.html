Graphics

From micron reference
micron reference › Graphics

Linux window-system integration for X11 and Wayland, shared by the OpenGL and Vulkan wrappers. Displays and windows own native resources; the rendering backends add explicit context, device, memory and submission facilities.

Runtime dependencies and availability

The graphics headers are Linux-facing interfaces that load host client/driver libraries dynamically. X11 needs libX11.so.6, Wayland needs libwayland-client.so.0 and an xdg-shell compositor; GL additionally needs the selected libGL.so.1, libEGL.so.1 and Wayland EGL bridge; Vulkan needs libvulkan.so.1 plus an appropriate driver. Header availability alone does not establish a usable server, context, device or enabled feature. The root gfx.hpp includes GL and Vulkan; gl.hpp supplies the GL umbrella.

Backend choice uses cached environment evidence and can fall back after an opening failure on the exception-enabled path. It does not launch a server or create a virtual display. Native Wayland interface metadata, generated API declarations and extension names describe supported calling formats, not successful negotiation with the current environment.

Dependency order and thread scope

A display encloses its native windows. GL contexts borrow GL windows; EGL native windows borrow Wayland surfaces; Vulkan surfaces borrow native windows/displays, and Vulkan devices/resources/pools form a separate native parent hierarchy. Destroy dependent objects and complete their outstanding work before releasing the parents they borrow. Copyable native handles and view wrappers do not extend a parent's lifetime.

Display/window wrappers are neither copyable nor movable. Their event state, static environment/diagnostic storage and rendering dispatch tables do not form a synchronized application framework. Event pumping and context/device table loading require explicit coordination. Generic reference counting can manage one native handle's lifetime but does not serialize its API access or wait for GPU execution.

Cost model

Inline records and cached-handle observers have constant local cost. Processing k available events performs O(k) dispatch work plus callback/native-library cost. Library loading, connection setup, protocol round trips, shader/pipeline compilation, resource allocation and GPU completion have native implementation costs and can block where the invoked operation permits it. No relative performance claim or frame-latency bound is established by these wrappers.

micron::gfx::platform::backend_tag_t

Defined in header <micron/gfx/platform/platform.hpp>.

Identifies an unavailable, X11 or Wayland display backend.

Values and environment selection

The u8 values are none=0, x11=1 and wayland=2. Backend selection first considers XDG_SESSION_TYPE with a nonempty matching WAYLAND_DISPLAY or DISPLAY, then prefers a nonempty WAYLAND_DISPLAY, then a nonempty DISPLAY. Otherwise it returns none.

env reads /proc/self/environ into a cached mapping of at most 64 KiB on first use. Subsequent selections use that process snapshot. The mapping persists for the process lifetime; concurrent first use and later environment changes are not synchronized or refreshed. Selection identifies a candidate backend and does not establish that its server or host library is usable.

micron::gfx::platform::display

Defined in header <micron/gfx/platform/display.hpp>.

Owns one selected native display connection opened through a process-static client API table.

Construction and selection

The display stores X11 and Wayland backend objects inline and activates one. The x11_lib/wayland_lib accessors supply process-static client-library tables borrowed by those backends. An X11 or Wayland request tries that backend and then the alternative when the exception-enabled fallback path can recover from the first failure. A none request does not attempt either backend. Default construction obtains the request from environment selection.

Opening performs host-library loading and server communication and can throw network_error. Diagnostic buffers used while combining failures are shared static storage. The no-exception path directly opens the requested backend and does not provide the same catch-and-retry fallback.

Ownership and cost

The object is neither copyable nor movable. Native windows, GL contexts and Vulkan surfaces borrow its native connection and must be destroyed before it. Closing the display does not traverse or invalidate C++ child wrappers explicitly. Accessors return borrowed backend records or native handles; they do not transfer ownership.

Backend access is constant work. Opening and dispatching have host-library and display-server costs; Wayland discovery includes blocking round trips. No general latency bound or automatic display-thread serialization is supplied.

micron::gfx::platform::window

Defined in header <micron/gfx/platform/window.hpp>.

Owns an X11 window or a Wayland xdg-toplevel while borrowing a display and optional integration hooks.

Parameters and callbacks

Construction takes a live display, initial dimensions, title and optional window_hooks. x11_visual_choice supplies a borrowed XVisualInfo pointer plus an opaque extra value for a visual-selection hook. window_hooks contains caller-provided native Wayland create/resize/destroy functions and user data; it does not own those functions or that data. Without a visual hook the X11 path tries 24-bit and then 32-bit TrueColor visuals.

The set_resize_func, set_close_func, set_expose_func, set_focus_func, set_move_func and set_visibility_func templates adapt compile-time callable values, with or without a window reference. Their bridges are noexcept. A throwing callback terminates through that boundary. Native Wayland resize hooks run before the internal resize callback and then the user resize callback. There is one internal resize callback slot, used by GL context integration.

Dimensions and event processing

X11 resize requests take effect asynchronously through server events. Wayland resize changes the local logical dimensions and invokes its native resize hook; it does not impose a size on the compositor. Wayland render_scale multiplies logical dimensions to produce rounded render dimensions and accepts values from 1 through 8. The wrapper does not translate keyboard, pointer or touch input into a general input-event interface.

poll_events drains the native backend's available work. The X11 implementation drains the shared display event queue and can consume events for other windows. Wayland dispatches pending protocol work through the display connection. Event callbacks receive borrowed references and must not retain references beyond the corresponding object lifetime.

Lifetime and invalidation

The window is neither copyable nor movable. Its display must remain alive at the same address. Native surface/window handles cease to be usable after destruction; GL contexts, EGL native windows and Vulkan surfaces using them require an appropriate earlier destruction order. The wrapper contains no GPU-completion wait or shared ownership of its dependants.

micron::gfx::platform::x11_lib_t

Defined in header <micron/gfx/platform/x11.hpp>.

Owns a libX11.so.6 mapping and a table of Xlib function pointers.

Interface

The table covers connection opening/closing, screen and root-window queries, visual matching, colormap/window creation, window title and WM protocol setup, event polling, resize, map/unmap, flush/sync and XFree. PFN_X aliases describe these borrowed callable addresses with the local X11 ABI types. The constructor verifies a required subset of symbols; a populated library object does not establish that every optional table member is callable.

The client library must outlive every native display that borrows it. XInitThreads is attempted when available before opening a display. This does not add synchronization around the higher-level micron display/window state or its shared diagnostic buffers.

micron::gfx::platform::x11_display_t

Defined in header <micron/gfx/platform/x11.hpp>.

Owns an XDisplay connection and caches its screen, root window and connection descriptor.

Operations

open borrows an x11_lib_t and calls XOpenDisplay with the default display name. close calls XCloseDisplay and clears the cached connection. The class is neither copyable nor movable, and its native connection is borrowed by windows and GLX objects. Calling open again without first closing does not release the previous connection.

Cached observers are constant work. Connecting, closing, flushing and synchronizing execute Xlib operations and may communicate with the server. No child-window registry or connection-level ownership graph is maintained.

micron::gfx::platform::x11_window_t

Defined in header <micron/gfx/platform/x11.hpp>.

Owns an X11 window identifier and borrows its display and selected visual.

Creation and events

Creation allocates a colormap, creates the native window, installs WM_DELETE_WINDOW handling, maps it and flushes requests. Dimensions are converted to unsigned native fields without a negative-size check. Destruction destroys the window and flushes; the stored colormap is not freed by this implementation.

poll_events invokes the optional raw-event observer before interpreting each event, then handles configure, expose, focus, map/unmap and close requests. It drains the whole display queue. Most translated events test the window identifier; ClientMessage close handling tests the WM protocol and delete atom without an additional window-identifier test. Applications sharing a display between several independently polled windows must account for this consumption and routing behavior.

Lifetime

The class is neither copyable nor movable. Its display and client API must outlive it. The selected visual is borrowed; passing an allocated visual does not transfer responsibility for freeing that allocation. Accessors and callback installation perform constant work; processing k queued events performs O(k) wrapper work plus callback and Xlib costs.

micron::gfx::platform::wayland_lib_t

Defined in header <micron/gfx/platform/wayland.hpp>.

Owns libwayland-client.so.0 and its connection, dispatch and proxy-marshalling entry points.

Loading and embedding

The ordinary constructor loads the host client library, including wl_proxy_marshal_flags. That required symbol limits the usable client ABI to versions supplying it. The nested supplied_api tag constructs an unloaded table for an embedding caller to populate explicitly. Such a table must contain every entry subsequently used and remain valid while displays and proxies borrow it.

The wrapper marshals requests using its local protocol metadata and does not link generated client stubs. Resolving a function pointer does not negotiate a protocol object's version or create that object.

micron::gfx::platform::wayland_display_t

Defined in header <micron/gfx/platform/wayland.hpp>.

Owns a Wayland display connection, registry, compositor proxy and xdg_wm_base proxy.

Discovery and dispatch

open connects to the default display and performs two blocking round trips to discover globals. It binds wl_compositor up to version 6 and xdg_wm_base up to version 1, installs the ping/pong listener, and throws when required globals are absent. Registry global-removal notifications are ignored; removal does not clear the cached proxies automatically.

dispatch_pending drains queued work while preparing a read, flushes outgoing requests, polls the descriptor with zero timeout, reads if ready or cancels the prepared read, and dispatches pending callbacks. Several return codes are ignored and the function returns no error status. roundtrip is a separate blocking operation. These functions dispatch connection-wide callbacks and require caller coordination across windows and threads.

Ownership

The noncopyable, nonmovable object borrows its API table. close destroys its registry/compositor/xdg base proxies and disconnects. All child surfaces, shell objects and EGL native windows must be released first. No automatic reconnect or global rebinding is provided.

micron::gfx::platform::wayland_window_t

Defined in header <micron/gfx/platform/wayland.hpp>.

Owns a wl_surface, xdg_surface and xdg_toplevel and caches logical and render dimensions.

Configuration and scaling

Creation installs protocol listeners, sets the title, commits the surface and performs one round trip. It does not repeatedly wait until the configured flag becomes true. xdg_surface configure events are acknowledged and emit expose notification. Positive dimensions in xdg_toplevel configure update logical size and invoke resize; the protocol state array is ignored.

Render dimensions are logical dimensions times render_scale, rounded by adding 0.5 before conversion. Explicit scales outside [1,8], including nonfinite values failing the comparisons, are rejected. Preferred buffer-scale events update the surface buffer scale and local scaling. Output enter/leave notifications do not maintain an output-scale model.

Events and lifetime

Close events set a local request flag and invoke the close callback; take_close_request reads and clears that flag. Programmatic close requests may invoke the callback repeatedly. Focus, visibility and move callbacks can be stored but are not driven by this Wayland implementation. The class is neither copyable nor movable and borrows a display that must outlive all of its proxies.

Dimension and flag access is constant work. Creation and the explicit round trip can block. Destruction releases protocol objects without waiting for unrelated GPU work that may use the surface.

Lifetime

Metadata arrays and function pointers are borrowed. Protocol event arguments are valid for the callback's applicable native lifetime and are not retained by the ABI records. wl_argument does not tag or own its active payload. Correct opcode, signature, version and proxy identity remain caller requirements for direct marshalling.

micron::gfx::platform::wl_registry_listener_t

Defined in header <micron/gfx/platform/wayland_xdg_shell.hpp>.

Stores callback pointers for global discovery and the implemented xdg-shell events.

Listener records

wl_registry_listener_t supplies global/global_remove callbacks; xdg_wm_base_listener_t receives ping; xdg_surface_listener_t receives configure serials; xdg_toplevel_listener_t receives configure, close, configure_bounds and wm_capabilities. Callback user data and any protocol array arguments are borrowed. Installed listener and user-data storage must remain usable while callbacks can arrive.

The header supplies static wire metadata and xdg_shell_ops opcodes. The metadata's advertised interface versions do not make all requests available on a proxy bound at a lower version. The high-level Wayland display binds its xdg base at version 1 and does not expose popup/positioner ownership wrappers.
