WebAssembly target

From micron reference
micron reference › System interfaces

The native wasm32 backend uses linear memory, compiler WebAssembly instructions, and a versioned JavaScript host ABI. It supplies allocation, diagnostics, clocks, worker threads, exceptions, and software binary128 arithmetic without a WASI runtime.

Target and feature selection

This backend requires Clang's wasm32-unknown-unknown target. features.hpp rejects WASI, Emscripten, native kernel/metal and ELF attachment configurations, and fast-math compilation. Its ABI version is 1. The host imports provide randomness, diagnostic writes, clocks, panic, yielding, worker creation, and worker exit; they do not expose Linux descriptors or arbitrary system calls.

SIMD128 is selected when the compiler enables it and MICRON_NO_SIMD is absent. Otherwise the WebAssembly scalar implementation is selected; wider packets use composite representations. MICRON_WASM_THREADS additionally requires atomics, bulk memory, TLS, and shared linear memory. Compiler WebAssembly exception support selects the exception backend; defining __micron_eh without the corresponding compiler feature is rejected.

Memory ownership and growth

linear_reserve takes a positive byte count and a power-of-two alignment, advances a shared allocation cursor starting at __heap_base, and grows linear memory in 65536-byte pages as necessary. Arithmetic and address-space checks reject reservations whose one-past address would exceed the supported wasm32 range. A failed reservation returns null. Successful growth increments the memory epoch.

A linear reservation is permanent. wasmalloc can recycle allocations within its reserved regions, but releasing a C++ allocation does not shrink WebAssembly.Memory or return an earlier reservation to the cursor. Worker stacks and TLS areas are also retained for reuse. This distinction matters for long-lived instances and applications that repeatedly create large transient objects.

The JavaScript bytes/view helpers return bounded Uint8Array views of the current memory buffer. Obtain a new view after growth: ordinary-memory growth replaces/detaches the old buffer, and an existing shared-memory view retains its earlier extent. Bounds checks belong to the view helper; a raw C++ pointer carries no JavaScript buffer-lifetime information.

Host creation and execution

host.mjs exports createMicron for a compiled Module, bytes, Response, or a URL accepted by the compiler loader. The default memory has 256 initial and 8192 maximum pages. The selected thread profile must agree with whether the memory is shared; a browser threaded instance also requires cross-origin isolation and worker support.

A local instance exposes direct export calls. The threaded host routes calls through a primary worker and returns promises, while additional workers execute library threads. poolSize defaults to 4 and is checked against 1..1023. The host pool and the compiled MICRON_WASM_MAX_THREADS limit are separate bounds; increasing only one does not increase the other.

runMain uses the runtime entry protocol rather than merely invoking an arbitrary exported function. initialize prepares TLS and runs the constructor array once. In the threaded profile initialization runs on a worker that may block. Runtime state prevents a second simultaneous startup or execution after shutdown. An exception escaping an enabled C++ entry boundary is converted to a failure result; arbitrary exported calls still have their own ABI contracts.

Diagnostics, randomness, and host failures

write_diag forwards bytes and a stream identifier to the host. The JavaScript host maintains streaming UTF-8 decoders per stream and calls onWrite(text, stream); it copies shared-memory bytes before decoding them. Shutdown flushes remaining decoder state. Formatting and traversal occur on the C++ side, so a collection write includes those costs as well as the host callback.

Random bytes come from the host cryptographic provider in chunks no larger than 65536 bytes. A host generation failure is reported as -5. Panic reports the code and traps; it does not return a recoverable C++ status. Host callback and worker failures can poison an instance and stop its workers.

Normal shutdown refuses outstanding library threads with a recoverable MicronStateError carrying -16. Join/release them and retry shutdown. Successful shutdown runs the registered exit sequence and enters the stopped state. terminate forcibly stops workers and provides no C++ destructor or exit-handler completion guarantee. node.mjs is a command-line host with a default 30-second timeout; its test mode additionally checks the requested exported test counters.

Waiting, clocks, and sleeping

wait32 requires a four-byte-aligned address and timeout -1 or a nonnegative nanosecond count. A value mismatch returns -11. Without worker-side blocking support it returns -95; an expired atomic wait returns -110. wake32 notifies waiters in the threaded profile and returns zero when there are no threaded wait operations. These calls are synchronization primitives rather than general browser-main-thread blocking facilities.

The futex adapter accepts wait/wake and their bitset variants only within its implemented restrictions: bitsets must cover all bits, and operations requiring a second address are unavailable. Absolute timeout handling uses the selected clock domain. Code that assumes the complete Linux futex operation set must select a different interface.

Clock wrappers implement realtime and monotonic clocks and their coarse variants. Other clock identifiers return -95. The supplied JavaScript host uses Date/performance time and reports millisecond resolution; nanosecond integer units do not imply nanosecond measurement precision. Positive sleeps require a worker that can wait. The duration wrappers reject out-of-range conversions and treat nonpositive durations as no-ops.

Worker lifetime and cancellation

The compiled slot table defaults to MICRON_WASM_MAX_THREADS == 16, with slot zero reserved; at most 15 additional library threads can occupy slots. Spawn scans the table, reserves a stack and TLS area on first use, and submits work to the host. The default stack reservation is 1 MiB. Released slots reuse their permanent memory reservations, and generation counters distinguish successive occupants.

A thread is joinable until its completion has been collected, including after its callable has returned. Host publication of completion follows return from WebAssembly and output handling. Joining oneself returns -35; joining also requires a context that can wait. Slot search is O(T) in the configured table size; spawn and join additionally depend on memory growth, host scheduling, and callable execution, with no bounded latency guarantee.

Cancellation sets a flag and wakes a parked worker. The implementation observes it at cooperative checkpoints. Worker exit uses the host/broker protocol, and the runtime runs its registered thread/TLS and exception cleanup. This protocol does not unwind arbitrary automatic objects on an abandoned C++ call stack. A compute loop that never reaches a checkpoint is not made promptly cancellable by setting the flag.

Exceptions and RTTI

The WebAssembly exception backend uses the compiler's C++ exception tag with a payload pointing to its exception-control header. It does not walk native .eh_frame or ARM exidx tables. Exception allocations use wasmalloc and then a fixed fallback of 16 slots of 2048 bytes when the full request fits; exhaustion terminates. Per-thread bookkeeping tracks active allocations and registered cleanup during thread exit.

The backend supplies C++ catch matching, rethrow bookkeeping, termination hooks, and compiler RTTI entry points. Its class traversal applies recorded public/base offsets and checks ambiguous targets for dynamic_cast. These are compiler ABI records, not serializable application type descriptions. Negative exception-specification filters terminate; the runtime does not supply old dynamic exception-specification recovery.

Numeric implementation

The WebAssembly numeric backend preserves binary128 long-double representation and arithmetic instead of converting every operation through double. fp128.hpp supplies weak compiler runtime entry points for arithmetic, comparisons, integer conversions, and widening/narrowing conversions. Arithmetic packing rounds to nearest with ties to even and supports gradual underflow. Restoring division generates the significand and a guard bit, retaining the remainder as sticky information.

real.hpp implements format-aware classification, rounding, scaling, square root, and fused multiply-add. The FMA path forms the full significand product and aligns it with the addend in a fixed eight-word integer accumulator, retaining discarded low bits as sticky information before the final packing step. The integer conversion helpers truncate toward zero and saturate on overflow; signed conversions select a sign-dependent extreme for infinities/NaNs, while negative unsigned inputs saturate to zero.

symbols.hpp supplies the freestanding C math entry points. float/double transcendental functions forward to the corresponding scalar micron kernels, binary128 functions use the extended backend, and float/double square roots use compiler instructions. rint/nearbyint use the backend's nearest-even operation; these definitions do not implement a dynamically selected floating-point rounding mode.

Numeric domains and policy

policy::extended_tag is the binary128 transcendental policy and the default for 16-byte floating types on this target. It preserves the extended format/range but makes no global faithful- or correct-rounding promise. Selecting a different strict policy for binary128 triggers a compile-time rejection. Smaller floating types retain their scalar policy selection.

Special-function behavior is explicit in the kernels: tgamma returns signed infinities at signed zero and NaN at negative integers; lgamma returns infinity at nonpositive integral poles. The error-function complement uses a small-argument series or a continued fraction capped at 2000 steps. Bessel evaluation uses 256 series terms below its transition and a 40-term asymptotic expansion above it; y0/y1 reject negative arguments and return negative infinity at zero.

All fixed-format limb arrays and iteration bounds are compile-time bounded, but the cost of a transcendental call includes software binary128 operations, range reduction, and the selected branch. Storage-based comparisons explain likely costs; they are not measured performance claims. Strict floating-point compilation is part of the implementation contract.

micron::wasm::mutex

Defined in header <micron/bits/wasm/runtime.hpp>.

Small runtime mutex using an atomic word and worker waiting in the threaded profile.

Locking contract

lock first attempts an uncontended compare/exchange, then waits on the lock word when worker blocking is available. unlock releases the word and wakes a waiter. try_lock performs a single attempt. A contended operation may block indefinitely, and no fairness ordering is promised.

The nonthreaded form diagnoses recursive locking by panicking rather than providing recursive ownership. The type protects runtime metadata; it does not make arbitrary operations safe on the browser main thread. Keep the object alive until all users have stopped, and do not copy a live lock's word to create a second owner.

micron::wasm::thread_handle

Defined in header <micron/bits/wasm/threads.hpp>.

Pair of slot and generation numbers identifying a particular worker-slot occupant.

Handle and slot protocol

A zero slot denotes an empty handle. Validation checks both the slot and its generation, so a retained handle does not silently identify the next thread to reuse that slot. Copying the pair is constant-time and does not duplicate a join right or extend callable/argument lifetime.

thread_slot stores state, generation, cancellation/park words, permanent stack/TLS addresses, the thread_entry function pointer, its borrowed void* argument, and the integer result. States distinguish free, starting, running, complete, and failed. thread_entry is int (*)(void*). These records describe the runtime protocol; raw record copies bypass its atomic publication and lifetime rules.

micron::wasm::thread_packet

Defined in header <micron/bits/wasm/thread_api.hpp>.

Base result storage for a heap-allocated invocation submitted by the C++ worker-thread wrapper.

Callable and argument ownership

invocation_packet<F,A...> stores the callable and tuple of arguments by value after decay in the wrapper. run invokes that tuple and, for a trivially copyable return value no larger than eight bytes, copies its representation into the base value word. Void and unsupported larger results do not acquire a general result object. destroy deletes the correctly typed derived packet.

The packet belongs to its micron::thread controller until join releases it. References or pointers stored inside decayed arguments still borrow their referents. Storing an invocation packet does not deep-copy pointed-to application data or synchronize access to it.

micron::thread

Defined in header <micron/bits/wasm/thread_api.hpp>.

Move-only WebAssembly thread controller that owns an invocation packet and joins its worker on destruction.

Operations and lifetime

Construction allocates the decayed callable/arguments and spawns a worker; unavailable pool capacity or spawn failure raises thread_error after releasing the packet. Copying is disabled. Moving transfers the handle, packet, cached result, and status; move assignment first joins its current thread. Destruction joins and panics if a live handle remains after a join failure.

join waits, caches the result/status, destroys the invocation packet, and releases the slot. dismiss also joins; it is not a detached-thread operation. result<R> accepts only trivially copyable R no larger than a pointer, which on wasm32 is four bytes, despite the packet's eight-byte internal result word. Reading the wrong result type is not checked against the callable's actual type.

Stack_Size is checked against MICRON_WASM_STACK_SIZE; it does not independently reserve a smaller per-object stack. auto_thread<N> aliases this controller. terminate/kill are deleted. Select this type for scoped worker ownership when the calling worker may wait; the native Linux controller has a different backend and its own contracts.

micron::timespec_t

Defined in header <micron/bits/wasm/time.hpp>.

WebAssembly time record containing signed seconds and nanoseconds.

Time record family

timeval_t stores seconds and microseconds; itimerspec_t and itimerval_t each pair interval and current-value records in their respective units. The records are trivial values with no timer ownership, scheduling, or automatic normalization. Supply normalized fractions and representable durations to the corresponding wrappers.

Clock support is limited to the host-backed realtime/monotonic families. A matching Linux record name does not make Linux timer descriptors or every clock identifier available on this target. Copying these fixed-size records is constant-time.

micron::ar::record

Defined in header <micron/bits/wasm/ar.hpp>.

Current-frame diagnostic record with sp/fp pointers and a null program counter on WebAssembly.

Frame inspection limits

here returns the compiler's current frame address for sp and fp and leaves pc null. has_native_frames is false, caller always returns false, and frame_address supports only level zero. Native return-address/program-counter queries, stack-pointer mutation, arbitrary stack calls, and TLS-base mutation are deleted.

thread_pointer returns the compiler TLS base only in the threaded profile and null otherwise. The record neither owns its pointers nor provides a walkable native call chain. Use it only while the referenced current-frame information remains valid.

std::exception

Defined in header <micron/bits/wasm/eh_std.hpp>.

Minimal compiler exception base with a virtual destructor and fixed what() diagnostic.

Exception class family

bad_cast and bad_typeid derive from exception and return their corresponding fixed diagnostic strings. These small ABI classes do not allocate or store an application message. The returned text has static storage; retaining that text does not retain a caught exception object.

std::type_info

Defined in header <micron/bits/wasm/eh_typeinfo.hpp>.

Compiler RTTI base for the WebAssembly exception and dynamic-cast backend.

Compiler metadata

The base exposes name/equality/order and virtual catch/upcast hooks. Derived ABI records distinguish fundamental, array, function, enum, class, single/multiple-base, pointer, and pointer-to-member types. They borrow compiler-emitted names and base metadata rather than owning a general reflection tree.

Class traversal follows recorded base offsets, public accessibility, and ambiguity; pointer matching handles its implemented qualification/conversion rules. Dynamic-cast support reads source vtable metadata and traverses candidate subobjects. Cost follows the represented hierarchy and metadata visits; no constant-time cast bound is promised. Applications ordinarily obtain these records through language RTTI rather than constructing them.

micron::math::policy::extended_tag

Defined in header <micron/bits/wasm/math/policy.hpp>.

Empty policy selecting the binary128 transcendental backend without a global faithful-rounding guarantee.

Policy selection

extended is the inline constant policy value. default_tag<F> selects extended_tag for a 16-byte F and faithful_tag otherwise. The validation helper rejects a different policy for binary128 transcendental evaluation. This restriction concerns the implementation's error guarantee, not the representation or availability of basic binary128 arithmetic.

micron::wasm::math::format

Defined in header <micron/bits/wasm/math/real.hpp>.

Compile-time binary floating-format description used by the software arithmetic helpers.

Representation and helper values

For 4-byte and 8-byte floating types the description selects u32/u64 storage, 24/53 significand precision, and 8/11 exponent bits. The extended case uses unsigned __int128, precision 113, and 15 exponent bits. Bias, fraction, sign, infinity, and quiet-NaN masks follow those layouts. The helpers assume an appropriate binary representation; this is not a general arbitrary-size user format.

wide aliases unsigned __int128. parts stores a decomposed unsigned significand and exponent; sign is handled separately. accumulator is an aggregate of eight u64 limbs, operated on by the free term/compare/add/subtract helpers and the FMA normalization loop. These scratch values own inline storage and perform no allocation; their constant-size representation does not make all operations a single machine instruction.

micron::wasm::math::ieee128_traits

Defined in header <micron/bits/wasm/math/ieee.hpp>.

Binary128 bit-layout constants for the generic IEEE manipulation layer.

Constants

uint_type is the backend's unsigned 128-bit word. The constants describe 128 total bits, 112 stored fraction bits, 15 exponent bits, bias 16383, and the corresponding masks, implicit leading bit, and quiet-NaN bit. They describe representation only and carry no arithmetic state, allocation, runtime probing, or transcendental accuracy promise.

micron::wasm::math::real

Defined in header <micron/bits/wasm/math/extended.hpp>.

Alias for the target's long double used by the extended elementary and special-function kernels.

Precision and workspace

The extended kernels use binary128 values and compensated high/low intermediates. The 2/pi table supports full-range argument reduction without first narrowing the input to double. All scratch arrays are local or compile-time constants, and these kernels allocate no dynamic container storage. Their full-format arithmetic and finite iteration caps do not establish a uniform faithful/correct-rounding bound.
