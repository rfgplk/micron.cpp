Functions, tuples, and sum types

From micron reference
micron reference › Language support

Owning callable wrappers, product types, in-place sum types, matching, callable combinators, and process-control helpers. Product and sum storage is embedded; callable wrappers can allocate for large targets.

Ownership and cost model

Embedded storage does not imply that element constructors allocate nothing. Pair/tuple own value elements, while reference elements and raw pointers borrow external objects. Sum wrappers own only their active object. Callable closures own their captures according to the captured types; capturing a pointer does not retain its pointee.

Complexities below separate wrapper dispatch/element counts from target operations. Copy, move, destruction, callback execution, and allocation costs depend on their concrete types. Replacement/reset invalidates references into the replaced stored object. None of these wrappers contains synchronization for concurrent mutation or lazy evaluation.

Matching

match<Fs...> dispatches by exact handler argument type; lazy_match<Fs...> allows invocable conversions. Both execute immediately and return void. Every matching handler is invoked, rather than only a first matching handler. Unmatched values are ignored; there is no exhaustiveness check.

Pair and tuple overloads dispatch each element, index_sequence overloads dispatch integral_constant values, and any/option overloads dispatch only the active alternative. Empty sums invoke nothing. Handler constants are template values, so they must be usable as non-type template arguments. Strict matching requires the argument-type introspection supported by arg_type_t; generic/overloaded callables are not universally accepted.

The implementation removes cv/ref qualifications before checking mutable-reference invocability, so a const input combined with a mutable-reference handler can fail when the body attempts to cast away const. option<void,F> also has no value argument for the ordinary matching path. Treat these as implementation limits, not automatic const/void adaptation. Worst-case dispatch work is proportional to supplied handlers times dispatched elements, plus sum-alternative scanning and callback cost.

Option-combinator requirements

These functions conventionally treat the first alternative as success and the second as error. That convention is not imposed by option itself. Const-input overloads copy propagated payloads; rvalue overloads move them. Most branch combinators assume a nonempty input: an empty option can fall through to an unchecked cast of its second branch. They also generally require a concrete nonvoid T argument and distinct result/error types.

Each selected branch transformation invokes its function at most once; combining operations can examine multiple discriminants before invoking it. Tap returns a borrowed wrapper reference, so retaining its result from a temporary does not extend that temporary's lifetime. try_call does not convert a thrown exception to F; a throw across its noexcept boundary terminates according to the runtime.

Constant-evaluation queries

Is_constant_evaluated returns true from its if-consteval branch and false at runtime. Is_within_lifetime(ptr) is consteval and delegates to the compiler's __builtin_is_within_lifetime; it requires compiler support and is not a runtime dangling-pointer probe.

Process-control helpers

control.hpp selects a separate wasm control header on wasm32; the following bodies describe its non-wasm branch. Cancellation_point and park call the thread cancellation test; they do not themselves park on a wait queue. Mark emits a noinline, retained compiler memory barrier useful as a debugger breakpoint.

Halt sends the process a terminate signal and tries kill9 only when the first syscall reports failure. Stop raises the stop signal; cont(pid) returns the result of sending continue. Ignore_pipe installs the existing ignore behavior. Suspend_until copies its signal mask, removes signal 32, checks cancellation around rt_sigsuspend, and discards that syscall result. on_terminate installs handlers for interrupt, terminate, hangup, and quit; on_user_signals installs the two supplied handlers for usr1/usr2.

Crash<x> is declared noreturn: x=0 emits hlt on x86, udf on ARM, or a compiler trap elsewhere; x=1 raises the segmentation signal; other nonzero values except two write through a null pointer. The x=2 branch is empty despite the noreturn declaration and is not a defined assertion implementation. These helpers are process/thread control operations rather than sum-type error propagation.

micron::function

Defined in header <micron/function.hpp>.

An owning type-erased callable wrapper specialized for the signature R(Args...).

Storage and target requirements

A decayed target of at most 48 bytes and alignment at most 16 is constructed inside the wrapper; larger or more strongly aligned targets use matching aligned new/delete. A per-concrete-type operation table contains call, destruction, copy, move, size/alignment, noexcept metadata, and a type-identity token. Invocation performs an indirect call through that table.

The constructor requires an invocable target with a result convertible to R. It does not require copy construction, so move-only targets can be stored. Default/nullptr construction is empty, but a typed null function pointer is not specially converted to the empty state. is_noexcept reports the target's invocation metadata; it does not change the wrapper call operator's exception specification.

Copy, move, and errors

Copying duplicates the target. Copying a wrapper whose target is move-only reports except::bad_function_call at runtime. Copy assignment first constructs a temporary, preserving the destination if the copy fails. Move transfers a heap pointer or invokes the inline target's move constructor, destroys its former inline object, and empties the source.

Move construction, move assignment, swap, and the target move thunk are unconditionally noexcept; a small target with a throwing move is not screened out. Its exception cannot propagate from these paths. Destructor/reset by nullptr destroys the target and releases allocated storage.

Calling an empty wrapper reports bad_function_call. Its what() text identifies an empty-wrapper call, and which() is 0x7f00+15; the same error type is also used for copying a move-only target. Both const and non-const call operators invoke a mutable target through G*, so const wrapper invocation can mutate its callable state. target<G>() returns a matching typed address or null, using a per-type token rather than RTTI. It does not preserve target lifetime beyond wrapper replacement/destruction.

Member types and complexity

result_type is R. Boolean conversion tests nonemptiness; comparisons with nullptr test that same state. Swap is implemented by three wrapper moves rather than just exchanging byte arrays.

The wrapper adds O(1) dispatch to a target call. Copy/move/destruction perform one target operation, with heap allocation for a copied large target. Small-target movement physically relocates it, invalidating target addresses; heap movement transfers the same allocation to another owner. No concurrent-call guarantee is supplied for a stateful target.

Bound member functions

bind_method returns a lambda capturing the member-function pointer and object pointer. Const and non-const member overloads are provided. It does not own or copy the object, whose lifetime must cover every invocation. is_callable, is_typed_function, is_nullary, and is_arrow are compile-time invocability/result-conversion concepts, not wrapper classes.

micron::pair

Defined in header <micron/tuple.hpp>.

An embedded two-component product with public members a and b; either component type can be a reference.

Construction and assignment

Default construction value-initializes both members and therefore requires suitable non-reference types. Two-argument and converting-pair constructors copy or forward member values. Special members follow the capabilities of T and F. Reference components bind external objects rather than owning copies; their lifetime is external.

Initializer-list construction/assignment handles at most the first two values and ignores extras. Construction starts from value-initialized members, while assignment leaves omitted members unchanged. These overloads exclude reference components. Scalar-assignment overloads target a or b according to conversion constraints, so a scalar convertible to both components can require disambiguation. Assigning both components through another pair is clearer.

get() returns a pair copy; it is not an indexed accessor. tie(initializer_list) creates a homogeneous value pair, distinct from the variadic tie that creates a tuple of references. This header does not supply tuple_size/get<I> adaptations for pair, so pair_like does not automatically recognize pair.

Complexity and lifetime

Operations perform at most one operation per component, except for user conversion/assignment work. No wrapper allocation occurs. Reference proxies, including map iterator pairs, remain tied to their referenced objects.

micron::tuple

Defined in header <micron/tuple.hpp>.

An embedded heterogeneous product with value, reference, and empty-tuple forms.

Representation and construction

The tuple inherits indexed tuple_leaf bases through tuple_impl. An empty non-final element can be stored as a private base for empty-base optimization; other elements use a data member. The index distinguishes repeated element types. A reference element remains a reference and requires its referent to outlive the tuple.

Constructors forward one argument per element, with conditional explicitness from convertibility. Copy/move and cross-type construction/assignment depend on the element operations. tuple<> is the empty unit product with a no-op swap. CTAD tuple(args...) deduces by-value template parameters; make_tuple decays values and unwraps micron::reference_wrapper to references.

tie(lvalues...) returns tuple<T&...>. Forward_as_tuple returns tuple<T&&...> preserving value categories and can contain references to temporaries which expire at the end of the full expression. It is intended for immediate forwarding, not lifetime extension.

Access and algorithms

get<I> preserves the tuple's const/ref value category. get<T> is available only when T occurs exactly once. Tuple comparisons require equal arity and perform elementwise equality or lexicographic ordering. Swap swaps each element with an element-dependent noexcept specification.

Apply expands tuple elements into micron::invoke, while make_from_tuple constructs a result from the expanded arguments. Tuple_cat concatenates tuple types and forwards elements; its implementation repeatedly constructs a growing prefix, so many one-element inputs can incur quadratic element moves/copies rather than one operation per final element.

Complexity and invalidation

Indexed/type-based get has no runtime search. Elementwise construction, assignment, comparison, swap, and apply expansion perform O(arity) element operations; comparisons short-circuit. Apply additionally pays invocation cost. Tuple_cat's repeated prefixes cost the sum of their lengths. Moving or replacing value elements invalidates references according to those element operations; reference tuples do not own the objects they name.

micron::static_any

Defined in header <micron/tuple.hpp>.

An owning fixed-buffer erased object with compile-time byte capacity N and alignment A.

Template parameters and operations

A defaults to alignof(max_align_t). Emplace decays its selected type, statically rejects excess size/alignment, destroys the old object, and constructs a new one in embedded unsigned-char storage. It installs destruction/copy/move callbacks and a per-type identity token.

Default construction is empty. Has_value tests whether a type token is installed; is<T> compares that token. Cast<T> simply reinterprets the buffer and performs no active-type or emptiness check. The caller must establish both before access.

The emplace implementation installs copy_fn for every target, so move-only target types are not supported by this erased wrapper's callback construction. Copy duplicates the object. Move constructs a destination object, destroys the source object, and empties its metadata. Wrapper move operations are noexcept even if the concrete move can throw. Reset destroys the active object; a throwing new construction after reset leaves the wrapper empty.

Complexity and lifetime

Wrapper dispatch and type queries are O(1); copying/moving/destruction cost one concrete object operation. No heap fallback exists. Every replacement invalidates prior cast references, and moving an inline object changes its address. Choose any<Ts...> when the alternatives should be a closed, indexed set.

micron::any

Defined in header <micron/sum.hpp>.

An in-place tagged union of a nonempty alternative pack Ts..., with an additional empty state.

Storage and selection

Storage size/alignment are the maximum sizeof/alignof of its alternatives, plus an index and operation callbacks. Default construction is empty and index() is numeric_limits<usize>::max(). The raw sizeof/alignof pack requires ordinary object alternatives; void and reference alternatives are not supported.

A value constructor accepts an exact decayed alternative type rather than searching for an implicit conversion. tag<T> constructors and emplace<T>(args...) explicitly select an alternative. Duplicate types resolve to their first pack index, so they cannot represent independently selectable positions of the same type. Reset destroys the active object and returns to empty.

Access, visiting, and special members

Is<T> compares the active index to the selected alternative index. Cast<T> is an unchecked reinterpretation and can name a type without checking that it is active. Implicit conversions to an alternative reference/value perform an active-type check and report logic_error on an inactive alternative.

Visit scans alternatives and invokes the callback on the active value, discarding its result. The non-const visit forwards to the const implementation, so its callback receives a const alternative reference. An empty visit does nothing.

Copy operations exist only when every alternative is copy-constructible, even if the currently active object alone could be copied. Moves construct the active alternative at a new address, destroy its source object, and empty the source. Moves and their thunks are unconditionally noexcept. Assignment/emplacement destroys the previous alternative first; a construction failure leaves the wrapper empty.

Complexity and invalidation

Index/type queries and replacement dispatch are O(1) plus selected object work. Visit and matching can examine O(number_of_alternatives) discriminant comparisons before handler work. No wrapper heap allocation occurs. Reset, replacement, destruction, and movement invalidate references into the former active object.

micron::option

Defined in header <micron/sum.hpp>.

An embedded two-alternative sum with three states: empty, first T, and second F.

Template parameters and state

T and F must be distinct, and F must not be void. T=void is explicitly supported: emplace<void>() records the first branch with no payload callbacks. Other alternatives need storage-compatible object types. first_type and second_type name T and F.

Default construction is empty. Has_value is true for either active branch; it is not a success test. Is_first and is_second test the actual discriminant. is<U>() does not constrain U to an alternative: an unrelated U is treated as the second type by which_of, so is<U>() must not be used as generic membership introspection.

Construction and access

Tag constructors/assignment and emplace select a branch explicitly. First-value constructors require an exact deduced T; second-value constructors take F and may admit conversions through their ordinary parameter binding. Tags avoid ambiguous conversion cases.

Cast<U> is constrained to an alternative but does not check that it is active. It returns a reference, or returns void for T=void. Checked implicit conversion to a nonvoid alternative reports logic_error on an inactive branch. An empty wrapper has no readable payload.

Copy is available only when both payload slots are copyable, treating void as copyable. Move constructs the active object, destroys the source object, and empties the source; void-first movement transfers only the state. Wrapper moves are unconditionally noexcept. Emplacement/assignment destroys the previous object before construction, leaving empty state if the replacement construction throws.

Complexity and use

Branch checks are O(1); construction, copy, move, and destruction pay one selected payload operation. There is no wrapper allocation. References are invalidated by reset/replacement/movement. Use is_first when a chosen application convention places success in T, and check for empty state before generic combinators which assume one branch is present.

micron::tag

Defined in header <micron/sum.hpp>.

An empty selector record with a nested type alias naming T.

Use

Passing tag<T>{} to any or option selects T without relying on value-conversion overload resolution. Tag construction with no further arguments default-constructs a nonvoid payload; tag<void> selects the payload-free first branch of option<void,F>. The tag itself owns no payload and adds no runtime state.

micron::lambda_return

Defined in header <micron/closures.hpp>.

Return-type extraction for a non-overloaded const lambda/functor call operator.

Specialization and limits

The defined specialization recognizes R(F::*)(Args...) const and exposes type=R. lambda_return_t<F> applies it to decltype(&F::operator()). Mutable call operators, generic/overloaded call operators, and signatures outside that exact specialization do not have a complete supported extraction path. This is a compile-time helper and does not instantiate or invoke F.

function_traits

Defined in header <micron/closures.hpp>.

Callable signature traits declared in the global namespace, rather than micron.

Supported forms

The primary function-signature specialization exposes return_type, arity, args_tuple=micron::tuple<Args...>, and arg_type<N>. Pointer, member-pointer, const member-pointer, and corresponding noexcept forms inherit that signature information. Functors/lambdas dispatch through decltype(&F::operator()), which requires an unambiguous addressable call operator.

The global helpers for_each_type_impl and for_each_type invoke a templated callback once for each tuple element type. They pass no value argument and return void. Runtime work is one callback per type; the enumeration and type selection are compile-time pack expansion. A namespace-qualified micron::function_traits is not supplied by this header.

Defined in header <micron/function.hpp>.

The implementation carrier returned by lazy: an owned nullary callable plus an optional cached result.

Lazy lifetime and limitations

The thunk stores its result in aligned raw storage and destroys it only after successful evaluation. A thrown evaluation leaves it unevaluated, permitting a later retry. Copying or moving a thunk starts a new unevaluated cache; it does not copy/move the cached result. The source retains its own cached object until its destruction.

The implementation assumes a nonvoid nonreference result type suitable for in-place storage. The carrier constructor takes the decayed callable as an rvalue reference, so lazy with an ordinary lvalue callable is not a generally supported binding path. Move construction is noexcept without checking the callable's move. Evaluation is not synchronized, and recursive force has no in-progress guard.

Force performs one callable invocation plus result construction on the first successful evaluation and O(1) access thereafter. Its returned reference borrows the thunk's cache. Curry/partial construction can copy/move accumulated tuple prefixes; fix's depth/cost is the recursion performed by f. Composition adds the costs of its component invocations and captured-object lifetime operations.
