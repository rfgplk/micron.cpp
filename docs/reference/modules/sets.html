Sets

From micron reference
micron reference › Containers and strings

Key-only adapters over the map implementations. Five set classes provide fixed, growing, persistent, and hash-identity storage; each retains its underlying map's capacity, equivalence, and invalidation rules.

Container selection

Include sets/sets.hpp for all five adapters or the individual header. There is no root sets.hpp in this source snapshot. The adapters store an empty mapped marker rather than implementing independent set algorithms.

Common member types and contracts

All five expose key_type = K, value_type = K, and size_type = usize. Their category tag is map_tag; the adapters do not define a distinct set tag. Mutable variants use mutable_tag; immutable_set uses immutable_tag. swiss_set uses stack_tag, the others heap_tag.

Enumerable sets alias iterator to const_iterator. The __set_key_iter projection reads the underlying entry's key, pair first component, or tuple element zero and returns const K&/const K*. Iteration therefore cannot mutate a stored key. The helper and __set_empty_v are implementation details, not additional containers.

Mutable insertion returns bool and discards the underlying map's value pointer. Persistent insertion returns a new set. Raw-pointer keys are not automatically deleted. None of these adapters supplies a container lock, a merge operation, or a standard-library-compatible node handle.

Complexity and invalidation

The adapters add only an empty mapped value and, for robin_set and hopscotch_set, a preliminary membership lookup. Expected constant hashing costs require suitable hash distribution. Slot scans are proportional to capacity rather than size. Fixed-table insertion can still relocate Robin Hood entries, while Swiss insertion preserves existing slots until a heap rehash. The following entries state each distinction explicitly.

micron::robin_set

Defined in header <micron/sets/robin_set.hpp>.

A move-only fixed-capacity set retaining original keys in a Robin Hood hash table.

Capacity and operations

Alloc defaults to allocator_serial<>. Construction optionally requests a slot count, rounded upward to a power of two with at least 16 slots. max_size() is physical slots; new keys stop at floor(7*C/8) entries or the map's probe-distance limit. There is no reserve or growth API.

insert first checks membership and returns false for a duplicate; otherwise it inserts and returns true. Capacity and probe failures report the map's library error. emplace constructs a temporary K before insertion. contains, count, erase, clear, const iterators, and const-key for_each delegate to the map. Copying is explicitly deleted; movement transfers ownership.

Complexity

Membership is expected O(1) and subject to the backing map's probe bound. Insertion performs a preliminary lookup and Robin Hood insertion; erasure may shift a cluster. Their worst-case structural work is O(C). Clear and complete iteration scan C slots.

Iterator invalidation and use

Insertion may swap stored keys, and erasure shifts displaced keys. References and iterators into affected slots are not stable even though capacity is fixed. Choose this adapter for a planned maximum population when mutable set membership and original-key equality are required.

micron::swiss_set

Defined in header <micron/sets/swiss_set.hpp>.

A fixed-capacity Swiss-style set storing keys and controls directly in the set object.

Template parameters and operations

N is at least 16 and divisible by 16. NH bounds the slots inspected from each home position and defaults to 16, unlike the underlying map class's NH=N default. capacity() and max_size() return N. Only occupied key objects are constructed.

Insertion returns true for a new key and false for either a duplicate or placement failure. Because the adapter discards the map's pointer result, these two false cases are indistinguishable without a separate membership test. An exhausted NH window can fail with unused slots elsewhere. emplace constructs a temporary K. Membership, zero-or-one count, erasure, clear, const iteration, and key-only for_each are provided. Copy and move construct entries; moves clear the source. The adapter's move members are unconditionally noexcept, even when moving K can throw.

Complexity

Lookup, insertion, and erasure inspect at most NH slots, worst O(NH); suitable hashes and spare neighborhoods give expected O(1). Copying, moving, clearing, and enumeration are O(N). There is no container storage allocation or growth.

Iterator invalidation and use

Insertion does not move existing entries; erasure invalidates its own key only and leaves a tombstone. Clear and assignment invalidate affected entries. Suitable for small object-local sets when probe-window failure can be handled explicitly; N alone is not an insertion guarantee.

micron::heap_swiss_set

Defined in header <micron/sets/heap_swiss_set.hpp>.

A copyable, growing Swiss-style set retaining original keys and exposing read-only key iteration.

Capacity and operations

Alloc defaults to allocator_serial<>; the optional constructor argument and reserve(n) request slots, rounded upward to a power of two with at least 16. The backing map starts with floor(7*C/8) empty-slot budget and doubles when it reaches zero. Erasure leaves tombstones without restoring that budget; reserve is not a promise to hold n entries without growth.

insert and emplace return whether a key was newly inserted. Duplicate insertion preserves the original key. The remaining API is size, capacity, empty, load_factor, reserve, clear, contains, count, erase, const iteration, and key-only for_each. Copying constructs independent keys; movement transfers the blocks. hswiss_set<K,Alloc> is an alias of this class.

Complexity

Membership and erasure are expected O(1), worst O(C). Insertion is expected amortized O(1) for distributed hashes, with a full rehash on growth. Iteration, clear, and copying scan C slots.

Iterator invalidation and use

Growth or an expanding reserve invalidates all key pointers and iterators. Insertion without growth preserves existing slots; erasure invalidates its key only. Use when the set must grow and hash collisions must still be resolved by original-key equality.

micron::hopscotch_set

Defined in header <micron/sets/hopscotch_set.hpp>.

A growing set of nonzero 64-bit hash identities. Original K objects are not stored and cannot be enumerated.

Key equivalence and operations

A key is present when its hash<hash64_t> equals a stored hash. Distinct keys with the same hash are indistinguishable; zero hash insertion reports a library error. The default backing map uses an inclusive 32-displacement neighborhood and grows on population or placement pressure.

Only size, empty, clear, insert, contains, and erase are exposed. Insertion performs contains first and returns false for an existing hash. No iterator, for_each, count, reserve, capacity query, or custom allocator template argument is provided. The adapter's defaulted copy members are implicitly deleted because the underlying hopscotch_map is noncopyable; moves are available.

Complexity and use

Lookup and erasure examine at most 33 slots, excluding the cost of hashing K. Insertion can displace entries and rebuild the table. Clear scans the backing table. This adapter is appropriate only where hash identity rather than full-key identity is the intended membership relation.

micron::immutable_set

Defined in header <micron/sets/immutable_set.hpp>.

A persistent ordered set sharing reference-counted red-black tree structure between versions.

Key requirements and operations

K uses the backing immutable_map's total ordering and copying requirements. Equivalence is !(a < b) && !(b < a). Copying a set retains the root rather than copying all keys. insert(k) and erase(k) return a new set; neither changes the source handle. Assign the returned set to retain an update.

The exposed API is size, empty, insert, erase, contains, ascending const iteration, and key-only for_each. There is no clear, count, capacity, or reserve member on the adapter. Iterator and const_iterator are the same key projection, and each underlying iterator pins its originating version.

Complexity

Membership and updates take O(log n) tree work; updates copy O(log n) nodes. Copy construction is O(1), enumeration is O(n), and last-owner destruction can reclaim O(n). Copy/move assignment additionally releases the previous version.

Iterator invalidation and thread safety

Iterators keep their version alive and survive deriving or assigning other versions. Plain references obtained from them remain valid while an owning version or pinned iterator remains alive. Separate handles share atomically counted nodes; concurrent assignment or destruction of the same set handle still requires synchronization. Use when retaining historical ordered membership is useful.
