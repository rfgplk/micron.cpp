Terminal control

From micron reference
micron reference › Input and output

Terminal support provides indexed escape-sequence templates and Linux terminal-attribute records. Selecting a constant does not emit output, negotiate terminal capabilities, or restore changed terminal state.

Sequence tables

Each unscoped code enum is an index into its matching constant string array, rather than the terminal's numeric command value. For example sgr_code::fg_red indexes the stored ESC[31m string; it is not itself SGR parameter 31. Every family has a count sentinel that is not an array entry. Table strings have static lifetime and are not allocated.

Parameters, output, and validity

Parameterized sequences contain literal {} placeholders. Select and format the complete template with an appropriate formatter before writing; plain printing of that string does not substitute its parameters. Cursor/region coordinates in the documented templates use the terminal protocol's one-based convention. RGB and indexed colors are templates, not range-checked color objects.

The tables include ECMA/DEC controls and terminal-specific extensions. Presence in a table does not establish support by a given terminal. Report-request strings only request a response; this header supplies no reply parser. OSC/DCS/APC text payloads are not escaped, base64-encoded, or sanitized by the constants. Operations such as clipboard_set expect the already encoded payload indicated by their template.

Indexing a valid enum into its table takes constant work. Formatting/output costs depend on the selected formatter and byte length. Concurrent output can interleave escape sequences unless the output path supplies an enclosing synchronization protocol. The constants themselves are immutable and require no runtime initialization.

Linux attributes

terminal_getattr<Fd> and terminal_setattr<Fd> call Linux TCGETS/TCSETS ioctl on a compile-time descriptor, default 1 (stdout); select 0 explicitly for stdin. They return 0 on success or the negative ioctl error unchanged. Set always uses TCSETS: the TCSANOW/TCSADRAIN/TCSAFLUSH constants do not select a waiting mode for this function.

The caller owns saving/restoring terminal state. These helpers neither close the descriptor nor make a scoped restoration guard. File descriptors must represent an appropriate terminal, and ordinary stream buffering remains independent of the terminal attribute record.

Values and indexed code enums

Values are c0, c1, fe, csi, sgr, osc, dcs, pm, apc, charset, mouse, and misc, followed by internal __end. The header provides no function mapping (group, index) to an erased sequence; select the corresponding typed index enum and array directly. Each related code enum and table is described in the module table above.

All code enums use usize as their underlying type. They are table selectors, not bit flags. Do not use their count sentinels as indices, combine unrelated families, or assume enum ordinals equal the numeric escape parameter.

Use and lifetime

The header supplies Linux numeric constants for character slots, input/output/local/control modes, baud values through B38400, and attribute-action values. The record performs no validation, synchronization, initialization syscall, or automatic application. Value-initialize it or populate it through terminal_getattr before changing fields and applying it. Copying copies the record only; it does not change terminal state. Each get/set performs one ioctl with constant wrapper storage/work.
