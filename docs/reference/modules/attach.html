Module attachment

From micron reference
micron reference › System interfaces

Native host/guest attachment callbacks, fixed ABI entry records, continuation dispatch, and host TLS-surplus bookkeeping for specially linked micron modules.

Entry protocols

These protocols require a compatible loader, host runtime, linkage, and target ABI. They do not implement ordinary standalone program startup or a general shared-library constructor interface. The native entry path rejects WebAssembly. start.hpp's native branch contains an unfinished startup placeholder and is not the working CRT entry implementation.

Attachment lifecycle

_attach rejects an already attached or previously detached image and checks the supplied version/ABI/callback record. It installs borrowed fatal/thread-destructor hooks, calls an optional memory initializer, boots the guest thread pool, and optionally boots guest I/O buffers. It requires a freestanding build without the micron exception trampoline; it does not itself run arbitrary ELF init arrays.

_detach stops/joins guest pools, runs the attaching thread's registered destructors, drains the module's process-finalizer table, and shuts down its I/O buffers. The image remains marked spent and its host hooks stay installed. Detach does not unmap code or free a host TLS assignment; coordinate those loader actions only after guest execution and callbacks are finished.

The attachment-info pointer, callback code/context reachable through it, and any runtime services must remain alive for every guest call and late cleanup. Attachment state uses ordinary inline globals, without a general concurrent attach/detach serialization protocol. Module-local ABI glue supplies atexit/thread-atexit, static-initialization guards, a DSO handle, and selected ARM32 compiler helpers.

TLS storage and costs

An attach-capable host reserves MICRON_TLS_SURPLUS_SIZE bytes per TLS frame, defaulting to 4096 and requiring a multiple of 64. The landlord has 32 module slots and finds an aligned nonoverlapping hole by scanning existing slots. Assignments require ready host TLS, filesz<=memsz, a non-null nonempty template, and alignment at most 64, promoted to at least 16.

The live-frame registry holds up to 4096 frame bases and silently declines additional registrations when full. Assignment copies the initialized template into registered frames; later frame initialization copies each active template. These copies cover filesz only: zeroing/reinitializing the remainder of memsz is not performed here. Reused surplus therefore needs an appropriate surrounding initialization protocol.

Slot allocation performs O(M²) bounded scan work in the worst case for M=32; seeding F frames copies O(F·filesz) bytes. Releasing a token clears its slot metadata without erasing old frame bytes or running TLS destructors. Tokens are slot number plus one and have no generation, so stale tokens must not be reused after release. Assignment/release and registry operations use spin locks; seed_current requires external coordination with slot release.

micron_attach_info

Defined in header <micron/attach/info.hpp>.

Borrowed host-service record supplied to a guest's _attach entry.

Fields and validation

magic/version/abi/size identify the record. flags selects guest I/O buffers and optional stack-bound metadata. make_child_frame/free_frame create and release compatible host TLS frames; fatal supplies guest fatal handling; thread_atexit/run_thread_dtors supply host cleanup. surplus_size and host_image_memsz describe TLS storage, and stack/environment fields are borrowed host data.

The validator checks the expected magic/version/ABI, a minimum prefix size, non-null required callbacks, and nonzero surplus. It does not independently validate every optional pointer/span or prove the complete declared host record is mapped. Callbacks and the record must outlive guest activity and retained hooks. Return codes are attach_ok, attach_ebadinfo, attach_enospace (reserved here), and attach_ealready.

micron_mx_entry_args

Defined in header <micron/attach/mx_entry.hpp>.

Explicitly 8-aligned, 128-byte process-entry record using u64 address fields across native pointer widths.

Fields

abi/size/flags/argc lead the record, followed by argv/envp/auxv, self_base/page_size, optional stack bounds and TLS base, opaque user/user_len, and four reserved words. Flags determine which optional fields are meaningful. Required pointer fields are numeric addresses, not owners.

The validator checks ABI, full minimum size, known flags, and nonzero argv/envp/auxv addresses. It does not validate pointed-to arrays, argc agreement, optional ranges, or reserved-word zeroing. The record and referenced storage must remain valid for the user entry's use. Header static assertions specify size, alignment, and field offsets.

micron_cont_args

Defined in header <micron/attach/cont_args.hpp>.

64-byte continuation descriptor containing ABI/flags, guest/host spans, graph operations, and opaque user data.

Dispatch and validation

The ABI value is 3. graph marks ops as a graph-operation table; replace permits dispatch without a prior attachment. The validator requires known ABI/flags, a nonzero ops address when graph is set, and nonzero self/host spans. It does not check address-plus-length overflow or mapped extents.

__micron_continuec records a borrowed pointer and calls the configured entry (default mx_continue_main). Error returns distinguish null arguments, invalid arguments, and an unattached direct call. The replace flag does not itself enforce a nonreturning entry. Calls update one global borrowed argument pointer.

The header asserts 8-byte alignment but does not declare alignas(8) on this record. Targets whose natural u64 alignment is four, such as ordinary i386 ABI layouts, can therefore fail that assertion. The MX process-entry record supplies its explicit alignment separately.

micron_graph_ops

Defined in header <micron/attach/cont_args.hpp>.

Borrowed host graph-operation callback table paired with an opaque context pointer.

Callbacks

find/find_hash obtain IDs; addr_of obtains an address/length; replace changes a binding; resolve_extern/select/resolve support host graph resolution and selection. The record is eight pointer-sized fields and must match the loader's mirror ABI. Continuation validation only tests the table address when requested; it does not inspect individual callback pointers. These callbacks do not own or retain the module/address ranges they describe.
