Parallel algorithms

From micron reference
micron reference › Concurrency

Parallel range algorithms return lazy task objects and divide random-access ranges into coroutine work. A separate reusable scan workspace accepts a caller-supplied joined executor without a coroutine dependency.

Execution and constraints

Most interfaces in parallel/algo.hpp return micron::task<R>. Calling one constructs a lazy task; discarding it performs no range work. Use co_await, coro::sync_wait, or a scheduling interface and retain the input/output storage until completion. The task engine must be available; the task-based engine rejects wasm. scan_workspace.hpp is independent of the coroutine engine.

Range types must support subtraction, addition, and indexed access where used. Sorting additionally passes a contiguous T* into serial kernels, so a nominal random-access iterator is insufficient there. Ranges must be valid and ordered; a negative last - first is converted to a huge usize. Output spans and second inputs are not length-checked. Functions and predicates are copied into task/leaf state and can execute concurrently; captured shared mutable state requires its own synchronization.

The grain is max(1024, n / (workers * 8 + 1)), using one worker if no global engine yet exists when the task is created. Recursive bisection forks the left child, calls the right child, then joins. A fixed grain therefore creates order n/grain leaves and linear total leaf work for ordinary elementwise operations. Scheduling, frame allocation, callbacks, and synchronization add costs; no linear speedup is guaranteed.

Search and predicates

find, find_if, find_if_not, mismatch, adjacent_find, search, and search_n select the leftmost matching index by combining subtree results. find_last and find_last_if retain the rightmost. The no-match result is the first range's end iterator; mismatch returns only that iterator, not a pair. An empty search pattern or zero run length returns the first iterator.

Leaves can stop locally, but other subtrees are not cancelled once a result is found. All/any/none/contains similarly reduce local booleans without global early termination. Count/count-if visit every selected element. Ordinary find/mismatch/adjacent checks use at most linear element comparisons; naive subsequence and repeated-value search use worst-case O(n*m) comparisons for pattern/run length m.

Numeric reductions and ordering

reduce(first, last, init, op) reduces each nonempty leaf from its first element, combines left and right results, then applies op(init, combined) once. It requires an associative operation for grouping-independent semantics; it preserves left-to-right operand order at combine sites but changes parenthesization. Floating-point results need not match a serial fold bit for bit.

sum defaults to a wide accumulator: f128 for floating elements, intmax_t for signed integral elements, and umax_t otherwise. Mean defaults to f64; geometric and harmonic means default to flong and use direct product or reciprocal-sum formulas. No overflow, zero-denominator, or logarithmic-stability checks are added. inner_product sums products in T and adds init once.

Empty sum/mean/geometric/harmonic/min/max return a value-initialized result. Empty reduce and inner-product return init. min_at and max_at return end on empty input and the leftmost equal extremum otherwise. Value min/max require a default-constructible result for the empty path. is_sorted checks both leaf interiors and adjoining leaf boundaries. Total work is linear apart from element arithmetic and task overhead.

Compaction and scans

where and its alias filter retain matching elements in original order; unique retains the first element of each adjacent equal run rather than removing all duplicate values globally. They return the number written. A single grain compacts serially. Larger ranges count matches per block, compute offsets serially, and traverse the input again to write output; predicates can be called twice per element and must give consistent results.

For safe parallel compaction use disjoint input/output storage. In-place or partial overlap can let one block overwrite input another block has not read, particularly for unique's predecessor comparison. Auxiliary count/offset storage is O(number_of_blocks) and total work is linear.

scan produces an inclusive associative scan. It computes block totals, a serial carry sequence, and per-block output. scanl writes init at output zero, writes inclusive prefixes after it, then applies op(init, prefix) to each; it requires n + 1 output elements even for empty input. Its shifted write means identical input/output storage is not a safe general alias. scan can use identical or disjoint ranges when element operations permit; partial overlap is unsupported. Both change grouping and can differ from a serial nonassociative or floating fold. Coroutine scan allocates two block-sized vectors on multiblock input.

Sorting

parallel::sort::merge and stable fork recursive halves and then run the serial merge kernel. quick and sort use a median-of-three partition with a depth budget of twice floor-log2(n), falling back to serial merge sort at the grain or depth limit. Quick's partitioning does not preserve equal-element order. With suitable comparison and the serial-kernel contracts, total comparison work is O(n log n) in the worst case; serial partition/merge phases limit available parallelism. Temporary allocation follows the serial merge kernels.

radix first scans key min/max serially, biases keys by the minimum, then performs stable byte-digit histogram, offset, and scatter passes. It allocates an n-element scratch vector and two 256 * blocks counter vectors. For d processed bytes its work is O(n + d * (n + 256*blocks)); offsets are computed serially. Integral/custom keys are converted to umax_t; wider or non-order-preserving conversions are unsupported. Float overloads accept 32- or 64-bit representations and transform their sign bits into ordered unsigned keys; NaNs follow representation-derived ordering rather than ordinary numeric comparison. Equal transformed keys retain order.

The _range wrappers forward begin/end and return the same lazy tasks; they add no bounds, synchronization, or storage ownership. parallel/pipeline.hpp declares no pipeline facility, and poll.hpp contains no polling implementation.

Native-loop alternatives

parallel_for<Fn>(container) in parallel/for.hpp is a separate synchronous micron function. It splits into up to cpu_count() contiguous segments, launches independent thread<> owners, calls Fn(iterator) for each iterator, and joins all before returning. Its temporary owner stack has a fixed 1024-slot bound; more than 1024 selected segments is unsupported.

fork_for<Fn> submits segments through the concurrent native arena and waits on selected workers' work tokens. It requires concurrent pools to be initialized. The token is a wake/work flag, not a per-job completion count; it must not be treated as a general precise batch fence. Both helpers assume pointer-like random-access container iterators despite their broader iterable constraint.

micron::parallel::scan_workspace

Defined in header <micron/parallel/scan_workspace.hpp>.

A reusable inclusive-scan workspace with setup-owned block metadata and caller-selected joined execution.

Storage and executor protocol

Construction fixes a maximum block count and allocates vectors for totals, carries, and item records using allocator_serial with locking disabled. A zero-capacity workspace still allocates one slot in each vector but rejects scan. Copying is deleted; its const capacity and member ownership do not provide a reusable move-assignment interface.

scan(input, output, count, operation, executor) requires an associative nonthrowing operation, checked with a noexcept expression. executor.run<Op>(items, blocks) must complete/join every submitted item before returning 0 or a negative fault. It runs local scans, computes block carries serially, and runs carry application. There is no allocation in this scan body and no concurrent reuse of one workspace is supported.

Returns -22 for zero capacity, count-to-byte overflow, null nonempty input/output, or partial overlap. Identical buffers and disjoint buffers are allowed; empty input succeeds after capacity validation. A negative executor result is propagated with already-written output retained. scan_into forwards to this member. capacity() reports maximum blocks, not maximum input elements.

For b = min(count, capacity) nonempty blocks, work is O(count + b) operation calls and setup storage is O(capacity). Parallel execution depends entirely on the executor; the provided serial executor performs both stages sequentially. Input, output, operation, and executor must remain live through the joined call.

micron::parallel::serial_scan_executor

Defined in header <micron/parallel/scan_workspace.hpp>.

A scan executor that invokes each work item serially in index order.

Result and complexity

run<Op>(items, count) returns the first negative operation result or zero after all items. It allocates no memory and performs linear item-dispatch work plus the operations themselves. It satisfies the scan workspace's joined-return contract without starting threads or a coroutine runtime. Exceptions cannot escape its noexcept call.
