Lists

From micron reference
micron reference › Containers and strings

Singly and doubly linked owning sequences allocate one node per element. They provide element cursors for traversal and a separate raw-node-pointer interface for insertion, erasure, and chain transfer. Neither caches its length or final node.

Container types

TypeRepresentationUse
list<T>One root pointer; each node has a value and next link.Forward traversal and front insertion, with less per-node linkage.
double_list<T>One root pointer; each node has a value, previous link, and next link.Backward traversal and constant local removal of a known member node.

Iterators and node pointers

Container pointer/const_pointer aliases point to nodes, while cursor pointer aliases point to element values. begin/end provide cursors over values with null as the end node. ibegin() returns the first node pointer; iend() returns the final node pointer, not a past-the-end sentinel. These are different interfaces.

Insert, erase, next/prev, and splice accept raw node pointers. A cursor exposes .node() when a node pointer is needed. find(value) instead returns a const T* to a matching element, or null; it returns neither a cursor nor a node pointer. The types provide no standard iterator-category alias or random-access arithmetic.

Allocation and complexity choices

Each insertion uses new for a node; destruction uses delete, including destruction of the stored T. There is no allocator template parameter, contiguous element buffer, cached tail, cached size, or reserve operation. A stable node address avoids vector-style relocation but requires pointer chasing and a separate allocation for each element.

Both size() and iend() walk the chain. Repeated push_back builds an n-element list in quadratic traversal work; repeated push_front or a constructor building a tail chain is linear. double_list::begin/end also find the tail for decrement-from-end support, so repeatedly recomputing end inside a loop can make traversal quadratic. No measured performance ranking is implied.

Notes

The aggregate itself does not own or recursively delete its successor. The enclosing list manages the chain and deletes each node separately. External edits to next links can create cycles, lose owned nodes, or cause repeated deletion.

Construction and mutation

Default construction is empty. Count/default and count/value constructors build a chain in order. Copy construction deep-copies every node; move construction transfers the root and empties the source. Assignment first destroys the destination's current chain. Constructors building a prefix have no explicit cleanup owner if a later node copy/allocation throws; copy assignment has no rollback to the previous value.

Push-front prepends one node. Push-back scans for the final node and appends. insert(node, value) inserts after a nonnull node; emplace(node, T&&) is the moved-value form, not a variadic in-place constructor. Erase rejects null, removes the root directly, or scans to find its predecessor; an absent foreign node is unchanged after an unsuccessful predecessor search.

next(node, n = 0) advances up to n + 1 links and clamps at the last node; null input is an error. front/back return copied values and reject empty input. merge(other) concatenates and consumes the source chain without sorting, while splice(pos, other) inserts the complete source chain after pos and consumes it. Both leave surviving node values at their addresses.

Equality compares values in forward order; for_each visits them by mutable or const reference. max_size() returns the fixed literal 0xFFFFFFFFFFFFFFF converted to size_t; it is not a capacity reservation or checked allocation limit.

Complexity and iterator invalidation

Front access, empty, begin/end, push-front, and insertion after a known node are constant structural time, apart from allocation and element work. Back access, size, iend, push-back, and arbitrary erase are linear in the walked prefix/chain. Next is linear in distance advanced. Merge scans the destination tail; splice scans the source tail. Construction/copy/clear and full traversal are linear. Move construction is constant time; assignment additionally destroys old destination nodes.

Insertion preserves pointers/references/cursors to existing nodes. Erase invalidates only the removed node; clear/destruction invalidate the complete chain. Merge/splice/move transfer ownership of nodes without relocating them; retained node cursors then refer to nodes owned by the destination. Raw nonnull insertion/splice positions must belong to the destination; no membership check protects these paths. No synchronization is supplied.

micron::list::__cursor

Defined in header <micron/list.hpp>.

A forward value cursor storing one mutable or const list-node pointer.

Member types and operations

value_type is T; reference/pointer select T&/T* or const T&/const T* from Const. difference_type is ssize_t. Dereference and arrow expose the node's data, increment follows next, and equality compares current node pointers. .node() exposes the raw node. Mutable cursors convert to const cursors, not conversely.

A default cursor is null and equals end. Dereference and increment require a live nonnull node; no range ownership or bounds validation is performed. Copies are constant time and do not keep nodes alive.

micron::double_list_node

Defined in header <micron/doublelist.hpp>.

A doubly linked-list node aggregate containing T data and previous/next node pointers.

Notes

The enclosing double_list owns the chain; a node does not recursively manage either neighbor. Externally changing links must preserve both directions and the owning root, or subsequent mutation/destruction is invalid.

Ownership and operations

Stores only the root, with no cached tail or count. Default/count/value construction, deep copying, root-transfer moving, clearing, and assignment follow the singly linked ownership model, while constructors maintain both directions. A throwing later node construction has no explicit constructor-prefix cleanup owner.

Push-front is constant local linking; push-back finds the tail first. Insert and moved-value emplace insert after a nonnull node and repair its neighbors. Erase unlinks a supplied node directly using previous/next links; the caller must establish that it is a live member of this list. There is no membership search to reject a foreign node.

next(node, n) and prev(node, n) walk up to n + 1 links, clamping at the appropriate end. front/back copy values and reject empty input. merge concatenates and consumes another list without sorting; splice inserts its complete chain after a supplied node. find returns a const element pointer or null. Equality and for_each traverse forward. max_size is the same nominal converted literal as list.

Complexity and iterator invalidation

Known-node erase/insert, push-front, front, and empty are constant structural time. Size, tail/back lookup, push-back, and obtaining begin/end are linear in chain length. Distance stepping is linear in distance. Merge scans the destination tail; splice scans the source tail. Copy/clear/traversal are linear, and moving a new list transfers one root in constant time.

Existing node addresses survive insertion and chain transfers; erasing a node ends its value lifetime. A cursor additionally caches the tail as it existed when that cursor was created. After the tail changes, decrementing an old end cursor can select the former tail, and erasing that cached tail can leave a dangling tail field even in a cursor currently pointing elsewhere. Obtain fresh cursors for decrement-from-end after tail mutation. Clear, destruction, and ownership replacement invalidate affected nodes. No synchronization is supplied.

micron::double_list::__cursor

Defined in header <micron/doublelist.hpp>.

A bidirectional value cursor storing the current node and a snapshot of the list's tail pointer.

Member types and operations

value_type = T, difference_type = ssize_t, and reference/pointer select mutable or const element access from Const. Increment follows next; decrement follows prev, except decrementing a null end cursor selects its cached tail. Equality compares current node pointers only. .node() and .tail() expose those two raw pointers.

Mutable cursors convert to const cursors. Each increment/decrement/dereference is constant time, but obtaining a cursor from the list scans for its tail. Cursors do not retain node ownership. A fresh end cursor can be decremented only when the list is nonempty; mutation can make an old cached tail stale or dangling.
