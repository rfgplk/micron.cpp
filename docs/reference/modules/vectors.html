Vectors

From micron reference
micron reference › Containers and strings

The vector family contains resizable contiguous buffers, bounded inline storage, value-returning sequences, a persistent trie, an overwrite ring, and two containers that preserve element addresses during growth. Their capacity, copying, and synchronization contracts are specific to the selected type.

Container types

<micron/vector.hpp> includes vector, fvector, ivector, and svector. Include the other vector headers individually. <micron/circle_buffer.hpp> supplies the circular and circle_buffer aliases.

Capacity and allocation

For vector, fvector, ivector, and convector, max_size() means current allocated element capacity, not the largest theoretical sequence. The first two and convector expose the resource's capacity data member; ivector additionally provides capacity(). A size constructor creates live elements, whereas reserve obtains raw capacity and leaves the logical size unchanged.

The default Alloc is allocator_serial<>: its policy starts at one page, rounds byte extents to pages, recommends three times the previous byte capacity for automatic growth, and supplies a default alignment of 64 bytes. Actual element capacity is allocated bytes divided by sizeof(T); alignment and policy rounding can make it larger than a requested count. Supplying another allocator changes these rules.

With geometric growth and bounded-cost element relocation, repeated single-element appends to the mutable heap vectors have amortized constant element-movement cost; one growing append can still take linear time. An exact-growth allocator or repeated exact reserve(size()+1) calls need not preserve this bound. No comparative benchmark result is implied by the type names.

Checks, raw storage, and views

Sf defaults to true on templates that expose it. Its effect is limited to checks actually used by that class. In particular, fvector access is unchecked even with Sf == true, svector::operator[] is unchecked, and pvector::operator[] is unchecked. The fixed virtual and segmented vectors have their own boolean failure interfaces.

Heap-vector set_size changes only the recorded length, clamped to capacity. It does not construct newly exposed elements or destroy hidden ones. Use it only when element lifetimes have been managed separately; ordinary callers should use resize. Public resource inheritance also exposes low-level storage operations outside the ordinary container invariants.

Unary operator& on the ordinary heap and inline vector families returns a byte pointer to element storage. Where provided, addr() returns the container object address. Members returning slice<T> or slice<byte> allocate and copy the selected elements or bytes into independent owned storage. They are snapshots with linear copying cost, rather than borrowed ranges into the vector. Raw pointers and chunk<byte> descriptors still require the originating allocation to remain valid.

Construction and ownership

The default constructor allocates the allocator's automatic byte extent and starts with size zero. Count constructors initialize live elements; generator and transform constructors first construct n defaults. List construction copies its values. Copy construction allocates for the source's logical length and copies its elements; spare capacity need not match the source. Move construction transfers storage and resets the source's pointer, capacity, and length.

The specialization for a movable, noncopyable element type deletes container copy construction and copy assignment, copying append, copying insertion, and repeated-value assignment. Its move insertion and emplacement paths retain the contiguous representation. Interfaces whose selected body requires copying an element remain unavailable for a noncopyable T even where a declaration is present.

Construction from chunk<byte>&& adopts allocator-compatible aligned raw storage and starts with logical length zero. It does not infer or construct live elements from the byte count. Destruction destroys the recorded live prefix and releases the allocation through Alloc.

Element access and insertion positions

With Sf == true, subscript, at, itr, and indexed get/cget check the live length. at_n(pointer) accepts a pointer through the one-past-end position. Two-index slicing of the ordinary specialization checks a nonempty range against capacity, not live length; a valid capacity range can contain unconstructed slots. That overload is deleted in the move-only-element specialization.

Index-based insertion into a nonempty vector requires n < size(). Iterator insertion accepts end() for appending. On an empty vector, the insertion overloads take their special append path. insert_sort requires that the existing sequence is sorted and places the new value after existing equal values.

Complexity

Access, size queries, and append within capacity take constant time apart from element construction. Reallocation relocates the live prefix and is linear in size. Insertion and erasure are linear in the shifted suffix, copying append is linear in the appended count plus any reallocation, and linear search is linear in size. Slice construction and into_bytes allocate and copy their selected range. Repeating remove for several values makes a separate compaction pass for each value.

Copy construction and cloning are linear in source size. Move construction and storage exchange are constant time; move assignment also destroys the destination's former values. Clearing is linear in the recorded live storage, including zeroing for trivial types. drop and fast_clear are constant time for trivially destructible elements. Sorting follows the selected sorting algorithm; no stability guarantee is added by the container.

Iterator invalidation and notes

Reallocation may invalidate every pointer, reference, and iterator into the old buffer. Without reallocation, append preserves existing element addresses but changes the end position; insertion and erasure change the suffix beginning at the operation's position. Clearing ends the live prefix while retaining its allocation. Move and swap transfer storage to another owner. Previously returned slice copies own separate allocations and are unaffected.

No synchronization is provided. Sf == false removes the guarded checks, including guarded self-assignment handling. No general strong exception guarantee is established for element-throwing operations: shared append/emplace code increments length before the element construction completes, and suffix shifting assumes suitable move operations.

Ownership and interface

Requires is_regular_object<T>; it is not restricted to fundamental elements. Storage allocation, automatic growth, count/list/generator construction, reserve, resize, append, weld, insertion, removal, iterators, and byte views follow the mutable heap-vector model. Copy construction and copy assignment of the container are explicitly deleted. clone() const performs an explicit elementwise copy into a new fvector. Moving transfers ownership and empties the source.

at, subscript, get/cget, front/back, pointer positions, insertion positions, ranges, and pop_back do not check their arguments or empty state. Sf controls guarded self-move handling rather than enabling these missing checks. try_reserve is a void operation with the same body as reserve.

clear() destroys elements without zeroing their storage. drop() is the same operation; fast_clear() simply resets length for trivial destructors. insert_sort scans for the first value greater than or equal to the new value, so a new equivalent value precedes existing equivalents.

Complexity and iterator invalidation

The same relocation, suffix-shifting, linear-search, geometric-growth, and invalidation bounds as vector apply. clear, drop, and fast_clear are constant time for trivially destructible elements. Copying via clone is linear; moving the allocation is constant time apart from destroying a previous destination. All use of indices and pointers requires caller validation; no internal synchronization is provided.

Storage and construction

The raw inline union holds N element slots aligned for T; default construction creates no elements. Count, count/value, generator, list, and class-argument constructors construct the requested active prefix. Count and list constructors reject counts greater than N independently of Sf. max_size() and static_size equal N; size() is the live prefix. npos equals N.

Copying constructs the source's live prefix. A converting constructor from another capacity or a heap vector truncates to min(source.size(), N). A move relocates elements into the destination's inline buffer and resets source length; it is linear, not a pointer transfer. reserve and resize are deleted. swap performs three such moves.

Access and modification

Supports append, emplacement, middle insertion, erasure, fill, linear search, pop_back, and pop_front. Both pop functions return the removed value; popping the front shifts the remaining prefix. Insertion accepts the logical end if capacity remains. find returns nullptr for absence, while find_index returns npos.

Subscript is always unchecked. at(index) checks live length when Sf is true. Indexed get/cget and two-index slices check capacity instead: pointers can designate unconstructed slots, and slice construction must not copy from them. The pointer form of at uses a predicate accepting end() even though dereferencing that position is invalid. Checked push operations reject full capacity. Public __set_size writes length directly without construction, destruction, or clamping.

Complexity and iterator invalidation

Access and append within capacity take constant time. Middle insertion, erasure, and pop_front are linear in the shifted suffix; copy and move are linear in live element count. Search and full fill are linear. No operation allocates or relocates the underlying buffer. Changes within the prefix alter the meaning of positions at and after the changed index; growth or shrink changes the end iterator. Destruction ends the lifetimes of the active prefix.

Notes

The nontrivial-element append(other) body assigns into unused tail slots instead of constructing them; it does not establish object lifetimes there. A converting move to a smaller capacity resets the entire source length after moving only the retained prefix; source tail objects are not destroyed by that path. Prefer the ordinary emplacement and same-capacity movement paths when those element-lifetime distinctions matter. No synchronization is provided.

Member types and construction

const_iterator is const T*; the mutable iterator alias is private. Default construction is deleted, but count-zero construction is supported. Count, repeated-value, generator, list, mutable-vector copy, and raw-chunk constructors are provided. Copy construction deep-copies the live values and reserves for the source capacity. Move construction transfers the allocation and empties the source. micron::to_persist(vector) constructs this copied contiguous representation, not a pvector.

Value-returning operations

push_back, push_front, emplace_back, insert, erase, pop_back, append, assign, and clear return a separate ivector. They do not mutate the original. operator+ concatenates sequences. clear() returns a new empty allocation sized for the original capacity. The original retains its values and storage.

data, ordinary element access, and iteration expose const elements. capacity() and max_size() report allocated capacity. Index-based insertion requires a position strictly below the current size with checks enabled; appending uses push_back. Range slicing checks allocated capacity rather than live size. find returns nullptr for absence.

The container object remains assignable and swappable. Public inheritance exposes a mutable memory pointer and low-level resource members outside the const element-access model. into_bytes() const returns an independently allocated byte copy; changes to that copy do not modify this vector.

Complexity and iterator invalidation

Element access and size queries are constant time. A value-returning insertion, append, erase, or pop copies the retained elements into a new allocation and is linear in result/input length. Repeated appends therefore take quadratic total copying work. Copy construction is linear; move construction transfers ownership in constant time.

Creating a derived value leaves the original's pointers and iterators valid. Assignment to the original, moving it, destroying it, or releasing its inherited resource can invalidate them. Simultaneous const access requires that the owning object and element state remain unchanged; the class has no mutex.

micron::pvector

Defined in header <micron/vector/pvector.hpp>.

A persistent variable-length sequence implemented by a shared branching trie with path copying and a compile-time maximum capacity.

Template parameters and representation

T satisfies is_movable_object. K is 1 through 6 and determines branching B = 2^K; H is 1 through 8 and determines trie height. The static capacity is B^H, or 32768 with the defaults. The product must fit usize. Sf, defaulting to true, controls guarded bounds and capacity checks.

The object stores a root pointer and a logical size. Leaves contain B live objects, including defaults beyond the logical end of a partial leaf. Null subtrees denote implicit defaults. Nodes and leaves use abc allocation directly and atomic reference counts. An edit returns a new root and shares every untouched subtree. There is no contiguous data() buffer or allocator template parameter.

Value operations

Default construction is empty and allocates no trie nodes. Count/value, list, pointer/count, C-array, generic-container, and index-generator constructors are available. size() reports logical size; max_size() reports the static hard limit. identity() returns root identity. Copy construction and clone retain the root in constant time; move construction transfers it. Assignment additionally releases the old destination tree.

set, update, push_back, emplace_back, and pop_back return new versions. pop_back writes a default at the former last index and decreases size; it does not prune the branch. insert, erase, resize, append, remove, fill, assign, map, and filter also return values. clear returns a new empty value. append(first, count) where first is const T& treats its address as the start of count contiguous source elements; it does not repeat that value.

operator+(pvector) concatenates. Arithmetic with a scalar transforms every live value. Reductions include sum, product, ordered difference/quotient, min/max, and two forms of reduce. for_each visits live elements with their indices. sort copies live values into a temporary contiguous buffer, heap-sorts it, and builds a fresh trie.

Element access and complexity

at, checked edits, and empty-sensitive members use Sf-guarded checks. get and single-index subscript are always unchecked. Two-index subscript returns a newly built vector containing the requested nonempty range; it is not a view. find returns end() when absent, unlike the null-pointer convention of contiguous vectors.

Lookup and iterator dereference traverse H levels. A point update allocates a path of H nodes, copies the child table at each internal level, and copies or default-constructs B leaf values: O(B * H) work and H allocations. Retaining a version costs constant time, while destroying its final unique nodes is proportional to those nodes and their elements.

An insertion or erasure repeats path copying for the shifted suffix, taking O((size() - position) * B * H) work. Range extraction, append, map, filter, scalar transforms, and resize likewise repeat point updates for their affected elements. Most index-based reductions and searches cost O(size() * H); sum and for_each traverse the tree directly. Sorting uses O(n log n) heap comparisons, O(n * H) value lookup work, and a temporary array of n elements, in addition to the new trie.

Iterator invalidation and thread safety

Producing a new version leaves every retained original version unchanged. A reference into a leaf remains valid while a retained version owns that leaf. An iterator stores a pointer to the owner object and an index only; replacing or destroying that owner changes or ends its observations even if another container still shares the old root.

Atomic reference counting supports separately published versions, not concurrent assignment to one root variable or synchronization of state reachable through T. Updates that copy existing leaves require actual copying support from T despite the broad class-level movable constraint. The current multi-update and temporary-sort paths do not uniformly provide cleanup for every throwing element operation.

Storage and synchronized operations

The allocation and capacity model matches vector, with an additional fast_mutex. Count/list/value construction, deep-copy construction, move construction, copy/move assignment, resize, append, weld, insertion, erasure, sorting, and clearing are provided. Copy construction captures and copies a locked source snapshot. npos is the largest size_type value; find_index returns it on absence.

push_back, emplace_back, move_back, reserve, size queries, index search, contains, removal, fill, and clear acquire the mutex. Const subscript, const at, and const front/back copy the selected value while locked. for_each(fn) holds the mutex across every callback. append, weld, swap, and copy assignment acquire both involved mutexes in address order. remove(values...) performs a separate locked pass per value rather than one combined atomic operation.

Escaping references and thread safety

Nonconst subscript, at, front, and back return references after releasing their temporary lock. data, begin/end, get/cget, itr, and last provide unsynchronized pointers or iterators. These results require external exclusion from conflicting element writes, reallocation, and destruction. Slice and byte-slice members instead copy under the lock and return independent owned snapshots.

Move construction transfers a source resource without taking its mutex; move assignment locks only the destination. The source therefore requires exclusive ownership during those operations. Low-level inherited resource access bypasses the mutex. Callbacks invoked by for_each must not call another locking member of the same container: the mutex is not recursive. A const for_each body still passes elements through the stored mutable pointer.

Complexity and iterator invalidation

Apart from lock waiting and element copies, mutable-vector access, growth, search, suffix-shifting, and invalidation bounds apply. sort holds the lock while copying to a temporary ordinary vector, sorting it, and copying values back, so it uses an additional O(size()) element buffer. Mutex acquisition does not extend the lifetime of returned pointers and does not make an externally retained iterator safe during growth.

Member types and storage

N must be a positive power of two and satisfy the underlying carray<T, N> extent constraint. A carray member default-constructs all N slots. The ring stores a read index, a write index, and a logical count; wrapping uses N - 1 as a bit mask. max_size() and capacity() both return N.

difference_type is ptrdiff_t; iterator is circular_iterator<false> and const_iterator is circular_iterator<true>. Logical elements need not occupy one contiguous physical run. data() returns the physical buffer base, which need not be the logical front.

Operations

push, push_back, move_back, and emplace_back assign into the next existing slot. At full capacity they advance the front index and discard the oldest logical value. pop() moves out the oldest value and returns T{} when empty; pop_front() only advances the front and is a no-op when empty. Popping does not destroy the vacated slot.

clear() resets indices and count. For nontrivially destructible T, it additionally assigns T{} to the live logical slots. Copy/move construction linearizes logical contents into the destination's physical prefix; moving also clears the source. The carray member continues to own every physical element lifetime.

at always checks the logical index. Subscript and front/back checks depend on Sf. Push/pop/copy/move members are noexcept; throwing element construction or assignment therefore cannot be treated as a recoverable container exception.

Complexity and iterator invalidation

Indexing, push, pop, and iterator arithmetic take constant time, apart from the element operation. Default construction constructs N slots. Copy and move construction additionally copy or move live logical values. Clear is constant time for trivial destructors and linear in logical size otherwise.

Physical element addresses never reallocate. An iterator stores the owner and logical offset and uses the owner's current front index at dereference. Popping the front, overwriting a full ring, or clearing can therefore retarget an existing iterator to a different element. Saved physical references refer to slots whose values can be overwritten by future pushes. No synchronization is provided.

micron::reserved_vector

Defined in header <micron/vector/reserved_vector.hpp>.

An owning contiguous sequence that reserves a maximum virtual address range and commits pages during growth without moving existing elements.

Reservation and capacity

Default construction is uninitialized and empty. initialize(maximum) reserves a page-rounded PROT_NONE mapping. It rejects zero maximum, byte-size overflow, and alignof(T) > page_size. Reinitializing an existing reservation succeeds only for the same maximum. This facility uses Linux mapping/protection behavior and is rejected for the WebAssembly target.

max_size() is the exact configured hard element limit. capacity() is the committed byte extent divided by sizeof(T), capped at that limit. try_reserve(count) grows committed storage geometrically by replacing the new page prefix with readable/writable pages at its fixed address. It constructs no elements and returns false if the request or mapping fails.

try_resize(count) calls try_reserve, default-constructs a growing suffix, or destroys a shrinking suffix. The committed capacity is retained after shrink or clear. No append, middle insertion, iterator aliases, or begin/end members are declared; access is through data and unchecked subscript.

Copy, move, and failure

Copy construction reserves the source maximum and copies values. An existing destination uses its own reservation during try_copy; a larger source maximum does not enlarge that reservation, and copying fails only when the source's live size cannot fit or another operation fails. Moving transfers the reservation and resets the source.

The try_ operations return booleans and are noexcept. A throwing default constructor rolls back the newly built suffix but can leave additional pages committed. A throwing copy assignment leaves the resized destination with a valid, partially assigned prefix. The ordinary copy constructor and assignment report a memory error when their boolean copy operation fails. release() destroys live elements and unmaps the entire reservation.

Complexity and iterator invalidation

Indexing is constant time. Reserve performs mapping work for additional pages without relocating old elements. Resize performs one construction or destruction per changed element; copying assigns every live element. Move construction is constant time. Releasing is linear in live nontrivial elements plus unmapping.

Growth within the reserved maximum preserves all existing element addresses. Shrink and clear end affected element lifetimes. Release and destruction invalidate all pointers; moving transfers the allocation to another owner. There is no internal synchronization or bounds checking.

micron::segmented_vector

Defined in header <micron/vector/segmented_vector.hpp>.

A noncontiguous indexed sequence that allocates fixed-size arena chunks and preserves existing element addresses as it grows.

Template parameters and storage

ChunkSize, defaulting to 256, must be a nonzero power of two. Resource, defaulting to arena_resource<>, supplies allocate_objects<T>(ChunkSize) and release(). The object owns that resource and an ordinary vector<T*> directory. A logical index selects a directory entry by division and a slot by the ChunkSize - 1 mask.

Default construction starts with zero live elements. Copy operations are deleted; the declared destructor and deleted copying mean no implicit move operations are provided. The class declares no element/member aliases, contiguous data, iterators, or max_size member. capacity() is allocated chunk count times ChunkSize.

Resizing and lifetime

try_resize(count) checks chunk-count rounding for overflow, grows the directory, allocates missing complete chunks, then default-constructs a growing suffix or destroys a shrinking suffix. It returns false on handled allocation/construction failure. Failure can retain newly allocated chunks; successfully constructed new elements are destroyed on construction failure and the old logical size remains.

clear() destroys live objects and sets size to zero while retaining the chunks for reuse. release() also clears the pointer directory and releases the arena. Destruction clears live elements before the owned resource and directory are destroyed. Subscript is unchecked, including during internal construction of a new suffix.

Complexity and iterator invalidation

Indexing takes constant time with one directory lookup. Resizing performs one element operation for each changed live element, plus allocation of missing chunks and any pointer-directory relocation. Clear is linear for nontrivial destructors and constant time for trivial ones. Directory growth moves pointers rather than elements, so references to retained live elements survive growth. Shrink, clear, release, and destruction end the affected element lifetimes.

Chunk boundaries interrupt contiguity, and spare space exists in a partial final chunk. Choose this representation for stable indexed objects when one virtual reservation is unsuitable. Resource behavior determines allocation costs and limits; no synchronization is provided.
