Mutexes and locks

From micron reference
micron reference › Concurrency

Exclusive, shared, queued, recursive, and futex-backed locks provide distinct waiting and ownership protocols. Scope wrappers release acquired locks; they do not own the lock objects themselves.

Backoff, diagnostics, and ordering

spin_policy is a structural value with pause_cap, spin_rounds, and yield_rounds. The predefined policies are spin_only, spin_yield, and spin_park. spin_step reports spun, yielded, or park. default_backoff and park_backoff select the latter two escalating policies. A lock must explicitly implement parking: the generic backoff's relax() yields when its policy reports park.

Defaults are controlled by MICRON_LOCK_SPIN_LIMIT (64 pauses), MICRON_LOCK_SPIN_ROUNDS (6 pause rounds), and MICRON_LOCK_YIELD_ROUNDS (4 yield rounds). MICRON_LOCK_STATS enables acquisition/spin/yield/park counters; otherwise the statistic accessors report zero. MICRON_LOCK_DEBUG enables misuse traps in the sites that explicitly invoke them. It does not add universal ownership checking.

full_barrier(), read_barrier(), and write_barrier() issue sequentially consistent, acquire, and release thread fences. compiler_barrier() supplies an empty compiler assembly memory clobber. forced_read_barrier(x) is a GNU statement expression forcing a register read; it is not an atomic load or a lock.

Multiple locks

lock_all and lock acquire distinct locks using a rotating retry strategy: block on one lock, try the others, release acquired locks on failure, rotate to the failed lock, and yield. try_lock_all performs one ordered attempt, releases its acquired prefix on failure, and returns the zero-based failed index or -1 on success. try_lock converts this result to a boolean.

lock_in_order simply acquires left to right. try_lock_in_order short-circuits on failure and retains earlier acquisitions; the caller must release them. unlock calls the supplied objects left to right. None of these functions adds rollback when a user-supplied lock operation throws. Duplicate references and inconsistent external locking protocols are unsupported. A successful uncontended pass takes linear work in the number of locks.

Availability

mutex/rcu.hpp encloses all RCU declarations in #if 0. It provides no usable rcu_domain, rcu_ptr, reader guard, or retirement facility in this version.

micron::mutex

Defined in header <micron/mutex/mutex.hpp>.

A nonrecursive exclusive test-and-test-and-set lock with sequentially consistent acquisition and release.

Operations

lock() and operator()() wait for ownership and return a member-function pointer that unlocks this object. retrieve() returns the same handle without acquiring. try_lock() attempts one weak compare-exchange and may fail spuriously. unlock() clears the token. is_locked() and operator!() observe the token without acquiring it.

Contention polls with relaxed loads, pauses, then yields through default_backoff. Release by an execution context that does not own the lock is unsupported.

Lifetime and complexity

The lock object must remain at a stable address until its holder and all waiters have finished. These locks are neither copyable nor movable. Except for the explicitly recursive lock, acquiring a lock already held by the same execution context is unsupported. Destruction does not release a held lock or wait for outstanding users.

An uncontended acquisition and release use a constant number of atomic operations. Waiting has no finite step bound; a successful acquire requires the previous holder to make progress. Queue order, where provided, does not bound scheduling delay. Observation functions return snapshots and do not grant ownership.

micron::null_lock

Defined in header <micron/mutex/mutex.hpp>.

A lock-compatible object whose operations perform no synchronization.

Operations

lock, operator(), unlock, and the retrieved unlock handle are no-ops. try_lock() always returns true; is_locked() is false and operator!() is true. Copy and move are deleted. All operations have constant work. Shared mutable state still requires external synchronization.

micron::basic_ticket_lock

Defined in header <micron/mutex/locks/ticket_lock.hpp>.

A cache-line-aligned FIFO lock based on monotonically advancing 32-bit ticket counters.

Tickets and aliases

lock() obtains a ticket with fetch-add and waits with acquire loads until serving() equals it. The wait uses distance-proportional pauses capped at 512 and the selected backoff. Unlock increments the serving counter with release ordering. try_lock() succeeds only if no ticket is outstanding and one weak compare-exchange reserves the next ticket; it can fail spuriously.

An optional seed initializes both counters. queued() is the unsigned counter difference and includes the holder. Counter wrap requires that outstanding tickets never become ambiguous across the 32-bit space. No native-thread owner check is performed. ticket_lock selects spin_yield; ticket_spin_lock selects spin_only.

Lifetime and complexity

The lock object must remain at a stable address until its holder and all waiters have finished. These locks are neither copyable nor movable. micron::queuing_mutex

Defined in header <micron/mutex/mutex.hpp>.

An MCS exclusive lock whose caller supplies one node for each outstanding acquisition.

Node protocol

mcs_node contains an atomic next pointer and a waiting flag. node_type aliases it. lock(node) publishes the node at the queue tail, links it from its predecessor, and waits on its own flag. operator()(node) also returns the unlock member-function handle taking that node. try_lock(node) attempts an empty queue with one weak compare-exchange and may fail spuriously.

unlock(node) either removes the final tail or waits for its successor link before clearing the successor's waiting flag with release ordering. The same node must be supplied for release. A node cannot be moved, reused, destroyed, or shared between active acquisitions. Queue order follows the atomic tail exchange, rather than entry to lock().

queue_lock is an alias for this explicit-node lock; scoped_lock supplies the node automatically. enqueued() counts arrivals only when lock statistics are enabled. Release may briefly wait for a successor to finish linking, and no finite bound is supplied.

Lifetime and complexity

The lock object must remain at a stable address until its holder and all waiters have finished. These locks are neither copyable nor movable. micron::mcs_lock

Defined in header <micron/mutex/locks/mcs_lock.hpp>.

An MCS lock with an implicit node obtained from a bounded thread-local slot table.

Slots and release

Each thread has MICRON_MCS_DEPTH slots, default 8, for distinct active locks. Idle slots can be reused; a unique lock generation distinguishes a new lock at a recycled address. Exhausted blocking acquisition reports a thread error; try_lock() returns false. node_type is mcs_node.

The acquiring thread must remain alive while its node is queued or held. unlock() releases the lock's published holder rather than checking the calling thread; an already unheld lock is a no-op. This permits explicitly coordinated release by another thread but does not make concurrent duplicate releases valid. holds() checks whether this thread's slot is the published holder. Reentry into an active acquisition is rejected or waits up to MICRON_MCS_RECURSION_ROUNDS before reporting a nonrecursive-lock error.

Slot lookup scans at most MICRON_MCS_DEPTH entries. Node handoff has the waiting behavior of queuing_mutex; no per-acquisition heap allocation occurs. Destruction only removes the calling thread's slot-table association and requires that all acquisitions have finished.

Lifetime and complexity

The lock object must remain at a stable address until its holder and all waiters have finished. These locks are neither copyable nor movable. micron::basic_clh_lock

Defined in header <micron/mutex/locks/clh_lock.hpp>.

A bounded CLH queue lock with nodes stored inside the lock object.

Storage and admission

MaxThreads defaults to 32 and must be positive. The inline arena contains MaxThreads + 1 clh_node objects, including the initial dummy. Each node contains an atomic locked flag; node_type aliases it. Admission draws or recycles a node, publishes it as tail, and waits on the predecessor's acquire-loaded flag. Release recycles the inherited predecessor, then release-clears the holder's node.

Blocking admission reports a thread error if no arena node is available. try_lock() only proceeds from an apparently empty queue; it can fail from pool exhaustion or weak-CAS failure and can wait for a predecessor while resolving a race after its attempted tail update. It is not a strict bounded-step operation. participants() reports the number of nodes ever drawn beyond the dummy, rather than the current waiter count.

clh_lock is basic_clh_lock<32, spin_yield>. Pool search takes up to linear work in MaxThreads; storage is linear in that bound. The queue waits by polling/backoff, despite the source comment describing no spin waiting.

The lock object must remain at a stable address until its holder and all waiters have finished. These locks are neither copyable nor movable. micron::futex_mutex

Defined in header <micron/mutex/locks/futex_mutex.hpp>.

An adaptive native-thread mutex using a three-state atomic word and private futex waits.

Acquisition and timing

State 0 is free, 1 is held, and 2 is contended. A strong acquire CAS handles the fast path. After bounded pause-only backoff the slow path exchanges state 2 and futex-waits while another holder owns it. Unlock release-exchanges 0 and wakes one waiter if the old state was contended. Wait errors are retried and no fairness or owner validation is supplied.

try_lock_until(deadline) uses an absolute monotonic timespec but checks availability before checking the deadline. It may therefore acquire an immediately available mutex after the nominal deadline. Its futex waits use recomputed relative time remaining; timeout or clock failure returns false. try_lock_for(ns) constructs that deadline in nanoseconds, falling back to one try-lock if the clock fails; arithmetic overflow is unchecked.

timed_mutex and adaptive_mutex are aliases, not separate implementations. is_contended() and is_locked() are snapshots. A caller cannot use this blocking mutex from a scheduler worker without potentially blocking that worker.

Lifetime and complexity

The lock object must remain at a stable address until its holder and all waiters have finished. These locks are neither copyable nor movable. Except for the explicitly recursive lock, acquiring a lock already held by the same execution context is unsupported. Destruction does not release a held lock or wait for outstanding users.

An uncontended acquisition and release use a constant number of atomic operations. Waiting has no finite step bound; a successful acquire requires the previous holder to make progress. micron::recursive_lock

Defined in header <micron/mutex/locks/recursive_lock.hpp>.

An exclusive native-thread lock with a recursion depth and thread-local owner stamp.

Ownership

Each thread lazily obtains a distinct stamp from a global atomic counter. Reacquisition by that thread increments the depth; the first acquire claims owner 0 and sets depth 1. Every acquire requires a matching unlock. The final unlock release-clears the owner. lock_depth() returns a snapshot.

try_lock() can fail spuriously when claiming an unowned lock. Wrong-owner or zero-depth unlock invokes the optional misuse diagnostic. Recursion-depth overflow is unchecked. TLS identity is native-thread identity: unrelated coroutines running on the same thread are not separate owners for this lock. It is unsuitable for retaining recursive ownership across scheduler migration.

Lifetime and complexity

The lock object must remain at a stable address until its holder and all waiters have finished. These locks are neither copyable nor movable. micron::basic_shared_mutex

Defined in header <micron/mutex/locks/shared_mutex.hpp>.

A reader-writer lock with a writer bit, a 31-bit reader count, and queued-writer preference.

Shared and exclusive operations

Exclusive lock increments the queued-writer counter and waits until the state is zero, then acquire-sets its writer bit and decrements the queued count. New readers wait while a writer is queued. Shared acquisition increments the reader count with acquire CAS if no writer bit is set. Unlocks release state and wake all, or decrement the reader count and wake when the last reader departs.

try_lock uses one strong CAS. try_lock_shared checks queued writers and performs one strong reader-count CAS; a concurrent state change can make it fail without an exclusive holder. The reader count is not checked against overflow. Default P is spin_yield; a policy that reports park uses private futex waits on the state word. While queued writers are observed, reader backoff yields rather than parking.

shared_mutex selects the default policy. readers(), writers_queued(), and is_writer_held() are snapshots. Readers already admitted can finish while writers wait. The code supplies no upgrade/downgrade operation and no FIFO ordering among writers.

Lifetime and complexity

The lock object must remain at a stable address until its holder and all waiters have finished. These locks are neither copyable nor movable. Except for the explicitly recursive lock, acquiring a lock already held by the same execution context is unsupported. Destruction does not release a held lock or wait for outstanding users.

micron::seqlock

Defined in header <micron/mutex/locks/seqlock.hpp>.

A sequence-counter snapshot wrapper for a trivially copyable payload, with serialized writers.

Operations and memory model

value_type is T; Lock defaults to fast_mutex. Writers lock, change the sequence from even to odd, copy or mutate the payload, then release-publish the next even sequence. load() copies sizeof(T) bytes and retries unless the same even sequence is observed before and after the copy. try_load(out) makes one attempt and may modify out even when returning false. sequence() and writing() observe the counter.

The payload is copied and written through ordinary non-atomic bytes. Sequence validation and fences do not remove a C++ data race between a reader copy and a concurrent writer. Consequently this implementation is not a generally data-race-free snapshot mechanism for concurrent C++ accesses; use only with an explicitly suitable external/platform memory model or external exclusion. A callback passed to write() executes inside a noexcept operation and must not throw.

An uncontended read copies sizeof(T) bytes; retries are unbounded and a suspended writer with an odd sequence prevents readers from finishing. Sequence wrap can make an intervening change invisible if a reader spans a complete 32-bit cycle. Storage is inline and no pointer lifetime or pointee reclamation is provided.

micron::lock_guard

Defined in header <micron/mutex/locks/guard_lock.hpp>.

An immovable scope owner using a micron lock's reset member-function handle.

Construction

The M& constructor calls m() and destruction invokes its returned handle. Adopt-lock constructors retrieve the handle without acquiring. The supplied mutex must already be held for adoption, and must outlive the guard. The ordinary M* constructor calls the pointer variable as a function and is ill-formed when instantiated; use the reference constructor. Copying is deleted and no move operation is provided.

micron::auto_guard

Defined in header <micron/mutex/locks/auto_lock.hpp>.

An immovable scope owner that calls M::lock() and invokes the returned reset handle at destruction.

Requirements

M defaults to mutex and must satisfy the micron mutex constraint and the reset-member-function protocol used by this guard. The guard stores a reference, allocates no memory, and cannot outlive the lock. It supplies no deferred, adopted, or manual release operation.

micron::unique_lock

Defined in header <micron/mutex/locks/unique_lock.hpp>.

A movable scope owner with a compile-time initial acquisition policy.

Initial state and operations

The first template parameter is lock_starts: locked acquires, adopt retrieves a handle for an already held lock, defer and unlocked retain an unlocked mutex, and attempt performs one try_lock. M defaults to mutex. Constructors accept a pointer or reference. Copying is deleted; move transfers the pointer and ownership handle, clearing the source.

lock() does nothing when already held; try_lock() returns false when already held. unlock() releases only an owned lock. These operations report a library error when no mutex is associated. release() returns the associated mutex pointer, clears the guard, and does not unlock it; the recipient must release any retained ownership. Destruction and move assignment release current ownership. swap() exchanges state in constant time.

micron::free_guard

Defined in header <micron/mutex/locks/guard_lock.hpp>.

A movable scope owner for an atomic_flag test-and-test-and-set acquisition.

Operations

Template orders Aq and Rl default to acquire and release. Ordinary construction acquires through flag.ttas(Aq, Rl); the token clamps a release failure order to relaxed. Adopt, defer, and try-to-lock tags select the corresponding state. lock, try_lock, unlock, owns_lock, and boolean conversion track this guard's ownership. Ordinary acquisition requires a non-null flag.

Move transfers the flag pointer and held state. Destruction clears the flag with Rl only when owned. release() relinquishes the pointer and ownership record without clearing the flag. Escaping the guard therefore requires a separate eventual release. All state operations are constant work apart from acquisition contention.

micron::scoped_lock

Defined in header <micron/mutex/locks/queue_lock.hpp>.

An immovable MCS scope guard containing its own acquisition node.

Operations

Default construction is empty. Construction from queuing_mutex& acquires using the inline mcs_node. acquire(m) is a no-op while already held; try_acquire(m) returns false while held. release() and destruction unlock the recorded queue using that same node. This is a single-queue guard, not the variadic multiple-lock wrapper. The guard and underlying queue must remain live and at stable addresses until release.

micron::shared_lock

Defined in header <micron/mutex/locks/shared_mutex.hpp>.

A movable scope owner for shared ownership of a reader-writer mutex.

Operations

M defaults to shared_mutex. Default construction is empty; reference constructors acquire immediately, defer, adopt, or try according to the supplied tag. lock() does nothing if held or empty; try_lock() returns false in those cases. Unlock and destruction call unlock_shared only when owned. Move transfers ownership, releasing the destination's current lock first.

release() clears this wrapper and returns its mutex pointer without unlocking. owns_lock() and boolean conversion observe the wrapper's shared ownership. The mutex must outlive the guard. Wrapper state changes are constant work apart from the mutex's shared acquisition.

micron::lock_set

Defined in header <micron/mutex/locks.hpp>.

An immovable scope owner for a nonempty compile-time pack of lock references.

Acquisition and tags

Ordinary construction uses the rotating multiple-lock acquisition algorithm. Construction with adopt_lock records already acquired locks. Destruction and unlock() release in reverse argument order; repeated unlock() is a no-op. All referenced locks must remain live. The object stores one erased reference record per lock in an inline array.

adopt_lock_t, defer_lock_t, and try_to_lock_t are empty explicit-construction tag types with constants adopt_lock, defer_lock, and try_to_lock. Only adoption is a lock_set constructor; the other tags serve the individual guards. Uncontended acquisition, release, and storage take linear work/space in the number of locks.

micron::do_once

Defined in header <micron/mutex/once.hpp>.

Runs a compile-time selected callable once to successful completion per callable specialization.

State and retry

Each do_once<F> specialization shares one static atomic byte gate across all constructor argument packs. Construction claims uninitialized state, invokes F(args...), then release-publishes done; other constructors acquire-observe the gate and yield while a call is in progress. If invocation unwinds, a guard resets the gate to uninitialized so another constructor can retry. An exception can therefore repeat partial effects; use an effectively nonthrowing callable when exactly-once effects are required.

Completed construction takes constant work and stores no per-object ownership. Contending construction waits for the active invocation. Recursive construction of the same specialization waits on itself. Copy and move are deleted.

micron::token

Defined in header <micron/mutex/token.hpp>.

A one-shot flag with a legacy mutex-shaped callback for subsequent calls.

Call protocol

token_function<R, Args...> is the corresponding function-pointer alias. Although template parameters expose callback object and member-function types, static assertions require T = mutex* and A = void (mutex::*)(). The object stores a callback, an internal mutex, and an atomic fired flag.

operator()() makes one weak compare-and-swap from false to true: success returns true without invoking the callback; subsequent or spurious-failure calls invoke the callback if present and return false. The callback receives the internal mutex pointer and an unlock handle, but the token does not acquire that mutex first. Concurrent callback invocations are not serialized. The object is neither copyable nor movable and does not implement cancellation or stop-token registration.

micron::spin_policy

Defined in header <micron/bits/__backoff.hpp>.

Compile-time values selecting a lock's pause and yield progression.

Fields and aliases

pause_cap caps an exponentially increasing pause burst; spin_rounds controls how many calls perform pauses; yield_rounds controls subsequent scheduler yields before reporting spin_step::park. spin_only, spin_yield, and spin_park are predefined policy values. default_backoff and park_backoff alias the corresponding implementation specializations and expose next, relax, reset, rounds, and width.

These values select waiting strategy, not ownership or a memory order. A park result is a request for the enclosing lock to perform a wait; generic relax() instead yields. Backoff objects use inline counters and allocate no memory.

mutex::lock()

Waits until the mutex is acquired and returns an unlock member-function handle.

Defined in header <micron/mutex/mutex.hpp>.

auto lock();

Return value

A member-function handle used by micron's lock wrappers to release this mutex.

Notes

The call waits until it acquires the mutex. The mutex must be released after the protected work completes.

mutex::try_lock()

Performs one weak compare-exchange attempt without waiting. Returns true on acquisition; false may also be spurious.

Defined in header <micron/mutex/mutex.hpp>.

bool try_lock() noexcept;

Return value

True if the mutex was acquired. A false result may indicate contention or a spurious failure of the single weak compare-and-swap attempt.

mutex::unlock()

Releases the mutex.

micron::lock_guard<M>

Acquires an M& and releases it at scope exit. The adopt-lock constructors assume ownership of an already held lock. The ordinary M* constructor is ill-formed when instantiated.

Example

#include <micron/mutex/mutex.hpp>
#include <micron/mutex/locks.hpp>
#include <micron/sync/semaphore.hpp>

int main()
{
  micron::mutex lock;
  int value = 0;
  {
    micron::lock_guard<micron::mutex> guard(lock);
    value = 7;
  }
  micron::basic_semaphore permits(1);
  bool acquired = permits.try_wait();
  return value == 7 && acquired && !permits.try_wait() ? 0 : 1;
}
