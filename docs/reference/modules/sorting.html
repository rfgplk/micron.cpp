Sorting

From micron reference
micron reference › Algorithms

Sorting, order-statistic, and extraction functions in micron::sort. The default comparison sorter is introsort; stable sorting delegates to merge sort. Specialized integer and floating-bit radix paths provide noncomparison alternatives.

Parameters and requirements

Comparison container overloads normally use size(), indexed access, and/or flat begin() pointers. Merge sort requires data(). Iterator overloads, where provided, use half-open [start,end) random-access ranges and often require an explicit container template argument T because their parameters are T::iterator. is_iterable_container alone does not establish that these operations exist.

The default ordering is <. A supplied comparator must consistently report whether its first argument precedes the second; equivalent elements compare false in both directions. Many implementations copy keys or pivots and assign elements, so swappability alone does not provide move-only-element support. Merge scratch additionally requires default construction and copy assignment. Radix/counting record-key overloads require trivially copyable records and the corresponding key-function concept.

Prefix-limit overloads of quick, insertion, merge, stable, and as_heap clamp the requested count to the container's size and leave the suffix outside that prefix untouched. Ordinary full sorts do not resize their inputs. Exceptions are storage-replacing assignments performed by counting sort: allocation identity and pointer validity then follow container assignment rules.

Default, stable, and heap behavior

sort computes a depth budget of twice floor(log2 n), partitions ranges larger than 25 elements, and uses heapsort when that budget is exhausted. It recurses on the smaller partition and iterates over the larger. A full insertion pass finishes the remaining small runs. This combination bounds comparison work without requiring a heap allocation, but does not preserve the order of equivalent values.

stable forwards each overload to merge. The merge kernel chooses the left run on equivalent keys and reuses one allocated scratch array throughout a complete sort. merge_bottom_up performs width-doubling merge passes with the same stable kernel. Allocation and default construction of n scratch elements occur before merging; allocation/copy/comparator failures are not represented as a result error code.

sort::make_heap only establishes a max heap under the chosen comparator. sort::heap and sort::as_heap both complete a heapsort; as_heap is a chainable returning wrapper and does not leave the container in heap layout. These are distinct from the heap-manipulation functions in namespace micron.

Integer and floating keys

Counting sort computes the key span as max-min using unsigned arithmetic. A full-domain span, a span exceeding four times the input size, or a span at least 2²⁷ selects radix instead of allocating a span-sized histogram. Dense counting uses prefix sums and right-to-left scatter for stability, then assigns the scratch container back to the input.

Integer radix biases each key by the minimum key and processes significant bytes of the resulting span, including signed input without signed subtraction overflow. A 256-entry histogram is built for each pass. Container overloads copy the input container as scratch; iterator radix instead constructs a T scratch container of the range length. Projection functions can be invoked many times and must return consistent keys while sorting.

Floating radix maps 32-bit or 64-bit floating representations to unsigned keys by complementing negative bits and flipping the sign bit for nonnegative bits. This places -0 before +0 and orders NaN encodings by transformed bits; it does not implement ordinary < semantics for NaNs or collapse equivalent zero representations. The plain floating version sorts only the key representations and restores the values; the projected form scatters complete records by transformed keys. No numeric total-order guarantee beyond that transform is added.

Extracting sorted results

sorted(source[,comp]) copies an iterable range, or a supported value-only for_each source without begin/end, into a micron::vector, then calls sort. It leaves the source unchanged and uses O(n) owned output plus sorting stack. Two-argument map traversal callbacks are not covered by the value-only for_each overload merely because the source is a tree or map.

sort_into(source,out[,comp]) first builds that temporary sorted vector and then appends its values to out; it does not clear or resize out to replace existing contents. drain_sorted(heap) repeatedly calls extract_min, otherwise get, otherwise pop, until the heap is empty. Its result order is the extraction order of that heap, which can be descending for a maximum heap. It does not run a separate sorting pass. Cost is the sum of extraction costs plus output growth.

Return values and invalidation

Most named comparison sorts return the input container by reference; pointer/range overloads generally return start. heap, make_heap, counting, radix, and floating radix return void. These signatures are not uniform chaining interfaces. quickselect returns a copied element and mutates the container while locating it.

Sorting changes the value occupying an existing element position even when storage remains allocated. References/iterators may still address the same slots but must not be interpreted as following the same logical element. Scratch allocation and extraction/output growth follow the respective allocator/container failure and invalidation behavior; there is no generic optional error result for sorting.

micron::sort::__merge_buf

Defined in header <micron/sort/merge.hpp>.

Noncopyable RAII owner of the default-constructed temporary array used by merge sort.

Storage

Allocates new U[n], with one element for nonpositive requested n, and deletes the array on destruction. Copy construction and assignment are deleted. The public sorts normally create one buffer of the entire active range and reuse it for recursive or iterative merges. This helper is an implementation type rather than a general-purpose container.

micron::sort::__sort_scratch

Defined in header <micron/sort/radix.hpp>.

Noncopyable RAII array owner used for numeric sorting scratch.

Storage

Allocates new U[n] when n is nonzero and stores nullptr for zero. get() returns the pointer; destruction uses delete[]. Counting histograms and floating radix key buffers use this owner. The elements require the operations used by their kernels; the helper performs no capacity growth or bounds checks.

Example

#include <micron/algorithm/find.hpp>
#include <micron/sort/quick.hpp>
#include <micron/vector/vector.hpp>

int main()
{
  micron::vector<int> values({ 4, 1, 3 });
  micron::sort::quick(values);
  const int *found = micron::find(values.cbegin(), values.cend(), 3);
  const int *missing = micron::find(values.cbegin(), values.cend(), 9);
  return found && *found == 3 && missing == nullptr && values[0] == 1 ? 0 : 1;
}
