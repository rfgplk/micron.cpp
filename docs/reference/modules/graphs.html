Graphs

From micron reference
micron reference › Numerics and mathematics

Owning adjacency, edge-list, compressed-row, dense, bit-packed, and fixed-capacity graphs; borrowed graph adapters; graph algorithms, matrix conversions, and text/binary serialization. Representation policies control direction, parallel edges, loops, properties, and descriptor stability.

Representation selection

Container types are in micron::math; policies, concepts, adapters, algorithms, and most result records are in micron::math::graphs. The main umbrella is <micron/math/graph.hpp>. Bounded BFS and iterative Kosaraju require their individual headers. Graph I/O is in <micron/io/graph.hpp> and micron::io::graph.

Counts, costs, and properties

In complexity descriptions, V and E denote live vertices and edges; S and T denote vertex_slots() and edge_slots(). A stable graph can have S much greater than V, T much greater than E, and adjacency lists containing deleted arcs. An undirected edge has two incidences; an allowed self-loop contributes two to an owning graph's degree.

Unless stated otherwise, bounds exclude property construction, destruction, copying, comparison, allocation, weight/predicate/visitor calls, and arithmetic on user-defined types. Include these costs for the actual types. Conventional V/E-only algorithm bounds below assume packed slots and indexed adjacency. With holes, replace each complete vertex scan by S, each complete edge scan by T, and each neighborhood scan by its stored-arc length. Repeated minimum-vertex selection can therefore cost O(V*S), rather than O(V²). Edge-list/fixed graphs scan T slots for each neighborhood; dense matrices scan V entries per neighborhood; directed plain CSR scans E edges for each incoming neighborhood.

Owning graphs store property values. A pointer-valued property remains a pointer and does not acquire ownership of its pointee. Alloc is a graph-storage template parameter where provided; algorithm workspaces and result vectors generally use allocator_serial<> independently of the graph's allocator. Allocation and property-operation failures do not become algorithm_status automatically. A callback taken by value is copied/moved into the operation; state changes belong to that callable copy unless it refers to external state.

Descriptor and result conventions

A descriptor is a numeric slot, without a graph pointer or generation counter. valid() excludes only its sentinel; graph.has_vertex/has_edge checks membership. Passing a descriptor from another graph is not detected when the numeric slot happens to be live. Compaction and compact erasure can make an old descriptor denote a different object.

Algorithms usually return a record whose status must be checked. Parent, distance, color, component, score, and flow arrays commonly use raw descriptor slots, including unused slots; zero is not a universal unreachable sentinel. Result vectors own their values, but stored descriptors continue to refer to the original topology. Graph mutation can invalidate their interpretation.

Bit and matrix kernels

graphs::kernels supplies wordwise set_union, set_intersection, popcount_reduce, common_neighbor_count, expand_frontier, masked_slot_scan, dense_boolean_product, and csr_prefix_sum. These operate on caller buffers and do not allocate or retain them. Union/intersection/count cost O(words); dense Boolean product uses O(V³) scalar boolean work. csr_prefix_sum checks prefix addition overflow and can leave a partial output on false.

expand_frontier clears its destination before reading frontier words and ORs a row for each selected vertex, so the output must not overlap the frontier. masked_slot_scan writes at most capacity slot numbers and returns the number actually stored; it does not report the full required count. Caller-supplied word counts and unused tail bits must be consistent. SIMD selection is compile-time, with scalar tails and a scalar fallback; no runtime CPU detection is performed.

Lifetime and thread safety

Graph ranges, iterators, proxies, views, and property maps borrow their owner. Copying them does not retain the owner. Their invalidation follows the graph representation and any stored view object. Do not mutate topology while an algorithm or borrowed traversal is using it.

These graph objects and workspaces contain no synchronization. Separate immutable inputs can be read concurrently when properties, predicates, visitors, and allocators permit it. Reusing or modifying one graph, result, or workspace concurrently requires external synchronization. A const filtered view can invoke a mutable predicate, so constness alone does not establish concurrent-read safety.

micron::math::vertex_id

Defined in header <micron/math/graph/descriptors.hpp>.

A strongly typed integral vertex-slot descriptor with a reserved maximum-value invalid sentinel.

Descriptor family

vertex_id<I> and edge_id<I> each contain public I value, index_type, explicit integral conversion, valid(), invalid(), invalid_value(), boolean conversion, and ordered comparisons. Default construction selects numeric_limits<I>::max(). Construction from an integral type no wider than I casts the value; it does not validate signed negativity, truncation, or graph membership.

The two descriptor kinds are distinct types. All descriptor operations are O(1), allocate nothing, and do not own or retain a graph. A descriptor can remain numerically valid after its vertex/edge has been removed.

Defined in header <micron/math/graph/graph.hpp>.

A mutable compact adjacency graph with owned properties, dense vertex/edge slot vectors, and per-vertex arc indexes.

Template parameters and aliases

The template parameters are VertexProperty, EdgeProperty, GraphProperty, integral Index, Direction, Multiplicity, Loops, and Alloc. Defaults are empty properties, u32 indices, undirected simple loopless topology, and allocator_serial<>. The common descriptor/property/policy aliases describe these selections.

Storage and modifiers

GraphProperty is embedded. Each vertex slot owns its property and outgoing/incoming arc vectors; each edge slot owns its endpoints and a manually managed property. Directed edges add outgoing and incoming arcs; undirected edges add two outgoing incidences. Copies own independent properties and indexes. Defaulted moves transfer member storage; scalar live counters are not explicitly reset in the moved-from object.

add_vertex/emplace_vertex append; exhaustion of the reserved Index sentinel returns an invalid ID. Integral add_edge endpoints can default-create every missing vertex through the larger endpoint. Descriptor endpoints require existing live vertices. Unavailable default construction reports property_required. Simple duplicates return the old edge without replacing its property. Bulk insertion accounts for each attempted status.

remove_edge detaches its incidences, moves the last edge into the erased slot, and retags arcs. remove_vertex removes incident edges, moves the last vertex into the hole, and rewrites endpoints/neighbor numbers. clear destroys stored vertices/edges and resets live counts while retaining the graph property. compact rebuilds storage and returns old-to-new maps.

Access and traversal types

has_vertex/has_edge(id) are membership tests. source, target, opposite, and unchecked property access assume valid descriptors; opposite also assumes the supplied vertex is an endpoint. try_vertex_property/try_edge_property return null on invalid IDs. Checked vertex_property/edge_property trap on invalid IDs.

Complexity

Vertex insertion is amortized O(1) container work; a reallocation moves existing slots. Edge insertion is amortized O(1) after endpoint creation and duplicate lookup; simple duplicate lookup is O(outdegree). Endpoints created from a numeric gap cost O(number_created). Each incident-vector allocation contributes its own cost.

Live vertex/edge iteration is O(V)/O(E). Neighbor enumeration and degree queries are O(degree). Edge removal includes linear incident-list erasure and retagging. Vertex removal can scan and rewrite all edges/arcs, O(V+E) plus incident removals. Copying and compaction process vertices, edges, and arc indexes.

Iterator invalidation

Insertion can reallocate vertex, edge, or adjacency vectors and invalidate corresponding addresses and property references. Numeric descriptors to existing slots survive insertion. Compact erasure changes the identity of the last moved descriptor; vertex erasure also rewrites endpoints. Ranges retain slot positions, not snapshots. compact, assignment, movement, and destruction invalidate borrowed access to the replaced storage. Choose stable_adjacency_graph when unrelated erasure must preserve numeric IDs.

micron::math::stable_adjacency_graph

Defined in header <micron/math/graph/graph.hpp>.

An adjacency graph preserving surviving numeric descriptors by leaving dead vertex and edge slots after erasure.

Storage and removal

The property, policy, allocator, insertion, and access interfaces follow graph. Storage remains vector-based. Removing an edge destroys its property and clears its live flag but leaves its arc records in neighboring lists. Removing a vertex scans edge slots for incident live edges, destroys the vertex property, and clears that vertex's own arc vectors.

New elements append beyond the high-water marks rather than reusing tombstones. Iterators skip dead slots and stale arcs. Erased properties are destroyed; tombstones retain bookkeeping storage. compact discards holes and rebuilds indexes, returning compact_result maps.

Complexity and invalidation

Membership is O(1); full iteration scans S or T slots, and a neighborhood scan includes its stale arc records. Removing an edge is O(1) after validation; removing a vertex scans T edge slots. Simple duplicate lookup and degree queries traverse the stored adjacency list including tombstones. Compaction pays for old slot/index scans and construction of the live graph.

Unrelated removals preserve surviving numeric vertex and edge IDs. They do not guarantee stable element addresses: insertion can reallocate the vectors. Compaction, assignment, movement, and destruction invalidate references and can change IDs. This representation suits long-lived numeric handles when hole growth and occasional remapping are acceptable.

micron::math::edge_list_graph

Defined in header <micron/math/graph/graph.hpp>.

A compact vertex/edge-vector graph that derives neighborhoods by scanning its edge storage.

Representation and operations

It shares graph's properties, policies, allocator, insertion results, proxies, and compact erasure semantics, but does not populate per-vertex arc indexes. Edge enumeration is contiguous. Incoming/outgoing incidence, neighbors, degrees, and duplicate lookup scan stored edges.

Membership and endpoint access are O(1). A neighborhood or degree query costs O(T), and simple insertion costs O(T) for duplicate detection. Traversals repeatedly requesting neighborhoods can cost O(V*T). Erasure can move the last edge/vertex and therefore changes descriptors and property addresses as in graph. Choose this layout for edge-oriented passes when indexed traversal is infrequent.

micron::math::basic_csr_graph

Defined in header <micron/math/graph/csr.hpp>.

An owning compressed-row graph with fixed topology, densely numbered properties, sorted outgoing arcs, and optional incoming indexes.

Variants and construction

csr_graph selects csr_t; bidirectional_csr_graph selects bidirectional_csr_t and defaults to directed topology. The full class also accepts vertex/edge/graph properties, Index, direction, multiplicity, loop, allocator, and storage policies. Topology mutation is absent. Mutable property access is still provided through try/unchecked property functions, so frozen means fixed topology rather than deeply immutable properties. Arrays own their storage; copies are independent. Construction writes dense_to_vertex, vertex_remap, and edge_remap into caller-supplied vectors; freeze retains these in its representation_result, rather than in the CSR object.

micron::math::dense_adjacency_graph

Defined in header <micron/math/graph/dense.hpp>.

A simple graph storing a full V-by-V array of independently live edge-property cells.

Layout and modifiers

VertexProperty, EdgeProperty, GraphProperty, Index, Direction, Loops, and Alloc are selectable; parallel edges are not supported. Undirected endpoints use the canonical upper-triangle cell, although the full square is allocated. Presence is a live flag, so a zero-valued property can represent an existing edge. Edge ID is the cell offset u*V+v; edge_slots is V².

Adding a vertex rebuilds the square and moves existing edge properties. Numeric endpoint insertion can enlarge the matrix; descriptor insertion requires existing vertices. Removing a vertex swaps the last vertex into its slot and rebuilds/remaps the square. reserve_vertices, reserve_edges, and reserve_adjacency are no-ops. Repeated add_vertices performs repeated square rebuilds.

Traversal types and complexity

Public vertex_range enumerates vertices. basic_edge_reference<Const>, basic_edge_range<Const>, and edge_reference/const_edge_reference describe property proxies and cell scans. incidence_range<Neighbors> scans a row or column for neighbor or edge descriptors. Returned iterator classes are private implementation types. All borrow the graph.

Storage is O(V²) property-cell slots plus vertices. Edge lookup, insertion into an existing square, and edge removal are O(1). Neighborhood/degree scans cost O(V); full edge iteration costs O(V²). A vertex change costs O(V²) cell work; adding V vertices one at a time costs O(V³) cumulatively, excluding property work.

Iterator invalidation

Any vertex-count change alters the row stride and edge descriptor interpretation, rebuilds edge storage, and invalidates edge/property references. Vertex-vector growth can invalidate vertex properties. Removing an edge ends that property's lifetime. Choose this representation for dense property-bearing topology and frequent pair lookup when quadratic storage is appropriate.

micron::math::bit_adjacency_graph

Defined in header <micron/math/graph/bit.hpp>.

A simple graph with empty edge properties and u64-packed adjacency rows.

Storage and access

VertexProperty, GraphProperty, Index, Direction, Loops, and Alloc are selectable. Rows contain ceil(V/64) words. Undirected insertion sets symmetric bits, while edge IDs use a canonical u*V+v cell number; edge_slots remains V². Edge property access refers to a shared empty_property marker rather than a distinct object per edge.

bit_row contains const u64* data, words, and bits. neighbor_words returns this borrowed row descriptor. vertex_range, edge_range with const_edge_reference, and incidence_range<Neighbors> provide the public graph traversal records; their returned iterators are private implementation types.

Complexity and invalidation

Adjacency storage is O(V*ceil(V/64)) words. Pair lookup and existing-square edge updates are O(1). Out-neighbor enumeration scans words and selected bits, O(V/64+outdegree); out_degree uses word population counts. Directed incoming traversal scans a column in O(V). Full edge enumeration scans V² candidate cells.

Vertex addition/removal rebuilds topology by square scans, O(V²); repeated one-at-a-time population is O(V³). Reserve members are no-ops. A vertex-count change renumbers cell descriptors and invalidates borrowed rows and edge iteration. Use this type for topology-only dense operations and bitset common-neighbor queries.

micron::math::fixed_graph

Defined in header <micron/math/graph/fixed.hpp>.

A fixed-capacity graph with embedded vertex and edge arrays and append-only slot high-water marks.

Capacity, lifetime, and errors

VertexCapacity and EdgeCapacity precede the property/index/policy parameters. All property types must be default-constructible. Every physical property slot is constructed with the graph, including unused slots. Removal clears live flags without destroying property values; ordinary object destruction destroys the embedded arrays.

No container storage is allocated. Vertex insertion returns an invalid descriptor at capacity; edge insertion reports index_overflow. Erased slots are not reused, so capacity bounds lifetime append counts rather than current live counts. There is no clear/compact member. Both numeric and descriptor add_edge overloads can create missing default vertices. Defined in header <micron/math/graph/traversal.hpp>.

Capacities are integral and nonnegative; costs are signed arithmetic and finite. capacity_cost_property provides the default .capacity and .cost fields. Explicit capacity/cost maps follow the ordinary weight-map dispatch. Graphs must be directed, and source/sink operations require distinct live endpoints. Capacity, cost negation, flow totals, and final flow-times-cost arithmetic have explicit overflow checks.

min_cost_max_flowMaximize source-to-sink flow, then minimize its cost

Implementation and workspace

min_cost_flow_workspace<I,Capacity,Cost> owns residual rows, original capacities/costs, locations, levels/cursors, queue, potentials, shortest-search parents/flags, and binary heaps. Public arc_type and arc_vector name min_cost_residual_arc and its vector. edge_location contains source and arc offset. min_cost_residual_arc contains target, reverse, capacity, cost, original edge ID, forward, and auxiliary flags. Unlike the standalone max-flow construction, reverse indices account for self-loops.

The solver first attempts potential-based reduced-cost augmenting paths. If that path is inapplicable, Dinic obtains the required feasible flow; repeated Bellman-Ford negative-cycle cancellation then improves the full residual circulation. Disconnected negative-cost cycles can therefore alter flow and total cost even outside a source-to-sink path.

Circulation construction visits live vertices; nonzero supply entries for dead slots are not used in construction, while the circulation verifier rejects them. Supply arrays should therefore use zero for holes. feasible() means status==ok. Failure records can contain partial scalar progress, so inspect status before consuming arrays.

Complexity and lifetime

Let A be the number of shortest-path augmentations and K the number of canceled cycles. Potential/cycle searches use up to O(V*E) relaxation work per search; heap augmentation adds O((V+E)*log(V+E+1)) per augmentation, plus any feasibility-flow work. Cycle cancellation is value/cost dependent; no strongly polynomial bound is supplied by this implementation.

Residual/search storage is O(S+T+E), and results use O(S+T). reserve reuses outer buffers, but residual.clear/resize rebuilds nested arc vectors, and returned arrays allocate independently. Reuse of a workspace is not an allocation-free guarantee. Results own numeric arrays tied to original descriptor slots.

micron::math::graphs::matching_result

Defined in header <micron/math/graph/matching.hpp>.

An owned matching cardinality, slot-indexed mate descriptors, selected edge IDs, and status.

Matching and edge cover

greedy_maximal_matching visits edges once, skips loops and endpoints already used, and returns a maximal matching in enumeration order. Its O(S+E) work does not guarantee maximum cardinality. validate_matching checks that selected edges are live, loopless, endpoint-disjoint, and equal in count to cardinality; it does not validate mate-array consistency or optimality.

hopcroft_karp first runs bipartite_test, rejecting nonbipartite input. Directed input is treated as undirected by searching outgoing and incoming neighbors. It repeatedly builds BFS layers and recursively searches augmenting paths, then finds representative original edges for the final mates. Each layer build is adjacency-linear. Failed recursive searches mark an active flag that subsequent recursion does not consult, so the usual O(E*sqrt(V)) optimized Hopcroft-Karp bound is not established by this body; repeated DFS visits contribute additional work.

minimum_edge_cover starts with hopcroft_karp's edge list and adds an incident edge for uncovered vertices. It returns only an edge vector, does not propagate the matching status, and cannot cover isolated vertices. Its minimum-cover interpretation requires bipartite input without isolated vertices. General graphs should use maximum_cardinality_matching for maximum matching, rather than assuming the edge-cover wrapper changes matching algorithms.

Storage and invalidation

Mate arrays use S slots, selected edges O(V), and traversal state O(S+V). Recursive augmenting paths can use O(V) call depth. Results own descriptors and are not updated when the graph mutates. Representation-specific incoming scans and pair lookup also affect runtime.

micron::math::graphs::weighted_matching_result

Defined in header <micron/math/graph/blossom.hpp>.

An owned general-graph matching with original-slot mate/mate-edge arrays, edge list, total weight, cardinality, and vertex count.

Objectives and edge handling

maximum_weighted_matching rejects directed graphs and non-finite weights, ignores loops, densely numbers live vertices, and retains the highest-weight parallel edge for each unordered pair, breaking equal-weight ties by edge ID. matching_objective selects maximum_weight or maximum_cardinality_then_weight. Default maximum_weight omits nonpositive edges; the cardinality-first objective adds a magnitude-dependent bonus before solving. maximum_cardinality_matching uses unit_edge_weight and that cardinality-first objective.

The engine implements weighted blossom contraction/expansion with dual labels, slack arrays, alternating forests, and dense edge/flower-origin matrices. Integral scores use int128_t intermediates; floating scores use long double with exact comparisons. Final total_weight addition is checked, but internal score/bonus arithmetic is not uniformly overflow-checked. Engine node indices use int, independently of the graph Index; input size must fit those indices and square allocations.

Workspace and complexity

weighted_matching_workspace owns dense/original maps and V² chosen-edge/weight tables. reserve covers those buffers, but each solve creates a new dense blossom engine with its own O(V²) matrices and vectors; supplying a workspace does not retain the engine allocations.

Preparation costs O(S+E+V²), plus weight-map work. The solve performs at most floor(V/2) successful augmentation steps. Each alternating-forest search scans all vertices for queued leaves, adjusts dual/slack state, and can contract/expand blossoms; contraction scans dense node pairs and flower data. These dense operations, rather than a sparse E-only cost, determine runtime. Total auxiliary storage is O(S+V²). Coloring

greedy_coloring(graph,ordering) skips invalid vertices and assigns the lowest color absent from already colored incoming/outgoing neighbors. cut_heuristic_result<I> owns cut_edges and original-slot u8 side flags; it has no status. max_cut starts from alternating vertex sides and repeatedly flips a vertex when its outgoing same-side incidences exceed different-side incidences, then counts crossing stored edges.

Topology and property limits

Text formats carry only numeric endpoints and optional intrinsic edge weights. Vertex labels, additional properties, graph properties, dead slots, and original edge IDs are not preserved. Numeric endpoint insertion can create gap vertices; Matrix Market/DIMACS dimensions likewise populate the declared slot range. Matrix Market endpoints are not constrained to the declared dimensions when the target can autoextend.

Every attempted text edge must be newly inserted. A duplicate in a simple target reports topology_rejected rather than silently coalescing it; forbidden loops and capacity/property failures propagate through insertion status. Failure generally returns an empty graph or clears the partially built graph, rather than an accepted prefix. Error position precision varies by parser; not every insertion branch updates byte/column to the failing token.

Undirected adjacency formatting omits lower-endpoint repetitions but emits each loop incidence, so an allowed loop can be emitted twice and then rejected as a duplicate by a simple target. Weighted Matrix Market output still writes a fixed integer/general banner even when the weight's textual value is nonintegral. These formatters are topology/weight exchanges, rather than lossless property serialization.

Binary format

binary writes MCGF version 3, little-endian structural integers, index-width metadata, direction/multiplicity/loop flags, slot/live counts, and ordered live vertex/edge records. Records include serialized slot IDs and endpoint IDs. The property-free overload requires all three property types to be empty_property. The codec overload writes length-prefixed graph, vertex, and edge property payloads.

parse_binary validates version, metadata, representable slot counts, ordered unique live records, live endpoint references, accepted topology, record counts, and complete input consumption. Target policies must match metadata; its index width can be at least the encoded width. Stable adjacency imports dead slots to preserve numeric IDs. Compact targets densely reconstruct live elements and return remaps. CSR targets decode through a mutable temporary, freeze, and compose mappings.

A custom codec provides bool encode(property,byte_vector) and decode(bytes,size,property); decode_construct<P>(bytes,size,void*) is used when available to construct non-default vertex/edge properties. Without it, those properties must be default-constructible. The graph property itself must be default-constructible and is decoded into the existing object. Codec encode failure makes binary return an empty byte vector; malformed/truncated payloads return parse failure.

Native codec, file wrappers, and cost

native_property_codec copies sizeof(P) object-representation bytes, including any padding, and requires trivially copyable P. Its payload format depends on type layout, native endianness, and ABI; structural little-endian metadata does not make those payloads portable. decode requires exact size; decode_construct also requires a non-null output address and constructs P from the copied representation.

write_edge_list/write_adjacency_list/write_matrix_market/write_dimacs/write_binary format in memory, then call write_file, returning its signed max_t byte/error convention. Codec write_binary returns -22 when encoding produces an empty vector. read_* load the entire file and return option<parse_result<G>,io::error_t>: the error alternative is a file error; the parse alternative can itself contain a failed parse_status.

Text work is O(input/output bytes) plus numeric conversion and graph insertion/iteration costs. Binary scans S+T slots when encoding and constructs target topology when decoding; stable reconstruction also imports holes, and CSR adds freezing work. Codec cost includes payload bytes, temporary encoded vectors, and user encode/decode operations. All formatted/parsed outputs own their storage; input buffers and codecs are not retained.
