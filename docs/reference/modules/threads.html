Threads

From micron reference
micron reference › Concurrency

Native-thread objects own or borrow worker stacks, retain backend join state, and publish results through a small controller payload. Arenas add fixed-capacity thread ownership or persistent queued workers; CPU and scheduler wrappers configure Linux execution separately.

Backends, stacks, and arguments

Native wrappers use clone/clone3 with a fresh TLS frame under __micron_freestanding; hosted wrappers use pthread creation/join with an explicitly mapped stack. The wasm branches redirect thread, auto_thread, threads, and solo entry headers to the wasm thread API, while native arenas and their worker variants reject wasm. The coroutine task engine is also unavailable there.

The default sizes are 524288 bytes for thread and group_thread, 262144 bytes for auto_thread and status_thread, and 131072 bytes for the concurrent-arena worker. Stack_Size is the complete mapping size; the backend attempts to protect and remove its lowest page from usable stack space. Ordinary guard setup is best effort; failure leaves the complete region usable. status_thread instead reports a guard-protection error.

Ordinary launch arguments are decay-stored by value. The kernel invokes its stored function with argument lvalues, so a callable taking only an rvalue reference is not accepted by the launch constraint. Explicit pointer/reference-wrapper arguments retain caller-managed lifetimes. Hosted launch allocates an argument box; the freestanding backend allocates a payload and separate decayed argument objects. Setup failures report a thread error; only auto_thread supplies its own stack rollback guard around launch.

Results and cleanup

A void callback publishes a none tag. A trivially representable result no larger than one pointer is packed into the pointer-sized result slot; larger results and selected nontrivial class results are separately allocated with a type-specific deleter. result<R>() accepts only trivially copyable R no larger than a pointer and returns a value-initialized R for a nonliteral result. It does not check that R matches the callback's result type.

Retrieve a literal result before join: join clears the tag and destroys heap results. Ordinary wrappers expose no general typed extraction of the heap-result path. Child completion runs registered thread-local destructors and allocation/TLS exit hooks while TLS is still live. Attached TLS frames return through the host's release callback rather than being directly unmapped by the guest.

Native sleep/cancel checkpoints are reached by the sleep wrappers and explicit checkpoint calls. An ordinary compute loop is not preempted by setting the control word. Process-wide alarm/suspend/resume handlers are installed by the thread support; application handlers for those signals can interact with this behavior.

Joining and solo helpers

solo::spawn<Tr> constructs a unique owning pointer to a thread object; default Tr is auto_thread<>. Pointer overloads of join and dismiss clear that owner after forwarding the call. dismiss still joins; it is not detach. solo::kill forwards cooperative cancel, while terminate and force_stop forward the hard-stop interface. park changes CPU affinity rather than the native park word; yield(thread) sends the alarm signal.

Join return conventions differ: regular/group/worker controllers generally use 0 for successful or empty join; auto_thread::join uses 0 after release and 1 if already released, and its successful try_join returns 1. solo::try_join(owner) clears the owner only for return 1, so a successful regular-thread try-join leaves an empty controller allocated.

can_join() calls the backend try-join, not a pure ownership query. Hosted pthread_tryjoin_np actually reaps a completed thread, but can_join does not clear the stored handle. Avoid using that query before a later join on hosted wrappers. solo::is_joinable converts can_join() to bool, including a positive busy error, so it does not reliably distinguish an exited thread from a busy one.

Arena startup and limits

The standard global arena is initialized through constructor/boot hooks and intentionally retained for process lifetime. The concurrent global arena is initialized by start_concurrent_pools() unless startup concurrency is configured; it creates at most min(cpu_count(), 32) workers. end_concurrent_pools() does not shut them down or null the pointer. Concurrent calls to the plain initialization bookkeeping are not supported.

go(fn, args...) creates an arena thread, selecting a core using the current arena affinity distribution. go(core, fn, args...) chooses an explicit core. realtime selects FIFO intent and best-effort native settings; permission or affinity failure is not consistently surfaced by those arena paths. The root realtime(core, priority, fn, ...) overload forwards an extra priority argument to a creation overload that does not accept it and is ill-formed when instantiated.

maximum_threads is 1024 by default, 256 with MICRON_LOW_THREAD_COUNT, 4096 with MICRON_HIGH_THREAD_COUNT, or 32768 with ABSURD_THREAD_COUNT, in that precedence order. concurrent_threads is always 32. These are arena slot bounds, not guarantees that the operating system can create that many threads.

Cost model

Thread launch includes mapping, TLS construction/initialization, argument storage, and an OS thread-creation operation. Join has no bounded elapsed time. Arena placement and list queries can scan the arena; burden selection scans existing threads and their CPU masks. Persistent workers amortize thread creation across queued callbacks but retain their stack/TLS mappings and fixed worker queues. These storage and syscall differences do not establish a measured speedup for any variant.

micron::thread

Defined in header <micron/thread/thread_types/reg_thread.hpp>.

A native-thread controller that maps and owns its callback stack and TLS release state.

Construction and operations

Default construction is empty. A function constructor starts one child; operator[](fn, args...) joins the prior child and starts another. Destruction joins and releases. join, dismiss, and successful try_join release the stack, TLS, and retained result. Copying is deleted; move is permitted only from a controller with no backend handle, and move assignment first joins/releases its destination.

stack() exposes the owned mapping without transferring it and stack_size() returns the template size. native_handle() and thread_id() return the kernel tid obtained from the selected backend, not a pthread handle. stats() returns zero while the callback is alive, otherwise its final resource-usage snapshot. The literal-result, sleep, signal, and stop protocols are described above.

Lifetime and synchronization

A launched child retains addresses inside its controlling object. Keep that object at a stable address until it has been joined. A completed but unjoined child is still a live backend handle for the move restrictions. Manipulating one controller concurrently from multiple owner threads is unsupported.

Joining waits for backend termination before stack and TLS release. alive() observes the function-kernel flag, which can clear before the backend has finished its exit path; it is not a replacement for join. wait_for() polls that flag without releasing resources. active() probes the native tid with signal 0 and returns a snapshot.

sleep() requests cooperative parking at the next native checkpoint; awaken() clears the park word and wakes it. cancel() requests cooperative exit and joins, so a function that never reaches a checkpoint can prevent it from returning. terminate() waits up to the configured internal millisecond budget, then sends SIGKILL on timeout. Linux SIGKILL can terminate the entire thread group; this is not a safe isolated stop for arbitrary user code. Neither path unwinds the interrupted callback's stack as a C++ cancellation exception.

micron::auto_thread

Defined in header <micron/thread/thread_types/auto_thread.hpp>.

An immovable thread owner that starts from a callback and joins automatically at scope exit.

Ownership and operations

There is no default constructor. Construction maps the stack separately from the parent stack, marks the payload alive before launch, and rolls back that mapping if launch unwinds. Destruction joins a retained child. operator[] joins and relaunches using the same control object. cleanup() joins; it is not an asynchronous release.

join() and dismiss() return 0 after release and 1 if empty; successful try_join() returns 1, also the already-released value. result<R>() waits without joining and must precede join. stack() returns a byte pointer; stack ownership remains here. Copy and move are deleted because the child and kernel retain controller addresses.

micron::group_thread

Defined in header <micron/thread/thread_types/group_thread.hpp>.

A one-callback controller that adopts ownership of a caller-supplied mapped stack.

Adoption and launch

The prepared constructor takes thread_attr_t, adopts its stack pointer and scheduling fields, and launches. The attributes argument is not cleared by this const-reference adoption; it must be treated as a transferred stack description rather than an independent owner. Release unmaps exactly Stack_Size bytes, so the supplied mapping and template size must agree.

After launch the constructor waits up to the internal start-handshake budget for the child to publish started. On timeout it requests cooperative exit, joins, releases, then reports an error; the join can still wait indefinitely if the child never reaches a checkpoint. Scheduling fields are retained as intent; the launch helper itself does not apply them.

The controller can be default-constructed empty. Copying is deleted and move rejects any retained backend handle. attrs() exposes its attributes as a const reference. Result, observation, signal, and cooperative-control behavior follows the regular thread controller.

micron::void_thread

Defined in header <micron/thread/thread_types/void_thread.hpp>.

A persistent callback worker borrowing a caller-provided stack mapping.

Work and ownership

Prepared construction starts a worker, optionally submitting an initial callback. operator[](fn, args...) decay-captures a callback and values into its lambda_queue<256>, then release-publishes a work token. The worker drains callbacks serially and futex-waits when empty. The ring/payload bounds and callable-size constraints of lambda_queue still apply.

The arena owns the stack; this controller releases only its TLS and handle state. stop() requests exit and wakes the work word. Stop is tested before and between callbacks, and can abandon queued callbacks. A running callback is allowed to finish; stop does not interrupt it. Join/destruction stop and join the worker. There is no result, cancel, sleep, signal, or alive interface; those operations are deleted.

get_status() returns the work token and is_working() samples it; the token is a wake/work signal, not an exact completion counter for a submitted callback. stats() retries an ordinary resource-usage copy against a sequence counter; concurrent non-atomic payload accesses have the C++ data-race limitation of that copy scheme. Move is restricted to a controller without a retained backend handle.

micron::async_thread

Defined in header <micron/thread/thread_types/async_thread.hpp>.

An alternate persistent worker controller using the same borrowed-stack queue kernel as void_thread.

Operations

Prepared construction starts the same __worker_kernel, and operator[] enqueues a decay-captured callback in lambda_queue<256>. Stop release-stores the exit request and wakes the work token. The implementation does not expose a template parameter for a custom worker kernel despite the introductory source comment.

Stack ownership, TLS release, joining, non-result status observations, deleted control operations, sequence-copy usage statistics, and move restrictions are the same as void_thread. There is no asynchronous value result or future returned by this type.

micron::status_thread

Defined in header <micron/thread/status_thread.hpp>.

An immovable bounded freestanding callback thread with inline launch state and explicit negative-error setup.

Bounds and lifecycle

Stack_Size defaults to 262144 bytes and must be at least four default pages and a page multiple. TLS_Limit defaults to 1048576 bytes and must lie between one page and 16 MiB. reservation_bytes is their sum; mapped_bytes() reports the actual mapped stack plus TLS size when active.

start(void(*)(void*), context) returns 0 on success, -busy for an occupied controller, -invalid_arg for a null callback or unsuitable page geometry, and negative setup errors otherwise. Hosted use returns -op_not_supported. Attached freestanding execution is rejected. TLS-template size and alignment limits are checked before/after mapping; partial failure releases resources and leaves an empty reusable owner.

The callback and context are borrowed until join; no argument box or typed result is allocated. try_join() returns -busy while running or 0 after release; join() and destruction wait then release. Callback cancellation is the callback's own protocol. The public type provides no generic thread cancel/terminate methods.

micron::thread_attr_t

Defined in header <micron/thread/thread_types/thread_impl.hpp>.

A non-owning/native-control descriptor carrying thread identifiers, TLS, scheduling intent, and a stack address.

Fields and transfer

parent is the thread-group id; pid is the freestanding kernel tid; ctid is the address-bound CHILD_CLEARTID join word; tls is the child TLS frame; pth is the hosted pthread handle. Scheduling fields are sched_policy, sched_priority, sched_niceness, and detach_state; stack fields are stack_size in bytes and stack_addr.

The descriptor's destructor does not join, unmap, or free TLS. Move transfers the fields and clears source handle/stack state; it cannot safely relocate an active ctid. clear() clears handle/TLS/stack state without releasing resources. The constructor accepting pthread_attr_t ignores that argument. Passing this descriptor to a wrapper determines whether its stack is adopted or borrowed.

thread_returns names callback-kernel return_success, return_force, and return_fail; join_status names join_success, join_fail, join_allowed, and join_busy. Wrapper methods do not consistently return these enums, so inspect their documented integer conventions.

micron::thread_t

Defined in header <micron/thread/arena.hpp>.

An arena record combining a cpu_t<true> mask descriptor and one concrete thread controller.

Access and lifetime

Both cpu_mask and thread are public. operator()() returns the controller, stats() forwards its usage snapshot, and attrs() requires the concrete controller's matching member. Arena references and pointers to this record remain valid only until its slot is destroyed/reused or its arena is destroyed.

name() asks micthread::get_name, whose implementation ignores the requested tid and uses PR_GET_NAME for the calling thread. It therefore does not reliably return the represented worker's name. The 32-byte result is owned by value. This wrapper adds no synchronization to direct access of its public fields.

micron::standard_arena

Defined in header <micron/thread/pool.hpp>.

The public alias for the fixed-capacity standard arena of group_thread<> records.

Storage and operations

Aliases arena::__default_arena<thread_stack_size, group_thread<>>. The underlying template exposes type = thread_t<Tr> and thread_class = Tr, stores at most maximum_threads records inline in an fsstack, and maps one stack for each created child. Creation/list/cleanup operations serialize through an arena mutex.

create, create_at, create_burden, and their realtime variants append a record and return a reference. Burden selection counts existing affinity masks rather than sampling CPU utilization. Realtime/affinity/name changes are best effort. clean() waits for the most recently added child before popping it, so later long-lived work delays reclamation of earlier completed slots. join_all(retries) consumes one shared retry budget and eventually performs a blocking join; its retry count is not an elapsed-time bound.

list() allocates an immutable vector of borrowed record pointers. Pop/cleanup invalidates pointers to removed records. Several optional administrative members are incomplete for the provided record: priority methods refer to nonexistent rf.priority, move_thread uses nonexistent record accessors, and contains(record) calls record.native_handle() rather than its nested controller. Those instantiations are ill-formed. count() reads the stack size without taking the arena mutex.

Copy and move are deleted. Destruction joins all children. The global standard pool is deliberately not destroyed; users must finish work whose captured state has shorter lifetime.

micron::concurrent_arena

Defined in header <micron/thread/pool.hpp>.

The public alias for a fixed array of persistent queued native workers.

Storage and submission

Aliases arena::__concurrent_arena<>, whose Tr must be exactly void_thread<Sz>. It owns 32 inline thread_t<Tr> slots and remembers the separate mappings because worker release clears its borrowed stack pointer. create() launches one worker up to the 32-slot bound. add(fn, args...) holds the arena mutex, selects the next active worker round-robin, enqueues its callback, and returns that worker record.

type is thread_t<Tr> and thread_class is Tr. count() returns the fixed array size, 32, not the number of launched workers. list() and several searches also traverse all 32 slots, including unused slots. Submission requires at least one created worker. stop_all requests exit; join_all joins them, and destruction stops, joins, then unmaps all remembered stacks.

The administrative priority and record-based contains helpers have the same nonexistent-member instantiation problems as the standard arena. Worker sleep/cancel/await forwarding targets operations deleted by void_thread and cannot be used with this arena. Neither the array nor records may be relocated while workers are active; copy and move are deleted.

micron::schedulers

Defined in header <micron/thread/scheduling.hpp>.

Names Linux FIFO, round-robin, deadline, normal, idle, and batch scheduling policies.

Values

fifo, roundrobin, deadline, normal, idle, and batch map to the corresponding Linux values. none is the explicit 0xFFFFFFFF sentinel. The free get_scheduler() queries the calling process/thread id and reports a system error if the query fails.

micron::scheduler_t

Defined in header <micron/thread/scheduling.hpp>.

A cached Linux scheduling-policy and scheduling-attributes descriptor.

Configuration

Construction queries sched_attr for a pid. Copy copies the cache; move transfers it and resets the source to schedulers::none. set_scheduler(policy) updates the cache only, resetting relevant nice/priority/deadline fields. load_scheduler(pid) applies the policy first and the full cached attributes second; either failure reports a system error, and a partial change is not rolled back.

load_scheduler applies a legacy priority-99 scheduler call for deadline policy before its attribute call; that can fail before deadline attributes are applied. enable_deadline(time) sets runtime to time/2, deadline to (time/4)*3, and period to time only for deadline policy and time >= 1024. These are kernel scheduling time units, not the floating millisecond sleep interface. get_priority() returns cached nice for ordinary policies or realtime priority for FIFO/RR. Classification helpers do not query the kernel again.

State and copies are inline with constant wrapper work; construction/application perform syscalls. This descriptor does not own a thread, restore previous scheduling at destruction, or serialize concurrent reconfiguration.

micron::cpu_t

Defined in header <micron/thread/cpu.hpp>.

A CPU-affinity mask and cached scheduler descriptor bound to the pid selected at construction.

Mask and updates

D defaults to false: the initial mask is empty, or all reported cores up to 1024 for D = true. The object stores a fixed 1024-bit Linux mask and caches cpu_count(). Index checks compare against that reported count. On systems reporting more than 1024 cores, set_core, at, clear_core, and set_all do not separately clamp the mask index; use only representable indices.

clear, set_core, and clear_core change the local mask. update_cores applies it; update first enables all cores, applies cached scheduling, then applies the mask. Affinity setters generally do not report kernel failure. pin(c) clears the mask to one core and applies it, using the caller's current CPU when the sentinel is supplied. Copying retains the stored pid, rather than rebinding to the copying thread.

Frequency, governor, online, priority, and cache-line helpers forward to Linux/sysfs interfaces and can fail due to permissions or missing files. core_count() is reported system count, not the count of permitted CPUs; active_count() counts set mask bits. Mask operations take constant bounded space, with set-all linear in the reported count.

micron::proc_t

Defined in header <micron/thread/cpu.hpp>.

An immovable lazily allocated runtime CPU-information snapshot, separate from compile-time ISA dispatch.

Probe and storage

Construction caches cpu_count() and zeroes feature flags. instance() returns a function-local singleton. probe() serializes the initial CPUID/ID-register feature probe with a three-state atomic byte; probe_full() additionally populates up to 256 core/cache records. Large raw/core data is mmap-allocated on first probe and unmapped at destruction; failure leaves empty/default results and is not retried after the probe is marked complete.

features, vendor, and arch_level trigger the basic probe; core(n) triggers the full probe and returns a static empty record for n >= 256 or missing data. Raw family/model/stepping or ARM implementer/part accessors do not trigger a probe. l1d, l1i, l2, and l3 require a completed full probe and do not check their core_id against 256. raw() const does not probe; mutable raw() probes and exposes internal storage without locking it.

has_* convenience queries inspect feature bytes. These report observed hardware information; they do not change which instructions compiled library paths may execute, or automatically arrange OS vector-state support. simd_width() reports the compile-time SIMD width (zero for scalable vector tiers), while SVE vector-byte queries execute the compiled SVE width instruction only on the selected capability path.

Probe copies bounded architecture data and core records; subsequent feature queries are constant work. Returned references and pointers borrow the snapshot and must not outlive it. Concurrent direct mutation through raw() or __ensure_data() is unsupported.

micron::micthread::tier

Defined in header <micron/linux/sys/micthread/threads.hpp>.

Describes whether native TLS-template and clone support can launch freestanding threads.

Capabilities and low-level protocol

none means no usable TLS template, legacy means a template with the legacy clone path, and full means a template with clone3 currently selected. available() is true for either usable tier. threads_available() is always true for the hosted wrapper branch and asks this capability query for the freestanding branch.

micthread::spawn requires a supplied usable stack, TLS pointer, and stable join word. It allocates the decayed launch payload, calls clone3/legacy clone, and returns a kernel tid or thread_failed with errno recorded. join(ctid) acquire-checks the kernel-cleared word and uses a shared-class futex wait; private futex waits would miss the kernel's CHILD_CLEARTID wake. try_join returns 0 for cleared or positive error::busy otherwise.

stack_region contains low (lowest usable byte) and usable (byte count). guard_stack attempts to protect the lowest default page, then returns the remaining region, falling back to the whole region if protection fails. tid_t is pid_t. The compatibility enums thread_create_state, thread_mutex_type, cancel_state, cancel_type, and thread_sched_inherit name legacy joinability/mutex/cancellation/scheduling values; they do not by themselves configure the current high-level wrappers.

micron::posix::clone_args

Defined in header <micron/linux/sys/clone.hpp>.

The Linux clone3 argument descriptor with 64-bit ABI fields on every supported native architecture.

Fields and launch

Fields contain flags, pidfd output address, child/parent-tid output addresses, exit signal, lowest stack address and byte size, TLS argument, set-tid array address/count, and cgroup descriptor. Address fields use integer representations rather than owning pointers. clone3_kernel passes the complete descriptor directly to the kernel.

clone3_spawn initializes the child-tid word before launch, chooses clone3 through a probe gate, and falls back to legacy clone only on ENOSYS. Architecture trampolines preserve the callable/payload through the child stack pivot; i386 builds a TLS user descriptor, and arm32/i386 use the reversed legacy argument convention. Neither low-level launch owns the supplied stack or TLS.

clone_flags names Linux sharing, namespace, TLS, pid, and tracing bits; posix_process_flags names process-spawn attribute bits. The templated legacy clone<Sz, Fn> allocates a payload and argument copies, cleans the independent parent copy for a nonshared address space, and returns the raw signed syscall result. The callback-style clone overload borrows its payload. These are low-level process/thread primitives, not automatically joined owners.

micron::coro::executor

Defined in header <micron/thread/coroutine/executor.hpp>.

A structural concept requiring frame submission and an observable worker count.

Requirements

For an executor E, e.submit(coro::__frame_base*) must return void and e.worker_count() must be convertible to u32. The concept does not check frame ownership, scheduling fairness, exception behavior, or shutdown protocol. A submitted frame must remain live until all possible resumptions are finished.

micron::coro::work_stealing_executor

Defined in header <micron/thread/coroutine/executor.hpp>.

A non-owning concrete executor referring to a coroutine engine.

Operations

executor_tag is void. Default construction has no engine; submitting then traps. submit(frame) forwards to the engine and worker_count() returns its n, or zero for null. default_executor() starts the global runtime and returns a view of its engine. Copying the executor copies its borrowed pointer; stopping/restarting the runtime invalidates previously obtained engine views.

micron::coro::any_executor

Defined in header <micron/thread/coroutine/executor.hpp>.

A non-owning erased executor containing an object pointer and two function pointers.

Operations

make(e) binds any object satisfying executor, retaining its address without allocating or extending its lifetime. submit(frame) invokes the erased submit function and traps if unbound. worker_count() returns zero when unbound. These methods are noexcept, so an exception escaping a custom executor cannot propagate through them. Copies retain the same borrowed executor; that executor and its scheduling state must outlive all uses.

The stored literal result after waiting for completion; a value-initialized R if the payload is not a literal result.

Notes

Retrieve the result before joining: joining releases the thread payload.

auto_thread::join()

Waits for a joinable thread to complete and joins it.

Defined in header <micron/thread/thread_types/auto_thread.hpp>.

int join();

Return value

0 after joining and releasing a thread, or 1 if it was already joined or released.

micron::solo::spawn(function, args...)

Creates an independent thread object and returns an owning pointer to it.

micron::solo::join(thread)

Joins the specified thread. The pointer overload clears its owning pointer after joining.

Example

#define MICRON_ABC_MT 1
#include <micron/thread/thread_types/auto_thread.hpp>

int main()
{
  micron::auto_thread<> worker([](int value) { return value * 2; }, 21);
  int result = worker.result<int>();
  worker.join();
  return result == 42 ? 0 : 1;
}
