Fourier transforms

From micron reference
micron reference › Numerics and mathematics

Complex and packed-real discrete Fourier transforms, DCT/DST transforms, fixed-kernel convolution, frequency/shift helpers, and reusable serial or executor-based parallel workspaces. Plans own precomputed coefficients; execution borrows caller input, output, and scratch storage.

Interface selection

All public names are in micron::math::fft. <micron/math/fft.hpp> includes complex/real plans, convolution, and helpers. The parallel_workspace adapter requires <micron/math/fft/parallel.hpp> separately.

FacilityOperation and storage

plan<F>Repeated complex or packed-real transforms, arbitrary rank/axes, signed strides, offsets, and batches
r2r_plan<F>, dct, dst, real_transformReal-to-real cosine/sine transforms I-IV, with reusable or one-shot execution

Transform convention and normalization

Forward complex transforms use exp(-2*pi*i*k/n); backward transforms reverse that phase. Packed real spectra include DC and the nonnegative bins through floor(n/2). For multidimensional real transforms, only the last selected axis is packed; inverse reconstruction mirrors the selected transformed coordinates and conjugates them.

backward (default)11/N
none11
forward1/N1
ortho1/sqrt(N)1/sqrt(N)

Algorithms, precision, and complexity

Each smooth one-dimensional length is factored into radix-2/3/4/5/7 stages, with radix-8 leaves. Other prime factors use Bluestein convolution padded to next_fast_len(2*n-1). Twiddles use integer quadrant reduction followed by fixed polynomial-series evaluation. Arithmetic is floating point and has no user-specified accuracy or convergence tolerance.

For one smooth line, execution costs O(n log n); a Bluestein line costs O(m log m), m=next_fast_len(2*n-1), with two m-element scratch spans. Separable multidimensional execution applies an engine to every line of every selected axis, plus input/output and axis gather/scatter work. Let B be batch count, V full logical volume, and n_a each selected axis length: smooth arithmetic is O(B*V*sum(log n_a)). Noncontiguous indexing adds rank-dependent coordinate calculations.

Planning stores stage metadata and O(sum(engine lengths)) twiddles/chirps/kernels; Bluestein setup also computes the transformed kernel. Execution with an existing workspace performs no container allocation. One-shot wrappers allocate owned outputs and construct plan/workspace state. SIMD packet widths are chosen at compile time, with scalar tails; long double uses the scalar packet, ARMv7 double remains scalar, and MICRON_NO_SIMD selects generic packets.

Return values and buffers

Plan construction checks shape products, transform kinds, axes, layout rank, stride representability, and scratch byte sizes, reporting invalid_argument or length_error. Execute methods are noexcept and return a signed max_t: nonnegative logical output bytes, -22 for a domain/direction/null-pointer mismatch, or -105 for insufficient/invalid workspace. Zero batches return zero without reading sample buffers. One-shot wrappers convert negative execution status to invalid_argument.

Input/output capacities are not passed to execute and are not validated. Signed strides/offsets are element counts; the supplied pointer must make every accessed address valid, including negative offsets. Real-domain strides count F elements and spectrum strides count complex pairs. Layout overlap/injectivity and padded in-place capacity belong to the caller. Input/output equality is supported by scratch staging, but arbitrary partial overlap is not a uniform fast-path contract; workspace must be separate from sample buffers.

Helpers

next_fast_len finds the smallest 2/3/5/7-smooth length at least n by enumerating prime-power combinations, returning one for n<=1; it rejects sizes beyond its checked range. fftfreq returns n signed frequency bins in ordinary FFT order; rfftfreq returns floor(n/2)+1 nonnegative bins. Both require positive spacing and n>0, and cost O(n) output work.

Pointer-to-pointer fftshift/ifftshift require disjoint intervals and rotate by ceil(n/2)/floor(n/2) respectively in O(n). In-place overloads allocate a temporary. Multidimensional shift validates selected distinct axes and returns a new buffer; its index computation costs O(volume*rank*(selected_axes+1)). Returned buffers own their elements.

Lifetime and concurrency

Plans own configuration/coefficients and borrow only sample/scratch buffers during execution. A const plan can be reused concurrently with distinct workspaces and nonconflicting outputs. A workspace_view, split descriptor, or configuration reference does not retain an owner. Moving/replacing/destroying its owner invalidates borrowed association; sample buffers and executors must remain alive until execution returns.

micron::math::fft::descriptor

Defined in header <micron/math/fft/common.hpp>.

An owning transform configuration with dimensions, axes, layouts, batch count, domain, and scaling.

Fields and policy types

shape is a buffer<usize> of positive dimensions; constructors accept one length, an initializer list, or a dimension buffer. axes is empty to select all axes in row-major order, otherwise it lists distinct transformed axes in the supplied order. input/output are layout records; batches defaults to one, kind to complex, norm to backward, and forward_scale/backward_scale to one.

TypeValues and meaning
layoutOwned signed strides, signed offset, and signed batch distance; empty strides choose row-major, distance zero chooses contiguous logical volume
directionforward, backward
domaincomplex, real_forward, real_backward
normalizationbackward, none, forward, ortho
fft_scalarA supported complex scalar of size four/eight, or long double
buffer<T>vector<T,allocator_serial<>,false>; owns dynamic contiguous values

Validation and cost

Descriptor construction stores values; the plan performs full validation and fills default layouts/axes into its own copy. Strides cannot be zero for a dimension/batch count greater than one, but valid distinct strides can still overlap coordinates. Offsets may be negative. Scale factors are not checked for finiteness. Copy cost is proportional to rank and selected axes; the descriptor retains no sample pointers.

micron::math::fft::plan

Defined in header <micron/math/fft/plan.hpp>.

An owning reusable complex/packed-real transform plan with per-axis engines and precomputed coefficients.

Construction and dimensions

plan(n,norm) constructs a one-axis complex plan. plan(descriptor) validates positive nonempty shape, domain/normalization, distinct in-range axes, signed layouts, and checked size products. It builds one engine per transformed axis. Real even lengths use a half-length complex engine plus real recombination; odd lengths use a full complex engine.

configuration(), input_shape(), and output_shape() return borrowed const references to completed plan state. input_size/output_size count logical elements over all batches, excluding stride gaps. real_forward shortens the last selected output axis to n/2+1; real_backward shortens that input axis. Normalization N is the product of selected full axis lengths, excluding batches and untransformed axes.

Execution overloads

Complex execution accepts interleaved complex pointers or split_input/split_output records plus an explicit direction. Real forward accepts F input and complex/split output; real backward accepts complex/split input and F output. execute_inplace(F*) writes packed complex pairs into scalar storage or reconstructs real values without creating complex objects that alias F storage.

All variants stage/gather data in supplied scratch except selected contiguous one-dimensional fast paths. Those paths specifically handle exact input/output equality; they do not establish arbitrary partial-overlap safety. workspace_size(workers) reports complex elements, workspace_bytes reports bytes, and zero workers is rejected. A generic serial plan needs full-volume batch staging plus 5*maximum_axis_length and the largest engine scratch per worker.

Ownership and invalidation

Copies duplicate descriptor and coefficient vectors; moves transfer vector storage. Execution does not mutate plan coefficients. Returned configuration/shape references and any pointers into them are invalidated by replacing or destroying the plan. The plan does not retain the input, output, or supplied workspace after a completed synchronous call.

micron::math::fft::workspace

Defined in header <micron/math/fft/common.hpp>.

An owning default-allocator buffer of complex scratch elements for transform execution.

Workspace and split-buffer records

workspace(elements) allocates that many complex values; workspace(plan) uses plan.workspace_size(). size reports element count and view returns workspace_view<F>{data,size}. The view is a borrowed pointer/count descriptor, without resizing, allocation, or lifetime retention. A caller can provide its own suitably sized complex buffer through workspace_view.

split_input<F> stores const F* real and imag; split_output<F> stores mutable F* real and imag. They describe two separate arrays with the plan's complex-element indexing convention. Default pointers are null and execute validates nullness when batches are nonzero. Copying these records is O(1); copying an owning workspace duplicates its elements.

Views become invalid when their workspace is replaced, moved, or destroyed. One workspace is mutable scratch and cannot serve overlapping executions. Capacity must match the particular plan and worker count, rather than only the input length.

micron::math::fft::r2r_plan

Defined in header <micron/math/fft/real.hpp>.

An owning separable real-to-real cosine/sine transform plan with an FFT embedding per selected axis.

Kinds and inverse pairs

r2r_kind enumerates dct_i, dct_ii, dct_iii, dct_iv, dst_i, dst_ii, dst_iii, dst_iv. A one-dimensional constructor accepts n and one kind; the descriptor constructor requires one kind per selected axis and kind==domain::complex in the descriptor. Lengths must be positive, and DCT-I requires n>=2.

Backward direction exchanges DCT-II with III and DST-II with III; kinds I and IV are self-paired. Each engine embeds reflected/antisymmetric or phased samples in a complex transform. Logical normalization lengths are 2*(n-1) for DCT-I, 2*(n+1) for DST-I, and 2*n otherwise. Type-IV embeddings use 8*n complex points. Ortho additionally adjusts endpoint coefficients according to the kind.

execute accepts F input/output and workspace_view and returns logical output bytes or the common negative statuses. The one-shot real_transform/dct/dst wrappers allocate plans, scratch, and outputs; dct/dst type arguments must be 1..4.

Complexity and storage

Each axis costs its embedding engine's O(m log m) line transform work plus embedding/gather/scatter. Plan state owns phase arrays and FFT coefficients. Scratch includes batch-volume complex staging, two maximum-length line spans, and the largest embedded engine workspace per worker. size() counts all logical real elements. Plan and scratch lifetimes follow the complex-plan family.

micron::math::fft::convolution_plan

Defined in header <micron/math/fft/convolution.hpp>.

An owning fixed-kernel convolution/correlation plan with a precomputed kernel spectrum.

Descriptor and modes

convolution_descriptor owns input_shape, kernel_shape, optional period, mode=full, and correlation=false. Input/kernel ranks must agree and be nonempty. I/O is contiguous row-major. A nonempty kernel pointer is consumed during construction, copied into padded transform storage, and not retained.

convolution_modeOutput/crop per axis
fulln+m-1 samples, uncropped
samen samples beginning at floor((m-1)/2) of the full result
validn-m+1 samples beginning at m-1; requires n>=m on every nonempty axis
circularThe explicitly supplied positive period per axis; input and kernel dimensions must not exceed it

Implementation and errors

Linear modes pad each axis to next_fast_len(n+m-1). Linear correlation reverses/conjugates the kernel before transforming; circular correlation conjugates its spectrum. The short convolve/correlate length overload does not supply circular periods, so circular use requires the full descriptor.

A zero input/kernel dimension creates an empty plan/result, subject to remaining mode/period validation; execute then returns zero without dereferencing pointers. Otherwise execute embeds input, performs forward transform, pointwise multiplication, inverse transform, and crop. It returns output bytes, -22 for null sample pointers, or -105 for workspace failure. output_shape/output_size describe the cropped result.

Complexity and lifetime

Let P be padded transform volume. Planning computes one kernel transform; each execution computes two transforms plus O(P) multiplication/embedding and output cropping. Smooth multidimensional transform work is O(P*sum(log padded_axis)), with Bluestein costs where required. Plan storage includes O(P) kernel spectrum and FFT coefficients; scratch is two P-element arrays plus the FFT workspace.

The fixed kernel spectrum belongs to the plan and can be reused after the original kernel storage changes. Copies own independent coefficients. Distinct execution workspaces permit concurrent reuse of one const plan. convolve/correlate wrappers rebuild this state on each call.

micron::math::fft::parallel_workspace

Defined in header <micron/math/fft/parallel.hpp>.

An owning transform workspace and reusable job array executing through a caller-supplied executor.

Executor contract

Construction takes a plan and worker count in 1..0x7fffffff and allocates plan.workspace_size(workers) complex elements plus job records. Copying is deleted. The executor must provide noexcept bool-like submit(void(*)(void*) noexcept,void*). An accepted job must eventually run; false submission must not retain the job. Rejected submissions and the final partition execute on the calling thread.

Workers receive distinct scratch slices. The runner partitions lines or top-level transform work, uses atomic completion counts, and waits with futex helpers before returning or advancing an axis. A single large smooth transform parallelizes above the engine's 1024-point threshold. This adapter does not construct or own a thread pool.

Overloads execute complex/real plans, split complex buffers, scalar in-place real storage, r2r plans, and convolution plans. The chosen input/output types must match the plan domain. Output/error conventions match serial execution.

Complexity and concurrency

Parallel execution performs the same arithmetic/gather/scatter work, plus submission/barrier overhead; worker count does not itself guarantee a speedup or available threads. Storage adds one scratch slice and job record per worker. The same parallel_workspace cannot run overlapping calls because jobs, scratch, and completion state are shared. Executor and sample buffers must remain valid until execute returns; all accepted jobs have completed at that point.

Example

#include <micron/math/fft.hpp>

int main()
{
  double samples[4]{ 1, 0, 0, 0 };
  auto spectrum = micron::math::fft::rfft(samples, 4);
  auto restored = micron::math::fft::irfft(spectrum.data(), 4);
  return restored[0] > 0.999 && restored[0] < 1.001 ? 0 : 1;
}
