OpenGL

From micron reference
micron reference › Graphics

OpenGL object owners, Linux GLX/EGL context integration and a generated core procedure table. The high-level interface uses current-context GL state and dynamically resolved process-wide entry pointers.

Setup and state changes

Create a display and GL window, create the context, then make it current before constructing GL resource owners that allocate names. The ordinary context constructor does not make it current automatically. First make_current resolves all generated core entries without establishing that each is present. Direct gl* access is also available in micron through using declarations, and micron::gl aliases micron::gfx::gl. The GL display header reexports the shared platform display/backend facilities.

Buffer, texture, VAO, framebuffer, renderbuffer and program convenience operations use the ordinary binding-based API and leave native state changed. They do not save/restore previous bindings or infer resource hazards. Uniform setters operate on the currently used program. A wrapper's nonzero name records possession of a native identifier, not verified storage completeness or readiness for a draw.

Capability queries

has_extension requires a current context and all three glGetIntegerv, glGetStringi and glGetString entries. It compares a nonnull NUL-terminated extension name against indexed extension strings when NUM_EXTENSIONS is positive, otherwise searches the legacy extension string with word boundaries. A missing one of those entries returns false even when another query route could be usable. The search performs O(e) extension comparisons plus native query cost and does not enable an extension or repair missing procedure pointers.

Resource ownership and error conventions

GL resource owners are move-only and transfer their native name/handle, leaving the source empty. They retain no C++ context owner. reset/destruction calls the matching deletion entry only when it is present and then clears the stored handle; an absent deletion pointer can leave a native object unreleased. Resource destruction requires usable compatible current-context/dispatch state and does not wait for arbitrary application submissions.

Some helpers throw on missing creation entries, zero names, compilation/link failures or explicit completeness checks; many optional operations instead do nothing, return null, return zero or return false. This is not a uniform checked-result layer. check_gl consumes one current error and throws a named library_error; it ignores its where argument and does not drain all errors. last_gl_error also consumes one error. Both treat an absent glGetError entry as no error. The default debug callback writes messages to descriptor 2.

Cost and use

Choose the object owners for deterministic native-handle release and selected typed target/stage conveniences. Use the raw procedure surface for operations outside those wrappers, while checking required pointers and context features. Reusing buffers/textures/programs avoids repeating native creation work, but usage hints and wrapper shape do not establish a measured speed improvement.

Most fixed operations perform O(1) local work plus driver validation, storage transfer or GPU work. Full loading resolves 657 commands; a subset resolves only its selected N entries. Shader compilation, linking, uploads, mip generation, result reads, waits and swaps have their own native costs. The wrappers do not allocate general host containers for GL data or automatically batch/parallelize operations.

micron::gfx::gl::window

Defined in header <micron/gfx/gl/window.hpp>.

Extends a platform window with a GL-compatible visual or Wayland EGL native window.

Construction and ownership

Constructors either borrow an external platform display or create an inline owned display whose lifetime encloses the platform-window base. X11 creation selects a GLX framebuffer configuration and transfers its visual into the platform creation hook. The base window does not free that transferred visual. Wayland hooks own the wl_egl_window associated with the platform surface and resize it before user callbacks.

The object is neither copyable nor movable. A GL context borrows the window and must be destroyed before it. The constructor stages hints in shared static hook state, so concurrent window construction is not synchronized by this wrapper. Native setup can load libraries, allocate native resources and block on display-server work.

Interface

The platform window's size, event and callback interface remains available. The GL window supplies drawable/native EGL access needed by context construction; it does not itself create a GL rendering context, load GL entry points or perform a buffer swap.

micron::gfx::gl::context

Defined in header <micron/gfx/gl/context.hpp>.

Owns one GLX or EGL rendering context and borrows its GL window.

Creation, current state and dispatch

The ordinary window-and-hints constructor creates native context state without making it current. The additional Boolean overload can request an immediate make_current. On first make_current, the implementation resolves all 657 entries in the generated GL table and marks the context loaded. Missing entries remain null; the requested GL version and complete function availability are not verified.

Resolved GL entry variables are a process-wide table. They are not thread-local and are not stored separately for each context. The get_proc thunk uses the last context installed for resolution; destruction does not clear that static context pointer. Calls through the table, concurrent loading, mixed contexts and querying through a destroyed thunk require explicit application coordination.

Window integration and lifetime

Construction occupies the window's single internal resize callback slot. Resize integration makes an already-loaded context current and calls glViewport when its pointer is present. Destruction clears that slot and then destroys native context state. The window and display must outlive the context; independently constructed contexts using one window can overwrite the same callback slot.

swap delegates to GLX/EGL and flushes the Wayland connection where applicable. set_swap_interval passes the requested interval; when tear support is absent a negative interval is made positive. The interval must avoid signed-negation overflow. These operations do not add CPU/GPU completion guarantees beyond the called native API.

Cost

The object stores native wrappers inline and is neither copyable nor movable. First loading performs 657 resolver calls; later binding and fixed-state operations perform constant wrapper work. Context creation, shader execution, swapping and synchronization have driver/server costs without a wrapper-supplied bound.

micron::gfx::gl::offscreen_surface

Defined in header <micron/gfx/gl/offscreen.hpp>.

Owns an EGL or GLX pbuffer drawable while borrowing a display.

Scope and lifetime

The default object is empty. Construction from a display and dimensions selects a pbuffer-capable configuration and creates a pbuffer surface. It does not create a GL rendering context, make any context current or load GL entry points. The high-level context constructor accepts a GL window, not an offscreen_surface; using the pbuffer for rendering requires the lower-level native context interface.

The selected backend still requires an available display connection. This convenience class does not implement an EGL surfaceless or independent headless-device route. The display and native client library must outlive the pbuffer. Destruction releases its native surface without tracking resource use by other contexts.

micron::gfx::gl::glx_lib_t

Defined in header <micron/gfx/gl/platform/glx.hpp>.

Owns libGL.so.1 and a GLX function-pointer table for X11 integration.

Loading and capability

Loading obtains procedure lookup, framebuffer selection, visual queries, context creation/binding, swapping and pbuffer operations. The implementation opens libGL.so.1; it does not perform an additional libGLX fallback search. Availability of optional creation or swap-interval entries is checked at use sites where provided. GLX function aliases encode signatures over borrowed XDisplay, GLXContext and drawable/configuration handles.

micron::gfx::gl::glx_context_t

Defined in header <micron/gfx/gl/platform/glx.hpp>.

Owns a GLX context and optionally a selected visual, while borrowing its library and X display.

Requests and operations

glx_fbconfig_request_t defaults to 8 bits per RGBA channel, 24 depth bits, 8 stencil bits, no multisampling and double buffering. Selection chooses the first matching framebuffer configuration and frees the returned configuration array. glx_context_request_t defaults to a 4.6 core, forward-compatible, non-debug context and a null shared context.

Context creation first uses glXCreateContextAttribsARB when available and then can fall back to glXCreateNewContext. The fallback does not verify the requested version/profile. take_visual transfers the XVisualInfo allocation to the caller; otherwise the wrapper frees its retained visual. Pbuffer creation returns a raw drawable that the caller must destroy or otherwise assign to an owner.

Lifetime and state

The class is neither copyable nor movable. It borrows the GLX library, X display and framebuffer configuration. make_current changes native current-context state; it does not load the high-level global GL table. Destruction destroys the context and retained visual without managing child GL resources or pbuffer ownership returned separately.

micron::gfx::gl::egl_lib_t

Defined in header <micron/gfx/gl/platform/egl.hpp>.

Owns libEGL.so.1 and the EGL display, configuration, context and surface function table.

Selection

The table includes core and EXT platform-display functions, but the wrapper's display-open path uses eglGetPlatformDisplayEXT when available and otherwise eglGetDisplay. It does not select the loaded core eglGetPlatformDisplay alternative there. It binds the desktop OpenGL client API. Resolving EGL symbols does not establish a compatible display, configuration or GL version.

micron::gfx::gl::egl_context_t

Defined in header <micron/gfx/gl/platform/egl.hpp>.

Owns EGL initialization, a context and its attached surface, while borrowing an EGL library.

Requests and ownership

egl_config_request_t defaults to RGBA8, depth24, stencil8, zero samples, the desktop OpenGL renderable bit and a window surface. egl_context_request_t requests version 4.6, core profile and forward compatibility, with debug disabled and no shared context. Configuration selection takes the first match.

Display opening, configuration choice, context creation and surface attachment are separate operations. An attached surface is destroyed with the wrapper. Creating a pbuffer returns a raw surface and does not attach it automatically. Replacing or sharing handles requires explicit ownership discipline.

Lifetime and state

The class is neither copyable nor movable. Destruction destroys the attached surface, destroys the context and calls eglTerminate on its display; there is no wrapper-level reference count shared between objects using an equal native display. It does not explicitly release current-context state first or destroy child GL objects. The library and all borrowed native display/window state must remain valid.

micron::gfx::gl::wayland_egl_lib_t

Defined in header <micron/gfx/gl/platform/wayland_egl.hpp>.

Owns libwayland-egl.so.1 and the native Wayland EGL-window API.

Interface

The table stores create, destroy and resize entry points for wl_egl_window. Construction checks create and destroy, but not resize; a subsequent resize hook requires a valid resize pointer. These native EGL windows borrow their wl_surface and must be destroyed before that surface and its display. They do not own GL contexts or GL textures.

micron::gfx::gl::subset

Defined in header <micron/gfx/gl/loader.hpp>.

Stores an inline compile-time-selected array of GL procedure addresses.

Parameters and results

Template indices identify generated gl_table entries, commonly obtained with MICRON_GL_SYM or consteval sym_index_of. load invokes its get_proc_t resolver once for each index. raw returns the stored address, and as casts it to a caller-selected function-pointer type. Selection lookup within the pack is compile-time; a call through the resulting address remains an indirect function call.

The resolver must be nonnull, selected indices must be in range, and the requested cast must match the actual function signature. Unknown symbol names produce the u16(-1) sentinel rather than a compile-time diagnostic; passing that sentinel to load indexes outside the table. Null resolutions are retained and must be checked before calling.

Metadata and cost

sym_meta_t contains a borrowed symbol name, u16 index and major/minor version metadata. The full loader does not filter its resolution loop by that version. A subset of N entries occupies N pointers plus static index metadata, allocates no dynamic storage and performs N resolver calls when loaded. It does not retain a context or automatically refresh after context changes.

Tokens and calls

The generated GL_* constants describe selector, format, state, bit-mask and result values through the selected core API surface. A token's declaration does not establish driver support or validate a combination of parameters. PFNGL*PROC aliases describe function signatures; the corresponding gl* variables hold nullable resolved addresses. Raw functions preserve native GL state, error and pointer-lifetime requirements and perform no micron container allocation by themselves.

Procedure signature families

The PFNGL*PROC aliases cover fixed raster/depth/stencil/blend state, texture/image transfer and storage, buffers/mapping, vertex arrays and attributes, draw/dispatch commands, shaders/programs/uniforms/reflection, transform feedback, queries, synchronization, framebuffer/renderbuffer state, samplers, debug messages and object labels. Each alias encodes the exact native parameter/result signature in __gl_protos.hpp. It owns no address; the associated gl* variable is populated separately by loading.

Pointer/count arguments are native borrowed ranges; a buffer-binding-dependent pointer can instead be interpreted by GL as a byte offset. The wrapper does not globally distinguish those interpretations or validate current bindings. Raw native calls can allocate driver objects, mutate context state, enqueue GPU work or wait, according to the selected command; the function-pointer alias itself performs none of these operations.

Related native types

GLXContext and GLXFBConfig are opaque pointers. GLXDrawable, GLXWindow, GLXPbuffer and GLXPixmap are X11 identifier carriers. Related native types

micron::gfx::gl::buffer

Defined in header <micron/gfx/gl/buffer.hpp>.

Owns a GL buffer name and records its binding target.

Creation and operations

Default construction is empty; target construction generates a name. buffer_target selects array, element, uniform, shader-storage, copy-read/write or pixel-pack/unpack binding. buffer_usage supplies stream/static/dynamic draw/read/copy hints to the driver. The hints do not reserve a C++ buffer or enforce an access policy.

data and sub_data bind this buffer and forward byte counts, offsets and caller data. map uses MapBufferRange and returns a driver pointer or null when the entry point is absent; unmap returns false when unavailable or when native unmapping reports failure. Byte ranges, access flags, current-context compatibility and GPU synchronization are caller requirements.

Lifetime and state

The wrapper is move-only, transfers its name and zeros the source. reset/destruction deletes the name when its entry point is present and then clears it; it does not retain or restore prior bindings. Mapped pointers are borrowed and cease to be valid after unmapping, storage replacement or deletion according to the native operation. Fixed wrapper work is O(1); allocation, transfer and mapping cost belongs to the driver.

micron::gfx::gl::texture

Defined in header <micron/gfx/gl/texture.hpp>.

Owns a GL texture name and records a native texture target.

Targets and storage

tex_target includes 1D, 2D, 3D, cube-map, 1D/2D arrays, rectangle and buffer targets. The convenience storage/upload methods in this wrapper use the 2D API; declaring another target does not supply a matching dimensional upload implementation. Callers must use target/format/dimension combinations accepted by the invoked native operation.

storage_2d requests immutable storage; image_2d and sub_image_2d forward mutable image/upload requests; parameter methods set integer parameters and generate_mipmap invokes native generation. bind_unit(unit) first changes the active texture unit and then binds this texture. Prior active-unit and binding state are not restored.

Ownership and cost

Default construction is empty. Target construction generates a name; move transfers it and reset/destruction deletes it when available. Upload pointers are borrowed for the native call's applicable transfer semantics. The wrapper stores no image pixels or ownership of bound buffers. Fixed bookkeeping is O(1); pixel transfer, allocation and mipmap generation are driver/GPU work.

micron::gfx::gl::shader

Defined in header <micron/gfx/gl/shader.hpp>.

Owns a GL shader name and compiles a NUL-terminated source string.

Stages and compilation

shader_kind selects vertex, fragment, geometry, tessellation-control, tessellation-evaluation or compute stage. Default construction is empty; stage construction creates a shader. compile sends one source string with no explicit length, compiles it and checks compile status. Failure throws with a message from shared static 1024-byte log storage; the diagnostic may be truncated and is not an independent owned string.

Creation checks the creation entry point, while subsequent compilation calls require their GL pointers to be usable. Source is borrowed during source submission; the wrapper does not retain a source-string owner. Compile cost and compiler allocation are driver-dependent and are not bounded by the handle wrapper.

Lifetime

The shader is move-only and deletes its native name on reset/destruction when the deletion entry is present. Native programs may retain attached-shader references independently of the C++ shader object's lifetime. A live compatible current context and correctly loaded procedure table are required for its operations.

micron::gfx::gl::program

Defined in header <micron/gfx/gl/program.hpp>.

Owns a GL program name and provides shader linking, use and selected uniform operations.

Construction and results

Default construction creates a native program. Variadic shader-source construction compiles local shader objects, attaches them and normally links. The Boolean do_link=false form still compiles and attaches the supplied shaders, then destroys the local shader wrappers without linking. Native attached-shader references remain a GL responsibility.

link and validate query status and throw using shared static 1024-byte log storage on failure. attach/detach call their entry points only when present. uniform_location and attrib_location return native locations, or -1 when the query entry is absent; no location cache is maintained.

Uniform state and lifetime

use changes the current program. The static set_uniform helpers call glUniform* and therefore modify the currently bound program, not a program object selected by an instance receiver. Bind the intended program first. Matrix helpers read caller-supplied f32 arrays for one 3x3 or 4x4 matrix, forward the transpose flag and retain no storage.

The move-only owner deletes its program name on reset/destruction when possible. It owns neither source strings, shaders passed to attach, textures nor buffers referenced by uniforms. Local wrapper work is constant per fixed operation, or linear in the number of shader-source arguments; compilation/linking and rendering costs belong to the driver.

micron::gfx::gl::vao

Defined in header <micron/gfx/gl/vao.hpp>.

Owns a GL vertex-array object name and configures selected vertex attribute bindings.

Operations and dependencies

Default construction generates a vertex array. Attribute helpers bind the VAO and supplied buffer, issue floating/normalized or integer vertex-pointer setup, and enable the attribute. The supplied buffer must use the appropriate array target; byte offsets, component counts, types, stride and attribute index are forwarded without bounds or compatibility checks. Several subordinate GL entry points are used without individual null checks.

The owner is move-only and does not retain the C++ buffer object. Native attribute bindings refer to GL buffer state, whose usability must be maintained for later draws. Binding/configuration leaves current VAO and buffer state changed. O(1) wrapper work excludes native validation and draw processing.

micron::gfx::gl::framebuffer

Defined in header <micron/gfx/gl/framebuffer.hpp>.

Owns a GL framebuffer name and configures borrowed texture/renderbuffer attachments.

Operations

Default construction creates a framebuffer. fb_target selects read, draw or combined binding. Attachment helpers bind it and call FramebufferTexture2D or FramebufferRenderbuffer; the texture path is specifically the 2D attachment API. check throws if the object/query entry is absent and otherwise returns the native completeness code. require_complete accepts only FRAMEBUFFER_COMPLETE.

The move-only wrapper owns its framebuffer name, not its attachments. Attachments and their storage must remain usable for subsequent operations. bind_default binds zero, and other helpers leave native binding state changed. Fixed bookkeeping is O(1), while completeness checks and GPU work have driver costs.

micron::gfx::gl::renderbuffer

Defined in header <micron/gfx/gl/renderbuffer.hpp>.

Owns a GL renderbuffer name with a single-sample 2D storage convenience operation.

Storage and lifetime

Default construction creates a name. storage binds it and forwards internal format and dimensions to the ordinary renderbuffer-storage operation; it does not select a multisample storage API. The object is move-only and deletes the name on reset/destruction when possible. Framebuffer attachments borrow this resource rather than its C++ owner.

No CPU pixel array is retained. Binding remains changed, dimensions/formats are unchecked by the wrapper, and creation/storage cost belongs to the GL driver beyond constant local bookkeeping.

micron::gfx::gl::sampler

Defined in header <micron/gfx/gl/sampler.hpp>.

Owns a separate GL sampler object with integer parameter and texture-unit binding helpers.

Operations

Default construction generates the sampler. bind selects the supplied texture unit and parameter sets a native integer parameter. The wrapper owns no texture and does not infer a matching texture format or mipmap completeness. Parameter tokens, values and unit indices are caller requirements.

The sampler is move-only. reset/destruction deletes its name when the deletion entry exists and clears it. Fixed wrapper work is O(1); sampler state and validation are maintained by the driver.

micron::gfx::gl::query

Defined in header <micron/gfx/gl/query.hpp>.

Owns a GL query name and records its query target.

Targets and results

query_target includes samples passed, any samples, conservative any samples, primitives generated, elapsed time and timestamp. Default construction is empty. begin/end issue the native active-query operations without tracking active state; query_timestamp uses the counter operation. Destruction does not automatically end an active query.

available returns false when the availability entry is absent. result_u32/result_i32/result_u64/result_i64 use QUERY_RESULT with the selected integer width/signedness and can wait for GPU completion; zero can also be returned when the corresponding entry is missing. Results are raw native counts/time values rather than elapsed-time objects with a unit conversion. The caller must ensure the target and begin/end/counter sequence are valid.

Ownership

The object is move-only and deletes its query name on reset/destruction when available. No host result array is allocated. Local wrapper work is O(1); waiting and query execution are driver/GPU costs.

micron::gfx::gl::fence

Defined in header <micron/gfx/gl/sync.hpp>.

Owns a GLsync fence and forwards client/server wait operations.

Insertion and wait results

Default construction is empty. insert replaces the current handle with FenceSync when available. wait_for uses a client wait with the flush-commands bit and the supplied native timeout; is_signaled calls that path with timeout zero and is therefore not a separate side-effect-free status query. server_wait submits the server wait using the ignored-timeout token.

The current wait_for implementation returns true for numeric results 0x911C and 0x911D. In the generated constants these are CONDITION_SATISFIED and WAIT_FAILED; ALREADY_SIGNALED is 0x911A and returns false. Consequently its Boolean result does not reliably represent successful completion. Direct ClientWaitSync result inspection is required when distinguishing those outcomes.

Lifetime

The object is move-only; reset/destruction deletes the sync handle when possible. A missing wait entry or empty handle returns false. The wrapper does not retain resources whose commands precede the fence. Waiting cost depends on GPU progress and the native timeout, beyond O(1) local work.

micron::gfx::gl::debug_group

Defined in header <micron/gfx/gl/debug.hpp>.

Balances an optional GL debug-group push with a later pop on the current context.

State and diagnostic helpers

Construction pushes when the debug entry is available and remembers whether it became active. Move transfers that responsibility. Destruction pops on whichever compatible context is current then; callers must maintain proper nesting and context association. The label is borrowed for the native call and no host string is retained.

debug_marker and object-label helpers forward literal identifier tokens. Several literals differ from the generated token for their intended category: debug_marker uses 0x824B rather than GL_DEBUG_TYPE_MARKER 0x8268, and shader/program/query labeling use 0x8B31/0x8B40/0x8253 rather than GL_SHADER/GL_PROGRAM/GL_QUERY 0x82E1/0x82E2/0x82E3. These helpers can therefore produce native errors for the intended operation.
