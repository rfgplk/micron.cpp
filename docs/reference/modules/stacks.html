Stacks

From micron reference
micron reference › Containers and strings

LIFO containers include growing heap buffers, bounded inline storage, a mutex-serialized buffer, a shared persistent list, and two value-returning inline snapshot forms. Container tags and prefixes do not by themselves specify allocation or checking behavior.

Container types

<micron/stack.hpp> includes stack, fstack, sstack, fsstack, constack, and istack. Include <micron/stacks/cactus.hpp> for cactus_stack and fixed_stack.

Ordering, capacity, and results

For mutable contiguous stacks, subscript zero denotes the top, while ordinary stack/fstack iteration visits the underlying buffer from bottom to top. Their relational comparisons use bottom-to-top lexicographic order. Lists used by istack instead start at the top.

N defaults to alloc_auto_sz for mutable heap and ordinary inline forms. For heap forms it requests initial element capacity and does not limit growth; max_size() returns allocated capacity. For sstack/fsstack it is a hard inline capacity. cactus_stack/fixed_stack default to 64 and require 0 < N < 2^16. Their max_size/capacity are exactly N.

stack, fstack, and constack::pop() remove and return a value. sstack and fsstack::pop() discard a value and return void; their call operator returns the removed value. istack, cactus_stack, and fixed_stack::pop() return a new stack value. Retain that result to use the changed version.

Ownership and failure conventions

Mutable heap stacks use the default serial allocator's page-rounded storage and geometric automatic growth unless a different Alloc is supplied. Reallocation can move every live element. Inline stacks never transfer a heap buffer when moved; their move operations process elements.

The ordinary stack checks top, subscript, pop, and pop-range requests. fstack omits these checks and marks growth/element operations noexcept; an allocation or element exception cannot be treated as a returned error there. Inline fsstack likewise omits operation checks. Constructors and template bodies can require more element operations than the class-level constraint alone establishes.

Construction and operations

Requires is_regular_object<T>. Default construction allocates for N elements and starts empty. Count construction pushes n defaults; list construction stores list order with the final value on top. Copying creates an independent live buffer, while moving transfers its allocation and empties the source. Copy assignment clears its current values and reuses/grows capacity; move assignment destroys and releases the old destination.

push, move, emplace, and push_range construct new top values and grow when needed. top() and checked operator[](n) access top-relative positions. pop() moves out, destroys, zeroes, and removes the top slot. operator()() first moves from top and then invokes pop; this performs an additional move from the already-moved source slot. pop_range(outputs...) assigns successive removed tops to output arguments and checks sufficient count first.

reserve changes raw capacity, clear destroys/zeroes the live prefix, and swap exchanges storage metadata. data and raw iterators expose bottom-to-top storage. operator& returns a byte pointer to it; addr returns the object address. Size/empty/max_size and element-trait queries are provided.

Complexity and iterator invalidation

Top-relative access and a push within capacity are constant time; growing push/reserve relocates the live prefix. Geometric automatic growth gives amortized constant relocation work per push under bounded-cost moves. Pop is constant element work, range operations are linear in argument count, and copying/clearing/comparison are linear in visited elements. Move construction and swap are constant time; move assignment also destroys the previous destination.

Growth can invalidate every live element pointer/reference/iterator. Push within capacity preserves existing addresses but changes end; pop ends only the removed slot's lifetime. Copy assignment and clear end previous element lifetimes. No synchronization is provided. Several push/emplace bodies increment recorded length before construction succeeds, so no general strong exception guarantee is established for throwing constructors.

Differences from stack

Uses the same contiguous resource, initial-capacity parameter, automatic growth, top-relative indexing, bottom-to-top iteration, copying, moving, comparison, reserve, and clearing model as stack. Top, pop, call-operator, subscript, and pop-range do not check bounds or nonemptiness. A caller must establish those conditions before every operation.

The specialization selected for movable noncopyable elements deletes copying, initializer-list construction, and copied push. It retains moved push, default construction, emplacement, and ownership transfer. Most data-path functions, including automatic allocation and element construction, are noexcept; exceptions terminate rather than propagate as a recoverable stack error.

Complexity and iterator invalidation

The ordinary heap-stack bounds and reallocation invalidation rules apply. Removing checks does not remove linear relocation on a growing push, linear destruction, or element comparison cost. operator()() has the same extra move-through-pop behavior as stack. No synchronization or separate fixed-capacity guarantee is provided.

Storage and interface

Requires move construction of T. The anonymous union supplies N raw slots; default construction is empty. Count and list construction reject oversized input, then construct live elements in order. Copying copies live elements; moving move-constructs them into a different inline buffer and clears the source. Copy members additionally require copying, while swap additionally uses move assignment.

Push, emplace, top-relative subscript, top, and pop check capacity/range/nonemptiness. pop() destroys and discards the top and returns void; operator()() moves out the top value and then pops it. move(value) forwards to moved push. Clear destroys active class-type elements and resets length. full, overflowed, and full_or_overflowed compare length with N; max_size is the hard bound.

iterator/const_iterator alias element pointers, but no begin/end or data members are declared. There is no general reserve or resize API. The class does not allocate.

Complexity and iterator invalidation

Push, emplacement, pop, and indexed/top access take constant element work. Copy/move and swap process the live elements, so are linear; clear is linear for class-type elements and constant time otherwise. Storage addresses do not relocate, but pop/clear/assignment end element lifetimes. Move and swap are declared noexcept, so throwing element operations terminate. No synchronization is provided.

Operations and limits

Requires move construction. Count/list constructors reject input beyond N, but ordinary push/emplace do not check capacity, and top/subscript/pop/call-operator do not check logical size. A full push writes outside storage; an empty pop underflows length. The status queries report state and do not repair overflow. max_size() is exactly N.

Copy and move process the active prefix; moved-from sources are cleared. pop() discards while the call operator returns the removed value. Clear destroys active class-type objects. Reserve and swap are explicitly deleted. Pointer aliases are declared, but begin/end/data are absent.

Complexity and lifetime

Single valid LIFO operations are constant time; copy/move/clear follow the same bounds as sstack. Inline storage does not reallocate. A returned value is independent, and references to popped or cleared objects have ended lifetimes. Move operations are noexcept; no synchronization is provided.

Synchronized interface

Requires regular objects and uses N as initial element capacity. Count/list construction, copy/move, reserve, push/move/emplace, range push/pop, clear, swap, and comparisons are supplied. top and top-relative subscript copy a value while locked, rather than returning a reference. pop and the call operator remove and return a moved value while holding the lock.

Push-range and pop-range each hold one lock across their complete sequence; pop-range checks sufficient size first. Copy/move construction lock the source. Assignment, swap, and comparison lock both objects in address order. Size/empty/max_size queries also take the mutex. No ordinary data or iterator interface is declared.

Complexity and thread safety

Excluding lock waiting, ordinary heap-stack growth, copy, range, and destruction bounds apply. Geometric growth amortizes relocation across pushes; a single growing push is linear in live size. Copied observations remain independent of later pushes/pops.

The mutex is nonrecursive, and element operations run while it is held. Destruction requires no concurrent use. Public resource inheritance exposes pointer/length/capacity and low-level operations outside the synchronized stack interface. Throwing element construction can leave a length increment recorded before successful construction; the mutex does not add an exception-safety guarantee.

Nodes and value operations

Each heap node stores a value, a successor, and a non-atomic incoming-reference count. Default construction is empty. Count construction adds defaults; list construction pushes in list order, leaving the final value on top. Construction from a mutable stack preserves its top-to-bottom order. Copy construction retains the head in constant time; moving transfers it and empties the source.

push, default push, pop, and clear return new stack values. Push allocates one node and shares the old head; pop shares its successor and rejects an empty input. Top and the call operator return a checked const reference without removing it. Checked operator[](n) walks n successor links from the top. max_size() returns the largest usize value as a nominal bound, not reserved storage.

Pointer and iterator aliases are const element-pointer types, but no begin/end traversal interface is provided; linked nodes are not a contiguous array.

Complexity and lifetime

Push/pop and copying/moving a new version take constant node work apart from allocation and element construction. Indexed lookup is linear in the index. Assignment/destruction can reclaim an entire uniquely owned chain; clear creates a constant-size empty result without changing the source.

New versions preserve references into retained nodes, but an element reference requires some live version retaining that node. Reference-count changes are not atomic, so concurrent copying/updating/destruction of versions sharing nodes requires external synchronization. Count/list/conversion construction does not wrap its growing raw-node chain in rollback ownership; a throwing later element construction does not establish cleanup of the earlier prefix.

Representation and value operations

Requires a regular element type and 0 < N < 2^16. Raw storage for N nodes is inline; each node has one value slot and a signed parent index. Despite the declared memory_type = heap_tag, there is no dynamic allocation or sharing between container values. Copying compacts the active spine into a new inline object; moving processes that spine and destroys every allocated source slot.

push, child, move, and push-range return copies extended at the top. pop and parent copy the spine and step the new head to its parent; empty pop returns empty. The popped top can remain a constructed orphan within that result's allocated-slot prefix until a later copy or destruction. top/val return a checked const reference. try_pop returns a PopResult containing a copied value and popped stack; despite its name, it throws on empty.

pop_range(outputs...) copies the stack and repeatedly obtains top values and returned parents. size/len are active depth and capacity/max_size are N. Exhausting allocated inline slots traps rather than throwing or returning false. Assignment modifies the container object even though its transformation methods are const.

Ranges and complexity

vals() returns a forward top-to-bottom range of const element references. nodes() returns a forward range whose dereference constructs an independent snapshot of the remaining parent spine. The declared raw pointer iterator aliases are distinct from these range iterator types; the container itself provides no ordinary begin/end.

Top and size queries are constant time. Each push/pop/copy is linear in active depth; move additionally destroys allocated source orphans. Push-range and repeated pop-range can therefore be quadratic in the number of elements traversed. A full vals traversal is linear, while a full nodes traversal copies all suffix depths and is quadratic.

Ranges hold owner pointers and indices without ownership. New stack values leave the original's references intact; assignment/destruction of that owner ends them. Range iterator equality compares indices only, so cross-owner equality must not establish range identity. Several copying operations are declared noexcept; throwing element copies then terminate. No synchronization is provided.

micron::fixed_stack

Defined in header <micron/stacks/cactus.hpp>.

A bounded contiguous inline stack with value-returning push/pop and independent full-prefix snapshots.

Storage and member types

Requires a regular T and 0 < N < 2^16. Stores a 64-byte-aligned raw byte array for N elements plus a live depth. category_type is buffer_tag, mutability_type is immutable_tag, and memory_type is declared heap_tag although storage is inline and never allocates. size_type/value_type are usize/T; const_reference/const_ref are const T&; const_pointer/const_iterator are const T*.

The raw buffer is aligned to 64 bytes rather than alignof(T); element types requiring greater alignment are not accommodated by this representation. Copy/move process the live prefix; moving empties the source. Assignment replaces the current inline values.

Operations and complexity

push, child, and move return a copy with one appended top. Push-range copies the retained prefix once and constructs all added values. pop/parent return a copy of the prefix excluding its top; an empty input yields empty. Top/val check nonemptiness, while full push traps. try_pop() returns a PopResult and throws on empty rather than returning a status. Pop-range assigns successive top values to outputs and returns a copy of the remaining prefix.

Top, size, and capacity are constant time. Copy/move and a value-returning push/pop are linear in the copied live prefix. Push-range is linear in old size plus added count; pop-range is linear in output count plus retained size. vals traverses const values from top to bottom in linear time; nodes dereferences into successive independent prefix snapshots, making full traversal quadratic.

Range wrappers retain owner pointers without ownership; iterator equality compares indices only. New values leave the source's references intact, while assignment and destruction end its original element lifetimes. Copy helpers and several transformations are noexcept, so element exceptions can terminate. There is no shared-tail optimization or synchronization.
