Integration

From micron reference
micron reference › Numerics and mathematics

Allocation-free fixed and adaptive quadrature, sampled-data integration, finite differences, Monte Carlo estimators, and explicit ordinary-differential-equation solvers. Compile-time workspaces embed bounded storage; runtime ODE workspaces borrow caller arrays.

Algorithm selection

The umbrella is math/integrate/integrate.hpp. Monte Carlo algorithms require math/integrate/monte_carlo.hpp separately. Inputs and outputs remain caller-owned and callbacks are copied into calls; no algorithm retains a callback beyond its call.

Error and numerical conventions

Adaptive quadrature compares an estimated error with max(abs_tol, rel_tol*abs(value)). Embedded-rule differences, consecutive refinements, and sample dispersion are estimates rather than rigorous bounds. Finite, sufficiently regular callbacks and numerically representable intermediate values remain required. Fixed rules return only a scalar and do not diagnose convergence or nonfinite values.

accumulation_policy::fast uses ordinary sums, including architecture-selected unrolled/SIMD reductions. accurate uses a magnitude-aware correction for the sums that accept the policy; it does not change callback precision, local quadrature formulas, or all internal reductions. Optimized f32/f64 kernels use compile-time SSE/AVX/NEON selection, with scalar templates for other cases. Summation order can therefore differ across builds. Fixed vector results/states inherit vec<F,N>'s 2<=N<=16 and N*sizeof(F)<=128 requirements, and fixed matrices require positive extents with R*C*sizeof(F)<=1024. Runtime ODE state arrays avoid those fixed-type extent limits.

Sampled data

Pointer overloads require the stated readable/writable extents, distinct usable abscissas for irregular differences, and nonzero spacing for differentiation. Integration accepts oriented spacings without sorting. Container overloads call begin/cbegin as pointers and assume contiguous compatible element storage; the iterable constraint alone does not establish it.

Lifetime, invalidation, and concurrency

Embedded workspaces own their arrays, copy their contents, and allocate nothing. Each adaptive call resets/reuses its workspace, and heap updates move interval/region records: addresses remain within the object while their associated subregions change. Batch coordinate/value pointers are valid during the callback and are overwritten by later batches. Copying a batch workspace also copies its pointer-view members; the supplied algorithms rebuild those members before use.

Separate workspaces, outputs, and independent callback/engine state permit independent calls. No lock protects shared mutable workspaces, buffers, or random engines. Runtime descriptors copy borrowed addresses and do not extend the arrays' lifetime. No iterator interface is provided.

micron::math::integrate::accumulation_policy

Defined in header <micron/math/integrate/common.hpp>.

Selects ordinary or compensated accumulation where a quadrature operation accepts an accumulation policy.

Values

fast=0 adds directly. accurate=1 retains a correction chosen by the relative magnitudes of the old sum and the new term. machine_epsilon<F>() uses the f32 constant for sizeof(F)<=4 and the f64 constant otherwise; it is not a general extended-precision epsilon.

micron::math::integrate::quad_options

Defined in header <micron/math/integrate/quad.hpp>.

Stores adaptive scalar/vector quadrature tolerances, finite resource limits, rule choice, breakpoints, and accumulation policy.

Members and defaults

abs_tol/atol and rel_tol/rtol default to 100*default_eps<F>(). max_evals/max_func_evals=0 means no point budget. max_intervals/limit=128 is clamped to the workspace capacity; zero means its full capacity. max_depth=64. rule defaults to gk21. accumulation defaults to fast.

breakpoints/points borrows n_breakpoints/n_points finite values. They need not be sorted; each starting interval scans the whole array for the next interior point. Duplicates/outside points add no interval. The array must remain readable throughout the call. Infinite-bound transformations discard breakpoints.

Rule choice

gauss_kronrod_rule has gk15=15 and gk21=21, embedded with Gauss 7 and 10 points respectively. The scalar abs_tol/rel_tol overload selects gk15, uses 128 intervals, and caps its max_depth argument at 64; options-based calls retain the specified depth. Negative tolerances, zero depth, a null nonempty breakpoint array, and nonfinite breakpoints are checked. NaN/infinite tolerances are not comprehensively rejected.

micron::math::integrate::quad_result

Defined in header <micron/math/integrate/quad.hpp>.

Stores a scalar adaptive estimate and diagnostics, independently of the workspace that produced it.

Members

value and abs_err are the estimate and estimated absolute error. n_evals counts sampled points, not batch function invocations. status records termination. resabs estimates the integral of abs(f); resasc estimates weighted absolute deviation within rules. n_intervals, n_splits, and n_roundoff count active intervals, performed splits, and the scalar non-improvement heuristic.

Scalar quad supports reversed and infinite bounds using rational half-line or tangent whole-line substitutions. NaN bounds return invalid_input. Initial nonfinite callback failure returns zero accumulated fields and clears the heap; later failure retains the previous accepted mesh. Exhaustion during breakpoint initialization can return only the initialized part of the domain. Inspect status before treating value as a full-domain result.

micron::math::integrate::quad_workspace

Defined in header <micron/math/integrate/quad.hpp>.

Owns Capacity scalar interval records arranged as a maximum-error binary heap.

Storage and algorithm

quad_workspace<F,Capacity> requires Capacity>0 and embeds heap[Capacity], size, and a static capacity. quad_interval<F> contains a,b,value,error,resabs,resasc,depth. reset() changes size to zero without clearing records. Copies are O(Capacity); reset is O(1). A no-workspace quad overload creates Capacity=128 on the stack.

An initial rule uses r=15 or 21 samples. Each accepted split evaluates two new rules, removes the parent contribution, and pushes both children. S splits cost O((B+1+2S)*r) callback points, O(S*log(Capacity)) heap work, and O(B²) worst-case initial breakpoint scanning for B distinct interior points. Scalar callback cost multiplies the sample count. Storage is O(Capacity); it does not grow.

Batch overload

quad_batch with finite bounds sends a complete rule's points to one callback; an infinite-bound call adapts through single-point batch invocations. Its finite dispatch does not reproduce scalar quad's explicit NaN-bound rejection. Reusing the workspace overwrites its mesh. The error estimate has a 50*machine_epsilon*resabs floor; scalar quad also stops after 20 roundoff indications or a large late error-growth heuristic.

micron::math::integrate::quad_vec_workspace

Defined in header <micron/math/integrate/quad.hpp>.

Owns a shared adaptive interval mesh for an M-component integrand, where 2<=M<=16.

Related records

TypeMembers / role
quad_vec_interval<M,F>a,b, vector value/error, scalar priority, depth
quad_vec_result<M,F>vector value/abs_err, n_evals, status, error_norm, n_intervals
quad_error_normmaximum=0 chooses largest absolute component; l2=1 takes Euclidean norm

Complexity and overloads

The vector workspace embeds Capacity interval records, O(Capacity*M) storage/copy, and reset() clears only size. Each rule evaluates f(x) once per point and processes all M components. Splitting uses the norm of interval errors as heap priority; the target uses the norm of accumulated component errors. Work is O(M*r) arithmetic per rule plus callback work and O(M*log(Capacity)) record movement per heap update.

The overload taking scalar quad_workspace instead runs M independent scalar adaptive integrations. It reevaluates the entire returned vector for every component's mesh and sums their evaluation counts; it does not enforce a combined norm tolerance. Shared-mesh quad_vec supports the scalar bound substitutions but does not implement scalar quad's repeated-roundoff/divergence heuristics.

micron::math::integrate::cubature_options

Defined in header <micron/math/integrate/cubature.hpp>.

Stores scalar rectangular cubature tolerances, evaluation/region budgets, and accumulation policy.

Members

abs_tol/atol and rel_tol/rtol default to 1000*default_eps<F>(); max_evals/max_func_evals=0 is unlimited. max_regions/limit=128 is clamped to workspace capacity, with zero selecting full capacity. accumulation defaults to fast. micron::math::integrate::cubature_workspace

Defined in header <micron/math/integrate/cubature.hpp>.

Owns a bounded maximum-error heap of adaptive rectangular regions in 2 through 16 dimensions.

Storage

cubature_workspace<D,F,Capacity> embeds Capacity cubature_region<D,F> records and size; capacity is static and positive. Each region stores center[D], halfwidth[D], value, error, and split_dimension. reset() clears size. Storage/copy are O(Capacity*D); there is no allocator or region growth.

Rule and complexity

The degree-7 Genz-Malik estimate and embedded degree-5 estimate share P(D)=1+4D+2D(D-1)+2^D callback points. Axis differences select the split dimension, using the wider dimension as a tie-breaker. The largest-error region is bisected and both children are reevaluated. S splits require (1+2S)*P(D) samples unless a check stops a rule early. Coordinate construction costs O(D*2^D+D²) per rule, plus callback cost and O(D*log(Capacity)) heap movement.

No recursion depth limit is tracked; the region/evaluation budget bounds refinement. Region exhaustion uses quad_status::max_intervals. Callback samples are checked for finiteness; there is no comprehensive final-overflow diagnostic. The no-workspace overload embeds 128 regions.

micron::math::integrate::cubature_batch_workspace

Defined in header <micron/math/integrate/cubature.hpp>.

Adds reusable structure-of-arrays batch buffers to the bounded cubature-region heap.

Layout and callback cost

Besides Capacity regions, the workspace embeds aligned coordinates[D][BatchSize], values[BatchSize], and coordinate_views[D], with BatchSize>0 and default 64. The algorithm rebuilds pointer views and passes x[d][sample] to a callback, flushing axis, pair, and corner groups in chunks of at most BatchSize. The point count matches scalar cubature; function invocation count reflects these separate groups and chunk boundaries.

Storage is O(Capacity*D+D*BatchSize). The cubature_batch overload taking an ordinary cubature_workspace instead invokes the batch callback with count=1 per point; use this extended workspace for actual grouped evaluation.

micron::math::integrate::cubature_result

Defined in header <micron/math/integrate/cubature.hpp>.

Contains value, estimated absolute error, point evaluations, status, active-region count, and split count.

Interpretation

value, abs_err, n_evals, status, n_regions, and n_splits are independent copied scalars. A budget failure before the first rule leaves the estimate zero; failure during refinement retains the previous accepted region totals. The estimated error is the sum of local degree-7/5 differences with a floating-point floor, not a certified multidimensional bound.

micron::math::integrate::gaussian_rule

Defined in header <micron/math/integrate/gaussian.hpp>.

Owns N nodes, N weights, and a validity flag for a reusable Gaussian quadrature rule, with 1<=N<=64.

Rule families

TypeGeneration / weight
gaussian_rule<F,N>Base storage and apply/apply_batch; nodes and weights default to zero, valid=false
jacobi_rule<F,N>; gauss_jacobi_rule<F,N>generate(alpha,beta), both >-1; weight (1-x)^alpha*(1+x)^beta on [-1,1]
hermite_rule<F,N>generate(); weight exp(-x²) on the real line
laguerre_rule<F,N>generate(alpha=0), alpha>-1; weight x^alpha*exp(-x) on [0,infinity)

Implementation and complexity

Generation forms a tridiagonal Jacobi recurrence, brackets roots by row-radius bounds, and uses a Sturm-count bisection for each node (64 iterations for sizeof(F)<=4, 112 otherwise). Eigenvector recurrence supplies weights, with rescaling for large terms. Generation is O(N²*I), with I the fixed iteration count, and O(N) scratch. Copies are O(N). apply performs N callbacks and O(N) accumulation; apply_batch performs one N-point callback plus O(N) reduction.

Constructing a rule does not generate it. apply/apply_batch do not test valid; the caller must generate first. Jacobi/Laguerre reject <=-1 but do not reject every nonfinite parameter. Convenience gauss_jacobi/gauss_laguerre generate on every call and return zero on their checked parameter failure. gauss_hermite also regenerates each call. Chebyshev-1/i and Chebyshev-2/ii compute trigonometric nodes directly for inverse-square-root and square-root weights.

Fixed-rule behavior

Tables are immutable static constexpr arrays with no per-object allocation. gauss_legendre applies the symmetry pairs for exactly Order callbacks. clenshaw_curtis allows 2<=N<=64 and uses N+1 callbacks; unsupported table orders compute cosine-series weights at runtime with O(N²) arithmetic. No adaptive error or finite-value status is returned.

Newton-Cotes supports Order=1..8. Weights integrate each Lagrange basis polynomial; closed rules reuse no callback values at adjacent panel boundaries, and a leftover run is trapezoidal. Open rules use Order+1 interior nodes. Romberg/reusable Richardson keep two 16-element rows; level limits above 16 are clamped, successive differences trigger stopping after at least three levels, and no failure status is returned. A max_levels value of zero still evaluates the initial approximation.

micron::math::integrate::tanh_sinh_options

Defined in header <micron/math/integrate/weighted.hpp>.

Controls double-exponential quadrature by successive refinement levels and a per-base-grid tail limit.

Defaults and algorithm

abs_tol and rel_tol default to 100*default_eps<F>(), max_levels=12, max_terms=128. At level l the step is 2^-l and the term allowance scales as max_terms*2^l. Symmetric tanh((pi/2)*sinh(t)) nodes approach endpoints; nextafter moves rounded endpoint samples inward. For f32, transformed-coordinate arithmetic is promoted to f64 while callbacks still receive F.

Each level recomputes all samples. Three small tail contributions or saturation of the transform end a level. Error is 16 times the difference between successive levels. Worst-case work through L levels is O(max_terms*2^L) callback/transcendental operations and O(1) storage. Invalid level/term counts and negative tolerances return invalid_input; exhausted levels return max_depth, or max_evaluations when a term limit was reached. With one level, no successive-level error is available.

Weighted and nested algorithms

quad_sin/quad_cos multiply the callback by the requested sine/cosine and use ordinary quad; they do not precompute oscillatory moments. quad_cauchy cancels a symmetric interior principal-value pair, then separately integrates any asymmetric tail, so one cancelled evaluation invokes f twice. quad_algebraic and quad_algebraic_log multiply endpoint powers/logs and call tanh_sinh; exponents <=-1 are rejected.

dblquad halves each tolerance between scalar levels; tplquad divides by three before nesting dblquad; nquad divides by D. Their returned abs_err is the outermost error estimate, excluding a rigorous propagation of inner errors. n_evals adds evaluations from outer and inner quadratures and is not solely the number of original multidimensional callback calls. Status retains a non-ok nested termination.

micron::math::integrate::derive::fornberg_workspace

Defined in header <micron/math/integrate/derive.hpp>.

Owns a finite-difference coefficient table for arbitrary distinct stencil nodes.

Storage and algorithm

fornberg_workspace<F,MaxPoints=25,MaxOrder=12> embeds coefficients[MaxPoints][MaxOrder+1]; both capacities must be positive. fornberg_weights(nodes,count,x0,derivative,weights,workspace) returns false for an empty/oversized stencil, derivative above MaxOrder or not below count, or duplicate nodes. micron::math::integrate::derive::derivative_result

Defined in header <micron/math/integrate/derive.hpp>.

Stores the estimate, estimated error, step, evaluation count, level count, and termination of diagnostic adaptive differentiation.

Related types and behavior

adaptive_result<F> aliases derivative_result<F>. derivative_status has ok=0, max_levels=1, non_finite=2, invalid_input=3. adaptive_diagnostic/adaptive_ex repeatedly halve h and apply the four-sample fourth-order centered formula, using abs(current-previous)/15 as estimated error; each level costs four callbacks. h0=0 and tol=0 choose scale-dependent defaults.

Positive h0, nonnegative tol, and nonzero levels are checked. max_levels=1 evaluates the initial four samples but leaves value/error/step/levels at their zero defaults and returns max_levels. adaptive instead returns a scalar Richardson-extrapolated two-sample central difference, with the common 16-level cap. It exposes no diagnostic status. forward/backward/central use two callbacks, and central4 uses four.

micron::math::integrate::derive::derivative_batch_workspace

Defined in header <micron/math/integrate/derive.hpp>.

Owns structure-of-arrays coordinates and scalar values for batched multivariate finite differences.

Layout and algorithms

derivative_batch_workspace<D,F,Capacity> embeds aligned coordinates[D][Capacity], values[Capacity], and coordinate_views[D], with D=1..16 and positive Capacity. gradient_batch requires Capacity>=2D; hessian_batch requires Capacity>=1+2D². The workspace itself permits D=1, but gradient_batch returns vec<F,D>, whose separate constraint excludes D=1; hessian_batch returns a matrix and can represent that dimension. They invoke the callback once for all stencil points. Scalar gradient uses 2D callbacks; scalar Hessian uses 1+2D² callbacks. Hessian symmetry is assigned explicitly.

Coordinate initialization costs O(D²) for a gradient and O(D³) for a batched Hessian; stencil reduction costs O(D) and O(D²) respectively. Storage is O(D*Capacity), with no allocation. The callback must write every scalar output. central_nth_batch uses a local one-dimensional stencil rather than this workspace and invokes one Points-sized batch. No error tolerance or nonfinite diagnostic is provided by these direct stencils.

micron::math::integrate::derive::jacobian_batch_workspace

Defined in header <micron/math/integrate/derive.hpp>.

Owns coordinate and component-output batches for a centered finite-difference Jacobian.

Layout and complexity

jacobian_batch_workspace<D,R,F,Capacity> embeds coordinates[D][Capacity], values[R][Capacity], and their pointer views. D,R are 1..16 and Capacity>=2D for jacobian_batch. One callback writes R outputs for each of 2D points; the returned mat<F,R,D> is row-major. micron::math::integrate::monte_carlo_result

Defined in header <micron/math/integrate/monte_carlo.hpp>.

Stores an estimator, dispersion estimate, standard error, evaluation count, and Monte Carlo status.

Statistical conventions

monte_carlo_status has ok=0, no_samples=1, non_finite=2, invalid_input=3. Ordinary detailed/stats and stratified methods use Welford accumulation: variance is volume² times the unbiased sample-value variance, and standard_error=sqrt(variance/sample_count). It is not already the variance of the final mean. Antithetic sampling instead treats each pair average (and any unpaired final value) as an observation.

Scrambled Halton and Sobol use independently seeded replica estimates; variance is the unbiased variance across replica integrals and standard_error divides by the replica count. One sample or one replica leaves zero reported variance, without establishing zero true uncertainty. Nonfinite callback failure returns status and the evaluation count before final statistics are assigned. Scalar monte_carlo discards status; deterministic quasi_monte_carlo returns only a plain Halton average and does not check each callback result.

Algorithms and cost

Dimensions are 1..16. Bounds must be finite; reversed dimensions retain signed volume. Ordinary and antithetic methods cost O(N*D) coordinate work plus N callbacks. Stratified sampling forms an affine permutation of strata per coordinate using u32 multiplier/shift and coprime search; sample counts must fit that representation for its intended behavior. Plain/scrambled Halton uses digit expansion, O(N*D*log N); Sobol uses 64 direction words per dimension and incremental Gray-code updates, O(N*D) coordinate work after fixed setup.

Sobol scrambling is a digital XOR shift; Halton uses affine digit permutation per base. These routines use fixed samples/replicas, without tolerance-based stopping. RNG engines are borrowed and advanced by random methods; seeded quasi-random methods are deterministic for their seed. All workspace and scalar state are embedded or automatic.

micron::math::integrate::monte_carlo_batch_workspace

Defined in header <micron/math/integrate/monte_carlo.hpp>.

Owns reusable coordinate/output batches for ordinary and randomized quasi-Monte Carlo estimators.

Layout and use

The default BatchSize=64; D=1..16 and BatchSize>0. coordinates[D][BatchSize], values[BatchSize], and coordinate_views[D] are embedded with 64-byte coordinate/value alignment. monte_carlo_batch[_detailed], scrambled_halton_batch, and scrambled_sobol_batch pass at most BatchSize points per callback. A full N-sample run needs ceil(N/BatchSize) invocations per replica and the same number of point evaluations as its scalar method.

Storage/copy are O(D*BatchSize); callbacks write all count outputs. Batch pointers expire as meaningful data at the next batch/workspace reuse. Floating-point accumulation and architecture affine mapping can differ in rounding from scalar calls.

micron::math::integrate::ode::method

Defined in header <micron/math/integrate/ode.hpp>.

Selects an explicit fixed-step or embedded adaptive Runge-Kutta method.

Methods and costs

EnumeratorMethodRHS evaluations per attempt
euler=0First-order forward Euler2, including endpoint derivative for dense output
midpoint=1Second-order explicit midpoint3, including endpoint derivative
rk4=2Classical fourth-order Runge-Kutta5, including endpoint derivative
rk23=3Bogacki-Shampine 3/2 pair4 initially, then 3 with retained starting derivative
rk45=4Dormand-Prince 5/4 pair7 initially, then 6
dop853=5DOP853 coefficients with combined third/fifth error estimates13 initially, then 12

Selection

Fixed methods accept a prescribed step and do not reject for local truncation error. Adaptive methods use a normalized RMS embedded error and a bounded PI-style step factor. All are explicit: no Jacobian, implicit solve, stiffness detection, or automatic method switching is implemented. Each attempt adds O(N) vector work for fixed stage count, plus the listed RHS costs.

micron::math::integrate::ode::options

Defined in header <micron/math/integrate/ode.hpp>.

Stores adaptive local-error, step-size, controller, and attempt/rejection limits.

Defaults and validation

For sizeof(F)<=4, abs_tol=1e-6 and rel_tol=1e-4; otherwise 1e-9 and 1e-7. initial_step=min_step=max_step=0 choose span/100, a machine-scale minimum, and the full span respectively. safety=.9, min_factor=.2, max_factor=10, pi_beta=.04; max_steps=100000 and rejection_limit=32.

Options require finite values, positive abs_tol/safety/min_factor, nonnegative rel_tol/min_step/max_step/pi_beta, min_factor<=1, max_factor>=1, nonzero limits, and consistent explicit step bounds. RMS error scales each coordinate by abs_tol+rel_tol*max(abs(before),abs(after)); this is a local acceptance criterion, not a global trajectory-error bound. A negative initial_step is accepted and its magnitude used; integration direction comes from t_bound.

micron::math::integrate::ode::result

Defined in header <micron/math/integrate/ode.hpp>.

Owns the last accepted fixed-size ODE state and termination/counter diagnostics.

Members and related types

result<F,N> stores t,y,n_evals,accepted_steps,rejected_steps,attempted_steps,termination,event_index,event_time,t_eval_written,dense_segments_written,last_step. ivp_result aliases it. runtime_result<F> has the same diagnostic scalars but omits y: runtime algorithms update the supplied state array directly.

micron::math::integrate::ode::fixed_workspace

Defined in header <micron/math/integrate/ode.hpp>.

Owns fixed-size stages, scratch states, and the latest dense segment for a fixed-step ODE solve.

Workspace family

TypeEmbedded working state
fixed_workspace<F,N>k1..k4, temporary, next, last dense segment

Lifetime and operations

Storage/copy are O(N); no state history is allocated. solve_ivp resets has_fsal before each solve. Accepted/rejected attempts overwrite scratch; accepted endpoints provide the next starting derivative. Copies contain independent numeric state, with no borrowed arrays.

RHS overload selection accepts function(t,vec,out), function(t,y_ptr,out_ptr,N), function(t,y_ptr,out_ptr), or a returned vec. euler_step/midpoint_step/rk4_step return one next state without validation or status. integrate_fixed and its euler/midpoint/rk4 wrappers validate finite input and apply the magnitude of the step, shortening the last step to the bound. Fixed-size integrate_fixed does not explicitly detect t+h==t; an unrepresentable step can consume max_steps. Adaptive entry points detect step underflow and enforce error-based rejection.

micron::math::integrate::ode::dense_segment

Defined in header <micron/math/integrate/ode.hpp>.

Owns two endpoint times, endpoint states, and endpoint derivatives for a cubic Hermite interpolant.

Interpolation

t0,t1,y0,y1,f0,f1 are copied values. evaluate(t) clamps normalized time to [0,1], returns y1 for a zero span, and evaluates a cubic Hermite polynomial in O(N). This same cubic is used for every ODE method, including DOP853; there is no method-specific high-order dense polynomial.

workspace.last is overwritten by each accepted step. Copies and explicitly stored segments remain independent. Event location and requested-time output use this interpolant, so their accuracy also depends on its approximation. No separate dense-output tolerance is accepted.

micron::math::integrate::ode::output_buffer

Defined in header <micron/math/integrate/ode.hpp>.

Borrows requested times and output states for fixed-size ODE interpolation.

Buffer inventory

TypeBorrowed layout
output_buffer<F,N>const F* times, count, vec<F,N>* states, written
dense_buffer<F,N>dense_segment<F,N>* segments, capacity, written
runtime_output_buffer<F>times,count,F* states,stride,written; state i begins at i*stride, stride=0 means n
runtime_dense_buffer<F>times[2*capacity], coefficients[capacity*4*width], capacity,stride,written; width=stride or n

Ownership and invalidation

Descriptors allocate nothing and copy addresses/counters. Their arrays must outlive the call and retained dense evaluations. written is used as an append cursor and is not reset by solve_ivp. Remaining requested times must be finite, in integration order, and inside the solve interval; output states need capacity for count rows. Runtime stride must be zero or at least n.

A stored runtime segment has y0,y1,f0,f1 blocks and a t0,t1 pair. evaluate(segment,t,out,n) performs the same clamped cubic in O(n), and silently returns for null output or segment>=written. Full dense storage terminates with storage_full. Fixed dense_buffer with null segments is treated as disabled, whereas runtime dense storage with zero capacity reports full on the first attempted store. No ownership or extent is encoded in raw pointer types.

micron::math::integrate::ode::event_spec

Defined in header <micron/math/integrate/ode.hpp>.

Owns a callable and event metadata for one scalar event function.

Events and observers

make_event(function,direction=any,terminal=true,index=0) returns event_spec<Fn>. event_direction is any=0,rising=1,falling=-1. no_event disables event processing; null_observer accepts and ignores arbitrary arguments. Fixed-state event callbacks receive (t,vec) or (t,y_ptr,N), while runtime callbacks receive (t,state,n) or (t,state). Observers receive accepted states and the initial state, with supported pointer/vector forms.

One event is processed per solve. A zero initial value is recorded, and a terminal event returns immediately. Later events require a sign crossing in the requested direction; tangencies and multiple crossings within a step can be missed. Root location uses guarded interpolation/bisection on the cubic dense segment, at most 64 iterations. Each trial costs O(N) dense evaluation plus event cost; event evaluations are excluded from n_evals, which counts RHS calls. Nonterminal occurrences update only the most recent index/time. Direction refers to before/after progression along the integration, including backward solves.

micron::math::integrate::ode::runtime_workspace

Defined in header <micron/math/integrate/ode.hpp>.

Borrows stage, state, error, and dense-endpoint arrays for a runtime-length ODE state.

Storage requirements

Pointers are stages,temporary,next,error,start,start_derivative,end_derivative; length and stage_capacity describe available capacity. valid(n,required_stages) requires n>0, length>=n, enough stages, and every pointer nonnull. It does not validate actual extents or disjointness. Algorithms index stage s at stages+s*n, so provide at least required_stages*n elements and n elements for each other array. Use separate arrays and keep them alive through dense_evaluate calls.

Adaptive rk23/rk45/dop853 require 4/7/13 stages. Runtime fixed Euler/midpoint/RK4 require 2/3/5 stages and still require all seven workspace pointers. Descriptors copy in O(1), allocate nothing, and share the borrowed storage; each attempt costs O(n) vector work plus RHS calls. Output state is updated on acceptance, and failures retain the last accepted state.

Dense state and limits

Adaptive solve_ivp maintains last_t0,last_t1 and endpoint blocks for dense_evaluate(t,out,n); it uses the same cubic interpolation and clamping as dense_segment. Runtime integrate_fixed updates endpoint arrays but does not set last_t0/last_t1, so that workspace's dense_evaluate does not describe its latest fixed step. Runtime fixed entry points offer no observer/event/output-buffer parameters. These distinctions apply even though fixed and adaptive methods share the descriptor type.
