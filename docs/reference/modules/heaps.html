Heaps

From micron reference
micron reference › Containers and strings

Priority containers include a fixed-capacity array max-heap, a node-based max-heap with deferred consolidation, a mutex-protected array min-heap, a tournament-based comparator heap, and an implementation-facing binomial heap. The directory also contains a Bloom membership filter.

Ordering and ownership notes

The declared immutable_tag on these heap classes does not make insert/remove operations persistent: they modify the same heap object. Default comparators define maximum order for binary_heap and fibonacci_heap, minimum order for heapq, and minimum order for the default quake/binomial comparators. A name such as find_min on a comparator heap refers to its comparator extreme.

Heap-array traversal is not sorted traversal. Mutable access to a stored key can violate ordering unless followed by an appropriate update operation. The node heaps do not establish ownership or membership of an arbitrary external handle. Only heapq supplies internal synchronization. heap/functions.hpp currently defines an empty namespace and no algorithms.

Capacity and operations

Default construction allocates the allocator's automatic extent. A one-count constructor allocates capacity for that many elements but leaves logical size zero. A variadic constructor with at least two arguments constructs T values and inserts them. Capacity includes allocator rounding; there is no heap-specific reserve or automatic growth. Move construction transfers storage; copying is deleted.

insert(T&&) appends and sifts upward under <. If already at capacity, it silently returns unchanged. get() removes and returns the maximum, refills its slot from the final element, and sifts down with >; empty get reports a library error. max() returns a copied maximum and also checks nonemptiness. size/max_size report live count and fixed allocated capacity.

clear() destroys class-type live values and sets size to zero, retaining the allocation. for_each visits heap-array order; its nonconst form can modify keys without repairing order. Iterator aliases are element pointers, but the class declares no begin/end members. Public inherited resource operations exist outside the heap-specific capacity model.

Complexity and iterator invalidation

Maximum lookup and size queries are constant time apart from copying T. Accepted insertion and extraction make at most logarithmic sift steps. A full insertion is constant time and drops its argument from the logical heap. Building through repeated insertion is O(n log n) comparisons. Clear/traversal are linear; moving transfers the buffer in constant time apart from old-destination destruction.

Sifting swaps element values, so an address identifies a physical slot rather than a stable logical key. Extracting ends the final slot's lifetime and can change values along a root path. No comparator parameter or synchronization is supplied.

micron::fibonacci_heap

A move-only node-based max-heap with circular root/child lists and deferred equal-degree consolidation.

Representation and operations

Each node owns one value, parent/child pointers, circular sibling links, degree/mark fields, and its exact allocator extent. Nodes are individually allocated through Alloc; moving transfers the root graph, while copying is deleted. The root member is named min_root internally, but comparisons select the largest value.

Copied or moved insertion adds a singleton root and updates the cached maximum. max() checks nonemptiness and returns a mutable reference. pop() checks nonemptiness, promotes the removed root's children, consolidates equal-degree roots, moves out the value, and destroys/frees that node. clear destroys/frees the whole forest. Size/empty are cached constant-time queries.

There are no public handles, decrease-key, erase-by-handle, or meld members. Private cut helpers and a mark field do not by themselves expose the full conventional Fibonacci-heap interface.

Complexity and reference invalidation

Insertion performs constant pointer work plus one node allocation and construction. A pop can scan a linear number of roots after many insertions; deferred consolidation gives logarithmic amortized consolidation work for ordinary insert/pop sequences under the degree invariants, rather than a logarithmic worst-case single pop. Clear is linear in nodes; moving a new heap is constant time.

Nodes are relinked without moving their values. A reference to an unremoved node's value survives insertion/consolidation but ends when that node is popped or cleared. Mutating the reference returned by max does not repair heap order. No synchronization is provided. Consolidation uses a fixed 64-entry degree table, with oversized degrees clamped rather than dynamically growing the table.

micron::heapq

Defined in header <micron/heap/heapq.hpp>.

An exclusive-mutex-protected minimum-priority heap stored in a growing fvector.

Member types and interface

Declares value_type = T, size_type = usize, reference = T&, and const_reference = const T&. Default construction creates the underlying vector. Construction from fvector<T> copies values then performs bottom-up heapification. Copy construction locks and copies a source; move construction transfers its vector without locking the source. Assignments lock both objects in address order.

push(const T&) copies an appended value and sifts upward under <. pop() checks nonemptiness, copies the minimum, refills from the final value, removes that slot, and sifts downward. top() returns a const reference to the minimum after releasing its lock; data() similarly returns a reference to the underlying fvector. These references require external exclusion during later use.

Size/empty and for_each take the mutex. Nonconst for_each can modify keys without restoring the heap invariant, and callbacks execute while the nonrecursive mutex is held. There are no public clear, reserve, max_size, comparator, or rvalue-push members.

Complexity and iterator invalidation

Top and size queries are constant time apart from lock waiting. A push makes logarithmic sift steps and may also relocate a linear vector prefix; geometric growth amortizes relocation across pushes. Pop makes logarithmic sift steps. Construction from a vector is linear heapification plus copying. Copy/traversal are linear; moving a new object is constant time with exclusive source ownership.

Vector growth can invalidate all element references; sifts change slot values even without reallocation. Popping ends a slot lifetime. A temporary internal lock does not protect references retained after top/data return. Destruction and moving require coordination with concurrent callers.

micron::quake_heap

Defined in header <micron/heap/quake_heap.hpp>.

A move-only comparator-priority container formed from binary tournament trees, with stable entry handles and recycled node storage.

Template parameters and representation

Compare defaults to __quake_less<T>; this selects a minimum. __quake_greater<T> selects a maximum. Alloc supplies node, entry, and forest-directory storage. The quake ratio defaults to 3/4. The source requires AlphaDen != 0 and AlphaNum < AlphaDen; it does not reject zero numerator despite the assertion text describing an open interval.

Each payload belongs to an entry allocation, separate from tournament nodes that refer to it. The root directory is a fvector<node*>. For reducible key types with exactly one of the built-in comparators, a parallel fvector<T> caches root keys for SIMD argmin/argmax selection; other comparators scan roots. Per-height counts and root positions are u32; tournament bookkeeping has 64 height slots.

Removed entry/node allocations are recycled into per-heap pools. Clear destroys values and recycles nodes but retains those pools; destruction drains them. Copying is deleted. Moving transfers forests, handles' entry allocations, count metadata, comparator, and pools.

Operations and handles

insert and emplace return an entry handle. find_min/peek return a checked const reference to the comparator-extreme value. decrease_key(h, new_value) acts only when the comparator says the new value improves the old one; for a greater comparator this is a numerical increase. It updates the entry, cuts its highest relevant tournament subtree to a root when necessary, and updates the cached extreme.

extract_min removes and returns the comparator extreme, shakes out its winner path, consolidates equal-height roots, applies quake truncation when height ratios violate the threshold, and recomputes the extreme. erase(handle) exposes that entry as a removable root and uses the same extraction machinery. Null handles are no-ops for decrease/erase.

meld(other&&) appends the other forest's roots, combines counts, and empties its active forest without cloning payload entries. Comparators must describe compatible ordering; the operation does not validate that requirement. A self-meld is not guarded and must not be requested. There is no contiguous payload iterator interface or hard capacity query.

Complexity and reference invalidation

Extreme lookup and size/empty are constant time. Insertion and decrease-key perform constant local tree work but can grow the root/key vectors, giving linear worst-case directory relocation and amortized constant directory work under geometric growth. Meld is linear in transferred root count plus any directory relocation.

Extraction/erase can scan and link all roots and traverse tournament nodes during truncation; a single operation is linear in visited forest structure in the worst case. The implementation's ratio range and fixed-width bookkeeping do not establish a universal logarithmic bound for every accepted template argument and state. Clear is linear in retained active tournament structure; destructor also walks the free pools.

Entry addresses remain stable while root directories and tournament nodes change. A live handle follows its entry through decrease-key, meld, and moving ownership. Extraction, erase, clear, and destruction end that entry's lifetime; pool reuse can make a stale nonnull handle designate unrelated later storage. Membership and lifetime are caller responsibilities. No synchronization is supplied.

micron::quake_heap::handle

Defined in header <micron/heap/quake_heap.hpp>.

A nonowning pointer handle to one quake-heap entry.

Members and validity

The public member e is an entry pointer, initialized to null. valid() tests only whether this pointer is nonnull. It does not detect removal, pool reuse, a foreign heap, or destruction. Copying a handle neither retains the payload nor modifies its ownership; use it only while its original entry remains live.

micron::__binomial_heap

Defined in header <micron/heap/binomial.hpp>.

An implementation-facing move-only binomial heap with comparator-defined minimum order and a recycled-node pool.

Representation and interface

C defaults to __binomial_less<T>. node_type is __binomial_node<T, C>. Public root-list, cached-minimum, node-count, comparator, and pool members expose the implementation directly; there is no separate unprefixed binomial_heap class in this header. Tree roots are maintained in increasing degree, and equal degrees are linked during union.

Insert and emplacement allocate or reuse one node, union it into the forest, and return its pointer. find_min returns a checked const reference. extract_min removes the cached extreme root, reverses its child chain into degree order, unions those children back, destroys/recycles the removed node, and returns its moved value. Clear recycles all active nodes; only pool draining at destruction or ownership replacement returns their raw storage.

decrease_key(node, value) accepts only comparator improvement and swaps values upward until ordered. delete_node swaps the selected value to a root then extracts that root. A node pointer therefore tracks a physical node, not one immutable logical value through key updates. find performs equality search and returns a node pointer or null. meld(other&) consumes the other's active tree forest; its recycled pool remains separately owned.

Complexity, handles, and limits

Cached minimum/size/empty queries are constant time. Binomial degree consolidation scans a logarithmic root list: insert, extraction, meld, decrease-key, and node deletion take logarithmic structural work under intact binomial invariants, apart from allocation/element cost. Equality search and clear are linear in nodes visited; moves transfer the graph and pool in constant time apart from releasing an old destination.

Nodes are relinked without reallocating surviving nodes, but value swaps can retarget what a node handle represents. Extracted/recycled nodes invalidate their handles and may be reused. Callers must supply a live member node, compatible comparators on meld, and distinct heaps; self-meld has no guard. Exposed internal mutation can invalidate all structural bounds. There is no synchronization, general iterator, or capacity reservation API.

Template parameters and storage

N is a positive bit count divisible by eight. ExpectedN, defaulting to N/8, must be positive and is used only to choose the default number of hash rounds. Default L rounds (N / ExpectedN) * ln(2) to the nearest integer and clamps it to 1 through 64; an explicitly supplied L is only required to be at least one.

A 64-byte-aligned inline bitfield<N> stores N/8 bytes of bits, plus alignment padding. The declared heap storage and immutable tags do not match physical allocation/update behavior: no heap buffer is allocated, and insertion mutates bits. The element/pointer/iterator aliases are conventional type aliases; keys are not retained and no key traversal is provided.

Operations and interpretation

Construction clears every bit. insert(key) and emplace(key&&) set one bit for each seeded hash64 round; emplace hashes its argument without storing or consuming it. contains(key) tests the corresponding bits. False means at least one required bit is absent; true means the representation may have been inserted or may collide with other inserted representations.

Hashing reads sizeof(T) bytes, including any padding. Equal values whose object representations differ need not produce the same bits; use keys with canonical, consistently initialized representations when value-level membership matters. There is no erase, element count, false-positive estimator, saturation management, or public clear operation. Copying duplicates bits; the bitfield move operation copies them and zeroes the source.

Complexity and thread safety

Insert performs L hashes of sizeof(T) bytes. Contains performs at most L hashes and stops evaluating later hashes after a missing bit is found. Initialization and copying process N/8 bytes. Storage is fixed and exposes no element references to invalidate. Concurrent insertion modifies ordinary bitfield bytes and requires external synchronization, including against readers.
