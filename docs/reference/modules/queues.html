Queues

From micron reference
micron reference › Containers and strings

Queue containers provide mutable FIFO storage, persistent FIFO values, bounded concurrent rings, owner/thief work deques, and inline callable dispatch. Producer and consumer cardinality, capacity rules, and payload ownership are specific to each type.

Container types

<micron/queue.hpp> includes queue, conqueue, spsc_queue, static_mpmc, and both Chase–Lev deque variants. crossbeam, disruptor, immutable_queue/iqueue, and lambda_queue require their individual headers.

Capacity and ordering

queue and conqueue use N, defaulting to alloc_auto_sz, as an initial element count. That constant equals the target page size; it is not a byte-count argument here. Their max_size() returns current allocation capacity. The default serial allocator rounds byte extents to pages and recommends geometric growth, so allocated element capacity can exceed N.

spsc_queue, crossbeam, disruptor, and the Chase–Lev variants round the requested initial/fixed count up to a power of two. static_mpmc requires an already-positive power of two and uses exactly N slots. lambda_queue uses exactly N slots with modulo indexing and accepts non-power-of-two counts.

queue and conqueue name the oldest element last() and the newest front(). spsc_queue, disruptor, and immutable_queue use front() for the oldest element and last() for the newest. Work-stealing deques have two different removal ends rather than one FIFO removal policy.

Concurrency and lifetime

The concurrent rings publish payload construction with release stores and observe it with acquire loads; their cursor values are not locks held for a later caller operation. A separate empty() or size() observation does not reserve the next element. For MPMC rings, claimed but unpublished or cancelled tickets can also affect observations. Use the boolean result of the operation that actually transfers the value.

Cursor reset, storage destruction, and moving a container require the exclusivity stated by that type. References obtained from a ring slot must not survive its removal and reuse. Atomic payload slots do not own objects pointed to by a pointer payload. No container here arranges reclamation of those pointees.

Storage and ownership

Requires copy construction, move construction, copy assignment, and destruction of T. Default construction allocates for N elements and starts empty. Count constructors create n default or repeated values; list construction preserves list order. Copy operations are deleted. Move construction transfers the allocation, logical length, and head offset and empties the source. Move assignment first destroys and releases the old destination.

Removed elements leave unused space before the active prefix. Push appends at head + size() rather than wrapping. When the tail reaches the end, trivially copyable elements are compacted to index zero with memmove; nontrivial elements are relocated into a new allocation even when the total capacity need not grow. If the active count fills capacity, a larger allocation is requested through the allocator's growth policy.

Complexity and iterator invalidation

Push without compaction/growth and pop take constant time apart from element operations. Compaction, relocation, reserve, and clear are linear in the live count. Move construction and swap are constant time; move assignment additionally destroys the old destination. Iteration is linear and accessors are constant time.

Geometric capacity growth amortizes reallocation for a sequence of pushes, but head compaction is a separate cost: repeatedly popping one item from a nearly full queue and pushing one can compact the remaining sequence on every push. A universal amortized constant-time bound for arbitrary mixed operations therefore does not follow from the growth policy.

Compaction can move live values within the same allocation, and relocation can replace it, invalidating saved positions. Without either operation, push preserves existing live addresses; pop ends the oldest lifetime. No bounds checks protect last/front, and no synchronization is provided. Public resource operations can bypass the queue's head-offset invariants.

Storage and synchronization

Uses the same initial-capacity, active-head, compaction, and growth model as queue. Push, pop, clear, reserve, size queries, batch transfers, and locked traversal acquire a fast_mutex. Copy construction copies a locked source snapshot; moving locks the source and transfers its resource. Copy/move assignment and swap lock both objects in address order.

push returns the queue. Parameterless pop() discards an item and is a no-op when empty; pop(out) returns false when empty and otherwise assigns/moves the oldest value to out, destroys the source slot, and returns true. push_batch(items, count) copies all requested values under one lock, growing as needed; a throwing element copy can leave an already-inserted prefix. pop_batch assigns at most the available count and returns the number removed.

Access and complexity

last() means oldest and front() means newest. Both return unchecked references after releasing a temporary lock. Iterators likewise escape their acquisition lock; a separately obtained begin/end pair is not a locked snapshot. External exclusion is required while such references and iterators are used.

for_each_locked holds the mutex for the complete callback sequence. Its callbacks must not call another locking operation on the same nonrecursive mutex. Copying and locked traversal are linear; transfers, compaction, growth, and invalidation have the same bounds as queue, plus mutex waiting. Destruction requires that no other caller is using the object. Inherited low-level resource access bypasses synchronization.

Capacity and ownership

Requires move construction, move or copy assignment, and destruction. N is positive and at most half the unsigned counter range plus one; the actual capacity is its next power of two. The element-byte allocation is checked for representability. Construction allocates raw capacity without constructing every payload. Copy and move operations are deleted.

The producer caches the last observed consumer head, and the consumer caches the last observed producer tail. Push constructs a slot before publishing its cursor; pop assigns out and destroys the slot before releasing it for reuse. capacity() and max_size() return the rounded ring count rather than any allocator rounding. Initializer-list construction calls push repeatedly and ignores false results, so a list longer than capacity retains only its initial capacity-sized prefix.

Operations and results

push() and copy/move push return false when full. emplace(args...) constructs one payload in place. pop(out) assigns the oldest item and returns whether it succeeded; parameterless pop discards it. push_batch and pop_batch transfer as many values as fit/are available and return that count, including handling a wrapped two-run range.

peek(out) copies the oldest value without removing it. front() returns the oldest slot and last() the newest; neither checks emptiness. size and empty observe atomics but do not reserve a payload. Clear destroys queued nontrivial elements, resets both cursors and caches, and retains the allocation.

Complexity and thread safety

A single push/pop performs a fixed amount of cursor work and one payload operation, with no allocation after construction. Batch work is linear in transferred count. Clear is linear for nontrivial destructors and constant time otherwise. Slot reuse invalidates references to removed payloads.

Only the producer may call producer-side operations, and only the consumer may call consumer-side operations. Peek/front inspection must be coordinated with consumption. Clear and destruction require both sides stopped. Public resource inheritance is not an alternate synchronized resizing interface. If output assignment throws, a single pop retains its cursor and payload lifetime, although a move assignment may have changed the stored value; throwing batch assignment commits already-completed removals individually.

Representation and interface

Allocates a ring whose capacity is the next power of two at least N. Payload requirements and overflow bounds match spsc_queue. Copy and move are deleted. A cache-line-separated published cursor and consumed cursor, plus cached peer cursors, coordinate one publishing thread and one consuming thread. There is no consumer-registration API or multicast dependency graph.

publish and consume(out) are the primary boolean transfer operations; push and pop(out) forward to them. emplace constructs one value. try_publish_batch and try_consume_batch transfer a fitting/available prefix and return its length. peek copies without removal. pub_cursor and cons_cursor return the current monotonically advancing unsigned counters, not indices already reduced modulo capacity.

front and last expose unchecked references to the oldest and newest slots. capacity/max_size report the rounded bound. Clear destroys pending nontrivial payloads, resets counters/caches, and retains raw capacity.

Complexity and thread safety

Single transfers take constant cursor work and one element operation; batches are linear in transferred count. There is no automatic allocation or growth after construction. Counter snapshots and exposed references are subject to the same one-producer/one-consumer and lifetime restrictions as spsc_queue. Clear and destruction require quiescence. Batch exception handling rolls back newly constructed unpublished values or records completed removals, according to the side of the transfer.

Cells and capacity

N is rounded up to a power of two with the same counter-range restriction as spsc_queue. Each heap cell is aligned to the greater of the cache-line and payload alignment and stores an atomic sequence tag, a state byte, and raw space for one T. Cells are initialized at construction, while payloads are constructed only by successful pushes. Copy and move are deleted; the queue does not grow.

Producers claim tail tickets by CAS, construct payloads, then publish ready cells. Consumers claim head tickets, assign out, destroy the payload, and reopen cells for a later cycle. Contention uses retry/backoff loops. capacity/max_size report the rounded cell count. size/empty are cursor observations rather than an exact count of immediately transferable ready values.

Operations and failure

Copy/move push and emplace return false when the inspected ring state cannot accept an item. pop(out) returns false when the next claimed sequence is unavailable; an earlier producer may still be constructing its slot. Construction failure publishes a cancelled cell before rethrowing; a later pop skips cancelled tickets. If output assignment throws after a consumer claim, that payload is destroyed and its cell released before the exception propagates.

Clear discards ready or cancelled cells without invoking callbacks. Destruction scans remaining published ready cells, destroys their payloads and the cells, and frees the allocation. Both require that producers and consumers have stopped.

Complexity and lifetime

An uncontended successful operation uses constant cell/cursor work plus construction or assignment/destruction. Contention retries and runs of cancelled cells prevent a fixed per-call step bound; an operation is not promised wait-free merely because it has no mutex. Initialization is linear in capacity; clear/destruction are linear in the cells visited. No raw slot accessors or iterators are exposed, so payloads are transferred by value rather than retained cell references.

micron::static_mpmc

Defined in header <micron/queue/static_mpmc.hpp>.

A bounded inline multi-producer, multi-consumer ring for is_atomic_type payloads.

Storage and member types

Requires a positive power-of-two N within the unsigned counter-distance bound. Stores exactly N cache-line-aligned cells in the object, plus separated atomic head/tail counters. Each cell contains a sequence tag, an extra state byte for the one-slot case, and a default-initialized T. The only ordinary member alias is value_type = T. No allocation, copying, moving, iterator, or resource-adoption interface is provided.

Operations and complexity

push(value) and pop(out) copy an atomic-type payload after successfully claiming a sequence-tagged slot. They return false on the observed full/empty state. The value-returning pop() returns T{} when removal fails and therefore cannot distinguish that sentinel from a valid default-valued payload. drain(fn) repeatedly removes values, invokes the callback, and returns a u32 count; the count can wrap if more than its representable number are drained.

capacity/max_size equal N. size, empty, and relaxed maybe_nonempty are temporal probes; they do not reserve a slot or guarantee the next operation's result. Single uncontended transfers take constant work; CAS contention gives no fixed retry bound. Construction is linear in N; drain/clear are linear in successful removals. Clear and destruction require quiescence. There are no exposed references to cells.

micron::chase_lev

Defined in header <micron/queue/chase_lev.hpp>.

A fixed-capacity work-stealing deque with one owner end and a concurrently stolen opposite end.

Storage and operation roles

Requires is_atomic_type<T> and a positive requested capacity N; capacity rounds up to a power of two. Construction allocates and initializes aligned atomic payload slots. value_type is T and the public constant __empty is T{}. Copy and move are deleted.

Only one owner thread may call push_bottom and pop_bottom. Its pushes and pops form a LIFO stack. Nonowner thieves call try_steal or steal_top and remove from the oldest end. The owner/thief race for the last item is settled by CAS on the top cursor. A full push_bottom returns false without allocating.

Results, complexity, and lifetime

pop_bottom(out) returns a boolean. The value-returning owner pop and plain steal_top() return T{} on failure, so a legal default payload is ambiguous through those overloads. try_steal returns a steal_result; steal_top(status) also exposes the three-way status. A lost weak CAS is distinct from an empty observation.

Owner push/pop and one steal attempt perform bounded constant cursor/slot work. Construction and destruction are linear in rounded capacity. size clamps an observed signed cursor distance to capacity; empty is likewise only an observation while other threads act. No external element references or iterators are supplied. Destruction requires all participating threads stopped; pointer payloads do not transfer pointee ownership automatically.

micron::chase_lev_grow

Defined in header <micron/queue/chase_lev.hpp>.

A work-stealing deque that doubles its ring segments when its single owner exhausts capacity.

Storage and growth

The operation roles, atomic-type payloads, result/status conventions, and public value_type/__empty match chase_lev. InitN rounds to an initial power of two. A segment stores a header and aligned atomic slots. A tagged base pointer records its capacity shift, and an atomic publication step makes a new segment visible to thieves.

On growth the owner allocates twice as many slots, copies the live ticket range, and retains the previous segment in a linked history. Previous segments are freed only at deque destruction, so a thief's earlier observed buffer is not reclaimed during use. There is no shrink operation. capacity() reports the current ring count.

Complexity and failure

A nongrowing owner operation or individual steal attempt takes constant work. Growing push initializes the doubled segment and copies live slots, taking linear time in the old/new capacity; geometric growth gives amortized constant copying/initialization per owner push. Total retained segment space is proportional to the largest allocated capacity, not current live count. Destruction visits every retained segment.

push_bottom returns false when capacity arithmetic cannot grow further. It is declared noexcept while growth calls allocation; an allocation exception therefore terminates rather than returning false. Copy/move are deleted, and destruction requires the owner and thieves stopped. No allocator template parameter or externally stable slot addresses are provided.

micron::immutable_queue

Defined in header <micron/queue/iqueue.hpp>.

A persistent FIFO value using reference-counted front/rear lists and incremental Hood–Melville rotation.

Storage and member types

Requires copy construction, move construction, and destruction of T. The object retains a front list, rear list, rotation state, and any rear currently being rotated. Each heap node owns one value and a successor reference. Default construction is empty. Copy construction retains a fixed set of root references; move construction transfers them and empties the source. Reference counts are ordinary non-atomic integers.

Declares category_type = buffer_tag, mutability_type = immutable_tag, memory_type = heap_tag, size_type = usize, and value_type = T. const_reference/const_ref are const T&, const_pointer is const T*, and iterator aliases the nested const_iterator.

Value operations and access

push and emplace return a new queue with a value at the newest end; pop returns the queue without its oldest element and returns an empty queue when already empty. The source value is unchanged. Every update advances at most two rotation-state steps instead of reversing a whole rear list in one update. clear returns an empty value; update_front(fn) rebuilds a queue by visiting and copying the sequence with its first element transformed.

front returns the oldest value without an empty check. peek returns its pointer or null. last returns a newest value from a rear list when possible, otherwise walks the front chain; it requires nonempty input. at(i) checks the logical count and walks the appropriate list, including a reversed-index rear traversal. identity exposes front-root identity only; distinct queue states can have the same front pointer.

Complexity and iterator invalidation

Copy/move construction and size/empty/front/peek queries are constant time. Push/pop perform a bounded number of node allocations/copies and rotation steps, apart from element cost and reclamation of references becoming unowned. Assignment/destruction can release an entire uniquely owned chain. last and indexed access are linear in the worst case. update_front, traversal, and nonidentical equality are linear in the sequence length.

Traversal materializes reversed rear-node pointers: for_each uses temporary storage proportional to the rear portions, and begin creates a shared iterator backing array of that size. New values preserve nodes held by old versions. Element references and iterators require a live version retaining their nodes; the iterator's backing array owns pointer storage but does not retain the payload nodes themselves.

Non-atomic node and iterator-backing counts require external synchronization when copying, destroying, or updating versions sharing nodes across threads. Value-oriented immutability alone does not make the ownership operations concurrent-safe.

micron::immutable_queue::const_iterator

Defined in header <micron/queue/iqueue.hpp>.

A forward iterator over a queue's front chain followed by a materialized FIFO ordering of its rear chains.

Operations and lifetime

Construction can allocate and fill a backing array of rear-node pointers. Copies share that backing with non-atomic reference counting; moving transfers it. Dereference/arrow expose the current const payload, and increment advances one node or backing index in constant time. Equality compares the current node address, with null denoting the end. No node ownership, random-access arithmetic, or standard iterator-category aliases are provided; a suitable queue version must remain alive.

micron::lambda_queue

Defined in header <micron/queue/lambda_queue.hpp>.

An inline ticketed callable queue with 64 bytes of capture storage per slot and explicit completion of claimed tasks.

Storage and ownership

N is positive and within the unsigned ticket-distance bound. Each inline slot stores invocation, destruction, and transfer function pointers, atomic sequence/state, a ticket, and slot_bytes == 64 callable bytes. push(fn) decays the callable and requires its size to fit 64 bytes and its alignment not to exceed the cache-line alignment. There is no heap spill for a larger capture.

Producers obtain tickets atomically and spin until their assigned slot is free. Consumers claim head tickets and can spin until a producer publishes that specific slot. Thus full push is a blocking spin, not a boolean rejection, and a producer that has reserved a ticket can delay later consumers. Constructor failure marks the ticket cancelled so it can be skipped.

Task leases and execution

pop() returns null when no ticket is available, or a node_base_t* designating a running slot. Calling node->call() invokes the capture. The caller must subsequently call node->~node_base_t() exactly once, including on exceptions, to destroy the capture and release the slot. The pointer designates inline queue memory and must not be deleted.

execute() performs that protocol for one task and destroys it even if the callable throws. clear() discards pending captures without invoking them and resets cursors. It requires no producers, consumers, or outstanding running task pointers. size/empty count ticket distance and can exclude running tasks that still occupy slots; max_size() is exactly N.

Copy, move, and complexity

Copy operations are deleted. Moving repeatedly pops source tasks, move-constructs their captures into destination slots, and destroys source task nodes; it is linear in pending captures and requires exclusive ownership with no outstanding leases. Move assignment clears its previous captures first.

Slot claim and dispatch are constant metadata work when uncontended and ready, but spin/CAS waiting has no finite per-call bound. Invocation cost belongs to the callable. A slot cannot be reused until its running node is destroyed. A producer/consumer protocol that retains every task lease while attempting another full push can therefore wait indefinitely.
