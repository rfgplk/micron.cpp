Regular expressions

From micron reference
micron reference › Algorithms

Byte-oriented regular expressions compiled to a Thompson program. regex owns a runtime program; cmatch<pattern> provides a constexpr-capable pattern form. Capture searches use a Pike virtual machine, while selected boolean searches can use a bounded DFA accelerator.

Pattern language

Supported constructs are concatenation, |, capturing parentheses, ., ^, $, bracket classes/ranges/negation, *, +, ?, and decimal intervals {m}, {m,}, {m,n}. Matching operates on unsigned byte values, not decoded Unicode code points. Dot accepts every byte, including newline. Anchors assert only the start/end of the complete subject; there is no multiline option.

Bracket POSIX class names use fixed ASCII sets: digit, alpha, alnum, upper, lower, space, blank, xdigit, cntrl, print, graph, and punct. Bracket negation complements all 256 byte values. There is no locale-dependent classification, Unicode property matching, lookaround, backreference evaluation, named groups, noncapturing-group syntax, or case-insensitive flag.

A backslash quotes the following byte. For example a pattern containing backslash-d matches the literal letter d; it does not introduce a digit class. A decimal interval is recognized only when its complete lexical form is present. Other brace characters can be treated as literals. Repeated quantifiers are parsed as nested repetition nodes; a trailing question mark does not implement a separate lazy-quantifier mode. These parser rules do not amount to validating every POSIX ERE diagnostic requirement.

The VM retains the match with the smallest start offset and, for that start, greatest end offset. Split alternatives visit their first branch before the second and program-counter deduplication preserves one capture history per position. This specifies the implementation's whole-match and branch-priority behavior; it does not establish the complete POSIX subexpression-disambiguation rules.

Limits, failures, and compilation cost

Runtime compilation provisions 4*L+16 AST nodes, L+8 classes, and 8*L+32 instructions for a pattern of L bytes. Interval repetitions expand into emitted copies; a short pattern with a large count can exceed the instruction budget. More than 32 explicit capture groups is rejected. Invalid syntax or exceeded parser/emitter/group limits leaves valid()==false; subsequent searches return no match. There is no diagnostic object identifying the failing offset or reason.

cmatch uses corresponding local limits 4*L+8, L+4, and 8*L+16, and at most min(L,32) explicit groups. Compilation failure returns an unmatched rmatch, so it is indistinguishable from an accepted pattern with no match. The fixed pattern parameter enables constant evaluation but the function itself is constexpr, not consteval; a runtime invocation can still perform compilation work.

The parser and emitter recurse through pattern structure and repeat expansion. Compilation costs include emitted program size and can include DFA subset construction. DFA building is attempted only for programs of at most 256 instructions, stores at most 255 states, and considers all 256 input bytes for each state. It abandons acceleration on state overflow or unsupported mixtures of start-anchor paths and retains the Pike program. Its fixed cap bounds table size, but repeated linear state interning and epsilon closures make compilation more costly than a simple byte-copy pass.

Runtime constructors and matching functions are noexcept and use micron allocation directly; invalid syntax is represented by valid/no-match state rather than exceptions. The implementation supplies no independent recoverable allocation-error result. Pattern bytes are needed during construction only; the compiled object owns its resulting program rather than borrowing the original pattern.

Search cost and accelerators

Let P be instruction count, G the number of capture slots, and N subject length. Pike simulation visits at most P program counters per input step through its generation-marked lists, and copies G capture slots for retained threads. A conservative search bound is O(N*P*G), with O(P*G) per-call working storage and recursive epsilon-closure depth tied to program structure. This avoids enumerating every backtracking history, but does not make pattern-size cost constant.

A nonnullable pattern with a restricted first-byte set uses memchr or a nibble-table class scan to locate candidate starts. Up to 33 failed anchored candidate attempts are allowed before restarting a general search; dense candidate input therefore falls back. The prefilter changes the work performed, not the accepted pattern language.

A constructed DFA can serve boolean has-match searches with O(N) transitions and no per-call VM arrays when the object prefers that path. It can skip self-loop runs through single-byte or small-class scanning. With at most 16 states and a supported SSSE3/NEON build, a shuffle-table representation is available. uses_dfa() and uses_sheng() report constructed accelerator availability; they do not guarantee which path a particular has-match call selects, and an available self-loop accelerator takes priority over shuffle traversal.

has_match_path() reports the chosen category: 0 general VM, 1 first-byte prefilter, 2 table DFA, 3 shuffle DFA, or 4 self-loop DFA accelerator. dfa_states() reports the constructed state count, or zero. Compile-time feature selection determines SIMD availability; no runtime CPU detector is supplied. Capture-returning searches always use the VM path, even when a DFA exists.

Subject lengths, captures, and lifetime

Raw C-string subjects stop at the first null. Objects satisfying has_cstr are normalized from c_str() and size(); that size must be the number of bytes to search. A string type whose size reports capacity should be passed through search_n(data,len) with its logical length. Explicit-length forms require a readable range; they do not validate its address or append a terminator.

Group zero denotes the whole match, and groups 1 through 32 follow opening-parenthesis order. groups() returns the number of groups including zero for a successfully processed program; an unmatched result can still report that count. group_start and group_end return -1 for absent/out-of-range groups or an unmatched result. End offsets are exclusive.

group(i) returns a borrowed raw_slice<const char>, empty when the capture is unset or invalid. A legitimately matched empty group is also an empty span; offsets distinguish it from an unset capture. The descriptor's copied offsets remain valid independently of the regex object's lifetime, but its base pointer and extracted slices require the original subject storage to remain alive and unchanged. Mutating/reallocating that storage can invalidate captures.

Compiled regex objects are move-only. Const searches use call-local VM buffers and read the compiled program/DFA; no match state is stored back in the regex object. Subject and allocator concurrency requirements still apply. Moving or destroying a regex invalidates raw program views borrowed directly from its internal helper structures, while ordinary rmatch results borrow only the subject.

micron::rgx::regex

Defined in header <micron/regex/regex.hpp>.

Move-only owner of a runtime-compiled byte regular expression, exported as micron::regex.

Members and use

Construct from a null-terminated pattern or has_cstr object, inspect valid(), then search repeatedly. Copy operations are deleted. Move construction/assignment transfer instruction/class/DFA allocations and invalidate the source's valid state. Destruction frees them. match and search, including their _n forms, have identical unanchored behavior; use anchors in the pattern when the subject boundary must be asserted. Boolean has-match can use a separate DFA path.

micron::rgx::rmatch

Defined in header <micron/regex/regex.hpp>.

Capture-result descriptor storing success, group count, subject base, and 66 signed offsets, exported as micron::rmatch.

Fields and access

matched records success; ng includes whole-match group zero; base borrows subject bytes; caps[2*i] and caps[2*i+1] are start/end offsets. has_match and explicit bool conversion inspect matched. Accessors validate success/group bounds and return -1 or an empty slice for absent captures. Default construction is unmatched even though its offset array is zero-initialized. Copying the descriptor does not copy subject bytes.

micron::rgx::subject_t

Defined in header <micron/regex/regex.hpp>.

Nonowning (const char* p, usize n) byte-range descriptor used to normalize search input.

Normalization

as_subject(const char*) scans a nonnull C string and treats nullptr as a zero-length subject. The has_cstr overload copies c_str() and size() without rescanning or changing units. The descriptor owns no data and does not extend an object's lifetime.

micron::rgx::charreach

Defined in header <micron/regex/charreach.hpp>.

Fixed 256-bit set of byte values used for classes and prefilters.

Members and complexity

w[4] contains four u64 words. Single-byte set/unset/test, clear/set_all/flip, and union/intersection use constant storage; range insertion takes O(range width). count uses four population counts. single returns the only byte value or 256 when membership is not singleton. Copying copies the entire membership set without allocation.

micron::rgx::nk

Defined in header <micron/regex/ast.hpp>.

AST node-kind enumeration for Empty, Char, Class, Any, Concat, Alt, Star, Plus, Quest, Repeat, Group, Bol, and Eol.

Operands

The active kind determines which node operand fields are meaningful. Character/class nodes use a; binary concatenation/alternation use a and b; unary repetition uses a; Repeat uses a as child, b as minimum, c as maximum; Group uses a as child and b as its one-based group number. kInf marks an unbounded repeat maximum.

micron::rgx::node

Defined in header <micron/regex/ast.hpp>.

Compact AST record containing a node kind and three u32 operands.

Ownership

Children/classes are represented by indices into externally supplied arrays. The record owns no nodes or character sets and performs no dynamic allocation. Default construction denotes Empty with zero operands. Operand interpretation is specified by nk.

micron::rgx::parser

Defined in header <micron/regex/ast.hpp>.

Constexpr recursive-descent parser writing nodes and byte classes into caller-provided bounded arrays.

State and failures

Stores pattern pointer/length/current position, node/class pointers with capacities and live counts, explicit-group count, and ok. Parse routines mutate that state. Node/class overflow or recognized syntax errors set ok false; parse() additionally requires complete pattern consumption. The caller owns all backing storage. Decimal interval accumulators are u32 and do not provide a separate overflow diagnostic.

micron::rgx::op

Defined in header <micron/regex/program.hpp>.

Instruction opcode enumeration for Char, Class, Any, Match, Jmp, Split, Save, Bol, and Eol.

Execution

Char/Class/Any consume one byte; Match accepts; Jmp/Split change control flow; Save writes a capture offset; Bol/Eol assert complete-subject boundaries. Split visits x before y. There is no instruction for a backreference, lookaround, or decoded Unicode character.

micron::rgx::inst

Defined in header <micron/regex/program.hpp>.

Program instruction containing an opcode and two u32 operands.

Operands

Char uses x as a byte value, Class as a class index, Jmp as a target, Split uses x/y as branch targets, and Save uses x as a capture slot. Other opcodes use their implicit next instruction or no operand. Default construction is Match.

micron::rgx::prog_view

Defined in header <micron/regex/program.hpp>.

Borrowed view of instruction and class arrays with counts and explicit-group count.

Lifetime and invariants

code/ncode and cls/ncls delimit externally owned arrays; ngroups excludes whole-match zero. VM, first-byte analysis, and DFA builders consume this descriptor. Valid indices/targets and an appropriately sized capture workspace are caller requirements. Copying the descriptor does not copy or retain allocations.

micron::rgx::emitter

Defined in header <micron/regex/program.hpp>.

Constexpr AST-to-instruction compiler using a caller-owned bounded code array.

Effects

Stores AST pointer, code pointer/capacity/live count, and ok. emit appends an instruction or marks capacity failure. emit_node recursively emits branches, capture saves, loops, and expanded repeat copies. compile_regex wraps the body in whole-match saves and Match, returns bool, and publishes counts only after successful parsing/emission.

micron::rgx::vm

Defined in header <micron/regex/pike.hpp>.

Pike VM state for a single search, referencing a program, subject, and externally allocated thread/capture arrays.

Lists and captures

The a/b program-counter and save arrays alternate between current and next input position. seen/gen suppress duplicate program counters within a generation; work is the mutable epsilon-closure capture vector; mcaps retains the selected result. run initializes capture slots to -1 and performs anchored-at-start_at or unanchored search. addthread recursively follows epsilon edges and copies captures for consuming/accepting states. The VM owns none of these buffers.

micron::rgx::first_info

Defined in header <micron/regex/prefilter.hpp>.

First-byte analysis result containing a charreach set and nullable flag.

Meaning

The set combines reachable initial consuming classes; nullable records a path to Match without consuming a byte. compute_first clears caller-provided seen storage and recursively walks epsilon instructions. Boundary assertions are traversed for a conservative prefilter rather than encoding subject positions in the returned byte set.

micron::rgx::truffle_masks

Defined in header <micron/regex/classscan.hpp>.

Two 16-byte nibble-indexed tables representing a 256-byte membership set for scanning.

Layout and results

lo_clear covers bytes with bit 7 clear; lo_set covers bytes with bit 7 set. Low nibble selects a table byte and the next three bits select a membership bit. truffle_build creates the masks from charreach. truffle_find_first returns the first member's index or the input length, using a selected AVX2/ARM64-NEON loop with scalar tail/fallback.

micron::rgx::dfa

Defined in header <micron/regex/dfa.hpp>.

Compiled boolean-search accelerator with byte transition tables, acceptance flags, and optional shuffle/self-loop scan tables.

Storage and lifecycle

Contains state count/start state, state-by-256 transition array, accepting/end-only arrays, optional 256-by-16 masks, and per-state escape accelerators. build_dfa allocates these arrays or returns nullptr when unsuitable; dfa_free releases the complete structure. The aggregate itself has no destructor or ownership-managing copy semantics, so raw copying does not create independent allocations. Runtime regex owns and frees the pointer it builds.

Matching

Capture saves are ignored during subset construction. The resulting automaton answers only existence, preserving end-only acceptance for $. Unanchored construction reseeds start transitions as bytes advance. DFA execution reads its tables without storing per-search state in the object.

rmatch::group_start(i), rmatch::group_end(i)

Defined in header <micron/regex/regex.hpp>.

i64 group_start(usize i) const noexcept;
i64 group_end(usize i) const noexcept;

Parameters

iCapture index; zero identifies the whole match.

Return value

The offset from the start of the input, or -1 if there is no corresponding capture. The end offset is exclusive.

Example

#include <micron/regex.hpp>

int main()
{
  micron::regex expression("b+");
  micron::rmatch result = expression.search("aabbbcc");
  return expression.valid() && result.has_match() && result.group_start(0) == 2
         && result.group_end(0) == 5 ? 0 : 1;
}
