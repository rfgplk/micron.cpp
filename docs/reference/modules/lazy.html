Lazy algorithms

From micron reference
micron reference › Algorithms

Pull-based range adaptors in micron::lz compose with operator|. Most adaptors defer element work until iteration; ordering, right scans, and some window operations can materialize their input when applied.

Sources, evaluation, and lifetimes

of(lvalue) borrows the range. A nonfixed contiguous container is reduced to a pair of const pointers; other lvalues use a reference view. of(rvalue) and owned(rvalue) move the container into an owning view. Copying a borrowed view does not copy its source or extend the source's lifetime. An existing view is copied or moved into the next adaptor according to its value category; move-only views must be passed as rvalues when ownership is transferred.

Adaptors store their base view and callable by value. Iterators for stateful callables usually retain a pointer into the view through fn_carrier<F>; empty callable types are copied into the iterator. Such iterators must not outlive, or survive movement/destruction of, the view carrying the callable. Owning views and buffers likewise retain storage needed by their iterators.

begin() can perform work: filtering seeks the first match, unfolding invokes its generator, deduplication creates history, and prefix-dropping advances upstream. transform_view applies its callable on every dereference rather than caching it. Composing filter after transform can therefore evaluate a transform more than once per accepted element. Callable effects and repeated dereferences remain observable.

Iteration is not universally multipass. Several cursors hold their own accumulator or history, while by-value flattening stores the current inner range in a slot shared by the parent view. Repeated begin() can restart or re-evaluate a pipeline; separate traversals are suitable only when the underlying range and callables support them.

Size information and collection

size_kind::exact records a known count; bounded records an upper bound; unknown gives no guaranteed count; endless identifies a source without an intrinsic end. kind_of<V>, static_size_of<V>, and materializes<V> expose compile-time traits. A zero static size is also the no-static-extent sentinel, so it does not generally encode a known empty fixed range.

collect<Out>() and to<Out>() return the same terminal. Exact sizable output is constructed/resized to the hint and filled through pointers. Bounded sizable output is initially sized to its bound, filled, then shrunk; a flat filter can use a direct drain loop. Unknown-length output requires push_back, with optional reservation. A fixed output with no resizing or append requires a matching nonzero compile-time extent. Runtime take, filtering, and most generators erase that extent.

Collection rejects endless metadata at compile time. An unknown source can still fail to terminate, and take_while only terminates when its predicate eventually rejects. Bounded/exact collection assumes the supplied hint is valid; it does not grow a pre-sized buffer if the implementation emits more elements than that hint.

Pairwise metadata requires care with unknown-length generators. zip_with_view classifies a mixed nonexact pair as bounded; two unknown sources can provide a zero reserve hint despite producing values. zip_arith_view also classifies two endless operands as bounded. Such combinations must not be sent directly to a sized collector: establish a valid explicit finite bound with take(n) first. Metadata is an optimization contract, not a proof of termination for every composition.

The sizable, reservable, pushable, and size_constructible concepts test output operations, not general container suitability. cheaply_sized recognizes contiguous, static-size, or explicitly tagged ranges. reversible requires matching iterator/sentinel types and bidirectional movement; flat_exact requires exact size and contiguous iteration; indexable_exact additionally identifies exact random-access ranges with an exact-size member.

Complexity and allocation

Simple mapping, selection, concatenation, zip, scans, and weaving require O(number of upstream advances plus callable work) for one traversal and O(1) adaptor state. Selection may examine arbitrarily many upstream elements for one output. take(n) avoids a final upstream increment in its counting-iterator path, but obtaining the initial upstream iterator can still perform work even when n is zero.

sort and sort_by drain all input to an fvector, then introsort in O(n log n), returning a move-only buffer_view. reverse uses a reverse cursor for reversible input; otherwise it drains and reverses O(n) buffered values. foldr similarly traverses backwards or buffers; scanr always returns a buffer of n+1 accumulator values. chunk, sliding, and grouping keep flat exact input directly and otherwise drain it first.

nub allocates a seen set with the same equality-aware hash/fallback selection as eager nub. nub_by stores previously accepted values and scans them, requiring O(n²) equality work in the worst case. materializes<V> marks selected full-buffer views; false does not imply allocation-free execution or a transitive absence of a materialized base.

count() returns exact size without dereferencing elements when exact-size metadata is present, so upstream mapping functions need not run. Integral sum() returns umax_t; floating sum() returns f128 using compensated double lanes with a wide fallback. The nonindexable floating fallback can restart the whole source after a nonfinite first pass. Empty checks in safe aggregates can also call begin() separately before the reduction. These paths require repeatable sources and callables when a second traversal occurs.

Exact-size mean uses the sum kernels and known count; unknown-size mean accumulates directly in the selected result type while counting. Numeric results can consequently depend on pipeline structure. Safe means/extrema/sums check emptiness, not arithmetic domains or overflow. Unchecked min/max require nonempty input. Lazy inner product truncates to the common prefix; safe inner product requires both inputs to end together.

Results and materialization boundaries

Search/access terminals return copies in option<Value,fp::empty_container_error> or option<usize,fp::empty_container_error>; at/nth instead use index_out_of_bounds_error. find_of(value) returns an index, not a borrowed iterator. Quantifiers and first-match searches may terminate on endless inputs when a deciding element is reached. Full reductions, last-element searches, ordering, and most materializing terminals reject endless metadata or require a terminating source.

partition<C> evaluates its predicate once per consumed element and builds two C values. span_at<C> splits at the first predicate failure; sbreak<C> splits at its first success. traverse<C> and sequence<C> stop at the first second alternative and preserve its actual error type. sequence_check returns bool. zip_strict<C> builds common-prefix results before detecting unequal final lengths; checked arithmetic terminals similarly may have invoked earlier element operations before failure.

chunk_into<Out>(0) returns empty, whereas lazy window chunk(0) and sliding(0) normalize the width to one. transpose<Out> drains the rows and reports ragged widths with bad_zip_error; transpose_trunc<Out> uses the shortest row width. These terminals own their resulting data.

Lazy merge(other) is an alias for concatenation, without sorting. Lazy zip_with, zip, ap, and zipped arithmetic stop at the shorter input. Their names do not imply the equal-size checking performed by eager fp::zip_with and fp::ap. zip_with_trunc is an alias for the ordinary lazy zip-with adaptor.

Nested and helper types

View value_type names the decayed element value. Cursor reference can instead be a borrowed reference, a reference to cursor-owned state, or a produced value; it is not uniformly value_type&. Cursor difference_type is the underlying iterator difference type or ssize_t. Most transforming/filtering/generating views expose a dedicated empty sentinel type whose comparison asks the cursor whether traversal has finished; an end sentinel cannot be dereferenced or decremented.

take_view::iterator aliases either the base iterator or counting_it; reverse_view::iterator aliases the reverse cursor. flatten_view::Inner is the decayed inner-range type. as_view_t<R> names the selected source-view type. fn_carrier<F> stores an empty callable directly or a pointer to a nonempty const callable; hold and call implement that storage convention. Public __-prefixed tags and trait members are implementation metadata, not independent owning containers.

micron::lz::size_kind

Defined in header <micron/algorithm/lazy/__lazy_bits.hpp>.

Enumeration describing the size information available before traversal.

Enumerators

exact=0 denotes a known count; bounded=1 an upper bound; unknown=2 no guaranteed count; endless=3 no intrinsic end. degrade(exact) produces bounded; bound_endless(endless) produces unknown for predicate-limited traversal. These transformations do not themselves examine input.

micron::lz::ptr_view

Defined in header <micron/algorithm/lazy/source.hpp>.

Borrowed exact view of a contiguous half-open range of const T elements.

Storage and operations

Stores two pointers, with O(1) construction, begin/end, exact size, and reserve hint. Owns no elements. Its source allocation and live elements must remain valid; source reallocation invalidates the view. Used by of for ordinary contiguous lvalues and as the element type of window/group views.

micron::lz::ref_view

Defined in header <micron/algorithm/lazy/source.hpp>.

Borrowed view retaining a pointer to an existing range object.

Storage and operations

Begin/end forward to the referenced range. Cheaply sized ranges receive exact size metadata; others remain unknown. Small unrollable fixed containers preserve their static extent. The range object and its iterator storage must outlive use. Const access to the view does not add constness to a mutable referenced range.

micron::lz::owning_view

Defined in header <micron/algorithm/lazy/source.hpp>.

Move-only view that owns an rvalue container and exposes its const iteration.

Storage and operations

Construction moves C into the view; copying is deleted and move construction is defaulted. Exact/static metadata follows the container's traits. Destruction releases C normally, invalidating borrowed iterators/subviews. Used to retain temporary source containers throughout a named pipeline.

micron::lz::transform_view

Defined in header <micron/algorithm/lazy/transform.hpp>.

View applying a stored const-invocable function on each dereference.

Effects and complexity

Retains base size and static extent, and adds no element buffer. A dereference returns the function's exact result reference/value category; value_type is its decay. Increment advances upstream without evaluating the function. Repeated dereference repeats the call. The cursor optionally supports decrement when its base does, but its separate sentinel can still prevent the whole view from satisfying reversible. Scalar arithmetic and key/value projection are specializations of this mechanism.

micron::lz::filter_view

Defined in header <micron/algorithm/lazy/filter.hpp>.

View of elements accepted by a stored predicate, preserving source order.

Effects and complexity

Begin and increment seek the next accepted element; dereference forwards the current base reference. Exact size degrades to an upper bound; no static extent is retained. One full traversal performs O(n) predicate tests with O(1) cursor state. A rejected endless source can make seeking fail to return. reject wraps this view with a negated predicate.

micron::lz::take_view

Defined in header <micron/algorithm/lazy/take.hpp>.

View of at most the first n elements of a source.

Iterator and size

Exact random-access input uses its original iterator and a clamped end. Other inputs use counting_it, stopping at the count or source end. Exact input remains exact; other kinds become bounded with n as an upper bound. The counting cursor avoids advancing upstream after its final requested output. Runtime n removes compile-time extent.

micron::lz::drop_view

Defined in header <micron/algorithm/lazy/take.hpp>.

View omitting the first n source elements or all elements if the source is shorter.

Effects and complexity

Begin jumps in O(1) for exact random-access sources; otherwise it advances up to n times on every begin call. End forwards the base sentinel. Exact size decreases by the clamped skipped count; other metadata is preserved. No copied element buffer is created.

micron::lz::take_while_view

Defined in header <micron/algorithm/lazy/take.hpp>.

View of the initial source prefix satisfying a predicate.

Effects and termination

Sentinel comparison tests both source exhaustion and the predicate on the current element. Repeated comparisons can repeat predicate evaluation. No failing element is emitted. Exact input becomes bounded and endless input becomes unknown; termination of an endless source requires eventual predicate failure.

micron::lz::drop_while_view

Defined in header <micron/algorithm/lazy/take.hpp>.

View omitting the maximal initial prefix satisfying a predicate.

Effects and complexity

Begin performs the prefix scan each time and then returns the base iterator, leaving later elements untested. Exact size becomes bounded; endless input stays endless. An endless all-accepted prefix never produces a first element. No element buffer is used.

micron::lz::init_view

Defined in header <micron/algorithm/lazy/take.hpp>.

View of every source element except its final element, using one-element lookahead.

Cursor state and lifetime

The cursor copies a current element into its own held value and advances upstream to establish that another element exists. Dereference returns const value_type& into that cursor; increment replaces it. Empty and singleton finite inputs produce no outputs. Exact count is max(n-1,0), and retained state requires default construction and assignment of the element type.

micron::lz::iota_view

Defined in header <micron/algorithm/lazy/generate.hpp>.

Endless incrementing generator produced by counting(from).

Effects

Each iterator owns its current T, dereferences by value, and advances with ++T. The sentinel never compares equal. No allocation is performed. Bound the sequence before a complete traversal; overflow and increment semantics are those of T.

micron::lz::iterate_view

Defined in header <micron/algorithm/lazy/generate.hpp>.

Endless recurrence generator storing a seed and function.

Effects

Begin copies the seed to cursor state. Dereference returns a const reference to that state; increment replaces it with function(current). repeat supplies the identity recurrence and replicate(n,value) adds a take adaptor. Functions are called on advancement, unlike eager fp::iterate, which also calls after its final emitted value.

micron::lz::fixed_view

Defined in header <micron/algorithm/lazy/generate.hpp>.

Single-value storage backing the zero-element and one-element generators.

Supported extent

once(value) uses N=1 and empty<T>() uses N=0. The representation contains only one T while end is formed as its address plus N. Direct instantiations with N greater than one do not provide an N-element array and must not be used as repetition containers. repeat or replicate provides repeated values.

micron::lz::unfold_view

Defined in header <micron/algorithm/lazy/generate.hpp>.

Generator repeatedly applying a state-to-option function until its error alternative.

Effects and results

A success pair supplies the emitted value and next state; pair extraction accepts the supported member/tuple conventions. Begin performs the first call, and increment performs the next. The current value and state are stored in the cursor, requiring their construction/assignment operations. Error ends traversal and is discarded. Metadata is unknown, so finite termination remains the callable's responsibility.

micron::lz::zip_arith_view

Defined in header <micron/algorithm/lazy/arith.hpp>.

Pairwise arithmetic view advancing two sources together and stopping when either ends.

Results and constraints

Dereference invokes the stored binary operation and can return a promoted arithmetic type. Scalar division is unchecked; divide_zip_each<A,B> selects a binary callable returning a division-error option per element. Both exact operands yield exact minimum size; other pairs are classified bounded. Two endless operands do not automatically become endless metadata, so establish a finite take bound before complete traversal.

micron::lz::zip_with_view

Defined in header <micron/algorithm/lazy/zip.hpp>.

View combining corresponding elements of two sources with a const-invocable function.

Results and complexity

Stops at the shorter source, with O(1) cursor state and one binary call per dereference. Exact size is the minimum of two exact counts; two endless inputs are endless; other pairs are bounded. zip creates value tuples and ap invokes source functions on corresponding values. Stateful function iterators borrow their callable from the view. Owned secondary ranges must be transferable through the adaptor's copying requirements.

micron::lz::enumerate_view

Defined in header <micron/algorithm/lazy/zip.hpp>.

View producing value tuples of zero-based index and copied source value.

Results

The cursor stores an index, advances it with the base iterator, and returns tuple<usize,range_value_t<V>> by value. Source size/static extent is retained. Enumeration does not provide references for mutation through the tuple.

micron::lz::flatten_view

Defined in header <micron/algorithm/lazy/flatten.hpp>.

View concatenating nested ranges while skipping empty inner ranges.

Ownership and iteration

Lvalue inner ranges are traversed directly. A prvalue inner range is constructed in a single manual-lifetime slot held by the parent view until the next inner range replaces it. Iterators and references into that produced inner range then expire. Concurrent cursors over the by-value case share the slot and are not independent. Work is linear in visited outer ranges and emitted elements, plus inner-range construction; output count is unknown unless the outer range is endless. flat_map composes transformation with this view.

micron::lz::concat_view

Defined in header <micron/algorithm/lazy/flatten.hpp>.

View traversing all of a first range followed by a second range.

Results

Both sources are retained by value as views. Identical source reference types are preserved; differing reference types are converted to the first range's value type. Exact lengths add; either endless operand makes the concatenation endless. The second range is never reached if the first is endless. merge is an alias of this concatenation.

micron::lz::intersperse_view

Defined in header <micron/algorithm/lazy/weave.hpp>.

View alternating input elements with a stored separator, with no leading or trailing separator.

References and size

An n-element exact input has max(2n-1,0) output elements. The cursor returns const value_type& to either the view's separator or the current source element. The base must yield stable compatible references: applying this implementation directly to a value-producing transform can return a reference to a temporary. Retain a materialized source before this operation when source dereference produces values. intercalate composes this operation on inner ranges with flattening.

micron::lz::step_view

Defined in header <micron/algorithm/lazy/weave.hpp>.

View selecting every step-th source element, beginning with the first.

Effects and complexity

A zero step is normalized to one. Increment performs up to step upstream increments; it does not use random-access jumps. Exact input degrades to a bounded count with a ceiling-divided hint. Traversing n original elements requires O(n) advances even if few outputs are emitted.

micron::lz::unique_view

Defined in header <micron/algorithm/lazy/unique.hpp>.

View retaining the first element and skipping following elements equal to the most recently retained value.

State and comparison

The cursor stores a copied retained value and returns a const reference to that value. Equality is tested as (candidate,retained). O(n) equality tests and O(1) retained element storage are used for a complete traversal. Stateful equality callables are borrowed from the view. It removes consecutive duplicates, not duplicates across separated runs.

micron::lz::nub_view

Defined in header <micron/algorithm/lazy/unique.hpp>.

View retaining first occurrences using an iterator-owned equality-aware seen set.

Storage and complexity

Begin allocates/reserves history from the input hint and searches for the first fresh value. Hash-compatible values use a Swiss set; other types use a vector of prior values. Expected linear hashing behavior or O(n²) fallback equality work, and O(k) distinct-value history, follow the eager seen-set rules. Dereference forwards the base reference, so repeated dereferences can re-evaluate a transformed base. A fresh begin creates fresh history.

micron::lz::nub_by_view

Defined in header <micron/algorithm/lazy/unique.hpp>.

View retaining first occurrences according to a supplied equality predicate.

Storage and complexity

The cursor stores each accepted value in an fvector, scanning retained values as (retained,candidate) before acceptance. Worst-case O(n²) equality work and O(k) retained storage are required. Begin and increment can scan many duplicates. Dereference forwards the upstream result rather than the stored history value.

micron::lz::scanl_view

Defined in header <micron/algorithm/lazy/scan.hpp>.

View emitting an initial accumulator followed by each successive left-fold result.

Effects and size

An n-element finite source emits n+1 accumulator values. The cursor stores A and replaces it using (accumulator,element) on increment, returning a const reference to cursor-owned state. The reference changes at the next increment. Input size kind is retained and its finite hint increases by one; no full output buffer is allocated. scan aliases the left-scan adaptor.

micron::lz::buffer_view

Defined in header <micron/algorithm/lazy/order.hpp>.

Move-only exact view owning an fvector<T> of materialized values.

Storage and uses

Exposes const pointer begin/end, exact size, and the full buffer size as its hint. Copying is deleted; move construction transfers the vector. Destruction releases all retained values. Used by sorting, nonreversible reversal, right scans, and nonflat window preparation. materializes<buffer_view<T>> is true.

micron::lz::reverse_view

Defined in header <micron/algorithm/lazy/order.hpp>.

Nonmaterializing reverse traversal of a reversible retained base view.

Iterator and constraints

Uses a reverse cursor initialized from the base end, dereferencing the preceding element. Random-access operations are supplied when the base cursor supports them. Source size and static extent are retained. The public reverse adaptor selects this type only for matching bidirectional iterator/sentinel input and otherwise returns a materialized buffer.

micron::lz::chunk_view

Defined in header <micron/algorithm/lazy/window.hpp>.

Exact view of consecutive borrowed pointer subranges, retaining a final partial chunk.

Storage and lifetime

Requires flat exact input. The public adaptor first buffers other finite inputs. A zero width becomes one, and count is ceil(n/width). Dereference constructs a ptr_view<T> without copying elements. Subviews borrow the retained source, including an internal materialized buffer, and must not outlive it. Advancing between chunks is O(1).

micron::lz::sliding_view

Defined in header <micron/algorithm/lazy/window.hpp>.

Exact view of complete overlapping borrowed windows advanced by one source position.

Storage and lifetime

Requires flat exact input; the public adaptor buffers other finite input. A zero width becomes one. Output count is max(n-width+1,0). Each dereference constructs a ptr_view<T> in O(1), with no per-window element copy. Collected window views continue to borrow the parent/source storage.

micron::lz::group_view

Defined in header <micron/algorithm/lazy/window.hpp>.

View partitioning a flat exact sequence into maximal runs whose adjacent elements satisfy an equality predicate.

Effects and lifetime

Begin and increment extend a run by testing adjacent source elements. A complete traversal performs O(n) tests and emits ptr_view<T> subranges with O(1) cursor state. The number of groups is bounded by source size. Nonflat finite input is buffered by the public group/group_by adaptor, and emitted subviews borrow that storage.

Example

#include <micron/lz.hpp>
#include <micron/vector/vector.hpp>

int main()
{
  namespace lz = micron::lz;
  micron::vector<int> values({ 1, 2, 3, 4, 5 });
  auto result = values | lz::filter([](int x) { return x % 2 != 0; })
                       | lz::fmap([](int x) { return x * 10; })
                       | lz::take(2) | lz::collect<micron::vector<int>>();
