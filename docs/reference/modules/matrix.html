Matrices and linear algebra

From micron reference
micron reference › Numerics and mathematics

Fixed and dynamic dense matrix storage, borrowed row/column-major views, and real linear algebra. Fixed matrices keep elements inline; dynamic matrices own serial-allocator vectors. Factorizations, solves, spectral decompositions, matrix functions and polynomial utilities use explicit result records or documented numeric failure values.

Dimensions, arithmetic and lifetime

Fixed matrix dimensions are positive template arguments, and both the input and every intermediate/result type must fit its own inline byte bound. mat<T,R,C> uses row count before column count; its underlying int_matrix_base<B,C,R> uses column count first. These classes accept arithmetic scalar elements. Decompositions generally require ieee754_floating and use real arithmetic; they do not instantiate complex-valued matrices.

at, flat indexing, row and column access, submatrix construction and dynamic shape operations do not check bounds. dynmat::with_ld allocates rows*ld elements without requiring ld>=cols or checking the multiplication for overflow. All dimensions, products, leading dimensions and addressed extents must fit their integer types and the actual storage. Square dynamic algorithms generally take N=A.rows and do not verify A.cols==N.

Elementwise matrix +, -, *, / and their compound forms operate coefficient by coefficient; use matmul, ops::gemm or BLAS gemm for matrix contraction. Fixed returns are values with inline storage. Dynamic returns own allocations; views and raw pointers borrow their owner, and assignment, reallocation, move of the owner or destruction can invalidate them. Fixed moves copy coefficients and zero the moved-from base. Algorithms taking const input normally form independent factor/result storage; named apply/solve-inout and raw band routines mutate their designated buffers.

All bounds, finite-input requirements and mathematical structure remain caller preconditions unless a particular result states a check. noexcept is not a separate recoverable allocation-status mechanism. FMA, reduction order, packed kernels and compile-time ISA selection can change floating-point rounding; no cross-ISA bitwise identity or general overflow/NaN guarantee follows from these interfaces.

Solve and determinant conventions

linalg::solve and linalg::inv are fixed-matrix conveniences using pivoted LU. On a singular factor they return all-NaN values; decomp::inv instead returns a zero X with singular=true. decomp::det and linalg::det return zero for singular LU. log_det returns {0,0} for singularity, otherwise log(abs(det)) and sign; zero sign is the indicator, not log_abs alone. condition_number forms the inverse and multiplies Frobenius norms, returning infinity on singularity; decomp::rcond forms the inverse and returns 1/(one_norm(A)*one_norm(inv(A))), or zero when singular/zero.

lu_solve and lu_full_solve do not inspect singular/rank flags before division. Check the factor first. Full/partial pivoting use different stopping tests, and colpiv QR compares tol to a squared column norm while fullpiv QR compares it to an entry magnitude. Tolerances are not interchangeable relative-rank thresholds. Rank truncation and finite numerical pivots do not certify conditioning.

linalg::lstsq and linalg::pinv use unpivoted Gram-Schmidt QR and unchecked division by R's diagonal; their intended case is a full-column-rank tall matrix. pseudoinv::pinv and rank use singular-value thresholding instead. Choosing an SVD/COD path is necessary when rank truncation or a minimum-norm construction is required rather than an unchecked full-rank triangular solve.

Spectral result constraints

Symmetric routines assume symmetry without comparing both triangles. eigen_sym3 and eigen_sym_qr sort ascending; general Jacobi eigen_sym leaves its diagonal in sweep order. eigen_sym2 emits descending values, but its diagonal-input branch leaves vectors as identity even when the first value corresponds to the second input axis. The value/vector association therefore requires care for diagonal A with A(1,1)>A(0,0), and svd2 inherits this branch. svd3 sorts descending after forming A^T*A.

General eigen returns Schur vectors Z, not individual eigenvectors. Real 2x2 Schur blocks encode conjugate pairs through values_re/values_im. A false converged flag leaves the current iterates; eigen still extracts values from those iterates. The fixed/dynamic one-sided Jacobi SVD initializes U to zero and fills only C columns, leaving trailing columns and zero-singular-value columns zero rather than completing an orthonormal full U. pseudoinv::svd has no runtime tall-shape check: direct wide input can write beyond its R-by-R U allocation. Its callers pinv/rank/orth/null adapt wide shapes before invoking it.

pseudoinv utilities use a positive supplied tol, otherwise max(rows,cols)*largest_singular_value*default_eps; values strictly greater than that threshold are retained. They do not propagate the SVD convergence flag to their return type. null's wide path pads to a square matrix, so its default tolerance uses the padded dimensions. Use the direct SVD result when convergence must be checked separately.

Despite its name, svd_bdc performs bidiagonal QR, and svd_bdc_dnc currently raises threshold to the entire reduced dimension before calling its helper. The latter also allocates an off-diagonal vector of K-1 elements although its QL helper writes the trailing e[K-1] workspace entry during iteration. For K>1, that path cannot be treated as a generally valid checked alternative to svd_bdc. Forming A^T*A or B^T*B squares the scale of singular values and can lose information or overflow before the final square root.

Matrix-function domain and failure notes

All public matrix-function interfaces store real F values. Real-Schur 2x2 blocks handle conjugate eigenvalue pairs using real block formulas; they do not return a complex matrix when the selected real branch is unavailable. The exists flags report the implementation's block tests and denominator tests rather than a complete mathematical classification of every possible real square root/logarithm. A repeated-block Sylvester denominator can fail even when another matrix-function construction exists.

parlett_sqrt/parlett_log accept a quasi-upper-triangular Schur-form input rather than reducing an arbitrary matrix. sqrtm/logm perform the Schur reduction and back-transform. sqrt/log failures usually fill NaNs, while Schur trigonometric and power wrappers use zero results on their stated failed paths. Check both the existence and convergence fields where present. A true flag is not an error bound or proof that every coefficient is finite. Fixed-size result bounds also apply to all internal matrices.

Polynomial result notes

roots returns an empty successful result for constant/all-zero/empty coefficient sequences. For effective degree above 11, dispatch returns converged=false without solving or populating the root vectors. It does not trim small coefficients, sort roots, report multiplicity separately or supply a backward-error estimate. polyfit constructs powers directly without centering/scaling and divides by its QR diagonal; insufficient samples or rank deficiency are caller errors rather than a returned fitting status.

micron::int_matrix_base_avx

Defined in header <micron/math/matrix/bits.hpp>.

Aligned inline arithmetic matrix base with C columns and R rows; int_matrix_base is its alias.

Storage and members

Stores public B data[C*R] in row-major order, with positive dimensions and at most 4096 payload bytes. int_matrix_align_v selects alignment 16, 32 or 64 by total payload size; the type name does not imply that every operation uses vector registers. category_type, mutability_type and memory_type are type_tag/mutable_tag/stack_tag; size_type is usize; value/reference/pointer aliases refer to B or const B. Default construction zeroes coefficients; fill, exact-size variadic and initializer-list construction initialize coefficients, with a mismatched list diagnosed. Copy is O(R*C); move copies then zeroes the source. Accessors are unchecked and row(r)/col(c) return a reference to the first element of that row/column, not an independent view.

Operations

Coefficient arithmetic is O(R*C) and returns or updates inline storage. mul requires a square matrix and performs matrix contraction in O(R^3); transpose mutates a square matrix in O(R^2). No operation grows or allocates storage. Division and integer overflow follow the element operations without additional validation.

Member type aliases

size_type is usize; value_type is B. reference/ref are B&, const_reference/const_ref are const B&, pointer/iterator are B*, and const_pointer/const_iterator are const B*. The aliases describe direct access to the inline row-major coefficient array and do not introduce iterator ownership or bounds checking.

micron::math::mat

Defined in header <micron/math/matrix/mat.hpp>.

Fixed positive R-by-C arithmetic matrix with inline row-major storage bounded to 1024 bytes.

Members and construction

base_type is int_matrix_base<T,C,R>, value_type is T, and rows/cols are static dimensions. Constructors and coefficient operations forward to that base; at(r,c) and flat operator[] return unchecked references. identity initializes the first min(R,C) diagonal coefficients to one and other coefficients to zero; zero produces a zero-filled value. A matrix::row_view over data can borrow this object's coefficients without copying its payload; the view's dimensions and leading dimension must be supplied consistently.

Algorithms

Scalar and matrix operators are elementwise. matmul forms a separate R-by-C contraction result with a compile-time inner dimension; matvec returns a fixed vector where its dimension constraints are satisfied. Each intermediate fixed matrix must fit the inline size limit. linalg::mat aliases this same type; linalg::arith_scalar reuses the quants arithmetic-scalar concept.

micron::math::dynmat

Defined in header <micron/math/matrix/dynmat.hpp>.

Runtime-shape owned row-major matrix with public vector storage and element leading dimension.

Members and storage

value_type is T; storage_type is vector<T,allocator_serial<>,false>. Public buf owns rows*ld coefficients, rows/cols are logical dimensions, and ld is the row stride in elements. The ordinary shape constructors set ld=cols; the fill constructor supplies a coefficient value. with_ld permits padded row storage and allocates rows*ld elements without checking that ld>=cols. size reports the buffer's element count, including padding, not necessarily rows*cols.

Ownership and access

Copying copies owned vector storage; moving transfers the vector and clears the source dimensions. at computes buf[r*ld+c] without validation. zero/identity allocate new storage; from_fixed copies coefficients. as_row_view/submat_view are O(1) borrowed descriptors, invalidated by storage replacement/destruction. Public metadata and buf can be changed independently, so consistency is a caller-maintained invariant. linalg::dynmat is an alias of this type; linalg::dynvec, vec and quat alias their quants counterparts rather than introducing new storage.

micron::math::matrix::row_view

Defined in header <micron/math/matrix/views.hpp>.

Nonowning row-major matrix descriptor with pointer, logical rows/cols and element leading dimension.

Addressing and construction

at(r,c) directly returns data[r*ld+c]. A zero omitted leading dimension is replaced by cols. Raw-pointer, raw_slice and data()-providing container constructors accept the supplied shape without verifying the backing extent. pointer/const_pointer and value_type refer to the selected T; row_major_tag identifies layout to kernels. A const descriptor does not independently make a mutable T allocation immutable. Construction and copying are O(1), allocate nothing and do not extend the owner's lifetime.

View operations

transpose_view changes to col_view, swaps dimensions and preserves pointer/ld; submat offsets the pointer and retains ld. Both are O(1), borrow the same allocation and perform no bounds validation or conjugation. Raw-slice construction can cast away the slice descriptor's const-qualified access; choose a const element type when read-only access is required.

micron::math::matrix::col_view

Defined in header <micron/math/matrix/views.hpp>.

micron::math::matrix::pack::workspace

Defined in header <micron/math/matrix/pack.hpp>.

Owned reusable A/B panel buffers for the ordinary blocked GEMM path.

Capacity and use

Vectors a and b are sized for default_mc=72, default_kc=256 and default_nc=256, with panel dimensions rounded for the selected microkernel. ready checks that both buffers have the required sizes. Constructing allocates buffers; subsequent gemm_blocked calls reuse a ready active workspace. Without one, ordinary blocked GEMM constructs local vector buffers. For the f64 6-by-8 kernel the default A/B panel payloads are 18,432 and 65,536 doubles respectively. Coefficients are overwritten during packing; the workspace does not retain input/output matrices or a factored product.

Packing APIs

pack_a_panel and pack_b_panel accept row/column element strides and zero-pad incomplete microtiles. Microkernels accumulate alpha*A*B+beta*C; normal blocked loops apply beta on the first k panel and one thereafter. Direct blocked calls return immediately for zero m/n/k, so a direct k==0 call does not scale C. Buffer alias

buffer names vector<T,allocator_serial<>,false>; a and b own this buffer type. The alias adds no alignment guarantee beyond the selected allocator and does not make a vector's element count interchangeable with its reserved capacity.
