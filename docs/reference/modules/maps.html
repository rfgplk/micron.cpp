Maps

From micron reference

Associative containers storing keys and mapped values. The implementations differ in key equivalence, growth, ordering, persistence, and synchronization; their insertion results are not interchangeable.

Keys and ownership

Hash tables invoke hash<hash64_t>(key). Except for hopscotch_map, the implementations retain the original key and verify equality after routing or hash filtering. Equal keys must produce equal hashes. A prehashed overload must receive the same hash used to place and subsequently locate that key; it does not validate the supplied hash.

Ordered immutable_map uses equivalence under <: neither key is less than the other. immutable_table uses exact integral equality. rb_map uses equality in chain bins and ordering in tree bins, so equality and ordering must agree. Keys exposed through mutable node or callback interfaces must not be changed in a way that alters their hash or ordering.

Containers own their stored key and value objects, except that hopscotch_map owns only hashes and values. Raw-pointer keys or values remain non-owning pointers. Persistent copies share nodes; ordinary copying, where provided, constructs independent entries. No hash container in this family accepts a user-supplied hashing or equality policy template parameter.

Complexity

Complexities below count container work, excluding the cost of hashing, comparisons, allocation, and user-defined key/value operations. Let n be the number of entries, C the number of table slots, h a tree/trie path length, and c a collision-chain length. Expected constant hash-table costs assume a suitable hash distribution; the implementations do not provide collision-independent constant time.

Slot-scanning iteration and clearing generally cost O(C), even when few entries are present. A rehash or arena expansion can process all stored entries. Persistent copy construction retains a root in O(1), but assignment also releases the destination's former version; reclaiming its last unshared nodes can cost O(n).

Thread safety

conmap synchronizes individual stripe operations. Other mutable maps contain no container-level synchronization. Persistent node reference counts permit shared-node lifetime management across independently owned versions; publication, assignment, movement, or destruction of the same container handle still requires synchronization. Thread safety also depends on the selected allocator and on key/value operations.

micron::robin_map

Defined in header <micron/maps/robin.hpp>.

A move-only, fixed-capacity Robin Hood hash table storing a cached hash, the original key, and a mapped value in each occupied slot.

Template parameters and representation

K is the key, V is move-constructible, Alloc defaults to allocator_serial<>, and Nd defaults to robin_map_node<K,V>. Operations additionally require the copying, assignment, swapping, equality, and hashing used by the selected overload. A custom Nd must implement the same hash, key, value, and construction interface.

Nodes and one-byte probe-distance controls occupy separate allocator-owned blocks. Capacity is rounded upward to a power of two, with a minimum of 16 slots. The default derives its requested slot count from Alloc::auto_size()/sizeof(Nd). A zero control byte denotes an unconstructed slot; occupied bytes store displacement plus one.

Insertion swaps entries when the incoming entry has travelled farther from its home slot. Erasure shifts the following displaced cluster backward, avoiding tombstones. Control scans use the compiled SIMD tier where selected, with scalar probe logic otherwise.

Member functions

insert, insert_hash, emplace, and add replace an existing value. insert_hash_if_absent preserves it and returns {inserted, pointer}. find and find_hash return null on absence; at reports a library error; operator[] inserts V{}. contains, exists, and count test membership, with the latter two returning zero or one.

max_size() is the number of allocated table slots, not the permitted population. Inserting a new key at floor(7*C/8) entries reports a library error; an existing value can still be replaced. Probe distances above 253 or an exhausted traversal also report an error. There is no growth operation; reserve() is deleted.

value_type is Nd, and reference, ref, pointer and their const counterparts refer to nodes. Iterators skip empty slots and expose nodes, including their cached hashes and keys. for_each accepts a node callback or a constrained (const K&, V&) callback. raw_begin()/raw_end() span every slot, including unconstructed storage; use the control bytes or slot_occupied before accessing a slot.

Complexity

Lookup is expected O(1) with distributed hashes and bounded by the representable probe run. Insertion can inspect O(C) slots and perform swaps; erasure can shift O(C) entries in a cluster. Iteration and clear are O(C). Move construction and swap are O(1); copying is deleted.

Iterator invalidation

Insertion may swap existing entries even though it never reallocates. Erasure relocates following displaced entries. Pointers, references, and slot iterators into affected entries therefore do not provide stable element identity. Clear and destruction invalidate all entries. Mutating a node key or hash through a mutable iterator breaks table invariants.

Notes

The header's early hash-collision comment is superseded by the implementation: hash matches are followed by key == key, so different keys sharing a hash remain distinct. Insertion does not roll back swaps if a later probe-limit error or user operation throws. Choose this table when capacity can be planned and relocation is acceptable.

micron::robin_map_node

Defined in header <micron/maps/robin.hpp>.

The default Robin Hood table entry: hash64_t hash, K key, and V value.

Construction and use

Constructors accept a cached hash with moved or copied key/value arguments; a forwarding constructor constructs the mapped value from arguments. Special members are defaulted. This is an entry object, not an owning container or an intrusive link. The map controls its lifetime with placement construction and the corresponding control byte. The stored hash is a filter, not a replacement for original-key equality.

micron::stack_swiss_map

Defined in header <micron/maps/swiss.hpp>.

A fixed-capacity Swiss-style hash table whose control bytes and entry storage are embedded in the map object.

Template parameters and representation

N must be at least 16 and divisible by 16; NH <= N bounds the number of slots inspected from a key's home position. The class default is NH=N; the swiss alias defaults to 16. N need not be a power of two. NH=0 is admitted by the declaration but prevents every insertion.

Entries own K and V in raw aligned storage; only occupied entries are constructed. Each control byte is empty, deleted, or a seven-bit hash fingerprint with its high bit set. Probing proceeds in groups of 16, clips the final partial NH window, and handles wraparound without reading past the control array. SIMD or scalar fingerprint scans filter candidates before key equality.

Copy and move scan the entire table and construct occupied entries. Moving clears the source. The public __swiss_entry, __emplace_tag, control array, raw storage, and size counter are implementation surfaces; changing them bypasses lifetime and lookup invariants.

Member functions

insert, prehashed insert_hash, and emplace preserve existing values and return {false, existing_pointer} for duplicates. A new entry returns {true, pointer}. A full table or exhausted home window returns {false, nullptr}; failure can occur with size() < N. insert_or_assign replaces an existing value. operator[] and load_find report a library error when insertion cannot find a slot.

For K = u64, load treats the supplied integer simultaneously as the stored key and its already-computed hash. exists performs the matching prehashed lookup, whereas ordinary find hashes the integer again. These two key-placement conventions must be used consistently.

find returns a nullable V pointer; at reports absence; contains and count test presence. Erasure destroys the entry and leaves a tombstone. Iterators return pair<const K&, V&> or its const counterpart; arrow operators return pairs of pointers rather than a pointer to a stored pair. for_each visits (key,value) in physical slot order. Both capacity accessors return N.

Complexity

Lookup, insertion, and erasure inspect at most NH slots, so their worst-case table work is O(NH), with expected O(1) work for suitable hashes and spare probe windows. No allocation or rehash occurs inside the table. Construction initializes N control bytes; copying, moving, clearing, and full iteration cost O(N).

Iterator invalidation

Insertion constructs an unused slot and does not move existing entries. Erasure invalidates the erased entry; other slot addresses remain valid. Clear, assignment, movement, and destruction invalidate affected entries. Tombstones remain until reused or cleared; there is no separate compaction operation.

Notes

Use a sufficiently large NH when many keys can share a home neighborhood. The N-slot capacity alone does not guarantee that N distinct keys can be inserted. In-object storage follows the lifetime and location of the containing object; it is not necessarily on a thread's stack.

micron::heap_swiss_map

Defined in header <micron/maps/heap_swiss.hpp>.

A copyable, growing Swiss-style hash table with separate heap blocks for control bytes and key/value entries.

Template parameters and representation

Alloc defaults to allocator_serial<>; V is constrained to be copy- and move-constructible. Actual operations also require corresponding K construction and key equality. Slots are rounded upward to a power of two with a minimum of 16. The control block has C+16 bytes: the extra group mirrors the first 16 controls to permit wrapped group loads.

Lookup filters 16-byte control groups by a seven-bit hash fingerprint and then compares original keys. Insertion scans groups for empty or deleted slots. Entry objects exist only in occupied slots. Iteration yields reference pairs, while value_type is the internal key/value entry type.

Capacity and modifiers

The empty-slot budget starts at floor(7*C/8). Insertion into an empty slot consumes it; reuse of a tombstone does not. Erasure does not restore it. When the budget is zero, a new-key insertion doubles and rehashes the table, even when deletions have reduced size. Duplicate insertions do not grow.

reserve(n) rounds n as a slot request, not an entry-count guarantee under the 7/8 policy. It rehashes only when that rounded slot count exceeds the current capacity. Rehash recalculates hashes from stored keys; a separately supplied prehash must agree with ordinary hashing if the entry is to remain locatable after growth.

insert, insert_hash, and emplace preserve duplicate values and return {inserted, V*}; insert_or_assign replaces. find returns null on absence, at reports a library error, and operator[] supplies V{}. clear destroys occupied entries, resets tombstones and budget, and retains both blocks. Copying duplicates entries and control state; movement transfers the blocks.

Complexity

Lookup and erasure are expected O(1), worst O(C). Insertion is expected amortized O(1) under distributed hashes, with O(C) rehash work on growth and potentially greater collision-search work while rebuilding. Iteration, clear, and copying scan C slots. Move construction and swap are O(1).

Iterator invalidation

Growth and an expanding reserve replace all entry storage and invalidate every pointer, reference, and iterator. Insertion without rehash preserves existing slots; erasure invalidates its entry only. Iterators store the owning map and slot index, so retaining their numeric slot through rehash does not retain element identity.

Notes

This is the growing choice among the Swiss map variants. A copyable key causes rehash to copy key/value objects into the replacement; otherwise the rebuilding path moves them. No container lock is provided.

micron::hopscotch_map

Defined in header <micron/maps/hopscotch.hpp>.

A growing, hash-identity table that keeps each entry within a bounded distance of its mixed-hash home slot. Original keys are not stored.

Template parameters and storage

MH defaults to 32, Nd to hopscotch_node<K,V>, and Alloc to allocator_serial<>. Each occupied entry is one nonzero 64-bit hash plus V; zero is the empty-slot marker and is rejected on insertion. Distinct K objects with equal hashes designate the same entry. K is used to compute hashes only.

The constructor's n argument is a requested byte budget, default 4096, rather than an entry count. It derives at least 64 power-of-two slots and stores them in an fvector. Slots are default-constructed, and insertion, deletion, displacement, and rebuilding use value assignment or copying; V must support those operations despite the class having no equivalent explicit constraints.

A SplitMix-style finalizer selects the home slot. Lookups inspect offsets 0 through MH inclusive. Insertion first tries the neighborhood, searches up to 512 additional positions, and can move entries backward through up to 256 displacement attempts. It resizes at 3/4 population or when placement fails; rebuilding tries up to four candidate table sizes.

Member functions

insert, insert_asis, emplace, and add retain the value already stored for an equal hash and return its pointer. insert_asis receives the actual nonzero identity hash; ordinary insert hashes K. find_hash and erase_hash take only a hash. find is nullable, at reports absence, and operator[] inserts V{}.

capacity() and load_factor() use the underlying vector capacity, which can differ from the logical power-of-two probe table; __slot_count() reports the latter. Iterators skip zero-hash entries and expose Nd. for_each receives (const hash64_t&, V&), not original K. Copying is deleted; movement transfers the table.

Complexity

Lookup and erasure take O(MH+1) slot inspections, independent of population for a fixed MH. Insertion includes bounded neighborhood/displacement scans and potentially a full rebuild; repeated growth for pathological hashes has no constant-time guarantee. Full iteration and clear scan the logical slot count. Rebuilding requires copying occupied values.

Iterator invalidation

Displacement can relocate existing entries without allocating. Growth invalidates all table addresses. Erasure clears a slot without shifting other entries; it resets V for nontrivial values. Treat any insertion as potentially invalidating entry pointers and iterators.

Notes

Choose this representation only when hash identity is an acceptable application contract. It cannot recover original keys for enumeration and does not distinguish a genuine duplicate from a 64-bit collision. Copy declarations in the set adapter do not make this underlying map copyable.

micron::hopscotch_node

Defined in header <micron/maps/hopscotch.hpp>.

The default hopscotch slot: hash64_t key and V value. Its member named key stores a hash, not K.

Construction and occupancy

Default construction sets the hash to zero and default-constructs V. Boolean conversion tests nonzero hash; logical negation tests an empty slot. set hashes a K and assigns the value; clear sets the hash to zero and assigns V{}. Move construction and move assignment clear the source hash. The slot itself does not track the containing table's size.

micron::conmap

Defined in header <micron/maps/conmap.hpp>.

A move-only concurrent map composed of independently spin-locked fixed-capacity Robin Hood tables.

Template parameters and routing

Stripes defaults to 64 and must be a positive power of two. Each cache-line-aligned stripe owns a spin lock and robin_map<K,V,Alloc>. The requested total capacity, default Stripes*64, is divided by Stripes with integer division, clamped to at least 16 per stripe, and rounded again by each Robin Hood table.

A finalizer of the full 64-bit hash chooses the stripe; the original hash selects slots within it. Each stripe has its own 7/8 load and probe limits. An insertion can fail because one stripe is full while other stripes have unused space. There is no resizing or redistribution.

Member functions

insert and emplace return true only for a new key and preserve an existing value. insert_or_assign replaces or inserts. find(key,out) copies a found value to out while locked and returns bool; at default-constructs a temporary, copies into it, and returns a value. No V pointer or iterator is returned.

update calls fn(V&) only when present. upsert inserts its fallback or invokes the function on an existing value, returning whether it inserted. for_each invokes (key,value) while holding one stripe at a time. RAII releases the stripe lock if an operation or callback throws.

size, empty, load_factor, clear, and for_each visit stripes separately. Their result or effect is not a single snapshot or atomic transaction across the complete map. Capacity is the sum of physical stripe slots.

Complexity

A single-key operation adds one spin-lock acquisition to the underlying stripe operation. Waiting under contention is unbounded; this is not a lock-free map. size costs O(Stripes) lock acquisitions; enumeration and clear scan all stripe slots.

Thread safety and lifetime

Single-key operations synchronize accesses within their stripe. A callback must not retain references for later unsynchronized use, mutate key identity, or reenter an operation on the same stripe: spin locks are not recursive. Moving, assigning, swapping, or destroying either handle requires exclusive external access.

Notes

The current swap exchanges the stripe pointer and per-stripe request but omits the allocator block descriptor. Subsequent destruction can therefore use a descriptor belonging to the other buffer; swap must not be treated as a valid ownership transfer until that implementation is corrected. Ordinary move operations transfer the descriptor. This limitation is independent of stripe synchronization.

micron::rb_map

Defined in header <micron/maps/rb_map.hpp>.

A growing hash map whose light bins use chains through dense structure-of-arrays storage and whose heavy bins use red-black trees.

Template parameters and representation

Alloc defaults to allocator_serial<>; V is copy- and move-constructible. K must be hashable, equality-comparable, and orderable: tree bins compare (hash,key) using <, while chain bins use cached hash plus ==. These notions of equivalence must agree.

Separate arrays store hashes, keys, values, next indices, and home-bin indices. A bin contains a list head, tree pointer, and chain length. Dense erasure moves the final array entry into the removed slot and repairs its chain link. Arrays grow geometrically; bin counts are powers of two, at least 16, and grow before total load exceeds 3/4.

With at least 64 bins, a chain is converted before inserting its eighth member. Tree bins become chains again after erasure takes them below six members. Conversion moves or copies entries between the dense arrays and an allocator-backed rb_tree. No global sorted iteration is supplied.

Member functions and types

insert, insert_hash, and emplace return {inserted,V*} and preserve existing values; insert_or_assign replaces. find returns null on absence; at reports a library error; operator[] inserts V{}. treeified(bin) exposes the representation of an indexed bin. bin_count() and max_size() both report the current bin count, not a maximum number of storable entries.

iterator aliases const_iterator, which yields pair<const K&,const V&>. It visits dense entries first, then the ordered entries of each tree bin. Mutable for_each permits value updates. Copying is deleted; move and swap transfer all arrays and trees. clear frees the storage and allocates a new 16-bin table.

Complexity

Lookup costs O(c) in a chain bin and O(log c) in a tree bin, in addition to hashing/comparison costs. With distributed hashes it is expected O(1). A normal dense erasure also searches for the link to the final dense entry; tree conversion can scan all n dense entries. Growth, treeification, and untreeification make individual mutations potentially linear or greater, even though tree lookup itself is logarithmic. Iteration costs O(n + number_of_bins).

Iterator invalidation

Array growth and rehash can invalidate all pointers and iterators. Treeification and untreeification relocate a bin's values; dense removal also relocates the final dense entry. No reference-stability guarantee should be inferred from its use of red-black nodes.

Notes

This container trades conversion and multiple-array overhead for tree lookup in heavy bins. The source labels the implementation experimental. erase assumes a live bin array; the moved-from state is not a generally reusable empty map.

micron::btree_map

Defined in header <micron/maps/b_map.hpp>.

A growing hash-routed map with a B tree per bucket, buffered internal operations, and linked leaves. It does not order entries by K.

Template parameters and representation

V satisfies is_movable_object; Alloc defaults to allocator_serial<>. K is hashed and compared for equality, and the implemented insertion paths copy K even for the rvalue-key overload. FanoutOverride selects both leaf and internal fanout; the default selects leaf fanout 32, 16, or 8 for combined key/value sizes at most 24, at most 64, or larger, and internal fanout 16.

Nodes occupy 64-byte-aligned slots in one growing contiguous slab, addressed by u32 indices. Leaves store separate hash, key, and value arrays and doubly linked traversal links. Internal nodes contain hash pivots, child indices, and small pending insert/erase buffers. Equal hashes retain distinct keys and can use an unbounded overflow-leaf chain.

Bucket counts are powers of two with a minimum of 16. The constructor argument requests buckets, not entries. The advertised max_size() is bucket_count*leaf_fanout; it is a capacity measure used by the 7/8 rehash policy, not a hard population bound. value_type is V; iterator dereference instead returns kv_ref or const_kv_ref, with named key/value references.

Buffered operations

insert, insert_hash, emplace, and operator[] insert or replace values and return V pointers/references. An internal buffer may hold the newest value before it reaches a leaf. Lookup checks the latest matching buffer entry at each level; a pending erase masks an older leaf entry.

Buffered acceptance is not always proof of a distinct-key change. A newly buffered insertion can temporarily increment size for a key already present deeper in the tree, and a buffered erase can return true for an absent key. Buffer drainage corrects total size when it discovers those cases. size() and empty() therefore must not be interpreted as fully reconciled logical state while such operations remain pending.

flush_all drains buffered work. begin, including its const overload, invokes it; for_each obtains begin and therefore flushes too. Hash min/max, lower/upper bound, predecessor, and successor flush and then scan all leaf entries. They compare hashes only, not K, and return mapped-value pointers. Linked-leaf iteration is not a global key or hash ordering.

Complexity

A normal find checks O(h) bounded buffers and in-node hash searches, plus any equal-hash overflow chain. Worst-case equal-hash lookup is O(n). Mutations may drain buffers, split nodes, grow the slab, or rebuild all buckets; no per-insertion constant or logarithmic worst-case bound follows from the B-tree name. Hash-bound queries cost O(n) after flushing, not O(log n). Iteration after flushing costs O(n + allocated_leaf_nodes).

Iterator invalidation

Slab growth relocates all nodes and invalidates all stored addresses. Leaf shifts and splits move entries; buffer drainage moves pending values into other storage. Even const begin() and const hash-bound queries can flush, allocate, and invalidate previously returned pointers. Treat structural changes and flushing as invalidating entry references and iterator positions.

Notes

Erasure does not merge underfilled tree nodes. Clear releases entries and resets slab usage while retaining allocated slab/bucket storage. Copying is deleted. The override is only checked for a minimum of three; larger values are also constrained in practice by u8 counts and the 32-bit leaf-match mask, so values beyond the implementation's default maximum of 32 are not a supported scaling mechanism. This buffered map has materially different contracts from the ordered b_tree.

micron::immutable_map

Defined in header <micron/maps/immutable.hpp>.

A persistent ordered map using a left-leaning red-black tree with atomically reference-counted nodes.

Template parameters and ownership

K satisfies totally_ordered; V satisfies is_movable_object. Path copying also copies existing keys and values, so practical modifying operations require their copy construction. Nodes own K and V, a right pointer, and a left pointer whose low bit stores the red flag. Each node is individually allocated through the micron allocation seam, respecting its alignment.

A copy retains the root. A new version copies the modified search path and shares untouched subtrees; rotations and color changes maintain left-leaning red-black balance. Reference counts are atomic u32 increments/decrements and are not saturating in this implementation. The last owner recursively reclaims newly unshared nodes.

Member functions

insert, set, and emplace return a new version and replace an equivalent key's value. erase returns an updated version and clear returns an empty one; discarding these return values leaves the original handle unchanged. update calls a function on the existing const value only when present; update_or calls it with the stored or supplied default value.

find returns const V* or null. at reports absence. operator[] never inserts: it returns the stored value or a shared static V{} for a missing key. capacity() equals size, and load_factor() is zero or one; neither measures reserved tree storage. identity() exposes the root address for structural identity, while equality compares contents when root identity differs.

iterator aliases const_iterator. It exposes node members, key() and value() references, and maintains an explicit 64-pointer traversal stack. Each iterator pins the root with a reference count, including copied iterators. Iteration and for_each are ascending by K. for_each_morris delegates to for_each; it does not thread or mutate the tree.

Complexity

Lookup and path-copy updates take O(log n) comparisons and O(log n) newly allocated nodes for balanced trees, excluding key/value copy costs. Copy construction and move construction take O(1). Iteration and nontrivial equality take O(n). Destruction or replacing the last owner of an unshared version can reclaim O(n) nodes.

Iterator invalidation

An iterator retains its complete version, so deriving or assigning another version does not invalidate it. A pointer or reference returned by find/at does not independently retain a root: keep a containing version or pinned iterator alive. Iterators retain an exhausted version until their destruction. The fixed 64-entry traversal stacks impose an implementation depth limit.

Thread safety

Independent handles can share immutable structure with atomic lifetime accounting. The same handle's root and size are ordinary fields; changing or destroying that handle concurrently with a read still requires synchronization. Atomic counts do not publish a version to another thread.

micron::immutable_table

Defined in header <micron/maps/itable.hpp>.

A persistent ordered map restricted to integral keys and integral mapped values, implemented as a binary Patricia trie.

Representation and ordering

Both K and V satisfy integral. Signed keys have their sign bit flipped for routing, so unsigned bit order corresponds to ascending signed order. Each branch stores a differing-bit position and two tagged child pointers; a low pointer bit distinguishes leaf nodes, which own the original integral key and value.

Branches compress stretches of equal bits rather than storing one node for every bit. A modification allocates the affected branch path and leaf while retaining unchanged children. Allocations use abc::alloc and matching deallocation. Atomic u32 reference counts saturate at their maximum; a saturated node becomes permanently live.

Member functions and types

insert, set, and emplace return an updated table and replace an existing value. erase and clear also return versions. update transforms an existing value; update_or transforms the stored or supplied fallback value. find is nullable; at reports absence; operator[] returns the stored const value or static V{} without insertion.

capacity() equals the entry count and load_factor() is zero or one. identity() returns the tagged root identity. iterator aliases const_iterator, pins its root, and walks in ascending integral-key order with a stack bounded by sizeof(K)*8. Dereference and arrow expose a const leaf; key() and value() return integral copies. Equality checks root identity first and otherwise compares all ordered entries.

Complexity

At most W=sizeof(K)*8 increasing branch-bit positions occur on a path. Lookup, insertion, and erasure cost O(W); updates allocate O(W) nodes. Copy construction and move construction are O(1); enumeration and content equality are O(n). Last-owner reclamation can be O(n).

Iterator invalidation and thread safety

Iterators retain their version and survive reassignment of the originating handle. Plain returned pointers require an owner of the relevant version to remain alive. Independent immutable handles share atomically counted nodes; concurrent mutation of the same handle is not synchronized.

micron::pmap

Defined in header <micron/maps/pmap.hpp>.

A persistent hash-array-mapped trie with 32 logical children per internal node, compact child arrays, and equality-checked leaf collision chains.

Template parameters and representation

K and V must be copy- and move-constructible. An internal node stores an atomic reference count and a 32-bit presence bitmap followed by only its populated child pointers. Popcount maps a logical five-bit hash fragment to an array index. A tagged leaf stores the first (hash,key,value) entry inline and owns an overflow linked list.

Routing uses twelve five-bit fragments from the original hash, followed by twelve fragments from a mixed hash, for a maximum split depth of 24. Leaves are considered for splitting beyond eight entries only when entries diverge at the current fragment. Thus eight is a split threshold, not a chain-size bound: equal hashes, exhausted depth, or repeated equal current fragments can leave long chains.

A new version copies internal nodes on its modified path and copies the affected leaf's complete overflow chain, sharing other nodes. Allocation uses new/delete. Intrusive atomic u32 reference counts saturate, making saturated nodes permanently live.

Member functions

insert, insert_hash, set, and emplace return a new map, replacing an equal original key's value. erase and erase_hash return an updated version, sharing the original root if nothing was erased. clear returns an empty version. find returns const V* or null, at reports absence, and identity() reports root identity.

for_each visits const key/value pairs in hash-trie and chain order. There are no begin/end iterators, ordering bounds, subscript operator, reserve operation, or content-equality operator. Copies share a root in constant time; they do not duplicate the entire table.

Complexity

A lookup costs O(h+c), with h at most 24 and c the reached leaf-chain length. Modification costs O(32*h+c) structural work and copies the affected chain; c can be n. With well-distributed hashes, short chains and shallow branching provide expected small lookup/update costs, but worst-case linear behavior remains. for_each is O(n + internal_nodes). Last-owner destruction can reclaim O(n + internal_nodes).

Reference invalidation and thread safety

Deriving a version leaves source entries unchanged. A returned pointer is valid while an owning version retaining that node remains alive; it does not keep the node alive itself. Separate handles share atomic lifetime accounting, while publication and mutations of one handle need external synchronization.
