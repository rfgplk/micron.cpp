Dynamic loading

From micron reference
micron reference › System interfaces

Explicit native shared-object loading with dependency traversal, eager relocation, symbol scopes, generation-checked handles, and optional host validation/resolution callbacks.

Loading and symbol scope

dynamic_open resolves a name/path, maps its DT_NEEDED closure, relocates it, applies recorded RELRO protection, and runs dependencies' initializers before the requesting object's initializers. Mapping/relocation failure reports except::library_error; dynamic_error can supply a more specific borrowed diagnostic. These native interfaces are unavailable in WebAssembly.

Resolution first asks the supplied host callback. deepbind/DF_SYMBOLIC then permit the requesting object's own definition, followed by registered global objects, a breadth-first dependency search, and discovered host symbols. A requested symbol version can fall back to an unversioned search. This is the implemented search policy; it does not reproduce every system dynamic-linker rule.

dynamic_sym on a normal handle searches that handle's dependency closure. dynamic_default searches registered global objects and the host; dynamic_next searches global objects loaded after the caller's owning registered module. dynamic_sym_as and dynamic_call cast the address to a caller-selected function type. They do not verify a C++ signature or calling convention.

Ownership and synchronization

Opening increments a registry reference count. Copying dynamic_t itself does not retain a reference; each successful open requires a matching explicit close. dynamic_close can finalize/unmap a zero-reference object and its released dependencies. nodelete retains mappings at zero references. dynamic_finalize runs initialized finalizers once while retaining mappings, for controlled host shutdown.

Registry operations hold one mutex, including host callbacks, initializer/finalizer calls, and iteration callbacks. Such callbacks must not reenter these locking APIs. A returned symbol or string pointer is borrowed after the lock is released; callers must prevent concurrent close/unmapping for its complete use. The loader does not wait for executing code or external readers to finish.

The path-taking dynamic_call convenience overload opens a module and does not close its handle. Repeated calls therefore retain registry references. Failed recursive loading unwinds newly created slots; it does not provide a transactional rollback of every reference increment or flag promotion made to pre-existing dependencies.

Search paths and limits

A path containing slash is probed directly. Name lookup tries the object's RPATH, nonsecure LD_LIBRARY_PATH, RUNPATH, and compiled architecture-specific system directories. $ORIGIN is expanded; $LIB and $PLATFORM currently expand to empty text. Empty list components are skipped. No ld.so.cache is read.

Secure execution is detected from AT_SECURE or differing real/effective credentials. It disables LD_LIBRARY_PATH, rejects relative direct paths, and requires absolute list components without substitution tokens. This describes path selection only; the validation callback is responsible for application-specific module acceptance.

The registry has 256 slots, dependency recursion is bounded at 32, each dynamic record holds up to 256 DT_NEEDED offsets, and paths use fixed-capacity strings. Truncated needed lists are rejected. Slot searches are linear in the registry high-water mark. Closure search is O(modules + dependency links), plus each module's hash lookup. Mapping/initialization cost also includes pages, relocations, and application callbacks; no constant load-time bound is supplied.

micron::dynamic_t

Defined in header <micron/dynamic/call.hpp>.

Non-owning explicit-close registry handle consisting of slot index and generation.

Validity

Default construction has generation zero. Boolean conversion only tests generation!=0; it does not consult the registry. Close and lookup compare both fields against the active slot, so a copied stale handle fails after slot reuse. dynamic_default and dynamic_next are special lookup handles and cannot be closed. Generation counters have finite u32 width.

micron::dynamic_options

Defined in header <micron/dynamic/flags.hpp>.

Borrowed resolver/validator callbacks and their context for a loaded dependency closure.

Callback contracts

resolve(context,name,version) returns an optional host address; null allows normal lookup. validate(context,module) returns null to accept or an error string to reject after mapping and before dependency relocation/initialization. Callback code and context must outlive the closure. Reusing an existing ordinary module/dependency requires matching callback pointers and context. Callbacks execute while the registry mutex is held.

micron::rtld

Defined in header <micron/dynamic/flags.hpp>.

Bitmask selecting symbol scope and retention behavior.

Flags

now selects eager resolution; lazy is accepted as a flag but dynamic_lazy_supported() is false and relocation remains eager. local is zero and keeps symbols out of global search; global promotes them. noload queries existing loading after path resolution, deepbind prioritizes self symbols during relocation, and nodelete retains the mapped object. Bitwise OR/AND and has support flag composition.

micron::elf::dl::dl_module

Defined in header <micron/dynamic/registry.hpp>.

Registry bookkeeping owning one module mapping, options, reference count, flags, and fixed dependency indices.

Storage

Slots are mmap-backed and reused with a new generation; their backing slot mappings remain allocated. Dependencies store indices into this fixed registry. soname() falls back to the stored path. This record is implementation bookkeeping; editing it bypasses handle validation and synchronization. found_t pairs a resolved address with an optional registry owner, while load_state tracks newly created slots during recursive mapping.

micron::elf::dl::link_map_t

Defined in header <micron/dynamic/debug.hpp>.

Debugger-facing chain record containing load bias, borrowed name, dynamic pointer, and neighboring records.

Related debugger records

r_debug_t records version/state/breakpoint and the chain head. Registry changes rebuild this private chain and publish add/delete/consistent states through _micron_dl_debug_state; the chain's l_ld is currently null. This is a micron debugger hook rather than automatic registration in a host linker's own chain.

dl_phdr_info_t contains callback-scoped load bias/name/program headers and TLS metadata. dl_iterate_phdr visits registry objects and then discovered host records while holding the registry mutex. Host rows currently provide address/name without program headers. A nonzero callback result stops iteration. Its adds/subs/tls_data fields remain defaulted.
