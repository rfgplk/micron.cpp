Splines and interpolation

From micron reference
micron reference › Numerics and mathematics

Owned scalar interpolants, piecewise polynomials, B-splines, smoothing/least-squares fits, parametric curves, and tensor-product B-spline/NURBS fields. Construction copies input samples or controls into micron vectors; evaluation borrows the resulting representation and may update a lookup cache.

Construction and errors

Use math/splines.hpp for the complete family. Factories normally accept borrowed raw_slice inputs and copy successful representations; original samples need only remain valid during construction. They return a representation and optionally update build_info. Status is not implicit in the result type: check the supplied info, especially for builders that can return partially populated data after a solve fails. Vector-valued families inherit vec<F,D>'s 2<=D<=16 and D*sizeof(F)<=128 requirements; a nominal D<=16 clause does not permit every extended-precision extent.

Strictly increasing sample coordinates, correct extents, usable finite values, and degree/shape consistency are required. Checks differ by factory: knot arrays permit repetitions, and comparisons that reject descending knots do not comprehensively reject NaNs. Public representation fields permit direct modification without revalidation. Logical builder failures are reported without throwing; the noexcept factories provide no separate allocation-failure result.

Smoothing and adaptive knots

make_smoothing returns a natural cubic through Reinsch-smoothed sample values. It needs at least four points; optional w contains one precision weight per sample. lambda=0 delegates to natural interpolation, lambda>0 solves the fixed-penalty system R+lambda*Q*W^-1*Q^T, and lambda<0 selects a penalty by generalized cross-validation. The scalar builder checks weight length but does not explicitly reject nonpositive weights; use positive finite weights. make_smoothing_curve additionally validates positive weights and shares a factorization across D coordinates.

The implementation owns a single O(n) scratch allocation with bound internal array views, factors a pentadiagonal SPD system, and computes fitted corrections. One fixed lambda costs O(n) scalar work or O(n*D) curve work. GCV performs golden-section search in log10(lambda) over [-12,12], stops at bracket width 1e-3 or 60 iterations, and computes an inverse-band trace for its score. Its worst-case work is O(I*n) or O(I*n*D), I<=62 score evaluations plus a final fit; there is no configurable optimization tolerance or separate search-convergence status. Scratch is discarded after construction.

make_adaptive_knots starts with endpoints and two interior input indices, repeatedly rebuilds a natural cubic, measures errors only at unselected input samples, and inserts the worst sample until max_abs_err or max_knots is reached. It requires at least four inputs, max_abs_err>0, and max_knots>=4; the knot budget is clamped to input count. With k retained knots per pass, work is O(k+n*log k) worst-case and O(n+k) scratch; up to max_knots-3 fits are made. The returned error target does not bound behavior between sample positions, and an internal cubic-build failure is not separately propagated by this loop.

Lookup and batches

Most scalar and irregular-curve evaluations first test a mutable last_hit interval and its immediate successor, then use binary search. This gives O(1) lookup for nearby hits and O(log n) worst-case lookup. A lookup cache records an index, not an owned iterator. Polynomial evaluation adds O(p), a vector local polynomial O(D), and a B-spline adds its basis/De Boor cost.

Ordinary nearest/linear/cubic scalar array evaluation checks the entire query array for nondecreasing order, then walks segments for O(n+q) lookup work; otherwise it uses q scalar calls. evaluate_sorted omits the ordering check and requires sorted finite queries. Its B-spline overload still calls a cursor-based span lookup per query, so arbitrary jumps can cost O(q*log n). evaluate_streaming supports scalar linear/cubic families and checks sorting; optimized x86 kernels can use non-temporal stores for aligned complete cache-line spans and issue a store fence. Other backends use ordinary stores. No relative speed guarantee is implied.

Ownership, invalidation, and concurrency

Representations own micron vector members; copying duplicates their dynamic arrays and moving transfers member storage. Construction, fitting, conversions, calculus, refinement, and packing may allocate. Scalar evaluation and direct finite-degree derivatives use automatic scratch and normally allocate nothing; integral/roots helpers that construct a new representation do allocate.

Vector reallocation, assignment, and destruction invalidate addresses into affected storage. Editing knots, degree, shape, or sample grids must preserve all parallel-array invariants and can invalidate cached basis reciprocals. rebuild_basis_cache regenerates those values; invalidate_basis_cache clears their active length so evaluation recomputes basis divisions. A same-size knot edit is not detected automatically. Editing only controls/weights does not change knot reciprocals.

Ordinary const evaluation often writes mutable last_hit, including tensor axis caches, and is not safe for concurrent calls on the same object without synchronization. Supported evaluate(...,spline_cursor&) overloads and evaluate_stateless keep lookup state outside the representation; separate cursors permit independent reads while data/cache storage remains unchanged. There is no internal locking.

Diagnostic conventions

Defaults are status=ok,n_iterations=0,residual=0. Most simple factories write only status; reusing info does not reset the other fields. micron::math::splines::bc_kind

Defined in header <micron/math/splines/tags.hpp>.

Selects natural, endpoint-slope, or not-a-knot boundary equations for cubic interpolation.

Policies

natural=0 uses zero endpoint second derivatives. clamped=1 uses supplied left/right first derivatives. not_a_knot=2 matches third derivatives across the first/last interior joins. Two points produce a line for every policy, ignoring supplied slopes; three-point not-a-knot produces the unique quadratic. Boundary metadata does not identify every builder's construction: slope-based Hermite/PCHIP/Akima/cardinal builders store bc=clamped.

micron::math::splines::extrap

Defined in header <micron/math/splines/tags.hpp>.

Selects the original nearest, linear, cubic, and polynomial-curve endpoint behavior.

Values

clamp_to_endpoints=0 holds an endpoint value; linear_continue=1 uses endpoint tangent lines for linear/cubic families; error_value=2 returns zero rather than throwing or returning NaN. These evaluators test x<=first and x>=last, so error_value also returns zero at the exact endpoints. Nearest interpolation holds endpoint samples for both clamp and linear_continue.

micron::math::splines::extension_mode

Defined in header <micron/math/splines/policies.hpp>.

Selects domain extension for additive piecewise-polynomial, B-spline-curve, Bezier, and tensor families.

Values

clamp=0 holds the endpoint; linear=1 continues its tangent; zero=2 returns zero strictly outside; periodic=3 wraps; reflect=4 mirrors; polynomial=5 evaluates the endpoint polynomial/basis outside. Reflection changes odd derivative signs. Periodic wrapping does not by itself impose matching endpoint derivatives or close control points; use a closed/periodic builder when that continuity is needed.

The implementations differ at exact upper endpoints: piecewise periodic mapping always wraps the upper endpoint to the lower one, whereas B-spline curves and tensors bypass mapping for already in-domain values. Constant interpolation treats linear/polynomial extension as endpoint holding. Scalar bspline has no extension_mode field and always clamps its parameter.

micron::math::splines::spline_cursor

Defined in header <micron/math/splines/policies.hpp>.

Stores an external segment index in a 64-byte-aligned, 64-byte-sized value.

Use

segment defaults to zero; padding fills the remaining bytes. Pass a distinct cursor to supported scalar, cubic/closed/packed, B-spline, and NURBS curve overloads to keep lookup state out of mutable last_hit. evaluate_stateless creates a fresh cursor for each call and therefore forgoes retained locality across calls. The cursor owns no data and remains subject to the representation's grid/degree invariants.

micron::math::splines::spline_domain

Defined in header <micron/math/splines/policies.hpp>.

Contains lower/upper parameter limits and a valid flag, without borrowing or owning spline data.

Queries

domain overloads report the first/last sample coordinate for xs/ts-based families, the first/last break for piecewise polynomials, and [knots[degree],knots[control_count]] for B-spline families. Empty storage returns valid=false. knot_count reports the stored grid/knot length; control_count reports ctrl.size(). These queries do not validate every parallel member or support every representation merely because it is a spline.

micron::math::splines::nearest_1d

Defined in header <micron/math/splines/nearest_1d.hpp>.

Owns a strictly increasing scalar sample grid and sample values for nearest-neighbor interpolation.

Storage and evaluation

xs and ys are independent owned vectors, last_hit is mutable, and mode defaults to clamp_to_endpoints. make_nearest requires equal lengths and at least two strictly increasing abscissas. It copies O(n) values with O(n) storage. Evaluation chooses the right sample on an exact midpoint tie. Empty/manual single-point representations return zero/the sole value. Nearest interpolation preserves sample values but has discontinuities between selected samples.

micron::math::splines::linear_1d

Defined in header <micron/math/splines/linear_1d.hpp>.

Owns a scalar sample grid and values for piecewise linear interpolation.

Operations and complexity

make_linear checks equal lengths, at least two points, and strict increase, then copies xs/ys in O(n). mode defaults to linear_continue. Scalar evaluation computes an interval fraction and a fused multiply-add after lookup; sorted batches share each segment's slope. No coefficients or slopes are retained, so direct valid ys edits affect the next evaluation. Empty/single-point states return zero/the sole value.

micron::math::splines::constant_1d

Defined in header <micron/math/splines/piecewise_1d.hpp>.

Owns samples for previous, next, or nearest piecewise-constant selection with extended-domain policies.

Policy and use

constant_side has previous=0,nearest=1,next=2; the default is nearest. At an exact knot, evaluate returns that knot's value regardless of the selected side; midpoint ties in nearest go right. mode defaults to clamp and additionally supports periodic/reflect/zero. make_constant requires equal lengths, two points, and strict increase; construction/storage are O(n). derivative returns evaluate for order zero and zero for every positive order, without representing jumps as distributions.

micron::math::splines::quadratic_spline_1d

Defined in header <micron/math/splines/piecewise_1d.hpp>.

Owns knots and three local ascending-power coefficients per interval for a continuously differentiable quadratic interpolant.

Boundary and construction

quadratic_boundary has minimum_curvature=0,left_slope=1,right_slope=2. make_quadratic determines the initial slope from the selected endpoint slope or a weighted minimum-curvature expression, then propagates slopes using next=2*secant-current. Equal lengths, two points, and strict increase are checked. Construction/storage are O(n); no linear-system factorization is required. mode defaults to linear.

evaluate uses Horner after lookup; derivative implements orders 0..2 and zero above degree, with extension/reflection behavior. integral converts to a copied piecewise polynomial and constructs an antiderivative: it allocates and follows polynomial antiderivative extension, which can differ from the original evaluate mode.

micron::math::splines::cubic_spline_1d

Defined in header <micron/math/splines/cubic_1d.hpp>.

Owns knots and four local ascending-power coefficients per interval for scalar cubic interpolation.

Construction families

make_cubic solves a tridiagonal second-derivative system with reusable factors, then forms local coefficients. It checks equal lengths, at least two strictly increasing points, and each spacing greater than 1e-12 times the full span. A pivot magnitude <=4*default_eps<F>() fails the factorization. For fixed degree, construction/storage are O(n). mode defaults to linear_continue.

BuilderSlope/continuity choice
make_cubicNatural, clamped, or not-a-knot global C² interpolation
make_cubic_hermiteUser supplies one first derivative per sample; C¹ Hermite pieces
make_pchipSign-aware weighted harmonic secants and limited endpoint slopes; shape-preserving local interpolation
make_akimaLocal differences weight adjacent secants; akima_kind::makima adds half absolute secant sums
make_cardinal / make_catmull_romScaled centered secants with tension in [0,1]; Catmull-Rom uses tension zero
make_steffenSign-aware secant limits inside, with PCHIP endpoint slopes
make_smoothing / make_adaptive_knotsReinsch fitted values or greedy sample-knot subset, returned in the same coefficient type

Calculus and limits

derivative handles orders 0..3 in interior segments and zero above degree. At exact endpoints, its endpoint branch implements only orders 1 and 2, so order 3 returns zero even when the adjacent cubic's third derivative is nonzero. Strictly outside, only a first derivative under linear_continue is nonzero.

integral integrates segment polynomials exactly in floating-point arithmetic over the intersection with the knot domain, retaining reversed-bound sign and ignoring extrapolation mode. It costs O(k+log n) for k crossed intervals and allocates no new representation. roots converts to an allocated piecewise polynomial and searches only stored intervals.

micron::math::splines::quintic_spline_1d

Defined in header <micron/math/splines/piecewise_1d.hpp>.

Owns six local coefficients per interval for Hermite interpolation of values, first derivatives, and second derivatives.

Requirements and operations

make_quintic_hermite requires equal xs/ys lengths, at least two strictly increasing points, and matching dydx/d2ydx2 lengths. It solves each interval's endpoint equations directly in O(n) work/storage. Supplied shared endpoint derivatives give C² joins; no global derivative estimation is performed. mode defaults to linear.

Evaluation is degree-five Horner after lookup. derivative supports arbitrary order by falling-factorial coefficients and returns zero above degree. Extension modes govern outside derivatives, including odd-order reflection signs. integral uses to_power_basis and an allocated antiderivative, so its outside behavior follows polynomial continuation.

micron::math::splines::piecewise_polynomial_1d

Defined in header <micron/math/splines/piecewise_1d.hpp>.

Owns breakpoints and flattened ascending-power coefficients for independent local polynomials of degree 0 through 16.

Layout and calculus

coeff[segment*(degree+1)+k] multiplies (x-breaks[segment])^k. make_piecewise_polynomial checks at least two strictly increasing breaks and exactly (break_count-1)*(degree+1) coefficients, then copies O(n*p) storage. No join-continuity requirement is enforced. mode defaults to polynomial. to_power_basis copies cubic/quadratic/quintic coefficients and maps their extension metadata.

Value evaluation costs O(p) after lookup. Direct derivative costs O(p*(order+1)) for falling-factorial coefficient scaling and returns zero above degree. derivative_spline allocates a coefficient representation and retains mode, so its outside behavior need not equal the derivative of a clamped/linear extension. antiderivative_spline allocates a degree-p+1 representation with continuous constants, zero initial constant, and polynomial extension; degree 16 returns empty. integral builds that antiderivative, so degree-16 integration returns zero.

Roots and solve

roots/solve subtract target from each segment's constant coefficient, recursively isolate derivative roots, and bisect sign-changing subintervals for 72 iterations. Small leading coefficients and near-zero stationary/endpoint values use the supplied positive tolerance (defaults 1e-5 for <=4-byte F, 1e-12 otherwise). Adjacent roots within tolerance are merged. A polynomial identically equal to target contributes no continuum representation. Only the stored breakpoint interval is searched, irrespective of extension mode.

With fixed p<=16, work is linear in segment count with bounded degree-dependent recursion/bisection; varying degree gives O(72*p³) arithmetic per segment in the root-isolation recurrence. Temporary root vectors allocate at successive derivative levels. No convergence/status object or scale-normalized root guarantee is returned.

micron::math::splines::periodic_cubic_spline_1d

Defined in header <micron/math/splines/piecewise_1d.hpp>.

Owns a cubic coefficient spline and period metadata for periodic scalar interpolation.

Construction and mapping

make_periodic_cubic needs at least four strictly increasing points and matching first/last values within a scaled 1e-5/1e-12 tolerance. It solves cyclic second-derivative equations using two tridiagonal solves and a rank-one correction, repeats the first moment at the final knot, and builds O(n) coefficients. The wrapper maps x to the half-open period before evaluation or derivative. The stored period equals the grid span; mapping uses the embedded grid, so editing period alone does not change it. No periodic integral overload is supplied.

micron::math::splines::bspline

Defined in header <micron/math/splines/bspline.hpp>.

Owns a scalar B-spline's degree, nondecreasing knot vector, scalar controls, and mutable span cache.

Invariants and choice

The public maximum degree is bspline_max_degree=16. make_bspline_from_ctrl accepts degrees 1..16, control_count>=degree+1, knot_count=control_count+degree+1, and nondecreasing knots; it does not require a nonempty active knot interval or comprehensive finite-value validation. Data are copied in O(control_count+degree) work/storage. The active domain is [knots[degree],knots[control_count]]. evaluate clamps into it and uses De Boor recursion, O(p²+log n) worst-case with O(p) automatic scratch; degrees 1..5 have specialized loops.

make_bspline_interpolating uses averaged clamped knots, one basis row per sample, and a no-pivot general band LU solve to obtain scalar controls. It requires strictly increasing equal-size samples and n>=p+1. Assembly/factorization cost O(n*p²), with O(n*p) banded storage. make_lsq_bspline accepts a caller knot sequence and positive optional sample weights, checks sample-domain membership and n_samples>=n_ctrl, and chooses banded Givens QR or normal-equation Cholesky. lsq_method::householder_qr aliases givens_qr=0; normal_equations=1. There is no Householder implementation behind that alias. Both fitting paths cost O((m+n)*p²) for m samples and n controls, with O(n*p) banded storage.

Basis, calculus, and allocation

basis returns n_ctrl entries with at most p+1 local nonzeros; pointer basis first clears out_count entries and returns without basis values when out_count<n_ctrl. basis_derivatives returns row-major (min(order,p)+1)*n_ctrl entries. design_matrix allocates a u32-indexed CSR matrix with p+1 stored entries per row, including local zeros; counts/indices must fit u32.

derivative_spline drops the outer knots and forms n-1 difference controls in O(n). For a degree-1 input its result has degree 0, but evaluate(bspline) returns zero for degree 0; it therefore does not evaluate the intended piecewise-constant derivative. antiderivative_spline adds endpoint knots and cumulative controls, with a supplied initial constant; degree 16 returns empty. integral constructs an antiderivative on every call and evaluates its clamped endpoints; it allocates O(n), and the degree-16 case returns zero.

make_uniform_clamped_knots, make_averaged_clamped_knots, make_unclamped_uniform_knots, make_periodic_uniform_knots, make_knots, and greville_abscissae allocate returned vectors. knot_style enumerates clamped_uniform=0,averaged=1,unclamped_uniform=2,periodic_uniform=3. Averaged/Greville generation costs O(n*p); uniform generation is O(n+p). periodic_uniform is the same uniform knot sequence as unclamped_uniform and does not alone repeat controls or create a periodic curve.

micron::math::splines::bspline_split

Defined in header <micron/math/splines/bspline_helpers.hpp>.

Owns independent left and right scalar B-splines produced by interior knot splitting.

Refinement operations

insert_knot returns a copied/refined B-spline rather than mutating its input. It rejects out-of-domain knots and multiplicity beyond p inside or p+1 at endpoints. Each repetition scans/copies the growing knot/control arrays and blends affected controls: r repetitions cost O(r*n+r²) for fixed p. refine_knots repeats these allocated insertions and returns empty on a checked failure.

split requires a strictly interior parameter, inserts until its multiplicity reaches p, then copies child knot/control arrays, sharing a control value by value at the join. The input and both outputs retain independent storage. A split costs O(p*n+p²) copying/refinement work at degree p and O(n+p) output storage; no geometric approximation is introduced by the knot-insertion formula apart from floating-point rounding.

micron::math::splines::nearest_curve_nd

Defined in header <micron/math/splines/curve_nd.hpp>.

Owns parameter samples and vector points for a nearest-neighbor path in 2 through 16 coordinates.

Storage and related linear path

nearest_curve_nd and linear_curve_nd own ts and vector<vec<F,D>> pts, plus mutable last_hit and extrap mode. Factories check ts.size()==n, n>=2, and strict increase, then copy n points; the points pointer must name n readable elements. Construction/copy/storage are O(n*D). Nearest defaults to endpoint holding and selects the right point on midpoint ties; linear defaults to tangent continuation and uses a common scalar fraction for all coordinates. Empty representations evaluate to a zero vector.

Evaluation costs O(log n+D) worst-case, with O(D) local arithmetic/copy and cached nearby lookup. Their array overloads repeat scalar calls rather than using the scalar interpolants' sorted segment walk. There are no direct nearest/linear-curve cursor or derivative overloads in this surface.

micron::math::splines::cubic_curve_nd

Defined in header <micron/math/splines/curve_nd.hpp>.

Owns a shared parameter grid and vector cubic coefficients for a path in 2 through 16 coordinates.

Layout and construction

curve_seg<F,D> is aligned as vec<F,D> and owns vectors a,b,c,d, representing a+b*u+c*u²+d*u³. cubic_curve_nd owns ts, a vector of n-1 segments, last_hit, bc, and mode (default linear_continue). make_cubic_curve validates parameter count/order, factors one scalar cubic system, then solves each coordinate with the same factors. Construction/copy/storage are O(n*D), with O(n*D) temporary moment/value arrays. A solve failure can leave a nonempty grid and zero-initialized segment storage, so inspect build_info.

Scalar evaluation costs O(log n+D) worst-case; a cursor/stateless overload avoids shared cache mutation. derivative supports orders up to three, with first-derivative-only tangent continuation outside. speed, tangent, curvature, and three-dimensional torsion use these derivatives, O(D) local work each after searches; zero speed/degenerate cross products return zero rather than a singularity status.

Parameterization and sampling

curve_parameterization is uniform=0,chord_length=1,centripetal=2. parameterize returns cumulative unnormalized steps of 1, Euclidean distance, or its square root, O(n*D); repeated points can yield repeated parameters and be rejected by subsequent strict-grid builders. callable_real_curve<Fn,F,D> tests conversion of fn(F) to vec<F,D> and imposes no lifetime or numerical guarantees.

arc_length uses composite Simpson speed samples (default 128, rounded up to an even count); reversed bounds return negative length and no tolerance/error estimate is returned. sample_uniform_arc_length builds a cumulative Simpson table, binary-searches target lengths, and applies three safeguarded Newton updates per interior sample. With J integration cells and q samples, work is O(J*(D+log n)+q*(log J+D+log n)) and allocated storage O(J+q*D). The spacing is approximate, with no convergence status.

micron::math::splines::regular_cubic_curve_nd

Defined in header <micron/math/splines/curve_nd.hpp>.

Owns vector cubic segments on a regular grid described by t0 and positive dt.

Choice and cost

make_regular_cubic_curve requires n>=2 and dt>0, builds a temporary n-point grid, and uses the same shared cubic factorization as cubic_curve_nd. Stored data omit the grid vector and lookup cache: an interior segment is floor((t-t0)/dt), giving O(D) evaluation independent of segment count. Construction/storage remain O(n*D); mode defaults to linear_continue. Finite usable t0,dt and representably distinct generated grid points remain required. The regular type has evaluation array overloads, without direct derivative/arc-length helpers.

micron::math::splines::bspline_curve_nd

Defined in header <micron/math/splines/curve_extensions.hpp>.

Owns knot/control vectors and cached knot-denominator reciprocals for a vector B-spline path.

Layout and operations

D=2..16, degree=1..16, n_ctrl>=degree+1, knot_count=n_ctrl+degree+1, and a positive active domain are required by factories. Controls and knots are copied; __basis_inverse stores (n_ctrl-p)*p*(p+1)/2 reciprocals. mode defaults to clamp. Construction/cache generation is O(n*(D+p²)) time/storage. Evaluation uses p+1 local basis values, O(p²+p*D+log n) work and automatic fixed-capacity scratch.

Factories support explicit controls, interpolation, weighted least squares, and closed uniform paths. Interpolation factors a single p-band matrix and applies it across coordinates; least squares shares Givens/normal factors and vector right-hand sides. Closed construction repeats the first p controls and selects periodic extension; it is distinct from merely choosing periodic_uniform knots.

derivative evaluates basis derivatives directly; derivative_spline allocates reduced knots/controls and a rebuilt cache. As for scalar B-splines, a degree-1 derivative_spline result has degree 0 and evaluate returns a zero vector. Direct derivative(s,t,1) does not share that representation limitation. Extension modes handle endpoint tangents, reflection derivative signs, periodic mapping, zeros, or polynomial basis continuation.

micron::math::splines::nurbs_curve_nd

Defined in header <micron/math/splines/curve_extensions.hpp>.

Owns positive rational weights alongside the vector B-spline representation and basis cache.

Rational evaluation

make_nurbs_curve validates weight count/positivity and copies controls, knots, and weights. make_closed_nurbs_curve repeats the first p controls/weights with a uniform extended knot sequence. Evaluation contracts local weighted controls and divides by the local weight sum; if that sum is zero the value path leaves the numerator unnormalized rather than reporting an error. Derivative evaluation uses weighted basis derivatives and a binomial quotient recurrence, returning zero for a zero denominator.

Derivative orders above degree return zero in this implementation, although a rational curve can have nonzero derivatives above its polynomial numerator degree. For requested order r<=p, work includes O(p²*(r+1)) basis derivative work and O(D*(p*r+r³)) quotient/binomial work, plus search. Ordinary values cost O(p²+p*D+log n). Rational data can lose denominator positivity under polynomial extension; finite valid in-domain data remain the intended case.

micron::math::splines::bezier_curve_nd

Defined in header <micron/math/splines/curve_extensions.hpp>.

Owns 2 through 17 vector control points for a single Bezier segment on [0,1].

Polynomial and rational variants

bezier_curve_nd stores ctrl and extension mode; rational_bezier_curve_nd additionally owns one positive weight per control. Their factories copy arrays, reject incompatible counts, and default to clamp. De Casteljau interpolation uses automatic scratch for 17 vector controls; the rational form interpolates homogeneous weighted controls and weights. Evaluation is O(p²*D) with O(p*D) scratch, for degree p=n_ctrl-1.

Supported extension modes include endpoint clamping, zero, tangent-line continuation, parameter reflection/wrapping, and evaluating the interpolation polynomial/rational expression outside [0,1]. Rational zero final weight leaves the homogeneous numerator unnormalized. These types have value evaluation only in the reviewed surface; curve derivative/length helpers target cubic_curve_nd. There is no retained lookup cache, so immutable value evaluation does not mutate the representation.

micron::math::splines::closed_cubic_curve_nd

Defined in header <micron/math/splines/curve_extensions.hpp>.

Owns a cubic vector path built with periodic second-derivative equations and a repeated endpoint sample.

Construction and evaluation

make_closed_cubic_curve requires n>=4, matching strictly increasing parameter samples, and a first/last point match in each coordinate within a scaled 1e-5/1e-12 tolerance. It factors the cyclic scalar system once, solves vector right-hand sides, applies the rank-one correction, and builds O(n*D) coefficients/storage. Checked pivots can report singular_system.

The wrapper owns cubic_curve_nd curve and period metadata. evaluate wraps using curve.ts endpoints and supports an external cursor; period alone is not the mapping source. There is no direct closed-wrapper derivative overload, but the embedded curve remains accessible. A closed builder establishes periodic coefficient conditions; wrapping an arbitrary open cubic does not.

micron::math::splines::packed_cubic_curve_nd

Defined in header <micron/math/splines/curve_extensions.hpp>.

Owns an irregular cubic vector path with coefficient coordinates packed contiguously rather than in aligned vector segment records.

Layout and selection

ts owns n knots; coeff holds (n-1)*4*D scalars. Segment i has contiguous a[D],b[D],c[D],d[D] blocks at i*4*D. pack copies a cubic_curve_nd in O(n*D) and carries its extrap mode. make_packed_cubic_curve first builds the ordinary representation and then packs, so construction temporarily holds both.

Evaluation uses the same cached/binary segment lookup and O(D) Horner arithmetic with architecture-selected coordinate kernels; an external cursor overload is supplied. Packed storage avoids the per-vector alignment padding present in curve_seg, without changing polynomial degree or establishing a benchmark advantage. There are no packed derivative/arc-length overloads.

micron::math::splines::tensor_bspline

Defined in header <micron/math/splines/tensor.hpp>.

Owns a 2-through-4-parameter tensor-product B-spline with scalar or algebraically compatible control values.

Storage and invariants

tensor_bspline<F,V,P> owns degree[P],shape[P], knots[P], reciprocal caches[P], ctrl, mutable last_hit[P], and mode[P]. Each axis follows degree 1..16 and nondecreasing knots with a nonempty active interval; ctrl.size() must equal product(shape). The factory checks product overflow and copies all data. Controls use row-major flattening with the final axis contiguous. V must support zero initialization, scaled addition, and scaling; scalar F and vec values are supported by the supplied helpers.

With T=product(shape), storage/copy are O(T*sizeof(V)+sum(shape[a]*p[a]²)) plus knots. A value evaluation builds each local basis and contracts L=product(p[a]+1) controls, costing O(sum(p[a]²+log shape[a])+L*cost(V arithmetic)); scratch is bounded by P*(17) scalars and local value state. No global tensor matrix is formed.

Derivatives

partial_derivative takes one requested order per parameter axis and contracts derivative bases. Orders above an axis degree contribute zero. Scalar gradient calls P first partials; scalar Hessian calls P*(P+1)/2 second/mixed partials and mirrors them, rebuilding basis work each time. surface_normal for a 3-vector-valued 2-parameter surface takes and normalizes the cross product of two first partials; a degenerate cross product remains zero. Batch coordinates are interleaved coords[sample*P+axis] and use repeated scalar evaluation.

Each axis has its own extension_mode, default clamp. Tangent extension is applied to basis functions along that axis; periodic/reflect mapping does not itself make the control lattice periodic. Public knot/shape/degree edits require cache invalidation/rebuild. No external-cursor tensor overload is supplied, so concurrent const evaluation shares mutable axis hits.

micron::math::splines::tensor_nurbs

Defined in header <micron/math/splines/tensor.hpp>.

Adds an owned positive weight per control to the tensor-product representation.

Operations and limits

make_tensor_nurbs validates all axis data, product size, control/weight lengths, and positive weights. Value evaluation contracts weighted controls and divides by the total basis-weight sum when nonzero; a zero sum leaves the numerator unnormalized. A first partial along one specified axis uses two contractions and the quotient rule; a zero denominator returns zero. surface_normal is available for a 3-vector-valued two-parameter surface.

The public rational derivative surface supplies first partials by axis, without arbitrary mixed-order, scalar gradient, or Hessian overloads. Axis linear extension extends numerator/weight basis functions before division, so the resulting rational extension is not generally a straight tangent line. Storage/work follow tensor_bspline with O(T) additional weights. Shared mutable axis caches and explicit invalidation rules are unchanged.
