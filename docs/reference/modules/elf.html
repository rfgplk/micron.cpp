ELF

From micron reference
micron reference › System interfaces

Native shared-object mapping and symbol handles, low-level ELF records and relocation support, plus read-only ELF32/ELF64 file inspection with normalized result rows.

Interface selection

Native loading behavior

The native loader requires matching class, byte order, machine, ET_DYN type, and native program-header entry size, with at most 96 program headers. It reserves an address range, maps PT_LOAD file/BSS regions, restores segment permissions, records dynamic data/TLS, applies the requested relocations, and optionally protects RELRO and runs initializers. Setup failures report library_error.

RELATIVE/IRELATIVE, selected absolute/global/jump-slot/PC-relative forms, packed RELR, and module-local dynamic TLS forms are implemented per architecture. Static TLS, TLSDESC, COPY, cross-module undefined TLS, and unimplemented relocation kinds are rejected. strict also rejects an unresolved nonweak symbol; best_effort tolerates that unresolved result. Weak misses leave their relocation unwritten.

The mapped loader assumes compatible shared-object layout and dynamic metadata; it is not a complete validation layer for arbitrary corrupted files. It treats load_base as a bias in symbol/relocation calculations, while reset uses it as the unmap address, so nonzero lowest PT_LOAD virtual addresses do not have a general correct teardown contract. Protection calls do not all propagate failures.

handle_t's legacy options use best_effort relocation and enable initializers/RELRO. Its destruction unlinks/unmaps the object but does not run DT_FINI/DT_FINI_ARRAY. elf::execute calls a named exported function, not the file's ELF entry point; its path overload keeps the handle only for that call. Match the exact ABI and retain the handle for any returned pointer into the module.

File inspection behavior

Include linux/elf/read.hpp for the inspection family. source::open returns option<source,const char*>; first is the source and second is a static error. open_image validates identification/class/encoding and complete header size, then normalizes the header into fixed-width fields. It accepts nonnative ELF classes/machines for inspection and owns no source storage.

Walkers materialize vectors of sections, segments, symbols, relocations, version rows, and dynamic entries. They clamp many record counts to file availability and stop at incomplete records; an empty/truncated result is not a separate comprehensive validation status. Section extended numbering is handled through section zero. Symbol walking chooses the first static and first dynamic symbol table and reads fixed ABI record sizes.

vaddr_to_offset resolves only bytes backed by a PT_LOAD file range, excluding zero-filled BSS. read_dynamic prefers PT_DYNAMIC and falls back to SHT_DYNAMIC, then resolves strings through load segments or .dynstr. read_interp copies the interpreter text; classify_link uses PT_INTERP/PT_DYNAMIC presence. Name helpers return null for unknown type/machine/tag/relocation pairs. Processor-specific tags and relocation numbers must be interpreted with their machine identifier.

Most walks are O(record count + copied name bytes) and allocate result vectors/strings. Section and name searches are linear. Version-chain walks have a 4096 outer-chain bound, and RELR expansion caps emitted offsets at 2^22. These limits do not turn every offset arithmetic operation into a checked parse. from_file_order currently swaps every MSB-encoded value and leaves LSB values unchanged, so the implementation assumes a little-endian host for correct cross-endian inspection.

Symbol lookup and dynamic TLS

lookup_sym tries GNU hash/Bloom lookup and then SysV bucket chains. Name hashing is O(name length); hash-chain traversal can be linear in the symbol count. Lookup results borrow table entries. The symbol-count helper uses hash metadata and neighboring dynamic-table addresses with an upper cap; it is not a file-section symbol enumerator.

Dynamic TLS uses a fixed module table of 64 entries with index zero reserved. Each participating thread lazily maps its own initialized/zero-filled block for each active module; a global spin lock serializes registration, lookup allocation, and unregister. Unregister frees every recorded thread's block for that module. Callers must ensure no execution/callback retains those addresses. Hosted thread cleanup uses a pthread key; freestanding cleanup uses the micron exit hook.

micron::elf::handle_t

Defined in header <micron/linux/elf/elf.hpp>.

Move-only owner of one loaded module and a vector snapshot of its dynamic symbols.

Operations and invalidation

open/open_path map the object, link it into the legacy loaded-module list, and build O(symbol count) symbol rows. valid()/Boolean conversion test the load base. sym searches this object's dynamic hash tables; sym_as casts its result. symbols/dyn/path/soname/base return borrowed data or references. Move transfers the mapping and updates list links; destruction or replacement invalidates mapping pointers and snapshot references. The legacy list is not a general independently synchronized shared registry.

micron::elf::module_t

Defined in header <micron/linux/elf/loader.hpp>.

Move-only owner of a native mapping, its dynamic table pointers, TLS registration, RELRO range, program headers, and fixed path.

Lifetime

reset/destruction unregister TLS, unmap the load span, invalidate host-module discovery, and clear mapping metadata. They do not run finalizers. Move transfers ownership and clears the source's mapping fields. Dynamic/program-header pointers borrow the owned mapping and become invalid at reset. next is legacy list bookkeeping and is not an owning dependency link.

micron::elf::load_opts_t

Defined in header <micron/linux/elf/loader.hpp>.

Relocation policy, initializer/RELRO switches, and an optional symbol resolver/context.

Policies

reloc_mode_t has defer, relative_only, best_effort, and strict values. Defaults are relative_only, run_init=false, apply_relro=true. defer returns after mapping/TLS/dynamic discovery before the later relocation, RELR, RELRO, and initialization steps. A custom resolver receives context, symbol name, and symbol index. This lower-level loader does not traverse DT_NEEDED automatically.

micron::elf::fmt_class

Defined in header <micron/linux/elf/bits.hpp>.

ELF file-class selector with invalid, elf32, and elf64 values.

Related scalar types

fmt_data selects invalid, lsb, or msb encoding. addr32/off32/word are u32; addr64/off64/xword are u64; sword/sxword are signed 32/64-bit; half is u16. These describe file field widths, not ownership or validated addresses. native_class/native_data derive from target definitions.

micron::elf::ehdr_t

Defined in header <micron/linux/elf/header.hpp>.

ELF64 file-header aggregate, alongside the program, section, dynamic, symbol, relocation, and version record families.

Record families

The aggregates contain file values; a pointer-shaped field is an integer until interpreted in an appropriate image. They do not bounds-check, endian-convert, allocate, or load a file on construction. Keep ELF32/ELF64 layouts distinct even on a native 64-bit target.

shdr_tSection name index/type/flags/address/offset/size, linked table metadata and alignment/stride; shdr32_t narrows wide fields.

micron::elf::elf_traits

Defined in header <micron/linux/elf/header.hpp>.

Class-selected aliases and relocation/Bloom encoding operations for ELF32 and ELF64.

Member types

addr/off/uword/sxwd choose the corresponding widths; ehdr/phdr/shdr/dyn/sym/rel/rela select class-specific records. r_sym/r_type decode the 8-bit ELF32 or 32-bit ELF64 relocation type field. bloom_bits is 32 or 64 and relr_bits is 31 or 63. native_traits selects native_class; nehdr_t/nphdr_t/nshdr_t/ndyn_t/nsym_t/nrel_t/nrela_t/naddr_t/nword_t are its aliases. Traits perform constant compile-time/scalar work and carry no image.

micron::elf::dyn_info

Defined in header <micron/linux/elf/header.hpp>.

Class-specific borrowed dynamic tables and scalar metadata, plus an inline list of needed-library string offsets.

Fields

The record groups symbols/strings/hashes, REL/RELA/RELR/PLT tables and byte lengths, GOT, initializer/finalizer arrays, version metadata, flags, SONAME and search paths. Array sizes such as init_arraysz are bytes. needed_count selects up to max_needed=256 inline offsets; needed_truncated records overflow. dyn_info_t selects the native class. Copying this record copies pointers and offsets without retaining the image.

micron::elf::symbol_info_t

Defined in header <micron/linux/elf/header.hpp>.

Dynamic symbol snapshot with borrowed name/address and size/type/binding/visibility/defined fields.

Lifetime

handle_t builds one row per counted dynamic symbol, including undefined rows with null address. The name points into .dynstr and the address is formed from load bias plus symbol value. The row is not a retained symbol handle and does not keep its module loaded. handle_t::sym does not invoke an IFUNC resolver, whereas some registry/host resolution paths do.

micron::elf::reloc_view

Defined in header <micron/linux/elf/reloc.hpp>.

Normalized relocation offset, symbol index, type, addend, and RELA flag.

Context and result

reloc_ctx_t borrows the load base/dyn_info and callback context, with TLS module/offset metadata. resolve_fn is the callback signature. apply_reloc returns reloc_result::applied, skipped_weak, unresolved, or unsupported. An implicit REL addend is read from the destination slot; a RELA addend is carried by the record. These operations directly write mapped memory and require valid compatible metadata and writable target slots.

micron::elf::tls_module_t

Defined in header <micron/linux/elf/tls.hpp>.

Dynamic TLS template metadata: module id, borrowed initialized image, total/image byte sizes, alignment, and active state.

Supporting records

tls_block_t owns mapping metadata used by the runtime: aligned ptr, original map, and map_sz. tls_thread_block_t links a thread id and 64 block slots. tls_index_t carries the module/offset pair consumed by __tls_get_addr. These aggregates do not independently free storage; the TLS registry/exit hooks perform cleanup. Alignment and sizes must describe a valid template.

micron::elf::host_module_t

Defined in header <micron/linux/elf/host_modules.hpp>.

Borrowed snapshot of an already mapped host object's address range, bias, dynamic tables, name/path, and executable/valid flags.

Discovery limits

Host discovery parses up to 64 KiB of /proc/self/maps into at most 256 module records, grouping absolute paths across segments and inspecting executable objects. It neither opens new dependencies nor retains host mappings. host_find/host_resolve_sym search the cached table; invalidate_host_modules clears it. maps_line_t is one parsed range/path record; path_str_t is sstring<512> for loader paths. Callers must synchronize direct host-cache access and external mapping changes.

micron::elf::read::source

Defined in header <micron/linux/elf/read/source.hpp>.

Move-only byte source that either borrows a pointer/length or owns a read-only mmap of a file.

Lifetime and access

reset/destruction unmaps only an owned mapping. at(off,want) returns a clipped span_t with ptr/len and returns empty for an offset at or beyond the end. image stores the address of its source object, so moving/destroying that source invalidates the image's source reference even if the mapping moved intact. Borrowed input must remain alive for every image/read operation. source::open needs a seekable nonempty file.

micron::elf::read::image

Defined in header <micron/linux/elf/read/image.hpp>.

Borrowed source pointer and a normalized ELF header.

Header and validity

header stores class/encoding, ABI, type/machine/version, entry, flags, and table offsets/strides/counts with u64 wide fields. ok() tests source presence and recognized class; it does not revalidate all bytes or tables. is_native checks class, encoding, and machine. is64 chooses a record layout. Header reads are constant work; source length and table contents do not become owned by the image.

micron::elf::read::section_row

Defined in header <micron/linux/elf/read/sections.hpp>.

Normalized section fields with an owning copied name string.

Storage and searches

Rows contain type/flags/address/file offset/size, link/info, alignment and entry size. walk_sections returns a newly allocated vector. find_section and find_section_by_type return a borrowed pointer into that vector and search linearly; vector relocation, erasure, or destruction can invalidate it. File offsets and virtual addresses remain distinct numeric fields.

micron::elf::read::segment_row

Defined in header <micron/linux/elf/read/segments.hpp>.

Normalized program-header fields for a segment.

Related classification

The record holds type/flags, file offset, virtual/physical addresses, file/memory sizes, and alignment. find_segment returns the first matching row. link_kind has static_exec, dynamic, and static_pie; classification is based on interpreter/dynamic segment presence, not on a full link audit.

micron::elf::read::symbol_row

Defined in header <micron/linux/elf/read/symbols.hpp>.

Normalized symbol value/size, binding/type/visibility/section index, defined state, table kind, and owning copied name.

Table selection

sym_table_kind distinguishes static_symtab and dynamic_dynsym. A row's value is the file's st_value, not an automatically relocated callable address. walk_symbols concatenates rows from the selected static and dynamic tables; it does not deduplicate names. Result-vector lifetime governs borrowed row pointers; copied names survive closing the original source.

micron::elf::read::dynamic_info

Defined in header <micron/linux/elf/read/dynamic.hpp>.

Owned dynamic-entry vector and copied needed/SONAME/RPATH/RUNPATH strings, with presence and origin flags.

Fields and cost

dyn_row stores signed tag and unsigned value. present means a dynamic segment/section was found even if no complete entry could be read. from_section marks the fallback. Extraction scans entries and copies strings; vaddr-to-file lookup also searches the segment list. The result is descriptive and does not resolve, map, or load any dependency.

micron::elf::read::reloc_row

Defined in header <micron/linux/elf/read/relocs.hpp>.

Normalized file relocation with offset, symbol index, machine-specific type, addend, and has_addend flag.

Packed relocation output

addend is meaningful only when has_addend is true. sym indexes the section-linked symbol table. relr_out instead owns a vector at of expanded pointer-slot virtual addresses and a capped flag. walk_relr stops at its 2^22-row cap or incomplete input; it describes slots without patching them. Time/storage scale with decoded entries and emitted offsets.

micron::elf::read::version_row

Defined in header <micron/linux/elf/read/versions.hpp>.

Owned symbol-version name/file strings, numeric index/flags, and an is_need flag distinguishing requirement from definition.

Lookup

read_verdef/read_verneed follow bounded version chains and copy selected names; read_versym returns the raw half-word indices. version_of strips the hidden flag, ignores local/global sentinel indices, and linearly finds the first matching row. Its returned pointer borrows the result vector.

micron::auxv_t

Defined in header <micron/linux/elf/auxv.hpp>.

Native unsigned-long type/value pair in the running process's auxiliary vector.

Related running-image records

The global micron::phdr_t and ehdr_t use native p_*/e_* field names for runtime startup inspection; they are distinct from micron::elf file records. tls_image borrows the PT_TLS initialized image and carries file/memory sizes and alignment. find_tls_in_phdrs derives bias from PT_PHDR and cannot handle every static-PIE layout alone; find_tls_from_ehdr can also use a zero-offset PT_LOAD.

getauxval caches up to 48 records from /proc/self/auxv and returns zero for absent values; auxval_has distinguishes an existing zero. No libc auxiliary-vector provider is consulted. First-use cache publication is not an exclusive once protocol. Repeated lookup scans at most that fixed capacity.
