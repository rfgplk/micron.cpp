Functional algorithms

From micron reference
micron reference › Algorithms

Eager functional algorithms in micron::fp return transformed containers, tuples, or scalar/optional results. Curried _c functions return callable objects that retain their supplied arguments.

Evaluation, requirements, and ownership

Sequence operations generally require pointer-valued begin()/end(), value_type, and the output operations used in the body (resize, indexed access, or push_back). Their broad iterable constraints do not guarantee that every container is supported. Outputs own their elements. Read-only inputs must remain valid for the duration of the call; results do not borrow sequence storage.

fmap(function, container) takes the container by value and preserves its type and element type. An lvalue input is copied; a moved input can transfer storage. fmap_into<Out> explicitly selects a different output element/container type. Pointer-callable overloads are available, with value-callable forms preferred in several constrained overload sets.

Each eager stage completes before the next begins and can allocate its own result. Use eager forms for reusable materialized results, random access, or independent ownership. micron::lz provides pull-based composition when intermediate sequences are unnecessary. Curried closures capture callables/scalars by value; whether invocation copies or moves a container is visible in the closure's parameter and call.

Options and errors

An option<Result,Error> succeeds when is_first() is true. Boolean conversion is not a substitute for this test. at returns index_out_of_bounds_error; missing head/last/search results and empty safe aggregates use empty_container_error. A failed search can therefore use the same error type as an empty input.

zip_with, ap, safe_inner_product, and nonrectangular transpose report bad_zip_error. safe_divide and divide_zip report a zero divisor. Raw arithmetic remains subject to normal overflow, signed-minimum negation, floating domain, and conversion rules; the safe aggregate prefix checks emptiness rather than numeric overflow.

Option-lifted mapping/filtering/arithmetic normally forwards an existing error alternative. The lifted divide(option<C,E>, scalar) instead returns option<C,division_by_zero_error> and replaces either an incoming error or a zero divisor with that error type. traverse propagates the inner option's actual error type; traverse_error is a declared tag rather than its universal return type.

sequence_check returns a plain bool indicating that all elements hold first alternatives. sequence validates those alternatives and returns a copy of the original container of options. sequence_extract<Out> checks all options before constructing the output container of extracted values. These are distinct operations.

Size rules, deduplication, and generation

Zipped add/subtract/multiply modify a by-value copy of the first sequence over the common prefix and retain its unchanged suffix. divide_zip follows the same size rule but checks each used divisor. zip_with_trunc constructs only the common prefix. Unchecked inner_product reads as many elements as the first input and requires at least that many in the second; safe_inner_product requires equal sizes.

nub uses a Swiss set only when hashing is known to agree with equality: integral/enum values, noncharacter pointers, ASCII string types, or a type declaring hash_equality_consistent::value, and only when the hash expression is available. Otherwise it scans a vector of previously retained values. Expected linear hash behavior is therefore not a universal bound; fallback and nub_by can perform O(n²) equality work and store O(n) values.

chunk_into(...,0) returns an empty output, while checked chunk(...,0) returns empty_container_error. A final short chunk is retained. sliding emits only complete windows and returns empty for zero width or an input shorter than the window. transpose checks every row width before producing columns.

flat_map for sequences returns the original sequence type and requires each produced inner element to fit its element type. iterate(n,fn,seed) emits the seed first and invokes fn after every emission, including the final one: n calls for n outputs. unfold stops on the first error alternative and discards that alternative; it returns the successful generated prefix. snoc returns a successful optional appended sequence even for empty input.

Maps and trees

Map keys, values, and unzip copy data into fvectors in the concrete traversal order. elem searches values. find_first returns an optional mapped-value copy. Tree equivalents distinguish set elements from mapped values. No map insertion-order guarantee is introduced.

Associative nub and flat_map return fvectors rather than rebuilt associative containers. Map concat rebuilds the first map then inserts entries from the second; tree concat similarly inserts both traversals. Duplicate-key handling follows the concrete container's insert semantics, so a universal second-input-wins rule is not specified.

Map/tree-map traverse maps values and retains the original map type and keys. Inner success values must fit the original mapped type. After the first inner error it suppresses further callable evaluation, although the enclosing for_each traversal may still complete. The error type must be default-constructible for the local error slot.

Tree take, drop, prefix forms, head, last, and enumerate use full for_each traversals and return value sequences or optional copies. A small requested prefix does not imply O(prefix length) structural traversal. Safe associative aggregates reject empty input before delegating to the ordinary reductions.

Representation and operations

When hash_dedupable<T> holds, storage is heap_swiss_set<T>; otherwise it is fvector<T>. reserve(n) forwards reservation. add(value) returns true on the first insertion and false for an already present equal value. The fallback compares each stored value with the candidate before appending it, requiring O(k) comparisons for k retained values; the hashed arm follows Swiss-set lookup/insertion costs. Both arms own retained copies and release them with the backing container.
