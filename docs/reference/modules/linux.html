Linux interfaces

From micron reference
micron reference › System interfaces

Direct Linux system calls, process creation and observation, signal handling, event polling, kernel keyrings, system information, and kernel ABI records.

Interface layers

proc.hpp includes the process porcelain. Individual Linux headers expose smaller interfaces, although several depend on sibling headers for declarations. Native syscall.hpp selects amd64, i386, ARM EABI, or AArch64 at preprocessing time and rejects the WebAssembly target.

Return values and argument ABI

Raw system-call failures occupy -4095 through -1. syscall_failed tests that range by an unsigned comparison; syscall_errno simply negates its argument and should be applied to an error result. Most wrappers preserve raw -errno. spawn, sigwait, and clock_getcpuclockid instead return zero or a positive errno. Some convenience queries return a default value after discarding an error.

amd64 uses syscall and AArch64 uses svc with up to six machine-word arguments. i386 splits 64-bit arguments into two consecutive slots; ARM32 also inserts an alignment slot before a 64-bit argument when required by EABI. The six-slot constraint counts these splits. Pass counts, flags, and pointers with the intended ABI width: an accidentally wide integer can occupy extra registers on a 32-bit target.

A wrapper usually adds constant local work to one kernel call. Blocking time, kernel data-structure costs, permission checks, filesystem latency, and scheduling are outside that bound. A supplied constant or record does not probe whether the running kernel implements the operation. Feature-gated wrappers and io_uring opcode probes provide only their documented checks.

Process creation

try_fork returns the raw clone-based fork result. fork throws on setup failure; callable overloads run the callable on the child's copy-on-write stack and terminate through exit_group. wfork waits in the parent and returns the decoded normal exit code, or the raw wait status otherwise. The Stack template argument on these fork paths does not allocate a separate child stack.

Ordinary spawn creates a close-on-exec error pipe, forks, applies requested child settings, and executes an explicit path. EOF on the error pipe indicates that exec closed its write end; an integer payload reports a positive errno and the failed child is reaped. The pipe read is not a complete framed/retried protocol: a short read or read error is treated as success. PATH lookup is a separate which_into operation.

Child limit setters discard individual errors, and spawn's capability setup ignores apply_caps_child's return. A successful spawn therefore establishes execution, without certifying every requested restriction. File-action OPEN errors and selected spawn-attribute errors propagate, but DUP2/CLOSE action errors are discarded. resetids, usevfork, and setcgroup flag constants have no implementation in the attribute interpreter.

rexecute replaces the current image; its inplace path exits 127 if exec fails. Several restricted rexecute overloads call execve directly and end in __builtin_unreachable when it returns: their failure path is not a recoverable error interface. execute_with_caps and execute_with_limits currently place a null argv entry before their appended extra arguments, so exec sees only argv[0]. Use an explicit argv array or child_spec when the full argument list matters.

The unsafe spawn family allocates a mapped stack and clone argument block without releasing those mappings on the ordinary parent path. It also conditionally writes the returned PID only when the incoming PID reference is nonzero. Prefer the ordinary fork-based spawn implementation.

Environment and executable lookup

env_get scans the borrowed null-terminated environ array for an exact key followed by '='; its returned pointer refers into that array. env_has requires a present nonempty value. No mutation, synchronization, or copy of environment storage is supplied.

which_into accepts an explicit slash-containing executable path or scans PATH. An absent or empty PATH uses /usr/local/bin:/usr/bin:/bin. Empty and relative PATH components are skipped; it does not implement the usual current-directory meaning of an empty component. Success returns the path length excluding the terminator, while failure returns -errno. Lookup is linear in the environment/path bytes plus filesystem access checks and does not reserve the executable against later replacement.

Signals and observation

Signal masks apply to the calling thread. Signal handlers remain subject to the target runtime's asynchronous execution restrictions. create_handler/create_info_handler return the configured action while discarding installation errors. query_handler temporarily installs ignore and then restores the old action; querying therefore changes the disposition during the call.

Process snapshots read several independent files and system calls. They are not an atomic observation of a process, and a disappearing or inaccessible process can leave zero/default fields. wait4 and waitid retry interrupted waits; several higher-level wait helpers discard other wait errors before decoding their zero-initialized status.

ptrace helpers preserve raw errors and use an output word for peek requests, matching the raw Linux ABI. They do not supply a debugger state machine. Mount, namespace, capability, quota, and prctl operations are direct process/kernel state changes, with no automatic rollback.

System information

sysfs readers use bounded stack buffers and return an empty string, zero, or false when a node is unavailable. Numeric readers parse a decimal prefix without overflow status. read_size accepts K/M/G binary multipliers. Strings lose one trailing newline; longer contents are truncated to the supplied capacity. These values do not distinguish a genuine zero from an I/O failure.

CPU frequency values use kHz unless the function name ends in _hz. Thermal temp uses millidegrees, temp_c truncates to whole degrees, and powercap energy uses microjoules. CPU topology/frequency/cache summaries issue multiple reads. All-CPU setters continue after failures and return a combined boolean; prior successful changes remain applied.

linux/sysctl.hpp currently supplies legacy numeric selector enums only. Its banner mentions /proc/sys access, but the header contains no parser or syscall wrapper. Actual bounded node readers and selected /proc/sys queries are in linux/sys/sysfs.hpp.

io_uring

linux/sys/uring.hpp supplies the mapped-ring owner, ABI records, request preparation, resource registration, and completion consumption. It is below the coroutine I/O scheduler. Choose it when submission batching and explicit asynchronous lifetimes are useful; use synchronous descriptor operations for a single immediate call or epoll for readiness-driven nonblocking I/O.

Preparation only writes an SQE. Obtain a slot, prepare it, set user_data and any additional flags, publish with advance_sq, and submit. Keep all referenced buffers, paths, vectors, timeout records, and descriptors valid until the operation's completion protocol releases them. A completion's res is the operation result or -errno; a successful submission call does not imply successful I/O. Multishot requests can produce several completions, and zerocopy send buffers can remain in use until the notification completion.

The header defines newer opcodes/flags/registration records even on kernels that do not implement them. supports probes request opcodes once, while init_best may remove requested setup flags after EINVAL. Examine the returned setup_flags/features and registration results. setup_mask_for_kernel computes a table-based candidate mask from supplied version numbers; it does not detect the running kernel or prove a configuration is usable.

micron::child_spec

Defined in header <micron/linux/process/child.hpp>.

Value configuration for the functional child-process launch interface.

Description

path and cwd are fixed-capacity strings; argv stores extra arguments and launch inserts path as argv[0]. env contains KEY=VALUE entries. The redirection records select inherit, pipe, null, or an existing descriptor; merge_stderr redirects standard error to the selected standard output. Existing descriptors are borrowed and duplicated in the child.

env_inherit appends configured entries after the inherited environment rather than replacing matching keys. clear_env disables inheritance. limits and capability fields are used only when their has_* flag is set. Constructing a specification also constructs limits_t, which queries all 16 current resource limits even when no limits are requested. Configuration combinators return modified values; combinators with moved captures are intended for one consuming application.

micron::spawn_fn

Defined in header <micron/linux/process/child.hpp>.

Function object behind launch, returning option<child, spawn_error>.

Description

Builds null-terminated argv/envp arrays, up to three redirections in an eight-action local table, optional session attributes, and the error-pipe spawn transaction. Success occupies the first option alternative. Failure occupies the second and includes a positive errno and stage; the current implementation reports pipe or spawn stages, while the fork enumerator is reserved.

Configuration strings and arrays remain alive through the synchronous fork/exec handshake. The returned child owns only the parent's pipe ends and process identifier. spawn_or_throw converts a failure to system_error. wait_for and communicate_with transform an option while preserving its error alternative.

micron::child

Defined in header <micron/linux/process/child.hpp>.

Move-only process identifier and optional owning standard-I/O pipe endpoints.

Description

Destruction closes pipe endpoints; it does not wait, reap, kill, or detach the child. Move assignment likewise closes the old endpoints without reaping the old process. Call wait or arrange another reaper for every launched child. valid tests only pid>0, including an already reaped PID, and signal helpers do not guard against stale IDs or an invalid moved-from object.

wait caches its decoded result; try_wait uses WNOHANG and distinguishes an observed exit from an unfinished/error result. wait_and_collect additionally obtains resource information but does not reuse the cached wait result. Calling it again after reaping is not an idempotent query.

read_stdout/read_stderr drain one blocking stream to EOF and close it. Independently draining streams or writing all input can deadlock when another pipe fills. communicate polls input, output, and error together, makes the input endpoint nonblocking, closes it after sending, accumulates output strings, and waits. It has no timeout or output-size ceiling; a descendant retaining a pipe can delay EOF indefinitely. It performs O(input bytes + output bytes) copying plus poll/read/write calls and growing-string allocations. I/O errors are not returned as a separate result, so captured data may be partial.

micron::exit_status

Defined in header <micron/linux/process/child.hpp>.

Decoded process termination state, paired with owned output strings by comm_result.

Description

exited identifies normal exit and code is then the ordinary exit code. signaled identifies signal termination and code is -term_signal. success requires exited and code==0; this is the child-process convention, independently of the repository test harness's success sentinel. A default record has neither terminal-state flag set. comm_result contains this status and independent out/err strings.

micron::status_t

Defined in header <micron/linux/process/wait.hpp>.

PID and raw wait-status word for waitpid and the W-controlled execute overloads.

Description

Both fields default to zero. The wif*/w* helpers decode the raw status bits and do not themselves wait. A nonwaiting execute result has a PID but an unobserved zero status; wifexited on that zero does not prove the child has exited. Check the wait call's return before interpreting the word. idtype_t selects all children, a PID, a process group, or a PID descriptor for waitid.

micron::uprocess_t

Defined in header <micron/linux/process/process.hpp>.

Copyable executable configuration and process metadata with owned path/argument strings.

Description

The default constructor observes the current process through /proc, identities, limits, and affinity. Path constructors create a launch configuration and include the path as argv[0]. process_list_t is fvector<uprocess_t>; create_processes builds one configuration per name. spawn(uprocess_t&) updates PID, selected identities, and the spawn status.

This type does not own a running process or reap on destruction. Its envp field is a stored snapshot/configuration field, but the provided spawn/run_processes overloads pass global environ instead. The stored lims and affinity are not automatically applied by plain spawn; use explicit limit overloads and affinity operations. vector_to_argv owns the pointer array while borrowing each source string's characters; mutation or destruction of those strings invalidates the pointers.

micron::proc_stat_t

Defined in header <micron/linux/process/resource.hpp>.

Selected parsed fields of /proc/PID/stat, including identity, CPU ticks, faults, and memory sizes.

Description

comm is copied into a 256-byte array and parsed using the last ')' delimiter. utime/stime/starttime are clock ticks, vsize is bytes, and rss is pages. read_proc_stat uses /proc/self for a nonpositive PID and returns a zero record for empty input. The parser expects kernel-format input and supplies no independent parse-validity flag.

micron::proc_status_t

Defined in header <micron/linux/process/resource.hpp>.

Selected /proc/PID/status fields in fixed storage.

Description

uid/gid arrays hold real, effective, saved, and filesystem IDs. vm_* fields retain the file's kB units, while signal/capability fields are bitmasks. Thread and context-switch counters are stored separately. Unrecognized lines are ignored and missing fields remain zero. Name copying preserves the text immediately after the colon, including leading whitespace; State skips spaces but does not generally trim every whitespace character.

micron::proc_resource_t

Defined in header <micron/linux/process/resource.hpp>.

Composite resource snapshot containing parsed stat/status, rusage, and all resource limits.

Description

For the current process, get_process_resources requests real getrusage data. For another process, usage is approximated from /proc using the fixed user_hz=100 conversion, with unsupported counters left zero. Each component is read separately and may describe a different instant. Work is linear in the proc-file text plus a fixed set of limit syscalls.

micron::proc_info_t

Defined in header <micron/linux/process/process.hpp>.

Extended process snapshot adding capabilities, executable path, and observed stack/heap addresses.

Description

Addresses in runtime_t are numeric addresses in the observed process; retaining them neither maps nor owns that process's memory. child_result_t combines a PID, decoded exit/signal flags, wait4 resource usage, and a pre-reap resource snapshot. wait_and_collect reads /proc before its blocking wait, so those resource fields need not represent final child usage.

get_proc_info currently passes status.cap_bnd into ucap_set_t's ambient argument and status.cap_amb into its bounding argument; interpret those two resulting fields accordingly. These convenience snapshots are not a validity-checked process handle.

micron::posix::limits_t

Defined in header <micron/linux/sys/limits.hpp>.

Inline array of 16 resource-limit pairs read using prlimit64.

Description

Construction queries every limit for the supplied PID, defaulting to self. Failed entries remain zero; there is no per-entry status. Copy copies the fixed array; move copies it and clears the source. Changing lim only edits the value object. apply_limits applies every pair and returns the first raw error while continuing subsequent updates.

rlimit_t uses native rlim_t fields for the legacy calls. rlimit64_t always uses u64 current/maximum fields and is the representation used by limits_t/prlimit64 on all targets. limits enumerates CPU, file/data/stack/core/RSS, process/descriptor/memlock/address-space/lock/signal/message/nice/realtime limits; none is a sentinel beyond the 16 resources.

micron::ucap_set_t

Defined in header <micron/linux/process/capabilities.hpp>.

Value representation of effective, permitted, inheritable, ambient, and bounding capability masks.

Description

Default effective/permitted/inheritable/ambient masks are zero and bounding includes the known capability range. grant edits the first three masks, revoke clears all five, and inherit_ambient also sets ambient. cap enumerates the known capabilities through checkpoint_restore; is_cap_set requires convertible effective/permitted/inheritable members and leaves ambient/bounding optional for application helpers.

set_caps changes effective/permitted/inheritable only. Thus drop_all_caps does not itself apply the record's empty bounding or ambient masks. get_caps queries ambient/bounding only for self; foreign-PID defaults do not establish those sets. apply_caps_child first keeps capabilities, drops excluded bounding bits, sets the main masks, then raises requested inheritable ambient bits. It stops or reports errors without rollback and does not clear unrequested ambient bits. Operations on the value are O(1); set enumeration uses the fixed known capability count.

micron::signal

Defined in header <micron/linux/process/signals.hpp>.

Strongly typed signal selectors and special disposition values.

Description

Named aliases include usr1/usr2, abort/iot, urgent/urgent_2, and the library's thread_suspend/thread_resume values 38/39. deflt, ignore, and error represent dispositions/sentinels rather than ordinary delivered signals. signal_maskable excludes only kill9 and stop; it does not validate every possible enum conversion. Name and core-dump helpers describe the provided named cases.

micron::signal_mask_guard

Defined in header <micron/linux/process/signals.hpp>.

Move-constructible scope guard that blocks a signal set and restores the saved thread mask.

Description

The default guard is inactive. Construction from a set or signal pack blocks immediately; release restores once. Copies are disabled and moving transfers the active flag. Repeated block calls replace saved with the already modified mask, so use one initial block per guard when restoration of the original mask is required. System-call failures are discarded and active is set even on failure.

micron::signal_t

Defined in header <micron/linux/process/signals.hpp>.

Inline signal set and handler table with synchronous wait operations.

Description

The signal-pack constructor optionally blocks when M=true. mask saves the prior mask once; destruction restores only when this object recorded a mask change. operator() and wait return the positive-errno sigwait convention and store the received signal internally. on_signal installs an action from the 65-entry table; it does not set SA_RESTART by default.

Defaulted copy and move operations copy saved-mask responsibility, so multiple objects can restore the same old mask. Avoid using those special members as an ownership-transfer protocol for an active masked object. critical_section is a separate explicit enter/leave saved-mask record; it has no destructor-based leave. Neither facility restores handler dispositions.

micron::posix::sigaction_t

Defined in header <micron/linux/sys/signal.hpp>.

Userspace signal-action record converted to the selected kernel signal-action layout.

Description

The handler union stores a one-argument handler or SA_SIGINFO callback, alongside sa_mask, flags, and a restorer pointer. The wrapper supplies mandatory x86 restorer trampolines; ARM uses its kernel-provided restorer path. It converts the action around rt_sigaction rather than passing this userspace record unchanged.

sigset_t reserves 128 bytes, but rt_sig* calls use the kernel's eight-byte mask. Set operations address signal numbers directly without validating bounds; use valid positive signal numbers and initialize the record. sigemptyset clears all words while sigfillset and set combinations initialize only the kernel-relevant prefix. siginfo_t is the 128-byte tagged event payload; access the _sifields alternative appropriate to si_code/signal. sigval_t stores a queued integer or borrowed pointer. stack_t describes caller-owned alternate-stack storage; sigaltstack does not allocate it.

micron::epoll_handle

Defined in header <micron/linux/poll.hpp>.

Move-only owning epoll descriptor with registration, rearming, and wait helpers.

Description

Construct with a cloexec boolean or legacy(size), then test valid: creation errors are retained as a negative descriptor rather than thrown. Destruction/close closes a valid descriptor and moving transfers it. Registered descriptors and user-data pointers remain borrowed; the wrapper does not own watched objects.

add/modify/remove/rearm return raw status; waits return event count, zero timeout, or -errno. Millisecond waits use -1 for indefinite waiting. wait_ns requests epoll_pwait2 and falls back to a millisecond wait after a failed feature gate/ENOSYS, rounding positive fractions upward and saturating at INT_MAX milliseconds. Edge-triggered draining and one-shot rearming remain the caller's responsibility.

The wrapper adds O(1) work per registration and O(returned events) caller processing; it does not scan a user-space watch array. poll helpers instead submit the full caller array. These local bounds do not specify the kernel's registration or event-delivery cost.

micron::posix::pollfd

Defined in header <micron/linux/sys/poll.hpp>.

Inline descriptor, requested-event mask, and returned-event mask submitted to poll/ppoll.

Description

nfds_t is unsigned long. The polling helper's reference parameter denotes the first of nfds contiguous records; pointer helpers likewise require accessible storage for the declared count. The wrapper does not allocate the array. poll_ok excludes error/hangup/invalid, but a readable final pipe segment may coexist with hangup and should still be inspected.

epoll_data is a union of borrowed pointer, descriptor, u32, or u64 cookie. epoll_event pairs it with an event mask; its layout is packed on amd64 and naturally aligned on the other targets. The aliases in micron name the same records. These records do not manage descriptors or referenced cookies.

micron::timerfd_t

Defined in header <micron/linux/process/timer.hpp>.

Move-only timer descriptor selected by system_clocks, with arm, disarm, and expiration-count reads.

Description

Construction creates a close-on-exec descriptor and throws on failure. nonblocking creates a replacement descriptor with the nonblock flag. The realtime/monotonic/boottime aliases select clock domains. Relative arm can set equal initial/period intervals or separate values; arm_once uses a zero period, and arm_abs sets absolute-time flags. A zero initial expiry disarms the timer.

wait retries EINTR and returns the accumulated u64 expiration count, throwing on a negative read. try_wait performs one read, returns zero and ok=false unless exactly eight bytes were read; on a blocking descriptor that operation can still block. gettime queries current remaining time, while the public current field is only the last submitted specification. Copy is disabled; moving transfers the descriptor, although move assignment lacks a self-move guard.

micron::posix::spawn_action

Defined in header <micron/linux/sys/spawn.hpp>.

Borrowed file-action description interpreted in the child before exec.

Description

spawn_action_type selects OPEN(path, flags, mode, target fd), CLOSE(fd), or DUP2(fd,newfd). spawn_file_actions_t contains allocated/used counts and a borrowed action pointer; iteration uses used directly without checking allocated. All pointed-to paths/actions must remain valid through the spawn handshake.

spawnattr_t holds optional session/process-group, signal mask/defaults, and scheduler settings. Initialize it with spawnattr_init before setting flags. spawn_ctx borrows path, argv, envp, actions, attributes, and an error descriptor. These are local protocol records, not owning process objects or general validation layers.

micron::key

Defined in header <micron/linux/process/keyctl.hpp>.

Copyable non-owning kernel key serial or special keyring selector.

Description

A zero ID is invalid; negative keyring_spec values are valid selectors. Destruction does not revoke, unlink, or invalidate a key. add_key/request/search return a zero key after a raw error and discard its errno. Other operations preserve raw status.

read, describe, and get_security return the kernel's required/true length, which can exceed the supplied buffer size. Do not treat a positive result as an in-bounds copied length without comparing it with capacity. key_perm is an OR-composable permission mask divided into possessor/user/group/other fields; keyring_spec identifies thread/process/session/user and request-related keyrings. The API adds constant local work and delegates lookup/lifetime to the kernel.

micron::posix::passwd_t

Defined in header <micron/linux/users.hpp>.

Fixed-capacity local /etc/passwd record returned by name/UID lookup.

Description

Name/password/gecos/home/shell fields are copied into bounded arrays and truncated with a terminator. UID/GID fields use the parsed numeric values. group_t similarly stores name/password/GID and one comma-separated members string, rather than a dynamic pointer list.

Lookups scan at most 65,535 bytes in a 64 KiB stack buffer per call; they implement neither NSS nor network/account-directory resolution. A false result conflates absence, I/O failure, and data beyond the buffer. Numeric parsing is a prefix parser with a 32-bit ceiling, not complete record validation. is_root tests real/effective UID zero and does not inspect effective capabilities or namespace authority.

micron::sysinfo

Defined in header <micron/linux/sys/sysinfo.hpp>.

Kernel sysinfo snapshot requested during construction.

Description

Fields contain uptime, fixed-point load averages, memory/swap/high-memory quantities, process count, and mem_unit. Memory quantities must be multiplied by mem_unit to obtain bytes. Construction discards syscall errors; initialized fields remain zero on failure. resources copies selected fields and can reload, but likewise preserves raw quantities and their separate mem_unit rather than converting them to bytes.

getpagesize returns the compile-time architecture default, including the conservative AArch64 page-size choice. getpagesizelive scans /proc/self/auxv for AT_PAGESZ once and caches a fallback on failure. That cache is an unsynchronized mutable static. get_phys_pages combines the queried size/unit with the live page size.

micron::posix::sysfs::cpu::cache::info_t

Defined in header <micron/linux/sys/sysfs.hpp>.

Bounded sysfs cache description with type, level, line size, associativity, sets, and byte size.

Description

read_info performs separate reads for each property; an unknown/missing type yields a zero description. A missing size can be reconstructed as line_size*associativity*sets. read_all scans successive indices until a missing type node or max_n, writing to caller-owned output; provide at least max_n records. l1d_line_size returns 64 if no L1 data cache is found.

micron::posix::cpu_set_t

Defined in header <micron/linux/sys/cpu.hpp>.

micron::uring::ring

Defined in header <micron/linux/sys/uring.hpp>.

Noncopyable, nonmovable owner of an io_uring descriptor and mapped submission/completion storage.

Description

A default object has no live descriptor. init performs setup and maps the returned rings and SQEs; shutdown/destruction unmaps those regions and closes the descriptor. Use a fresh or fully coordinated idle object for initialization and resize. The implementation maps ordinary kernel-backed rings; setup_no_mmap and registered-descriptor-only setup are not separate user-memory initialization paths here.

get_sqe/peek_sqe return available slots without advancing the published tail. Repeated get_sqe calls before advance_sq return the same slot. One preparer owns these ordinary tail accesses; acquire/release publication to the kernel and an atomic to_submit counter do not make multiple preparers/consumers safe. get_sqe128 needs a compatible wide/mixed setup and room for two base entries on mixed rings; the caller must publish the correct entry count.

submit tracks short submissions and recredits unsubmitted entries. SQPOLL avoids enter while the poller is awake unless a completion wait is requested. Waits may block; timeout waiting requires feat_ext_arg. EINTR during a completion wait is translated into a wake/retry-style result rather than proving that a completion arrived. wait_cqe loops until it consumes an event or gets an error.

resize_rings remaps and invalidates every retained in-ring pointer. Failure after a successful kernel resize can leave the descriptor live but the mappings unusable; shut it down. shutdown clears mapping owners but does not reset all counters, cached opcode bits, or public wired pointers, so live()==false is not a full state reset for arbitrary reuse. Pending I/O and external buffer lifetime require a separate completion/cancellation protocol.

Local slot acquisition/publication and one completion copy are O(1), with no per-request library heap allocation. Batch consumption is linear in copied completions. Initialization/resize use kernel mapping calls and storage proportional to ring capacities. Kernel work, registered-resource pins, pending operation storage, and blocking duration are additional costs.
