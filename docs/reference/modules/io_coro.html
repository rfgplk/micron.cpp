Coroutine I/O

From micron reference
micron reference › Input and output

Coroutine file ownership, borrowed descriptor streams, filesystem tasks, line/chunk processing, standard-stream helpers, and bounded small-file waves over the per-worker io_uring reactor. Ordinary operations return lazy micron::task values; descriptors, buffers, and referenced containers must remain valid until their operations finish.

Availability and interface selection

Public facilities are in micron::io::coro. Include <micron/coroio.hpp> to establish coroutine/reactor configuration before tasks headers. stdcoro.hpp defines MICRON_CORO_URING by default unless MICRON_CORO_NO_URING is selected; the coroutine-I/O subtree is conditionally absent when MICRON_CORO_URING is not defined. Enabling it after reactor headers were compiled out is rejected by the umbrella.

available() tests whether any reactor ring is live; it does not verify a particular descriptor, filesystem opcode, or current worker's registered-file support. Ordinary backend awaitables return -38 when no usable ring exists. wave::available instead requires the current worker's live ring and fixed-file registration. Reactor setup, scheduling, task ownership, and low-level timed awaitables are described with the coroutine execution facilities.

Tasks, buffers, and cancellation

A task initially suspends before its body runs. Retain and await it, run it through sync_wait, or transfer it to the scheduler. Dropping an unstarted task destroys its frame and performs no I/O. Each wrapper can allocate a coroutine frame through the task frame allocator; a raw-buffer overload does not imply that the complete coroutine call is allocation-free.

By-value paths, callback objects, and batch vectors become coroutine-frame state. A member coroutine retains its object's address, while pointer/reference parameters retain their referents. File/fd wrappers do not copy supplied bytes. Keep the wrapper, descriptor owner, input/output arrays, and referenced containers alive and stable from task creation through completion; moving/closing the owner during that interval does not redirect existing member calls to the new object.

Ordinary ring awaitables register the frame's cancellation flag and can return -125. A file has no separate cancellation method. Its close/destructor does not cancel or drain outstanding operations. Destroying a suspended ordinary task is not a completion barrier: its awaiter destructor unlinks cancellation metadata but does not drain the kernel operation that still references frame/buffer storage. Arrange completion before releasing those objects. Nonblocking read_some/write_some can take a direct syscall path and do not consult the ring cancellation flag.

The high-level wrappers expose no deadline argument and do not add transactions or rollback. Cancellation or a later transfer failure can leave bytes written, output objects partly changed, or a positive partial count. Allocation/callback exceptions use the task failure mechanism rather than becoming an io::error_t result automatically. wave has its own abandonment/drain behavior and bypasses ordinary task-cancellation registration.

Transfer and error conventions

Byte operations return task<max_t>: nonnegative values are transferred bytes, zero can mean EOF or zero progress, and negative values carry -errno. Invalid wrappers return their stored negative descriptor verbatim; the default -1 sentinel is not converted to -EBADF. Typed reads use option<T,io::error_t>; metadata tasks can instead return i32, bool, an owned file, or an option record.

Full read/write loops split requests into at most 1 GiB pieces, retry EINTR, and stop on EOF/zero progress. After earlier progress, a later error is represented by the positive transferred prefix rather than a separate error. Some callers require an exact count and convert a short transfer to -io_error; write_all and ordinary file.write can still return short positive values.

Ring-buffer exhaustion (-no_buffer_space) yields through reschedule_fair and retries without a fixed retry bound. EAGAIN retries yield for blocking/seekable descriptors, or poll readiness for nonblocking pollable descriptors; repeated readiness without progress is limited to eight retries. fd classification uses fcntl/fstat once and caches the result, so later external flag changes are not automatically observed. A some operation attempts one capped transfer and directly returns EINTR/EAGAIN instead of applying these full-transfer retries.

Let K be the number of attempted transfers and R retries: wrapper control work is O(K+R), plus scheduler/reactor/syscall costs and the actual byte/serialization work. There is no finite worst-case completion-time bound for device waits or repeated EINTR/ring exhaustion. Regular buffer indexing and descriptor access are O(1); kernel I/O costs are not made constant by an awaitable interface.

Filesystem operations

Paths are passed by value and retained until their pending kernel path access completes. open_file awaits openat, then synchronously fstats accepted descriptors for most modes. Its guard accepts regular/character files, returns -is_a_dir for directories, and -invalid_arg for other inode kinds; append, create, and readwritecreate skip this guard. A validation failure awaits close before returning a file carrying the negative result.

Copy, move, and fan-out

copy checks source metadata, rejects a destination already naming the same device/inode, uses the source's low nine permission bits for creation, opens the destination with create/truncate mode, and transfers successive chunks using positional I/O. It borrows a reactor fixed buffer when acquisition succeeds, otherwise allocates a 256 KiB buffer. Each written chunk must match its read count. It releases the slot on normal/error return and fsyncs the destination; it does not fsync a parent directory or roll back partial destination changes. The same-inode probe and subsequent open are separate operations.

move returns the rename result except for EXDEV, when it copies, fsyncs, then removes the source. That fallback is not atomic; a removal failure leaves both files. Copy work is proportional to bytes/chunk transfers plus metadata/sync costs, using one chunk of working storage. A live coroutine frame must reach its cleanup paths for the explicit fixed-slot release to run.

read_files and stat_many own a by-value vector of paths; write_files owns by-value write_spec records but borrows their data. They process consecutive windows of at most 64 through spawn_many, wait for the whole window, then move results into input order before starting the next window. Failures are per-entry option/error counts rather than fail-fast cancellation. For M items, result/dispatch work is O(M), storage includes O(M) results and at most 64 active child tasks, and I/O work is the sum of the individual operations. No throughput guarantee follows from the window size. Source-metadata failure in the copy probe is normalized to -io_error rather than retaining its original errno.

Functional and standard-stream helpers

with_file(path,mode,fn) owns a file during fn(file&), awaits an exact micron::task<R> callback result when returned, and wraps R in option<R,error_t>; void becomes io::unit_t. Plain callback results are returned directly inside the option. Only opening errors are added to that outer option; callback result/error types are not flattened. The no-mode overload opens read-only. modify(path,fn) opens readwrite and delegates the file's read/transform/rewrite operation.

read_lines<C>(path) copies each decoded line into an owned C and returns option<C,error_t>. The target-reference overload appends to existing target, returns a line count, and preserves already appended lines if a later read fails. Construction/storage costs include all retained line/container copies; callbacks in file.each_line/fold_lines and streaming helpers run synchronously and are not automatically awaited. read_lines calls push_back with a line lvalue, so its actual container must accept copying that line even though the factory constraint tests an rvalue push.

stdin_lines borrows fd 0 using kernel-position mode. read_in(out) appends all stdin bytes to an existing string until EOF, returning new bytes appended; a later error returns negative while leaving earlier appended bytes. write_out/write_err borrow fd 1/2 and full-write raw or string bytes without adding a newline. interact reads all stdin into one owned string before invoking fn(string&&) once, then writes its returned string to stdout. It is a whole-input transform, so memory grows with input rather than remaining line- or chunk-bounded.

Pipe and descriptor algorithms

fd_io/raw-fd/upipe overloads borrow descriptor ownership. read_some returns at most one capped operation; write_all uses the full-write loop. each_chunk(upipe,fn,chunk_size=4096) reads available chunks into one reusable buffer and calls fn(const byte*,size); write_with uses a producer returning usize and stops on zero, rejecting values above capacity and short writes. Callback buffer pointers are valid only during the callback. Supply a positive chunk size representable in u32; these custom sizes are cast without the ordinary 1 GiB cap.

splice(in_fd,out_fd,n) repeatedly requests at most 1 GiB through the ring with kernel-current offsets. It retries EINTR, yields on ring exhaustion, alternates input/output readiness polling on EAGAIN, and returns a positive moved prefix after later failure. It requires a kernel-supported splice pairing, ordinarily including a pipe; it does not allocate a user byte-copy buffer. tee(from,to,n) performs one at-most-1-GiB operation, returns its count/error directly, and adds no retry/full-length loop. Both leave descriptor ownership unchanged.

Concurrency and invalidation

No file, fd_io, line cursor, or wave object contains a mutex. file's logical cursor and fd_io/file classification caches are mutable shared state. Serialize cursor operations and owner close/move; explicit read_at/write_at avoid cursor advancement but still require stable descriptor ownership and nonconflicting buffers/regions. Cancellation is not a lock or destruction barrier.

Callbacks may execute after suspension on a resumed worker; ordinary wrappers re-resolve backend ring state at each awaited submission. Do not infer native-thread affinity from the initial call. Returned file-name references, line/chunk buffers, and wave results have the specific lifetimes stated below. Distinct task/output storage supports independent operations while the common reactor coordinates its own queues.

micron::io::coro::file

Defined in header <micron/io/coroutine/file.hpp>.

A move-only descriptor owner with an independent unsigned logical cursor, recorded name, and append policy.

Ownership and lifecycle

State is fd_t, u64 cursor, sstr<128> name, a cached classification, and an append flag. Default construction is invalid at cursor zero. Adopting fd_t transfers responsibility for closing it and records the optional name; it does not duplicate the descriptor. The path constructor performs a synchronous open, while open_file is the awaited factory with additional inode checks. Copying is deleted; moving transfers descriptor/name/cursor/append state and invalidates the source. Move assignment synchronously closes its previous descriptor first.

close and destruction call synchronous posix::close for a nonnegative descriptor, ignore its error, invalidate the handle, and reset cursor/cache. release returns fd_t and invalidates/reset state without closing; the caller then owns the descriptor. Neither waits for outstanding member tasks. The recorded name is descriptive, not a live directory entry; name returns a borrowed reference and as_path constructs a path value.

seek(off) and rewind change only the logical cursor, with no lseek or range validation. stat and size synchronously fstat; size returns a signed size/error. valid/bool test fd>=0; fd/raw_fd expose the stored descriptor. Accessors and cursor changes cost O(1), while name/path copies and system calls add their own costs.

Byte operations and positions

read/write use full loops at the logical cursor and advance it by positive counts. Appending write uses offset -1 and leaves the logical cursor unchanged. read_at/write_at use the explicit supplied offset and do not change the cursor. read_some/write_some use one capped attempt and update the same cursor/append policy after success.

Full file read/write operations pass explicit offsets without the some-path seekability translation. A nonseekable descriptor adopted as file can therefore fail positional full reads/writes; use fd_io/current-position helpers for streams. Some operations classify regular/block descriptors as seekable and use offset -1 for other kinds. They choose direct syscalls only for nonblocking pollable descriptors; blocking descriptors can still suspend in the ring even under a some name. External changes to descriptor flags/classification are not reflected after the cache is filled.

Typed representation and reads

Whole-value storage and costs

read<T>() default-constructs T and returns option<T,error_t>; read(T&) updates a borrowed object and returns bytes. Bulk/framed reads use fstat size when positive and greater than the offset; otherwise they allocate an initial 64 KiB probe buffer and double it until EOF. Growth copies accumulated bytes and can allocate O(B) temporary storage for B bytes. A probe-path error discards its temporary accumulation, while a known-size full read can report a positive prefix after a later failure.

Bulk reconstruction reserves elements+1 when reserve exists, checks max_size when available, and changes length through set_size/_buf_set_length when supported; a merely contiguous type must still supply sufficient writable capacity and compatible reconstruction. A framed read treats empty remainder as zero-byte success without invoking the decoder. Raw object representation is neither canonical serialization nor a portability contract. Total typed cost includes bytes, output growth, and the selected serializer/decoder work.

Returned read values own their members. User output references and writer inputs remain borrowed through completion. file name references are invalidated as associations by owner move/replacement/destruction; no element or file iterator is supplied.

Callbacks and rewriting

write(fn) calls a nonvoid nullary producer synchronously, retains its returned local value through the awaited write, and returns bytes. read(fn) deduces one input argument, reads it, advances the cursor, then synchronously invokes fn; void maps to unit_t and a nonvoid result is wrapped in option. These member callbacks do not automatically await a returned task.

modify rejects append mode, reads from offset zero, applies an in-place void(T&) or returning transform, computes the serialized size, writes at zero, checks the exact byte count, and truncates only when the new representation is shorter. On success it sets cursor to new bytes. It is not atomic, durable by default, or rolled back after callback/write/truncate failure.

read_with allocates one fp_window=16384 byte buffer and calls fn after each full-window read; write_with reuses that capacity for producer output and rejects oversized/short-write results. each_line/fold_lines allocate a line cursor and reusable string, process to EOF, and update the file cursor only on overall success; a later error does not undo callback effects. Streaming callback cost is added once per delivered chunk/line, and total memory includes the longest line where relevant.

Durability and extent operations

sync/datasync await fsync with ordinary/data-only flags; truncate awaits ftruncate; allocate awaits fallocate with mode zero. These return i32 status, not transferred-byte counts, and do not adjust the logical cursor. advise splits its range into at-most-1-GiB fadvise requests and attempts one zero-length request when len==0. There is no synchronous fallback here for an unsupported ring opcode. Destruction alone does not perform fsync.

micron::io::coro::fd_io

Defined in header <micron/io/coroutine/pipe.hpp>.

A borrowed raw-descriptor adapter for current-kernel-position byte I/O.

Fields and operations

Public fd defaults to -1 and __nb to an unknown classification sentinel. read_some/write_some perform one capped operation, while read/write use full loops; every operation passes offset -1 so kernel position, where meaningful, is used. Copying or moving copies descriptor/cache values and does not duplicate, close, or retain the OS descriptor. There is no destructor action or own close/release API.

Its owner must keep fd valid through every lazy operation. Writing a new fd into an already-classified adapter also requires resetting the cache; otherwise the old classification can select the wrong path. Use a fresh adapter for a newly borrowed descriptor. Control work is O(attempts+retries), without a byte-buffer allocation; coroutine frames and kernel transfer/wait costs remain. Concurrent member calls share cache state and kernel-position semantics.

micron::io::coro::__aline_cursor

Defined in header <micron/io/coroutine/__alines.hpp>.

The immovable buffered line cursor returned by file.lines and stdin_lines, borrowing its descriptor.

Storage and scanning

Although its name is internal, the public line factories return this type. It owns one chunk buffer, byte-position counters, error/EOF state, and an offset; it does not own or close the descriptor. Default chunk size is 4096, and zero requests choose that default. next(string&) is a lazy task that clears the string, appends segments until a newline/EOF, and returns whether one line was produced. The output string is caller-owned and can grow beyond the chunk size.

Newline is removed, and one carriage return immediately before it is stripped. A final nonempty unterminated line is emitted once, retaining any final carriage return. Empty input gives no line, a trailing newline gives no additional empty final line, and an empty newline-delimited line is returned normally. Error clears the current output, stores the error, and stops future next calls. The buffer and cursor must stay alive at stable addresses until pending next completes; copying/moving are deleted.

Offsets, lifetime, and complexity

file.lines starts at a snapshot of the file's logical cursor but advances only the cursor object's own offset; it does not update file.tell. Explicit each_line/fold_lines wrappers copy back the final consumed offset on success. stdin_lines uses offset -1 and advances the kernel stream position; read-ahead bytes held in a destroyed stdin cursor are not restored.

offset subtracts unread buffered bytes from the fetched-byte offset. error and at_eof are O(1) snapshots. Scanning costs O(bytes examined) plus string append/growth and awaited read/retry costs; working storage is one chunk plus the caller's longest line. Custom chunk sizes are cast to u32 without the full-transfer cap. Distinct cursors over a positional regular file have independent scan positions, while kernel-position cursors consume shared stream input.

Scope of checking

Recognition accepts direct await_ready/await_resume members or a member operator co_await, and checks conversion of await_resume to max_t. It does not inspect await_suspend, ADL operator co_await, ownership, retry behavior, cancellation, actual seekability, or a writable-position operation. micron::io::coro::write_spec

Defined in header <micron/io/coroutine/fsys.hpp>.

An owning path and borrowed byte-span record for one write_files item.

Fields and lifetime

path is io::path_t; data defaults to nullptr and len to zero. write_files takes a vector of these records by value, retaining paths but not copying the bytes addressed by data. Each item creates/truncates its destination and performs a full write without fsync. Keep every nonempty byte span readable until the batch task finishes, including windows not yet started.

Copy/move costs include the path value and O(1) pointer/count state; modifying the original byte array changes what later execution can observe. One write result is returned per input in original order. No record stores a completion state, ownership token, offset, or retry policy of its own.

Interpretation and lifetime

run can return zero while individual items failed or were unstaged; inspect every result. A read of exactly wave_cap bytes is conservatively marked partial even if that is the full file. Conversely, a short single read does not universally prove EOF. The data are raw bytes without an added terminator. A failed close can be followed by recovery slot eviction, while close_err still records the original completion.

Copying the record copies pointers, not names/data. Subsequent push/begin/run can overwrite the named/results/slab association, and destroying the wave invalidates borrowed storage. Copy any data needed beyond reuse. Indexed access is unchecked, and record copying/access is O(1).

micron::io::coro::wave

Defined in header <micron/io/coroutine/wave.hpp>.

An immovable owner of bounded small-file batches, fixed-slot chains, completion nodes, and a reusable mapped slab.

Capacity and storage

wave_items defaults to MICRON_CORO_WAVE_ITEMS=16, wave_cap to MICRON_CORO_WAVE_CAP=32 KiB, wave_sqes=3, and wave_name_cap=256. The object embeds wave_items short names/results/slot numbers and three SQEs/completion nodes per item; its first nonempty run maps wave_items*wave_cap bytes and touches each page before submission. Default slab size is 512 KiB. Later runs reuse it.

Macro overrides must keep positive counts, slab products, u32 read lengths, and u16 item indices representable; no general runtime validation enforces those constraints. Copying/moving are deleted because kernel completion records address embedded nodes. The supplied directory fd is borrowed and must remain valid through the batch; it is not closed by the wave.

Batch protocol

After previous work has completed, begin(dirfd) sets the directory base and resets item/progress/partial telemetry. push copies a nonempty terminated path shorter than 256 bytes and rejects full capacity, null, empty, or longer input. Paths can be relative to dirfd or absolute; the wrapper does not prohibit slashes. full/empty/size report pushed items. clear resets pushed/staged counts, without freeing the slab or clearing cumulative stranded slots.

run awaits one batch of as many complete three-SQE chains as current ring room and fixed slots permit. Each chain is O_RDONLY|O_NOFOLLOW openat_direct, one offset-zero read into its slice, and close_direct. Open uses a soft link to read; read uses a hard link to keep close attached on read failure. Remaining items become unstaged. There is no automatic conventional-read fallback or subsequent wave to finish them.

An empty run returns zero. Slab mapping failure returns -out_of_memory before initializing this run's result records. Other batch submission failures set err on staged records; per-item open/read/close failures are separate from the run return. Without current-worker staging resources, all items can be unstaged with return zero. begin/clear/push/run must not overlap a pending run.

Cleanup and cancellation

After awaiting completions, run reclaims slots on the recorded originating ring. If a successful open was not followed by a successful close, it tries registered-file eviction first. Failed eviction increments stranded and withholds that slot from the free bitmap. stranded is cumulative and is not reset by begin. Its nonzero value describes a retained backend resource rather than a data-read error.

A wave is not registered in the ordinary task cancellation registry, so cancelling the awaiting task does not immediately cut its chains short. Destruction requests abandonment, synchronously cancels/drains outstanding SQEs, then waits for any already-resumed continuation to report completion before reclaiming slots and unmapping. Draining has no finite wait bound while kernel/reaper progress is required. The final settle loop has a fixed spin/yield budget; failure returns from the destructor without releasing the slab/remaining slots. Destruction can therefore block and has an explicit resource-leak fallback.

The wave and its run coroutine must remain stable until completion; destruction is not a supported concurrent access protocol for callers still examining/mutating the object. Normal reuse requires completing run first, then consuming/copying result data before another run overwrites it.

Complexity and selection

For W pushed items, staging/result/reclamation control work is O(W) plus per-name scanning/copy, and at most 3W SQEs are staged. First-run mapping/prefault work touches O(wave_items*wave_cap/page_size) pages; read work is bounded by W slab slices plus kernel I/O waits. Resident storage is O(wave_items*wave_cap) plus O(wave_items) embedded metadata. Destruction adds cancellation/drain/settle costs.

inert becomes true when at least wave_items items have been staged since telemetry reset and more than half were partial. It is advisory: run does not stop when inert is true. Choose wave for batches whose single-read capacity and registered-file requirements fit; ordinary file/read_files supports remainder growth and general typed/streaming operations. Linked batching changes submission structure without establishing a workload-independent speed advantage.
