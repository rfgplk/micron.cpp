The micron reference describes the library’s facilities, function overloads, and headers. Choose a section below, browse the function, header, and symbol indexes, or search by name.

This reference is self-contained and can be opened from a local filesystem.

Language support

Types and language supportFundamental integer, character, floating-point, and Linux ABI types; byte order, fixed bit storage, and the foundation header.
Build configurationCompile-time build predicates, allocator/exception defaults, feature gates, and encoded library version information. Configuration must be consistent before dependent headers are included.
Bit operationsValue-oriented masks, rotations, bit counts, byte operations, alignment arithmetic, and extraction/deposition helpers in micron.
Type traits and conceptsCompile-time type predicates, transformations, expression constraints, and container dispatch tags. Traits describe types; concepts select overloads using the requirements listed below.
Ranges, iterators, and viewsArithmetic ranges, iterator adapters, owning contiguous sequences, and non-owning pointer descriptors. Storage ownership is specific to each type: slice owns heap storage and span owns embedded elements.
Functions, tuples, and sum typesOwning callable wrappers, product types, in-place sum types, matching, callable combinators, and process-control helpers. Product and sum storage is embedded; callable wrappers can allocate for large targets.
Errors and exceptionsSigned error results, thread-local error state, exception categories, allocation failures, and thread/process termination. The selected runtime mode determines whether exception reporting throws or terminates.
ReflectionCompile-time reflection vocabulary and queries in micron::meta, with field, enum, tuple, comparison, and hashing helpers in micron::reflect.

Containers and strings

ArraysArray containers provide fixed extents, sorted bounded sequences, persistent indexed values, multidimensional storage, and separate typed columns. Their storage and update models differ; an array-family tag does not imply inline storage or a fixed logical size.
VectorsThe vector family contains resizable contiguous buffers, bounded inline storage, value-returning sequences, a persistent trie, an overwrite ring, and two containers that preserve element addresses during growth. Their capacity, copying, and synchronization contracts are specific to the selected type.
StringsCharacter-storage containers, borrowed string ranges, constexpr literal strings, formatting, Unicode validation/transcoding, and numeric conversion. Container lengths are code-unit counts; selecting a wide character type alone does not add Unicode decoding or normalization.
MapsAssociative containers storing keys and mapped values. The implementations differ in key equivalence, growth, ordering, persistence, and synchronization; their insertion results are not interchangeable.
TreesOrdered, hashed, prefix, and spatial tree containers. The family includes a red-black set, an ordered B+ map, a hash-byte adaptive radix map, a sequence-prefix trie, two fixed-universe point indexes, and an R*-style box index.
QueuesQueue containers provide mutable FIFO storage, persistent FIFO values, bounded concurrent rings, owner/thief work deques, and inline callable dispatch. Producer and consumer cardinality, capacity rules, and payload ownership are specific to each type.
StacksLIFO containers include growing heap buffers, bounded inline storage, a mutex-serialized buffer, a shared persistent list, and two value-returning inline snapshot forms. Container tags and prefixes do not by themselves specify allocation or checking behavior.
HeapsPriority containers include a fixed-capacity array max-heap, a node-based max-heap with deferred consolidation, a mutex-protected array min-heap, a tournament-based comparator heap, and an implementation-facing binomial heap. The directory also contains a Bloom membership filter.
SetsKey-only adapters over the map implementations. Five set classes provide fixed, growing, persistent, and hash-identity storage; each retains its underlying map's capacity, equivalence, and invalidation rules.
ListsSingly and doubly linked owning sequences allocate one node per element. They provide element cursors for traversal and a separate raw-node-pointer interface for insertion, erasure, and chain transfer. Neither caches its length or final node.

Algorithms

AlgorithmsEager algorithms in micron inspect, transform, copy, reduce, and reorder ranges. Sequence, associative-container, and tree overloads have distinct requirements and result conventions.
Functional algorithmsEager functional algorithms in micron::fp return transformed containers, tuples, or scalar/optional results. Curried _c functions return callable objects that retain their supplied arguments.
Lazy algorithmsPull-based range adaptors in micron::lz compose with operator|. Most adaptors defer element work until iteration; ordering, right scans, and some window operations can materialize their input when applied.
SortingSorting, order-statistic, and extraction functions in micron::sort. The default comparison sorter is introsort; stable sorting delegates to merge sort. Specialized integer and floating-bit radix paths provide noncomparison alternatives.
HashingNoncryptographic hashes, incremental XXH64 state, and codec checksums. General hashes live in micron or micron::hashes; checksum functions use explicit initial values and do not share the default-hash dispatch policy.
Regular expressionsByte-oriented regular expressions compiled to a Thompson program. regex owns a runtime program; cmatch<pattern> provides a constexpr-capable pattern form. Capture searches use a Pike virtual machine, while selected boolean searches can use a bounded DFA accelerator.

Memory management

AllocationAllocation facilities reserve raw byte storage, adapt allocator protocols, and manage bulk storage lifetimes. A byte chunk describes a grant; an owning buffer, resource, container, or caller is responsible for returning it through the matching allocator. Allocating storage and constructing C++ objects are separate operations.
Memory operationsMemory operations copy, move, fill, compare, and search caller-provided ranges. Their counts have API-specific byte or element units. Raw storage operations do not infer destination capacity, construct arbitrary nontrivial objects, or synchronize concurrent accesses.
Pointer utilitiesPointer wrappers for unique, shared, immutable, atomic, and explicit lifetime management, plus raw observation and address utilities.

Concurrency

Atomic operationsAtomic facilities provide compiler-builtin operations on small values, atomic pointer publication, non-owning atomic access, and a separate lock-serialized wrapper for general objects. These interfaces have different ownership and synchronization contracts.
Mutexes and locksExclusive, shared, queued, recursive, and futex-backed locks provide distinct waiting and ownership protocols. Scope wrappers release acquired locks; they do not own the lock objects themselves.
SynchronizationNative-thread synchronization includes permit counters, condition epochs, completion counters, promises, guarded value cells, and polling helpers. These blocking and polling interfaces are distinct from the coroutine-aware awaitables in tasks/.
ThreadsNative-thread objects own or borrow worker stacks, retain backend join state, and publish results through a small controller payload. Arenas add fixed-capacity thread ownership or persistent queued workers; CPU and scheduler wrappers configure Linux execution separately.
Parallel algorithmsParallel range algorithms return lazy task objects and divide random-access ranges into coroutine work. A separate reusable scan workspace accepts a caller-supplied joined executor without a coroutine dependency.
Tasks and coroutinesLazy C++ coroutine tasks, continuation-stealing scheduling, manually resumed stackful routines, and asynchronous synchronization share frame/lifetime support but have distinct execution and ownership protocols.

Input and output

Input and outputLinux descriptor operations, byte streams, pipes, printing sinks, and synchronous line traversal. Descriptor values and borrowed buffers are separate from owners; most data paths return a byte count or a negative error, while selected stream and setup interfaces throw.
Files and filesystemFile descriptor owners, whole-file and windowed processing, lexical paths, directory traversal, and caches of open handles. Most path queries return sentinels on metadata failure; opening constructors and selected convenience reads can throw. These interfaces operate on trusted Linux pathnames and do not provide a confined path-resolution policy.
Asynchronous file I/OAn io_uring engine, completion-waiting descriptor/file operations, linked SQE chains, and bounded-concurrency path batches. Ordinary flash read/write/file helpers wait for completion before returning; queue_* plus explicit submit/reap/wait expose the asynchronous protocol. One engine requires exclusive, coordinated use of its submission and completion queues.
SerializationSerialization provides recursive native-representation MFR1 frames, raw byte/object dumps, and a separate bounded canonical little-endian scalar/byte interface. These encodings have different portability and reconstruction requirements.
Terminal controlTerminal support provides indexed escape-sequence templates and Linux terminal-attribute records. Selecting a constant does not emit output, negotiate terminal capabilities, or restore changed terminal state.
Input devicesInput support separates raw evdev device ownership and callback polling from keymap translation and Wayland seat events. Raw devices expose kernel events; translation requires a selected keymap and modifier-state protocol.
Coroutine I/OCoroutine file ownership, borrowed descriptor streams, filesystem tasks, line/chunk processing, standard-stream helpers, and bounded small-file waves over the per-worker io_uring reactor. Ordinary operations return lazy micron::task values; descriptors, buffers, and referenced containers must remain valid until their operations finish.

Numerics and mathematics

Mathematical functionsScalar arithmetic policies, floating-point elementary/special functions, compensated reductions, numerical array operations, activations, and compile-time constants. Specialized numeric containers have their own module pages.
Numeric typesNumeric limits, complex and rational values, compact floating-point storage, double-double arithmetic, and decimal conversion results.
Symbolic expressionsArena-owned symbolic expression DAGs with exact rational constants, declared assumptions, local simplification, differentiation, limited integration/substitution, and S-expression output.
Packed mathematical functionsLane-wise real mathematical functions over raw SIMD register types, with target-specific polynomial, table, CORDIC, hardware and scalar-lane implementations. A packed type's existence does not imply that every mathematical function has an overload for its width or enabled ISA.
Arbitrary-precision integersSigned and unsigned owning integers with dynamic or bounded magnitude storage; modular contexts, number-theory operations, text conversion, and caller-buffer multi-precision limb algorithms. Bounded arithmetic truncates to the configured magnitude width rather than reporting overflow.
BLASReal arithmetic vector and matrix kernels in level1, level2 and level3 namespaces, with borrowed strided views, compile-time operation/layout tags, mixed-input matrix multiplication and reusable packed GEMM scratch storage. Kernels mutate caller-provided output buffers; ordinary BLAS interfaces do not resize outputs or return general validation/status records.
Matrices and linear algebraFixed and dynamic dense matrix storage, borrowed row/column-major views, and real linear algebra. Fixed matrices keep elements inline; dynamic matrices own serial-allocator vectors. Factorizations, solves, spectral decompositions, matrix functions and polynomial utilities use explicit result records or documented numeric failure values.
GraphsOwning adjacency, edge-list, compressed-row, dense, bit-packed, and fixed-capacity graphs; borrowed graph adapters; graph algorithms, matrix conversions, and text/binary serialization. Representation policies control direction, parallel edges, loops, properties, and descriptor stability.
Fourier transformsComplex and packed-real discrete Fourier transforms, DCT/DST transforms, fixed-kernel convolution, frequency/shift helpers, and reusable serial or executor-based parallel workspaces. Plans own precomputed coefficients; execution borrows caller input, output, and scratch storage.
Random numbersDeterministic integer engines, width-aware uniform draws, rejection/inverse-transform distributions, cached distribution objects, buffer filling, and sequence sampling. Engine state is explicit and owned; the dynamic-arity Dirichlet distribution instead borrows its parameter array.
IntegrationAllocation-free fixed and adaptive quadrature, sampled-data integration, finite differences, Monte Carlo estimators, and explicit ordinary-differential-equation solvers. Compile-time workspaces embed bounded storage; runtime ODE workspaces borrow caller arrays.
Splines and interpolationOwned scalar interpolants, piecewise polynomials, B-splines, smoothing/least-squares fits, parametric curves, and tensor-product B-spline/NURBS fields. Construction copies input samples or controls into micron vectors; evaluation borrows the resulting representation and may update a lookup cache.
GeometryFixed-size geometric primitives, component translations/scales, homogeneous 2D/3D transforms, graphics projection/view matrices, and three-dimensional point-set alignment. Values own embedded vectors or matrices; operations borrow input values without retaining addresses or allocating shape-dependent storage.
ManifoldsCompile-time manifold policies over fixed vector/matrix point representations, concrete SO/SE Lie-group values, tangent-space/metric operations, and borrowed batched SO3/SE3 actions. A manifold policy describes operations; its point and tangent values hold the numeric data.
Quantities and quaternionsFixed arithmetic vectors, named floating-point vectors, dynamically allocated vectors, strided vector views, fixed three-dimensional tensors, and quaternion rotation algorithms. Quantities with embedded components own those components; vec_view borrows external elements. The dedicated quaternion algebra uses Hamilton products and explicit rotation conventions.
Sparse matricesOwned compressed sparse row/column matrices and indexed sparse vectors, with real-valued products, norms, conversions, and triangular solves. Public arrays represent stored entries; explicit zeros and duplicate indices are not automatically removed.
Computation graphsStatic-shape numeric computation graphs parametrized by a compile-time operation registry and memory-domain provider. A builder finalizes descriptors, dependencies, aliases, and reusable arena slots; a session binds inputs and executes the resulting plan.

System interfaces

Date and timeClock reads and interval measurement, typed durations, Gregorian calendar values, time-zone transition tables, and allocation-free timestamp parsing and formatting.
WebAssembly targetThe native wasm32 backend uses linear memory, compiler WebAssembly instructions, and a versioned JavaScript host ABI. It supplies allocation, diagnostics, clocks, worker threads, exceptions, and software binary128 arithmetic without a WASI runtime.
Linux interfacesDirect Linux system calls, process creation and observation, signal handling, event polling, kernel keyrings, system information, and kernel ABI records.
SecurityLinux seccomp filter construction, Landlock rulesets, namespace handles, SELinux labels, and child-process setup with explicit policy/result types.
Dynamic loadingExplicit native shared-object loading with dependency traversal, eager relocation, symbol scopes, generation-checked handles, and optional host validation/resolution callbacks.
ELFNative shared-object mapping and symbol handles, low-level ELF records and relocation support, plus read-only ELF32/ELF64 file inspection with normalized result rows.
Module attachmentNative host/guest attachment callbacks, fixed ABI entry records, continuation dispatch, and host TLS-surplus bookkeeping for specially linked micron modules.

Graphics

GraphicsLinux window-system integration for X11 and Wayland, shared by the OpenGL and Vulkan wrappers. Displays and windows own native resources; the rendering backends add explicit context, device, memory and submission facilities.
OpenGLOpenGL object owners, Linux GLX/EGL context integration and a generated core procedure table. The high-level interface uses current-context GL state and dynamically resolved process-wide entry pointers.
VulkanVulkan instance/device and resource owners, borrowed queue/command/descriptor views, explicit GPU memory allocation, synchronization and Linux presentation. Generated typed ABI records and a 252-command dispatch table support lower-level native calls.

SIMD

SIMDRaw register aliases, fixed-size SIMD packet classes, intrinsic wrappers and bounded buffer operations selected by target architecture and enabled instruction-set features. Register width, lane interpretation and the available operation set are separate properties; the implementations do not provide a uniform container or arithmetic interface across every target and width.

Implementation notes

Implementation notesCompiler-required support types, architecture number tables, formatting classification, and the freestanding exception-runtime implementation. Internal names describe implementation contracts rather than stable application interfaces.
